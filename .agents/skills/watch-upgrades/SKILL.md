# 盯著升級跟護盾

## 這一趟在做什麼

工人的升級、實驗室的研究、護盾都是倒數, 而且**畫面寫著還剩多久**: 讀一次、算出那個時刻、睡到那時候再看, 中間模擬器不必有人管.

## 先讀一次

```bash
uv run ai_coc status --label watch
```

它答當下**那一個**世界的工人、實驗室、倉庫跟護盾, **不切世界**. `result.json` 長這樣:

```json
{
  "world": "night",
  "builder": {"role": "builder", "world": "night", "outcome": "read",
              "free": 0, "total": 3,
              "jobs": [{"name": "X連弩", "remaining": 25020}, ...]},
  "lab":     {"role": "lab", "world": "night", "outcome": "read",
              "free": 0, "total": 1,
              "jobs": [{"name": "變異亡靈", "remaining": 324000}]},
  "stock":   {"world": "night", "filled": {"gold": "100%", "elixir": "100%"}},
  "shield":  null
}
```

`remaining` 是秒, 最快的那個要自己取最小值. `name` 讀不到是空字串, 沒有 API key 時全空, 倒數照樣準.

**`outcome` 說這一次讀成功了沒**, 五種:

- `read` —— 面板開了而且至少有一列, `jobs` 就是那些列
- `idle` —— 面板沒開, 但牌子上的數字說每一格都空著, 所以**推論**沒有東西在跑. 不用重讀
- `not_a_village` —— 畫面不是村莊, `world` 也是 `null`
- `no_badge` —— 那一格牌子沒出現在這張畫面上. 主村過幾分鐘再讀; 夜世界問護盾永遠是這個, 重讀不會變
- `panel_shut` —— 面板點不開

`no_badge` 跟「數字也讀不到的 `panel_shut`」欄位一模一樣, 下一步卻不同, 只有 `outcome` 分得出來. **不要比對 log 裡的句子**, 那些字隨時會改.

**兩個世界各讀一次**, 中間自己 `uv run ai_coc world --go day` / `--go night`, `status` 刻意不切. 讀完想一下要把遊戲留在哪個世界.

## 算出時間, 不要輪詢

兩個世界所有的 `remaining` 跟護盾倒數取**最小**, 就是下一件要講的事. 用你自己的排程能力睡到那個時刻前後 (Claude Code 裡是 `ScheduleWakeup`, 或者使用者開的 `/loop`), 醒來再跑一次 `ai_coc status` 確認.

**不要每十分鐘戳一次**, 這是使用者自己否掉 `--watch` 的理由: 等待是算術不是觀察, 而睡著的迴圈會佔住 `~/.ai_coc/state.json`, 讓別的 session 以為模擬器在忙. 一整晚一兩次讀取, 不是四十八次. 只有兩種情況密一點:

- **讀不到**: `remaining` 是 `null`, 或 `outcome` 是 `no_badge` / `panel_shut`, 過幾分鐘再讀. `idle` 不算, 那是真的沒東西在跑
- **快到了**: 最後幾分鐘縮短, 遊戲的倒數跟你的時鐘會差幾十秒

## 護盾比工人重要

**只有護盾到期會賠錢**: 過期村莊就能被打. 實測 2026-09-17 填到 26M/26M/430k 之後放著, 九個半小時後剩 2.3M/4.6M/299k. 所以護盾跟工人一起比, 誰先到算誰, 而且常常是護盾先到.

`shield` 的 `null` 要配 `world` 一起讀:

- `{"up": false, "remaining": null}` —— **牌子寫「無」, 村莊現在就可以被打**. 馬上講, 不等下次醒來
- `{"up": true, "remaining": 22080}` —— 還有這麼多秒
- `null` 而 `world` 是 `"night"` —— 夜世界本來就沒有護盾. 不用追
- `null` 而 `world` 是 `"day"` —— **說不上來, 過幾分鐘再讀**: 牌子沒照到、被全螢幕面板蓋住或倒數讀不出來, 判讀器不猜. `{"up": true, "remaining": null}` 這個形狀不會出現

## 講給使用者聽

時間到就講, 要具體: 哪個世界、什麼好了、幾個工人閒著、倉庫多滿.

**推播是關的**: `PushNotification` 在這台機器上只回 `Push not sent`, 他收不到. 要讓訊息推到他手機用選擇題 (`AskUserQuestion`), 但**沒有東西要他決定就不要問**, 寫在回覆裡就好.

要問的時候, 選項是他真正的那幾條路. 最常見的是工人空了要不要花: 那是 spend-loot, 而且**他沒開口要花就不要自己花** (farm 寫得更完整).

## 什麼時候收工

- 他要看的那件事發生了, 講完就收工
- 他說停
- **連續三次讀不到畫面**: 兩個 plate 的 `outcome` 都是 `not_a_village` (等於 `world` 是 `null`), 連著三次. 那是遊戲或模擬器的問題, 停下來講, 不要一直重試. 看欄位不要看句子, 那句話只在 `run.log` 裡
- 排到的下一次醒來超過他交代的範圍 (他說「盯到今天晚上」而最快的要三天), 就直接講還要多久, 不要排一個他沒要的鬧鐘

**收工就真的收工**, 不要在背景留迴圈「以防萬一」: 村莊的保護是遊戲自己給的護盾.
