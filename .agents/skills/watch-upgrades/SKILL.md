# 盯著升級跟護盾

## 這一趟在做什麼

工人的升級、實驗室的研究、護盾都是倒數, 而且**畫面寫著還剩多久**: 讀一次、算出那個時刻、睡到那時候再看, 中間模擬器不必有人管.

## 做完的樣子

使用者收到的是回覆裡一段具體的話, 有東西要他決定時再加一題選擇題. 只在下面幾個時刻出現:

- **他要看的那件事到了**: 醒來重跑 `status` 確認過, 講哪個世界、什麼好了、幾個工人閒著、倉庫多滿 (見「講給使用者聽」)
- **護盾讀到「無」**: 讀到的當下就講, 不等排好的下一次醒來 (見「護盾比工人重要」)
- **最快的那件超過他交代的範圍**: 直接講還要多久, 不排鬧鐘
- **兩格都讀到不是村莊**: 停下來問他玩完了沒 (見「什麼時候收工」)

這一趟只讀不花: 工人空了要不要花是給他選的題目, 不是你接著做的事. 講完就收工, 背景不留排程也不留迴圈.

## 先讀一次

```bash
uv run ai_coc status --label watch --agent <名字> --session <session id> --mission "盯升級跟護盾"
```

`--agent`、`--session`、`--mission` 每次都帶, 理由在 `AGENTS.md` 的 Say who is driving.

它答當下**那一個**世界的工人、實驗室、倉庫跟護盾, **不切世界**. `result.json` 長這樣 (節錄, `stock` 另外還有 `held` 跟 `capacity`):

```json
{
  "world": "night",
  "builder": {"role": "builder", "world": "night", "outcome": "read",
              "free": 0, "total": 3,
              "jobs": [{"name": "X連弩", "remaining": 25020}, ...]},
  "lab":     {"role": "lab", "world": "night", "outcome": "read",
              "free": 0, "total": 1,
              "jobs": [{"name": "變異亡靈", "remaining": 324000}]},
  "stock":   {"world": "night", "filled": {"gold": "100%", "elixir": "100%"}},
  "shield":  null
}
```

`remaining` 是秒, 最快的那個要自己取最小值. `name` 讀不到是空字串, 沒有 API key 時全空, 倒數照樣準.

**`outcome` 說這一次讀成功了沒**, `builder` 跟 `lab` 各一個 (護盾不在這裡, 看 `shield`), 五種:

- `read` —— 面板開了而且至少有一列, `jobs` 就是那些列
- `idle` —— 面板上一列都沒讀到, 但牌子上的數字說每一格都空著, 所以**推論**沒有東西在跑. 不用重讀
- `not_a_village` —— 畫面不是村莊, 這一格的 `world` 也是 `null`. 兩格都是就不重讀, 見「什麼時候收工」; 只有一格是 (另一格讀到了村莊) 就當成下面的「讀不到」, 過幾分鐘再讀
- `no_badge` —— 那一格牌子沒出現在這張畫面上 (例如被寶石雨蓋住). 過幾分鐘再讀
- `panel_shut` —— 面板點不開

`no_badge` 跟「數字也讀不到的 `panel_shut`」欄位一模一樣, 只有 `outcome` 分得出來. **不要比對 log 裡的句子**, 那些字隨時會改.

**兩個世界各讀一次**, 中間自己 `uv run ai_coc world --go day` / `--go night`, `status` 刻意不切. 讀完想一下要把遊戲留在哪個世界.

## 算出時間, 不要輪詢

兩個世界所有的 `remaining` 跟護盾倒數取**最小**, 就是下一件要講的事. 用 runtime 自己的排程能力 (或者使用者開的定時迴圈) 睡到那個時刻前後, 醒來再跑一次 `ai_coc status` 確認. 讀之前照 `AGENTS.md` 的 Look before driving 再看一次 `state.json`: 睡了幾個小時, 模擬器上可能已經有別的 run 在跑, 這時下 `status` 會借走它 (它帶 `--yield` 的話), 讀完馬上 `uv run ai_coc giveback`, 不然它要等 30 分鐘才接回去 (見 `.agents/skills/farm/references/running.md` 的「絕對不要同時跑兩個」).

**不要每十分鐘戳一次**, 這是使用者自己否掉 `--watch` 的理由: 等待是算術不是觀察, 而 `--watch` 那種在程序裡睡的迴圈會佔住 `~/.ai_coc/state.json`, 讓別的 session 以為模擬器在忙. 一整晚一兩次讀取, 不是四十八次. 只有兩種情況密一點:

- **讀不到**: `remaining` 是 `null`, 或 `outcome` 是 `no_badge` / `panel_shut`, 或只有一格是 `not_a_village`, 或主村的 `shield` 是 `null` (見「護盾比工人重要」), 過幾分鐘再讀. `idle` 不算, 那是真的沒東西在跑
- **快到了**: 最後幾分鐘縮短, 遊戲的倒數跟你的時鐘會差幾十秒

## 護盾比工人重要

**只有護盾到期會賠錢**: 過期村莊就能被打. 實測 2026-09-17 填到 26M/26M/430k 之後放著, 九個半小時後剩 2.3M/4.6M/299k. 所以護盾跟工人一起比, 誰先到算誰, 而且常常是護盾先到.

`shield` 的 `null` 要配 `world` 一起讀:

- `{"up": false, "remaining": null}` —— **牌子寫「無」, 村莊現在就可以被打**. 馬上講, 不等下次醒來
- `{"up": true, "remaining": 22080}` —— 還有這麼多秒. **十小時以上的護盾可能少讀十小時** (#260, 還沒修): 被打之後拿到長護盾時, 把讀到的時間當下限, 並且**當下**立刻再讀一次 `status --record`, 那次 `frames/` 裡的 `*_shield.png` 就是給 #260 的畫面, 修它缺的就是這張. 等下一次醒來才留就太晚了: 那時兩位數小時的牌子多半已經不在
- `null` 而 `world` 是 `"night"` —— 夜世界本來就沒有護盾. 不用追
- `null` 而 `world` 是 `"day"` —— **說不上來, 過幾分鐘再讀**: 牌子沒照到、被全螢幕面板蓋住或倒數讀不出來, 判讀器不猜. `{"up": true, "remaining": null}` 這個形狀不會出現

## 講給使用者聽

時間到就講, 要具體: 哪個世界、什麼好了、幾個工人閒著、倉庫多滿.

**推播是關的**: 推播通知在這台機器上只回 `Push not sent`, 他收不到. 使用者說過選擇題會推到他手機, 但推播關著時送不送得到還沒量過 (farm 的「他交辦裡有「通知我」的時候」), 所以要講的一定寫在回覆裡; **沒有東西要他決定就不要問**.

要問的時候, 選項是他真正的那幾條路. 最常見的是工人空了要不要花: 那是 spend-loot, 而且**他沒開口要花就不要自己花** (farm 寫得更完整).

## 什麼時候收工

- 他要看的那件事發生了, 講完就收工
- 他說停
- **讀到一次不是村莊就停**: 兩個 plate 的 `outcome` 都是 `not_a_village` (頂層的 `world` 多半也是 `null`, 但它還會退回去看倉庫那一次讀取, 所以以這兩個 `outcome` 為準). 常見的原因是使用者正在手機上玩, 模擬器那邊被登出了, 而每跑一次 `ai_coc status` 都會經過 `ensure_coc` 把遊戲搶回來, 等於把他從手機上踢掉 (`AGENTS.md` 的 Driving the game). 所以不重試: 停下來, 用選擇題問他玩完了沒 (見「講給使用者聽」, 回覆推不到他手機上), 他說可以了再讀. 看欄位不要看句子, 那句話只在 `run.log` 裡
- 排到的下一次醒來超過他交代的範圍 (他說「盯到今天晚上」而最快的要三天), 就直接講還要多久, 不要排一個他沒要的鬧鐘

**收工就真的收工**, 不要在背景留迴圈「以防萬一」: 村莊的保護是遊戲自己給的護盾. 睡著等下一次醒來的你, `state.json` 看不到, `ai_coc stop` 也停不了 (`AGENTS.md` 的 Two drivers that file cannot show), 留下的排程只有你自己收得掉.
