# 盯著升級跟護盾

## 這一趟在做什麼

村莊裡會跑完的東西有三種: 建築工人手上的升級、實驗室的研究、還有頭上那張護盾. 三種都是倒數, 而且**畫面自己就寫著還剩多久** —— 所以這件事不是「一直看著」, 是讀一次、算出那個時刻、睡到那時候再看一次.

使用者要的是那個時刻到了有人告訴他. 中間那幾個小時你不必醒著, 模擬器也不必有人管.

## 先讀一次

```bash
uv run ai_coc status --label watch
```

它答當下**那一個**世界的工人、實驗室、倉庫跟護盾, **不切世界**. 回來的 `result.json` 長這樣:

```json
{
  "world": "night",
  "builder": {"free": 0, "total": 3,
              "jobs": [{"name": "X連弩", "remaining": 25020}, ...]},
  "lab":     {"free": 0, "total": 1,
              "jobs": [{"name": "變異亡靈", "remaining": 324000}]},
  "stock":   {"filled": {"gold": "100%", "elixir": "100%"}},
  "shield":  null
}
```

`remaining` 是秒. 每一列的 `name` 是那個項目叫什麼, 讀不到就是空字串 —— 沒有 API key 的時候全部都是空的, 倒數照樣準.

**兩個世界要各讀一次**, 中間自己 `uv run ai_coc world --go day` / `--go night`. 這個指令刻意不幫你切: 一個會自己坐船的狀態查詢就不是狀態查詢了. 讀完記得想一下要把遊戲留在哪個世界比較好.

## 算出時間, 不要輪詢

把兩個世界讀到的所有 `remaining` 跟護盾的倒數放在一起, 取**最小**的那個, 那就是下一件值得講的事. 用你自己的排程能力睡到那個時刻前後 (Claude Code 裡是 `ScheduleWakeup`, 或者使用者開的 `/loop`), 醒來再跑一次 `ai_coc status` 確認.

**不要每十分鐘戳一次.** 這條是使用者自己否掉 `--watch` 的理由: 倒數讀得到, 所以等待是算術不是觀察; 一個睡著的迴圈還會佔住 `~/.ai_coc/state.json` 讓別的 session 以為模擬器在忙. 一整晚該有一兩次讀取, 不是四十八次.

只有兩種情況才需要密一點:

- **倒數讀不到** (`remaining` 是 `null`, 或者整個 `jobs` 是空的但牌子上寫著有人在忙). 那是畫面讀不出來, 過幾分鐘再讀一次通常就好了
- **快到了**. 最後那幾分鐘可以縮短, 因為遊戲的倒數跟你的時鐘會差個幾十秒

## 護盾比工人重要

**這是這幾個倒數裡唯一一個時間到了會賠錢的.** 護盾一過期村莊就能被打, 而打資源打滿之後放著不管的代價是實測過的: 2026-09-17 填到 26M/26M/430k 之後放著, 九個半小時後回來剩 2.3M/4.6M/299k. 填滿再放著就是把資源送人.

所以排下一次醒來的時候, 護盾的倒數跟工人的倒數一起比, 誰先到算誰. 而且這兩個常常是護盾先到 —— 實測過一次, 護盾剩 6 小時 2 分而最快的工人還要 7 小時 52 分, 中間那一個半小時倉庫是滿的而且沒有保護.

`shield` 欄位有三種答案, 意思完全不同:

- `null` —— 這個世界沒有護盾牌子. 夜世界永遠是這個, 它是即時配對, 本來就沒有護盾
- `{"up": false}` —— **牌子上寫「無」, 村莊現在就可以被打**. 這是要馬上講的, 不是等到下次醒來
- `{"up": true, "remaining": 22080}` —— 還有這麼多秒
- `{"up": true, "remaining": null}` —— 有護盾但倒數讀不到, 過幾分鐘再讀

## 講給使用者聽

到了時間就講, 而且講得具體: 哪個世界、什麼東西好了、現在幾個工人閒著、倉庫多滿. 「工人空出來了」比「監控完成」有用得多.

**推播是關的.** `PushNotification` 在這台機器上被關掉了, 送出去只會回一行 `Push not sent`, 使用者不會收到. 要讓訊息真的到他手上, 用選擇題 (`AskUserQuestion`) —— 那個會推到手機. 但**沒有東西要他決定就不要問**, 那只是多一則通知; 那種時候就好好寫在回覆裡.

有東西要他決定的時候才問, 而且選項要是他真正的那幾條路. 最常見的是工人空出來了要不要花掉 —— 那一步是 spend-loot, 而且**他沒開口要花就不要自己花**, 這條規矩在 farm 那邊寫得更完整.

## 什麼時候收工

- 他要看的那件事發生了, 講完就收工
- 他說停
- **連續三次讀不到畫面**, 或者 `ai_coc status` 一直回「畫面不在村莊」. 那是遊戲或模擬器的問題, 停下來講, 不要一直重試
- 排到的下一次醒來已經超過使用者交代的範圍 (他說「盯到今天晚上」而最快的一個要三天), 那就直接講清楚還要多久, 不要排一個他沒要的鬧鐘

**收工就真的收工**, 不要留一個迴圈在背景「以防萬一」. 村莊被打的保護是遊戲自己給的護盾, 不需要這邊跑任何東西.
