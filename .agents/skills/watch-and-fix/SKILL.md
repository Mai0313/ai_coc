# watch-and-fix

查出迴圈在遊戲裡哪裡做錯, 修掉. 盯的是**一輪的整條路**: 開起遊戲 -> 站上日世界或夜世界 -> 打完一場 -> 回到村莊 -> 開下一輪. 卡在載入、船沒坐成、彈窗蓋住攻擊鈕、結算畫面認不出來, 都跟戰術一樣是這裡的題目, 而在 log 上都像「這場打得爛」. 迴圈照 `takeover` 的 `references/farming.md` 開 (門檻、兩個 `--plan`, 要查的是 AI 規劃本身才不帶 `--plan`), 平常照它交給 subagent 跑; 使用者說「你親自監督執行」, 就是你自己跑, 不轉包給 subagent: 步驟照 `takeover` 的 `references/runner.md` (會佔模擬器的指令帶 `--yield`, `result.json` 是陣列, 每一步讀 `state.json`, 迴圈的指令帶 `<你的 session id>-farm`, 跟你自己驗證用的分開), 送背景照 `share-emulator` 的「背景跑」; runner.md 寫「回報」的地方, 就是該你判斷的時候. `--yield` 不能省: 沒帶的話, 你自己驗證用的指令會把這輪停掉而不是借走, 也沒有人會把它開回去. 改程式碼的規矩在 `.agents/rules/code.md`, 流程照 `AGENTS.md` 的 Development flow.

## 做完的樣子

- 要求裡有打資源的, 那一趟照 `takeover` 的「打資源 (一趟)」打到終點, 修東西的時候迴圈照跑
- 找到的問題各自修好 merge 了, 每一個都有量過的證據 (`.agents/rules/code.md` 的 Measuring a change); merge 時迴圈還在跑的話, 照 `share-emulator` 的「merge 進來的修正, 迴圈怎麼用上」換上新程式
- 或者一句「這批很順, 沒發現值得改的」: 那是結論, 不是空白
- 背景沒有東西留著 (`AGENTS.md` 的 Check what subagents leave behind yourself); 這批 `frames/` 在證據用完之後刪掉, log 留著
- 回報照「報告」

## 留證據

**存畫面是事前決定, 看畫面是事後決定.** 問題幾乎都是事後才發現, 而這個 skill 本來就在找問題, 所以迴圈一律開著 `--debug`: 存了不看不花什麼, 沒存就得再賠一整場. `--debug` 存迴圈自己讀的畫面, `--shot-every` 存定時的畫面. **分辨「判讀器讀錯」跟「點下去沒生效」只有畫面辦得到** (兩者在 log 上一模一樣), 所以查這類問題兩種都開; 問題跟戰鬥過程有關 (兵怎麼走、法術什麼時候下) 也加 `--shot-every`. 怎麼讀在 `references/evidence.md`. 貴的是看: 一晚幾百張, 所以圖拿來確認, 不拿來巡邏.

**迴圈在跑的時候看畫面, 看迴圈自己存的**: 跟 `run.log` 在同一個目錄, 每存一張 log 就有一行 `Saved frame <檔名>`, 一張對得上一步. `ai_coc capture`、`.agents/skills/repair-emulator/scripts/look.py` 只留給迴圈自己沒在拍的時候 (卡在某個畫面不動、開跑時沒開 `--debug`): 它們存在別的地方, 時間對不上這輪的 log, 還跟迴圈搶 ADB.

**每一輪的戰術不用開旗標**: `~/.ai_coc/runs.jsonl` 一場一行 `round`, 它的 `plan` 是那一場照著打的劇本 (AI 規劃的, 或 `--plan` 交進去的那份), 連同那一輪的 report 跟開打前的倉庫, 執行目錄刪了也還在. 用執行目錄的名字 (`run`) 跟輪數把某一輪拉出來重播:

```bash
jq -c 'select(.event=="round" and .run=="<執行目錄名>" and .round==2).plan' ~/.ai_coc/runs.jsonl > .runs/tuned.json
uv run --no-sync ai_coc attack --plan .runs/tuned.json
```

## 怎麼查

**出兵沒有成本, 一場不是證據**: 練兵不花錢也不花時間, 整場拿去量測是正常支出; 有疑問就打一場來問, 不要從一張截圖推理, 下結論照 `.agents/rules/code.md` 的 Measuring a change (它不只管改程式碼, 換設定檔或戰術檔的對照也照它).

**每一輪都成功也要找.** `outcome` 全是 `took_loot` 不代表迴圈沒事. 迴圈會自己救回來, 救的那一下只留在 log 裡: **每一行重試或修正都是上游某一步做錯了**, 結果對只說明救得回來. 一輪一輪數它們:

- `After the burst: N of M one-off card(s) never landed` 而 N 不是 0 (主村每一場開打的都有, 夜世界沒有), `retry card(s) landed at`, `took nothing`, `still hold something`, `flank pushed out`: 出兵有東西被拒, 或被判成沒下去. 大部分輪都有就是上游的問題, 不是運氣
- 每次都落在**同一個**重試點: 本來該分開的英雄被擠到一起, 攻城機器晚到
- `WARNING`: 每一條都對一次畫面

**一張畫面不下結論.** 截圖常常剛好拍在動畫中間: 英雄落地那一下卡片閃白還沒畫血條, 技能發動時血條變亮變色, 結算畫面的星星跟數字還在跑而回營還沒出現, 新對手淡入到一半. 判讀器跟你的眼睛在那一張上都會錯. 所以**拿它讀的那張跟下一張、中間沒再點過它的畫面一起看** (例如 `settled` 跟之後的 `before-drop`, 中間可能夾著推兵線的 `before-pass` / `pass`, 但判讀的那張卡沒被再點過; 或前後的 `*_tick`), 還看不清就連拍. 下一張就對了, 是讀太早或拍到動畫, 不是動作沒生效; 連著幾張都一樣才算數.

**卡住先翻 `references/symptoms.md`** (症狀對照該去看什麼), 不要直接改程式碼. **先 plan 後畫面**: 那一輪 `round` 行的 `plan` 對照 `run.log`: 對得上而結果還是爛, 問題在戰術 (prompt 或戰術檔); 對不上, 問題在迴圈, 才去畫面找哪一步歪掉. **這個遊戲對「拒絕」幾乎不給訊號** (兵被無聲吞掉, 不同錯誤共用一條紅色橫幅), 所以出兵成不成功看**卡片自己**有沒有少 (`card_drained` / `field_units`). 截圖上沒看到兵, 不代表沒下去, 也不代表下去了.

## 調整的階梯

**階梯是給「打得不夠好」用的**, 從便宜爬到貴, 每一層都比下一層便宜而且好回頭, 不要跳級. 迴圈做錯事 (讀錯, 點錯地方, 重試把技能燒掉) 是 bug, 量完直接修程式, 不用從設定檔爬起.

1. **`~/.ai_coc/config.json`**: 戰利品門檻, 倉庫上限, 模型. 它只決定打誰跟打到什麼時候, **沒有任何數字決定怎麼打**, 所以「打得不夠好」從第二層開始
2. **戰術檔案**: `--plan` 餵一份 JSON 進去**完全不呼叫 AI**, 只打它所屬的村莊. 寫 JSON 比改程式碼快, 而且拿掉 AI 這個變因才能對照. 預設的 `flat.json` 跟 prompt 的戰術是使用者定的 (`.agents/rules/attack.md`), 拿來對照的改法另存一份
3. **`src/ai_coc/prompts/attack_plan.md`**: AI 每次都畫爛線或漏欄位是 prompt 的事
4. **`src/ai_coc/ui/attack.py` 頂端的常數**: 到這層才需要量測撐腰, 來歷寫在各常數旁邊. `TAP_GAP` 住在 `adapters/adb.py`
5. **迴圈的邏輯**: 最後手段, 要跑測試, 要開 PR

## 報告

**從使用者的角度講改了什麼, 再給圖證明**, 不要長報告, 不寫 `report.md`.

```
改了 3 個地方 (都已 merge):
1. 英雄技能不會再被提早放掉: 以前英雄剛落地就被當成沒下去又點一次, 大守護者第 8 秒就放掉技能. [圖] #287
2. 攻城機器跟英雄不會再擠到同一點: 畫在紅線內的落點改投到部隊那條線上, 一次就落地. [圖] #288
3. 收集不會再點到建築: 點一下就收完同一種資源, 以前多點的那幾下會選到城牆. [圖] #408
```

- **每個修正一句**: 以前會怎樣, 現在不會, 講他在遊戲裡看得到的差別, 不講改了哪個函式. 附 PR 連結
- **每一項配一張證明的圖**, 一起發: 修正前出事的那一張, 或修正後做對的那一張
- 有打資源的, 前面先放 `farming.md` 的報告; 沒達成就照它的「沒達成, 或中途被問」講兩三句
- 看過但沒改的, 試過沒用的, 還沒解決的, 寫進 PR 或 issue 留給下一個人, 不寫進回覆; 其中要他決定的接在回覆後面 (`AGENTS.md` 的 Putting a decision to the user)
- 不在這條路上的 bug (`collect`、面板升級、刷牆、收工時讀工人的 `status`) 不在途中順手修, 記下來另開 PR; 收工後才修的也列在同一串裡
