# watch-and-fix

**主線是把資源打滿, 修東西是順便.** 使用者要的是滿倉庫, 不是一份分析報告. 所以迴圈永遠在跑, 你在它跑的空檔思考跟改東西, 而不是停下來研究.

先讀 `.agents/skills/farm/SKILL.md`: 開跑前的檢查, 盯的方式, 倉庫滿了怎麼把資源花掉跟哪些要先問過使用者, 停手的條件, 全部一樣, 這裡不重複. 背景跑的機制在 `.agents/skills/farm/references/running.md`.

## 管到哪裡為止

盯的是**一輪的整條路**: 開起遊戲 -> 站上日世界或夜世界 -> 打完一場 -> 回到村莊 -> 開下一輪. 這條路上任何一步壞掉都是這個 skill 的題目, 不是只有戰術畫得好不好. 遊戲卡在載入, 船沒坐成, 彈窗蓋住攻擊鈕, 結算畫面認不出來, 每一種都會讓整輪白跑, 而它們在 log 上跟「這場打得爛」長得很像.

`walls`, `collect`, `upgrade`, `hero` **不在這條路上**. 倉庫滿了會去跑其中幾個 (見下面「資源滿了」; `walls` 要使用者開口才跑), 但它們自己壞掉是另外開一次的題目, 不要在這一輪裡順手修.

## 誰在跑那個迴圈

兩種都可以, 你自己決定, 中途也可以換:

- **自己跑**: 用 `run_in_background` 送出去, 你在前景讀 log 改東西. 現場感最好, 有疑問隨時 `capture` 一張, 代價是每一輪的通知都會進你的 context.
- **交給 subagent**: 照 `CLAUDE.md` 那段派一個跑 `farm` 的 subagent, 降一級模型, 降 thinking budget, 你只讀它留下來的檔案. 省下的是盯的成本, 代價是你不在現場.

**使用者講明了就照他講的**, 這件事他會指名: 「你親自監督執行」是第一種, 不要為了省 context 把它轉包出去. 沒指名才輪到你選.

分界在這一句: **存畫面是事前決定, 看畫面是事後決定.** `--record` 是開跑時的旗標, 一場打完才想看那一場就沒有了, 而發現有問題幾乎總是事後. 所以人不在現場的時候傾向開著它, 硬碟很便宜, 存了不看不花任何東西, 但沒存而想看就得再賠一整場. 自己跑的時候可以不開, 反正隨時 `capture` 得到.

真正貴的是**看**而不是存: 一場 `--record` 幾十張, 加上 `--shot-every` 又三十幾張, 一晚上幾百張而其中絕大多數是好好的. 所以圖是拿來確認的不是拿來巡邏的, 順序在下面「卡住的時候先問對問題」那節.

## 兩個村莊, 動手之前先確認在哪一個

這個遊戲有日世界 (主村) 跟夜世界 (建築大師基地) 兩張地圖, 中間只有一艘船, 而**遊戲會開在上次離開的那一個**. 所以「遊戲開起來了」不等於「站在你要的那個村莊上」.

```bash
uv run ai_coc world               # 回 day / night, 不動畫面也不點東西
uv run ai_coc world --go day      # 坐船切過去, 已經在那邊就什麼都不做
```

不指定世界的指令做的是**當下所在的那一個**, 不會自己切. 兩邊的建築, 資源跟判讀器都不一樣, 所以在錯的村莊上是「找不到」而不是「找錯」, 而你會花好幾張截圖才發現.

## 三份文件的分工

- **程式碼**說「現在是什麼」: 常數現在是多少, 迴圈現在怎麼走
- **`CLAUDE.md`** 說「為什麼是這樣」: 每個數字是怎麼量出來的, 前一版錯在哪, 代價是什麼
- **這份 skill** 說「怎麼判斷」: 怎麼收證據, 該先動哪一層, 什麼時候可以下結論

`CLAUDE.md` 的 Attack loop 那幾段是這個 skill 最重要的前置閱讀. 動任何一個常數之前先在裡面搜一下它, 十次有九次會發現它是為了修某個實測過的 bug 才變成現在這個值的, 改回去等於把那個 bug 放回來.

## 出兵沒有成本, 不要客氣

現在的 Clash of Clans 練兵不用錢, 搜尋費微不足道, 一場打壞的仗也不用錢. **整場拿去做量測是正常的支出, 不是要道歉的浪費**. 練兵連時間都不用, 所以連「等兵」這個成本都沒有了 —— `MIN_ARMY_RATIO` 現在擋的是軍隊配置湊不到兵營一半的那種異常, 而且那一輪會把整個 series 收掉, 不是等一下再來.

這件事決定了整個工作方式: 有疑問就去打一場來問, 不要坐在那裡從一張截圖推理. 而且**一場不是證據**, 對手之間的差異比你改的東西大得多, 所以要下結論就跑 `--repeat 3` 以上再看.

## 開跑的旗標

```bash
uv run ai_coc attack --world day --repeat 0 --record --shot-every 5
```

**`--world` 一定要寫出來, 而 `--repeat 0` 才是主線的形狀.** 不給 `--world` 打的是遊戲當下停著的那個村莊, 而遊戲會開在上次離開的那一個, 所以少了它就可能整晚在打夜世界而你以為在打主村. `--repeat 0` 不是無限, 是「打到倉庫滿了自己收工」, 正好是主線要的語義; 固定輪數是做對照的時候才用的, 見下面「對照要怎麼做」.

`--record` 存的是迴圈自己讀的畫面, 檔名帶著它當下在問什麼問題; `--shot-every` 存的是另一種視角, 檔名帶著跑到第幾秒. **要分辨「判讀器讀錯」跟「點下去沒生效」只有畫面辦得到**, 而那兩種在 log 上一模一樣, 所以查這一類的時候兩種都要開. 理由跟怎麼讀在 `references/evidence.md`; 什麼時候值得開在上面「誰在跑那個迴圈」那節.

畫面、`run.log`、`result.json` 跟 `plans.jsonl` 都在這次執行自己的目錄底下, 路徑由開跑第一行 log 說出來, 不必自己重導向.

**`plans.jsonl` 不用開旗標, 而且它是查一場爛仗的第一步.** 一場一行, 帶著自己的輪數, 內容是 AI 那一場真的回答了什麼: 一串照順序執行的步驟, 誰下在哪、中間等幾秒。從頭讀到尾就是那一場的劇本。 先讀那一行再去翻畫面, 因為它便宜得多而且直接回答「這場是被指揮爛了, 還是指揮對了但執行歪了」—— 那是兩個完全不同的方向. 畫面上看不出兵為什麼往那邊走, plan 上看得出來.

要把某一輪拉出來重播:

```bash
jq -c 'select(.round==2).plan' ~/.ai_coc/logs/<run>/plans.jsonl > .runs/tuned.json
uv run ai_coc attack --plan-in .runs/tuned.json
```

`--plan-out` 也還在, 但它只留最後一輪而且要事先想到加, 所以它是「我知道這一份要留」的時候用的, 不是查問題用的.

**你拿來下判斷的那幾張, 順手發一份給使用者.** 這個 skill 的結論幾乎都是從畫面上讀出來的, 而使用者沒辦法看到你的工具輸出 —— 只留一個路徑等於要他自己去翻幾百張裡面的那一張. 用檔案傳送機制發出去, 說清楚那張圖為什麼重要.

## 卡住的時候先問對問題

這個迴圈失敗的方式有很多種, 而它們在 log 上長得很像. `references/symptoms.md` 是一張「症狀對照該去看什麼」的表, 卡住就先翻它, 不要直接開始改程式碼.

**順序是先 plan 後畫面.** 那一輪的 `plans.jsonl` 一行就說完 AI 打算怎麼打, 跟 `run.log` 對照就知道實際做了什麼. 兩邊對得上而結果還是爛, 問題在戰術, 那是 prompt 或戰術檔的事; 兩邊對不上, 問題在迴圈, 那才需要去翻幾百張畫面找是哪一步歪掉. 反過來先翻畫面, 就是在還不知道要找什麼的情況下翻.

一個貫穿全域的原則, 值得先記住: **這個遊戲對於「拒絕」幾乎不給訊號.** 紅線內的兵有時候被無聲吞掉, 各種不同的錯誤共用同一個紅色橫幅, 燒起來的建築也長得一樣. 所以迴圈判斷一次出兵成不成功是看**卡片自己**有沒有少 (`card_drained` / `field_units`), 不是看畫面. 你在查問題的時候也該用同一個標準: 一張截圖上沒看到兵, 不代表兵沒下去, 也不代表下去了.

## 調整的階梯, 從便宜爬到貴

每一層都比下一層便宜而且好回頭. 不要跳級.

1. **`~/.ai_coc/config.json`**: 戰利品門檻, 倉庫上限, 每打幾場重開一次模擬器, 模型設定. 改一個數字就重跑, 不用改碼, 不用測試, 不用開 PR. 但要知道**這一層已經沒有任何一個數字會改變一場仗怎麼打了**: 技能秒數跟法術秒數以前在這裡, 現在整批搬到 plan 的步驟上 —— 一份戰術就是一串 `AttackStep`, 而等待本身就是一個 `act: wait` 的步驟, 秒數從上一個動作做完開始算, `adapters/config.py` 甚至會主動把殘留的 `timings` 從既有檔案裡刪掉 —— 留著它才是害人, 因為那看起來像一個還有人在讀的設定. 這一層決定的是打誰跟打到什麼時候, 不是怎麼打, 所以「打得不夠好」現在要從第二層開始
2. **戰術檔案**: `src/ai_coc/plans/flat.json` 是那份「什麼都平均攤開」的預設戰術, `--plan-in` 可以餵任何一份進去而且**完全不呼叫 AI**. 想試不同的下兵線或不同的法術落點, 寫一份新的 JSON 比改程式碼快得多, 而且 `--plan-in` 把 AI 這個變因拿掉之後才有辦法做對照
3. **`src/ai_coc/prompts/attack_plan.md`**: 如果問題是 AI 每次都畫出爛的線或者漏掉欄位, 那是 prompt 的事, 不是迴圈的事. 注意 `AttackPlan` 除了 `deploy_from` 跟 `reason` 以外每個欄位都是必填的, 那是刻意的: 有預設值的欄位在 JSON schema 裡是選填, 而 Gemini 會直接不寫它, 所以迴圈少不了的東西一個預設都不給. 讀 model 上面的註解就知道漏掉一個的代價是什麼
4. **`src/ai_coc/ui/attack.py` 頂端的常數**: 到這一層才需要量測撐腰. 檔案頂端每個常數旁邊都有註解說它是怎麼來的. 有一個不在那裡: `TAP_GAP` 住在 `adapters/adb.py`, 因為它管的是 ADB 那層兩個 `input` 之間要隔多遠, 不是進攻的事
5. **迴圈的邏輯**: 最後手段. 改到這裡就是在改行為, 要跑測試, 要開 PR

## 改到程式碼的時候

**先量再改.** 這個 repo 的文化是每個常數都是量出來的, `CLAUDE.md` 通篇都在講某個數字是在哪一場戰鬥的哪一格畫面上量到的. 沒有量測就改常數, 等於把一個猜測寫進歷史, 而且下一個人會以為那是量過的.

**改最少的量.** 一次只動一件事, 然後跑幾輪看差別. 同時改三個東西, 就算變好了你也不知道是哪個改的.

**流程照 `CLAUDE.md` 的 `## Development flow`**, 這段不需要另外問使用者.

**量到新東西想寫進 `CLAUDE.md` 的時候, 先把那段文字給使用者看過.** 那個檔案每一次 session 都會被讀進去, 寫錯一行的成本會一直付下去.

改東西的時候讓上一輪繼續在背景跑, 那三分鐘的戰鬥本來就是給你用的. **要動到活的遊戲才驗得了的, 就自己把迴圈停掉, 驗完自己開回去** —— 不用問, 規矩在 `.agents/skills/farm/references/running.md` 的「你自己要用畫面」那節. 驗證的那一場對著的多半是一個已經打滿的村莊, 而 `attack` 讀到倉庫滿就收工, 所以測試場要加 `--stop-at 0`.

## 對照要怎麼做

想比較兩種打法, 變因只能有一個:

- 用 `--plan-in` 餵同一份戰術, 這樣 AI 不會每場給不同的答案
- 兩邊都跑 `--repeat 3` 以上
- 比的是**進帳的資源**跟**打完的百分比**, 不是「感覺比較順」
- 對手的差異吃掉一切. 三場對三場只能看出很大的差別, 看不出百分之十的改善

`--plan-out` 會把實際跑的那份計畫寫下來, 所以一場打得特別好的仗可以被重播, 打得特別爛的可以被拿出來吵.

## 資源滿了

照 `farm` 的「倉庫滿了」那節, 而那一節的第一句就是**預設什麼都不花**: 打到 `stop_at` 就收工通知, 除非使用者在交辦的時候講了要花. 他講了才有下面這些 —— 建築照他那句話做, 城牆跟英雄要指名, 兩種資源都花光不用留 (練兵不用錢, 見上面). 怎麼花是 `spend-loot`, 什麼時候停手是 `farm`, 這裡都不重複. **「不浪費一分一秒」講的是你的時間不是他的資源**: 沒開口要花的那一趟, 打完就是打完, 那段空檔拿去改東西而不是拿去花他的錢.

## 任務報告

主線達成 (資源打滿) 的時候, 交 `farm` 那份任務報告, 樣板一模一樣, 寫到這次執行自己的目錄 (`~/.ai_coc/logs/<run>/report.md`). 主線沒達成就不套樣板, 照 `farm` 的規則講一段話.

在那份報告後面接一節 `## 這批場次盯到什麼`:

- 這批場次裡看到什麼樣態: 整條路上哪一步最常出問題, 哪一種對手最常打壞
- 試了什麼, 結果是什麼, **包括試了沒用的那些**. 排除掉的可能性跟找到的答案一樣有價值, 而且下次不用再試一遍
- 改了什麼, 改的依據是哪一次量測, PR 在哪
- 還沒解決的是什麼, 卡在哪

沒調到任何東西也要寫這一節, 內容就是「這批很順, 沒發現值得改的」. 那是一個結論, 不是空白.
