# farm

代替使用者顧這個村莊. 開跑, 盯著, 判斷, 回報. 這個 skill 不改程式碼.

## 三份文件的分工

- **程式碼**說「現在是什麼」: 有哪些指令, 旗標叫什麼, 報告有哪些欄位
- **`CLAUDE.md`** 說「為什麼是這樣」: 每個常數背後的實測, 每個設計的代價
- **這份 skill** 說「怎麼判斷」: 什麼時候該介入, 什麼時候該停手

所以不要憑記憶下參數, skill 裡沒有一份參數表, 因為那種表一定會過期. 開跑前先讀這三個地方:

- `src/ai_coc/cli.py` 的 `_parser()` 是旗標的唯一真相
- `src/ai_coc/commands.py` 裡對應的函式說那個指令實際做什麼, docstring 通常已經把設計理由講完了
- `src/ai_coc/models.py` 的 `AttackReport` / `AttackSeries` / `WallReport` 說回報的欄位是什麼意思

## 開跑之前

**讀 `~/.ai_coc/config.json`.** 這份檔案是視窗跟終端機共用的, 兩邊會跑出一樣的結果. 三件事要看:

- `thresholds` 是打誰的門檻. 訂太高會一直跳過, 一輪搜幾十個對手還開不了打
- `stock` 是停手的倉庫水位. 任何一項到頂就整個 series 結束, 不是等三項都滿
- `timings` 是英雄技能跟法術的秒數, 跟這次要打幾輪無關, 但看一眼可以知道上次調到哪

如果使用者沒特別交代, 就照設定檔跑, 那是他調過的值. `--min-gold` 之類的旗標只在他明講要放寬時才用, 而且 `0` 跟不給是兩件事, 讀 `LootOverrides` 的 docstring.

**不用自己開模擬器或遊戲.** `commands._controller()` 會找 MuMu instance 並 `ensure_coc`, 遊戲沒開它自己會開.

**先估時間再開跑.** 一輪是搜尋加上最多三分鐘的戰鬥, 加上回營, 抓四到五分鐘. 軍隊沒練好的那輪會等 `IDLE_REST` 再來. 從現在的倉庫水位到 `stock` 的距離, 除以一場的平均收穫, 大概就是要跑多久. 如果算出來是好幾個小時, 先跟使用者講一聲.

## 怎麼跑

**背景跑, 輸出導到檔案.** 前景跑會把整個 session 卡住幾十分鐘, 中間你什麼都做不了, 使用者也插不了話. 機制跟目錄佈局讀 `references/running.md`.

**預設 `--repeat 0`.** 那不是無限: 倉庫滿了迴圈自己會 break, 這正是「打到資源滿」要的語義. 使用者指定輪數就照他的.

**要不要留畫面自己決定.** `--frames` 存的是迴圈自己讀的每一張, `--shot-every` 再加一條固定心跳. 留了就有東西可以事後翻, 代價是空間, 一張 PNG 一兩百 KB, 一場加起來幾十 MB. 覺得這批會有東西要查就開著, 覺得只是單純掛機就不開, 臨時想看現況隨時可以 `uv run ai_coc capture` 抓幾張.

## 怎麼盯

**log 跟畫面兩種手段都可以用, 用哪個你自己判斷.**

**log** 便宜, 適合回答「現在走到哪一步, 這輪結果是什麼」. 兩個地方都有: 你自己導出去的那份 stderr, 跟 `~/.ai_coc/logs/controller.log`. 前者只有這次跑的, 後者混著所有跑過的但會轉檔.

**畫面**貴一點但能回答 log 回答不了的問題: 畫面上現在到底長什麼樣, 兵有沒有真的在打, 判讀器讀到的跟眼睛看到的一不一樣. `uv run ai_coc capture <dir> --count N` 從活著的遊戲抓, `uv run ai_coc read <png>` 把一張圖丟給所有 parser 看它們各自讀到什麼.

沒有規定的順序. log 看得出來就不用截圖, log 講不清楚就去看圖, 一開始就想看圖也可以. 有疑問而 log 沒回答到, 截一張就是了, 那很便宜.

**盯的頻率**: 一輪四五分鐘, 所以幾分鐘看一次就夠, 不要每幾秒去 tail 一次. 中間的空檔拿去做別的事.

**每一輪結束會有一行 `Attack finished: <message>`.** 那個 message 就是 `AttackReport.message`, 它自己會講清楚這輪發生什麼事. 常見的幾種語義:

- 打完回營了, 附帶搶到的三種資源
- 兵力不足, 沒付搜尋費就退出來. 這是設計好的行為, 不是錯誤
- 倉庫已達停止門檻, 整個 series 到此為止
- 畫面不在主村, 沒開成攻擊選單. 這輪什麼都沒做
- 等不到對手畫面

不要去背這些字串, 它們會改. 要判斷一輪算不算成功就看 `AttackReport.attacked` 是不是 `None`.

**值得警覺的樣態**, 不是單一輪而是連續幾輪:

- 連續三輪以上 `attacked=None` 而理由都是兵力不足: 兵營可能根本沒在練, 或者軍隊配置被改過. 去看一眼再回報
- 連續打完但每輪 `skipped` 都是幾十: 門檻對現在的獎盃區間來說太高了, 值得跟使用者提一句
- 打完了但 `attacked` 的數字很小: 進攻打不動人家, 這是 tune-attack 的題目, 這裡只負責報告
- log 裡出現重新登入 / 重開遊戲: `ui/runner.py` 的 `restart_game` 自己會處理, 會回到村莊, 不用管. 但如果一直重複發生, 那是要查的

## 什麼時候停手

**倉庫滿了就轉去刷牆.** 這是唯一一個不用問就可以做的花錢動作: 城牆付錢的當下就升級完成, 不跑計時器, 所以建築排滿的時候它是村莊還花得掉資源的地方. 這個村莊會留一個工人給它用, **預設那個工人是可以動的, 不用另外問**.

**但它需要有一個工人閒著.** 城牆自己不佔工人, 可是工人全忙的時候遊戲會把整批退掉, 回一句「所有建築工人都在忙碌中」再附一顆寶石按鈕, 一片牆跟八片牆一樣退, 所以那不是批次大小或錢的問題. 開跑前先看工人數, `0/N` 就不要開, 直接進入下面的停手通知. `ai_coc builders` 順便會說最快的一個還要多久, 那決定了通知裡要不要叫使用者等.

跑 `walls` 的時候留一點聖水下來練兵, 不然打完這批就沒兵可練, 農場等於停擺. 留多少看使用者的習慣, 沒交代的話留得夠練一隊即可, 旗標名稱看 `_parser()`.

**牆也刷不動了就停手通知使用者.** 刷不動的原因是牆全滿級, 或者剩下的錢不夠下一批的單價. `WallReport.message` 會說是哪一種.

通知的時候一起附上工人的閒置狀況. `parsers/home.py` 的 `free_builders` 讀得到「閒著幾個 / 總共幾個」, 拿一張主村畫面丟給 `uv run ai_coc read <png>` 就有. 這不影響刷牆的判斷, 純粹是給使用者決定要不要手動把錢花在建築上, 因為建築升級不在這個 skill 的範圍內.

**其他停手的理由**: 遊戲一直回不到村莊, 同一個錯誤連續發生三次以上, 或者一輪也沒打成過. 這些都停下來講, 不要一直重試. 這個 repo 的原則是失敗要吵, 不是安靜地繼續.

## 順手做的事

`collect` 很便宜, 是這個專案裡最值得常跑的指令: 採集器裝滿就停工, 沒人去收的村莊多數時間是在發呆. 開跑前跑一次, 每過一段時間再跑一次, 花不到幾秒.

`donate` 也幾乎沒成本, 沒人開口要兵的話只花一次點擊跟一張截圖, 而且捐兵有回饋. 想跑就跑.

`upgrade` 跟 `hero` 會把工人派去升建築或升英雄, **不要自己跑**, 除非使用者當下要求. 牆壁以外的資源要花在哪, 使用者自己決定, 而那個決定是貴的也是不可逆的.

## 途中撞到 bug

**修掉, 不要繞過.** 這個 skill 的主線是跑迴圈而不是改程式碼, 但迴圈跑不動的原因如果是程式碼裡的錯, 繞過去只是把它留給下一次撞上. 照 `CLAUDE.md` 的開發流程走完: 讀 `gh-dev-flow`, 開 branch, 開 draft PR, 對 branch 跑 `code-review` 把站得住腳的意見修掉, 測試綠了 CI 也綠了就 merge. **這段不用另外問使用者.**

修的時候讓迴圈繼續在背景跑, 除非要修的正好是迴圈自己.

## 任務報告

**任務達成才交完整報告.** 達成的意思是倉庫打到停止門檻, 或者使用者指定的輪數跑完. 那是一個明確的時刻, 報告放在那裡才有份量.

**沒達成就不要交報告**, 給一段話講清楚三件事就好: 跑到哪, 為什麼停下來, 要不要繼續. 中途被中斷, 遊戲一直回不了村莊, 一輪也沒打成, 這些都屬於這一類. 對一個半路夭折的跑交一份完整格式的報告, 只是把壞消息包裝得很漂亮.

報告印在對話裡, 同時寫一份到 `.runs/<run>/report.md`. 檔案那份是給以後翻的跟拿來跟上次比的, 對話那份是給現在看的, 內容一樣.

**樣板不要改.** 使用者會拿這次跟上次對照, 每次換一種寫法就比不了.

### 開跑前先記下基準

進帳算不出來是因為沒有起點. 所以**開跑之前先讀一次倉庫水位**: `uv run ai_coc capture` 抓一張主村畫面, `uv run ai_coc read` 看 `stock` 欄位, 把三個數字記下來. 結束之後再讀一次. 這兩次讀取合起來才是「這次賺了多少」的唯一可信來源.

### 樣板

```markdown
# 任務報告

**目標**: <這次要達成什麼>
**結果**: 達成
**一句話**: <賺到了嗎, 現在輪到使用者做什麼嗎>

## 資源
|      | 開跑 | 結束 | 進帳 |
| ---- | ---- | ---- | ---- |
| 金幣 |      |      |      |
| 聖水 |      |      |      |
| 黑水 |      |      |      |

搶到的總量: 金 / 聖水 / 黑水
平均一場: ...    每小時約: ...

## 戰績
跑了 <時長>, <N> 輪, <M> 輪開打, <K> 輪空手 (<理由>)
跳過 <X> 個對手
最好的一場 / 最差的一場

## 花掉的
刷牆 <N> 片, 金幣 -<X>, 聖水 -<Y>
(沒花的話寫沒花, 以及為什麼)

## 為什麼停
<停手的理由>
工人 <閒著幾個>/<總共幾個>

## 需要你決定的
<沒有就寫沒有>
```

### 數字從哪來, 不准編

- **開跑 / 結束 / 進帳**: 上面那兩次 `read_stock`. 這是真的入庫的量
- **搶到的總量**: `result.json` 裡每輪 `AttackReport.attacked` 的加總. 這跟入庫的量**會不一樣**, 因為倉庫滿了之後搶到的會被丟掉. 兩個都列出來, 差很多本身就是資訊
- **輪數 / 開打 / 空手 / 跳過**: `AttackSeries` 數出來, 空手的理由看那一輪的 `message`
- **刷牆**: `WallReport.walls` 跟 `paid("gold")` / `paid("elixir")`
- **工人**: 一張主村畫面丟 `ai_coc read`, 看 `builders`
- **時長**: `run.log` 第一行跟最後一行的時間戳

**量不到的就寫量不到, 不要估.** 這個專案的規矩是寧可顯示破折號也不猜一個數字, 報告一樣適用.

### 那一句話怎麼寫

使用者多半只看這一句, 所以它要同時回答「賺到了嗎」跟「現在輪到我做什麼嗎」:

- `打滿了. 金幣聖水都到 15M 上限, 中間刷掉 34 片牆, 現在沒事要你處理.`
- `打滿了但花不掉. 金幣卡在上限, 牆也刷不動了 (剩下的不夠下一批 210k), 工人 0/5 全忙, 多出來的資源會一直被丟掉.`

## 沒達成的時候講什麼

不套樣板, 不寫檔案, 就一段話:

- 跑到哪 (幾輪, 進帳多少, 能講多少講多少)
- 為什麼停 (被中止 / 一輪也沒打成 / 回不了村莊 / 同一個錯誤重複發生)
- 要不要繼續, 以及繼續之前有沒有東西該先處理

被砍掉的跑 `result.json` 會是空的, 走 `uv run ai_coc stop` 停的不會. 空的那時候 `run.log` 是唯一的紀錄, 從裡面數得出多少就寫多少, 並且註明是從 log 數的.

## 中途被問進度

報當下的資源跟輪數就好, 而且**不要停下迴圈**. 報告留到任務真的達成再交.
