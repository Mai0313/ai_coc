# farm

代替使用者顧兩個村莊. 開跑, 盯著, 判斷, 回報. 這個 skill 不改程式碼.

## 三份文件的分工

- **程式碼**說「現在是什麼」: 有哪些指令, 旗標叫什麼, 報告有哪些欄位
- **`CLAUDE.md`** 說「為什麼是這樣」: 每個常數背後的實測, 每個設計的代價
- **這份 skill** 說「怎麼判斷」: 什麼時候該介入, 什麼時候該停手

所以不要憑記憶下參數, skill 裡沒有一份參數表, 因為那種表一定會過期. 開跑前先讀這三個地方:

- `src/ai_coc/cli.py` 的 `_parser()` 是旗標的唯一真相
- `src/ai_coc/commands.py` 裡對應的函式說那個指令實際做什麼, docstring 通常已經把設計理由講完了
- `src/ai_coc/models.py` 的 `AttackReport` / `AttackSeries` / `WallReport` 說回報的欄位是什麼意思

## 開跑之前

**讀 `~/.ai_coc/config.json`.** 這份檔案是視窗跟終端機共用的, 兩邊會跑出一樣的結果. 三件事要看:

- `thresholds` 是打誰的門檻. 訂太高會一直跳過, 一輪搜幾十個對手還開不了打
- `stop_at` 是停手的倉庫水位, 一個百分比, **主村跟夜世界共用**. 容量是迴圈自己去遊戲讀的 (點一下儲量條, 遊戲會寫 `最大儲存量`), 所以同一個 90% 在兩邊代表不同的數字, 而且倉庫升級之後不用改設定. **每一項都滿過那個百分比才停**, 不是任何一項到頂就走 —— 一場仗帶回來三種資源, 一個倉庫到頂不足以放棄另外兩種還在賺的. `0` 是永遠不收工; 容量讀不到的那一項不列入計算
- `restart_every` 是每打幾場重開一次模擬器, 算的是真的打完的場次而不是輪數. 這是全檔唯一一個不是實測出來的數字, 因為掉幀是模擬器的毛病, 程式這邊量不到; 看畫面的人才知道該多久重開一次. 掛整晚的跑一定會遇到它, 而且它也是一個結束理由, 見下面停手那節

如果使用者沒特別交代, 就照設定檔跑, 那是他調過的值. `--min-gold` 之類的旗標只在他明講要放寬時才用, 而且 `0` 跟不給是兩件事, 讀 `LootOverrides` 的 docstring. `--stop-at` 是同一個規矩蓋 `stop_at`, 但它不是打資源用的旗標: 倉庫滿了還打, 搶回來的東西進不了倉庫. 它是給**測試**用的 —— 某個 session 要對著一個剛被打滿的村莊打一場來驗東西, 給 `0` 那一場才開得了打.

**開跑之前先問一次 `uv run ai_coc stock`, 每一次都問.** 它答當下這個世界的水位、容量跟每一項的百分比, 走的是跟迴圈同一條路 (鏡頭放好再讀), 花的是幾次點擊跟三張截圖. 這一步決定的事情比它看起來多: 這個世界還有沒有空間 (滿的話開跑第一輪就收工, 那不是壞掉), 要跑多久 (見下面「先估時間」), 以及事後算得出進帳 (見「開跑前先記下基準」). **不要憑上一次的印象**, 使用者可能在中間把資源花光了, 而那正是一個 session 會拿著幾小時前的數字回報的原因.

**不用自己開模擬器或遊戲.** `commands._controller()` 會找 MuMu instance 並 `ensure_coc`, 遊戲沒開它自己會開.

**這個遊戲有兩個村莊, 而遊戲會開在上次離開的那一個.** 日世界 (主村) 跟夜世界 (建築大師基地) 是兩張完全不同的地圖, 中間只有一艘船可以來回. 所以「遊戲開起來了」不等於「站在你要的那個村莊上」.

- `ai_coc world` 回答現在在哪個世界, 不動畫面也不點任何東西, 所以隨時可以問
- `ai_coc world --go day|night` 坐船切過去, 已經在那邊就什麼都不做

**不指定的指令會做在當下所在的世界, 不會自己切.** `ai_coc attack` 沒有 `--world` 的時候打的是眼前那個村莊, 所以要打哪個就寫出來: `--world day` 或 `--world night`, 它會先確認並且需要的話坐船過去. 這一條很重要, 因為遊戲留在夜世界的時候, 一個以為自己在打主村的 session 會安靜地打了夜世界 —— 兩邊的倉庫容量差了十倍, 所以「還差多少才滿」的答案完全不同.

**沒有特別交代的話, 兩個世界的資源都要打完.** 兩邊都跑不用猶豫, 也不用先去問哪一邊還有空間: 一個已經滿的世界開跑第一輪就自己 `stock_full` 收工, 主村是在付搜尋費之前, 夜世界是在進配對之前, 所以多跑那個世界的代價是幾秒鐘的檢查, 不是一場仗. 只有使用者指定了某一個世界才只打那一個. 夜世界是同一個指令:

```bash
uv run ai_coc attack --world night --repeat 0
```

**一次只跑一個世界, 跑完再跑下一個.** 兩個指令同時開會搶同一個畫面, 兩邊都會壞掉. 判斷「這個世界打完了」看**最後一輪**的 `AttackReport.stock_full` —— `result.json` 是一個陣列, 最後一輪就是最後一個元素, 讀法在 `references/running.md`: 那是 `true` 的時候 series 自己就結束了. **哪幾種資源滿了、水位多少不在報告上**, 那在 `run.log` 的 `Storage limit reached (gold/elixir); farming stops with 金幣 …／聖水 …` 那一行, 夜世界的前面還有一行 `the cart holds X of Y` 說車子存了多少; 要寫進回報就去 grep 它, 不要從 `attacked` 推. 那一刻就換下一個世界, 指令一模一樣只是 `--world` 換掉, 它會自己坐船過去.

**「兩邊都打滿」是一個你要接的序列, 不是一個指令.** 第一個世界的 run 結束只是走完一半: 通知進來, 讀最後一輪, 確認是 `stock_full`, 開第二個世界, 等它也 `stock_full`, 這樣才算達成 (日世界那半還要接下面「倉庫滿了」那節). 實測一次, 一個 session 打完夜世界之後就停在原地: 它用 shell 層的 detach 開指令, harness 根本不知道有這個 run, 所以 run 結束的時候沒有任何東西叫醒它. 怎麼開才會被叫醒, 以及通知進來要看什麼, 都在 `references/running.md` 的「開跑」跟「盯」兩節.

**順序: 他指定了就照他的, 沒指定就先打當下所在的那個.** 省一趟船是一個理由, 但不是主要的那個 —— **切畫面就是使用者指定順序的另一個介面**: 想先打夜世界的時候他自己切過去再交辦, 不用多講一句. 所以那不是一個可以順手推翻的偏好.

**而「當下所在」是開跑前第一件事問到的那個答案, 不是後來再問一次.** `ai_coc world` 不動畫面也不點任何東西, 所以第一步就問它, 把答案記下來. 這一條不是講究: **`ai_coc donate` 在夜世界會先坐船回主村**, 而下面「順手做的事」正好建議開跑前跑它 —— 先跑 donate 再問 world, 使用者切到夜世界的那個指定就被安靜吃掉了, 而且回報裡不會有任何一行提到, 因為問到的就是 `day`. `collect` 沒有這個問題 (它自己讀世界, 夜世界做的是推車), `stock` / `worker` / `status` 也都不切.

**另外兩邊等的東西不一樣**: 夜世界的時間幾乎全花在等真人配對上, 主村是花在搜尋對手跟打完那三分鐘. **兩邊都不等兵營** —— 現在的遊戲造兵是即時的, 所以軍隊從來不是一輪在等的東西.

**一個世界打不動不要卡著, 先去打另一個.** 兩個都要打, 而且它們互不影響 —— 一個世界的水位卡住不會讓另一個跟著卡住, 所以耗在打不動的那個等於另一個一整晚沒打. 為什麼卡住不重要, 卡住了就換. 判斷方式是看進帳的斜率而不是輪數 —— 連續幾輪的水位幾乎沒動就是打不動了. **那一行在兩個世界叫不同名字**: 主村是 `Village holds gold=… elixir=… dark=…`, 夜世界是 `Builder base holds gold=… elixir=…`, 因為那邊只有兩排要讀. **夜世界倉庫滿了之後那行本來就不會動**: 那段是在把聖水車填滿 (見下面「倉庫水位」那條), 進帳看的是 `the cart holds X of Y` 那行的 X 有沒有在長, 它有在長就不是打不動.

**而這種情況下前一個 run 不會自己結束**, 所以要換世界就得停掉它: 那個世界永遠到不了百分比, 就永遠不會 `stock_full`, `--repeat 0` 會一直打下去. 停法是 `uv run ai_coc stop`, **而且要等它真的退出再開下一個**. 直接接著開不行, 因為新的一輪一開始就會把 `state.json` claim 成自己的 —— 等於把前一個 run 還沒讀到的那個停止請求蓋掉, 然後兩個 run 一起搶畫面, 而檔案上只看得到後開的那一個. 停止請求最慢是在打完手上這一場之後才讀到, 所以那個等待可能要好幾分鐘; 看 `result.json` 有沒有寫出來最準, `state.json` 的 `status` 回到 `idle` 也是同一件事.

實測的速率, 拿來估時間用 (2026-09-01, TH15 / 建築大師基地 10 級左右):

- **主村一場約 +1.1M 金幣、+1.1M 聖水**, 一輪連搜尋帶回營約 2 到 3 分鐘. 從幾乎空的倉庫打到 24M 的 90%, 大概 20 場、一個多小時
- **夜世界一場約 +100k 金幣**, 聖水不入庫要看推車, 每三場領一次約 116k. 一輪約 2 到 5 分鐘, 大部分是配對在等真人. 所以那邊的聖水是瓶頸, 從三成打到九成要三十幾場

夜世界跟日世界有幾個地方不一樣, 判斷的時候要記得:

- **沒有門檻可以設, 也不需要設.** 沒有偵察畫面, 對手是配對給的, 而且贏了拿金幣輸了拿聖水, 兩種結果都有收穫, 所以沒有東西好跳過
- **搜尋要等真人.** 那邊是即時對戰, 實測過一次搜了五分半, 也有四秒就配到的. 迴圈自己會在 `SEARCH_PATIENCE` 之後取消重搜, 所以看到 log 停在 searching 一兩分鐘是正常的, 不是卡住
- **倉庫水位跟主村共用同一個設定.** 設定檔裡只有一個 `stop_at` (百分比), 因為容量是迴圈自己去遊戲讀的: 它會點一下儲量條, 讀 `最大儲存量`, 再拿現在的水位去比. **一整趟只讀一次**, 不是每輪都讀 —— 倉庫要有工人花好幾天升級才會變大, 而問一次要六次點擊跟三張截圖, 所以第一輪讀到之後就一路用到收工 (`AttackRunner._settle_ceilings`). 判斷方式跟主村一模一樣 (**每一項都滿過那個百分比才停**), 所以 `--repeat 0` 在夜世界一樣會因為倉庫滿了而收工. 夜世界只讀兩排 —— 那邊沒有黑水, 第三排是寶石而且點下去會開商店, 所以它根本不點; 讀不到容量的資源不列入計算, 不會把另外兩項卡住. **夜世界的聖水車也算一個倉庫**: 聖水倉庫滿了之後, 每一場的防守獎勵還會存進車子裡, 所以兩個倉庫都過 `stop_at` 之後迴圈每輪開打前先去看一眼車子 (收得動就收), 車子也過同一個百分比才 `stock_full`. 夜世界打滿的意思因此是倉庫加車子都滿, 最後那段每輪多十秒左右. 車子怎麼看都讀不到的話 (同一趟看三次), 就退回只看倉庫
- **聖水在推車裡, 不會直接入庫.** 迴圈每 `CART_EVERY` 場會自己去領一次; 手動領是在夜世界跑 `uv run ai_coc collect`. 實測一次領到 30 萬聖水; 推車的容量寫在它自己的面板上, 而且會跟著村莊長大 —— 量到過 100 萬, 現在是 160 萬. 打完一輪記得確認有領到
- **領不到的時候分得出是哪一種.** 回報裡的 `CartReport.outcome` 有七種: `collected` 是領到了, `empty` 是按了收集而儲量沒動; `not_found` 是三個候選點都沒點開, `wrong_world` 是當下根本不在夜世界, `not_parked` 是鏡頭沒停好所以沒去找, `unreadable` 是領了但有一邊的儲量條讀不到
- **收集鈕被畫成灰的有三種 outcome, 而現在它自己分得出來**: `locked_holding` 是車上還有東西但領不出來 (`held` 是車上的數字, `capacity` 是車子的上限), 幾乎一定是聖水倉庫滿了 —— 那是車子在當額外的倉庫存聖水, **車子也滿了才是「這個村莊已經不再賺了」**; `locked_empty` 是車上本來就空的, 沒事, 遊戲在空車上也會把按鈕畫成灰的, 不管倉庫滿不滿 (實測過); `locked` 是按鈕灰的而車上那行數字讀不到, 那才需要自己去看. 以前這三種都報成 `locked` 還附一句「去跑 `ai_coc stock`」, 那一步現在不用了
- **報告的欄位不一樣**: 夜世界那幾輪的 `attacked` 是 `null` (那個數字是從偵察畫面讀的, 而那邊沒有偵察畫面), 要看的是 `phases`, 那是這一場出了幾次兵. `world` 欄位說這一輪打的是哪個世界

**先估時間再開跑.** 一輪是搜尋加上最多三分鐘的戰鬥, 加上回營, 抓四到五分鐘. 什麼都沒打成的那輪會等 `IDLE_REST` 再來. 從現在的倉庫水位到容量的 `stop_at`% 的距離, 除以一場的平均收穫, 大概就是要跑多久. 如果算出來是好幾個小時, 先跟使用者講一聲.

## 怎麼跑

**背景跑.** 前景跑會把整個 session 卡住幾十分鐘, 中間你什麼都做不了, 使用者也插不了話. 機制跟目錄佈局讀 `references/running.md`.

**預設 `--repeat 0`.** 那不是無限: 倉庫滿了迴圈自己會 break, 這正是「打到資源滿」要的語義. 使用者指定輪數就照他的.

**要不要留畫面自己決定.** `--record` 存的是迴圈自己讀的每一張, `--shot-every` 再加一條固定心跳. 留了就有東西可以事後翻, 代價是空間, 一張 PNG 一兩百 KB, 一場加起來幾十 MB. 覺得這批會有東西要查就開著, 覺得只是單純掛機就不開, 臨時想看現況隨時可以 `uv run ai_coc capture` 抓幾張.

## 怎麼盯

**log 跟畫面兩種手段都可以用, 用哪個你自己判斷.**

**log** 便宜, 適合回答「現在走到哪一步, 這輪結果是什麼」. 看這次執行自己的 `run.log`. 沒有第二份把所有執行混在一起的檔案了; 要跨好幾次找同一個症狀就 `grep -r ~/.ai_coc/logs/*/run.log`, 那樣還會順便告訴你每一筆是哪一次跑出來的.

**`plans.jsonl` 是第三種, 而且它回答的問題前兩種都答不了**: 那一場的 AI 到底叫部隊往哪打. 每次執行的目錄底下都有一份, 不用開任何旗標, 一場一行, 帶著自己的輪數. 一輪打得爛的時候它是最快的第一步 —— 先看那一行說要打哪一側、幾秒放法術、每個英雄下在哪, 再去對 `run.log` 說實際發生什麼. 兩邊對不上就是迴圈的問題, 對得上就是這份戰術本身的問題, 那是兩個完全不同的方向.

**畫面**貴一點但能回答 log 回答不了的問題: 畫面上現在到底長什麼樣, 兵有沒有真的在打, 判讀器讀到的跟眼睛看到的一不一樣. `uv run ai_coc capture --count N` 從活著的遊戲抓, 存進那次執行自己的資料夾(`--label` 給它取個名字就找得回來), `uv run ai_coc read <png>` 把一張圖丟給所有 parser 看它們各自讀到什麼.

沒有規定的順序. log 看得出來就不用截圖, log 講不清楚就去看圖, 一開始就想看圖也可以. 有疑問而 log 沒回答到, 截一張就是了, 那很便宜.

**看過的圖順手發一份給使用者.** 只要你看了它並且據此下判斷, 就用檔案傳送機制發出去, 不要只留一個路徑. 使用者看不到你的工具輸出, 而你在圖上看到的東西他多半也想看一眼.

**盯的頻率**: 一輪四五分鐘, 所以幾分鐘看一次就夠, 不要每幾秒去讀一次, 也不要掛一個東西在 log 上等新行進來 (為什麼不行見 `references/running.md` 的「盯」那節). 中間的空檔拿去做別的事.

**每一輪結束會有一行 `Attack finished:`**, 而要判斷發生了什麼事看 `result.json` 裡那一輪的 **`AttackReport.outcome`**, 不要去比對 log 裡的句子 —— 那些字會改, outcome 不會. 十四種, 分成兩組.

**打了一場的四種**, 而它們的差別就是下一步往哪走:

- `took_loot` —— 打完回營而且倉庫真的動了. 正常的一輪, **只有主村會出現**
- `deployed` —— **夜世界的正常一輪**: 兵出去了並回營, 而那邊沒有戰利品面板可以判斷搶到多少 (聖水進推車, 而主村讀面板的那個框在夜世界是戰場). 所以它不保證倉庫動了, 要看進帳就比對前後的 `stock`
- `loot_unread` —— 打完了, 但整場都沒有一格畫面讀得出戰利品面板, 所以這一輪**無從判斷**. 不是失敗也不是成功
- `no_loot` —— 兵確實出去了而倉庫沒動. 那是**戰術**的問題 (打進了沒有倉庫的那一側之類), 歸 watch-and-fix
- `nothing_deployed` —— 一張卡片都沒出得去. 那是**迴圈**的問題, 也歸 watch-and-fix, 但要查的是完全不同的地方

**沒打到的十種**: `army_short` (軍隊連兵營的一半都不到, 沒付搜尋費就退出來 —— **而且整個 series 到此為止**: 現在造兵是即時的, 所以這種軍隊不會自己變好, 是配置本身湊不出兵力, 要人進遊戲改) / `stock_full` (倉庫都滿過設定的百分比, 整個 series 到此為止; 夜世界還要聖水車也滿過同一個百分比, 除非車子看了三次都讀不到 —— 那時 `run.log` 在它前面有一行 `the storages decide alone`, 回報裡就不能說車子滿了) / `no_opponent` / `all_skipped` (跳過的都未達門檻) / `stopped` / `no_attack_menu` / `server_loading` 跟 `server_flapping` (伺服器那邊的事, 見下面警覺樣態那節) / `emulator_silent` / `world_unreachable`.

另外兩個欄位跟 outcome 無關而是疊在上面的: `forced` 是這一場被倒數逼開的而不是戰利品達標, `skipped` 是這一輪跳過幾個對手.

要判斷一輪算不算真的開打, 最穩的還是看 `AttackReport.attacked` 是不是 `None` (夜世界看 `phases`), 因為那是「有沒有對手」而不是「怎麼結束」.

**值得警覺的樣態**, 不是單一輪而是連續幾輪:

- 一輪 `army_short` 就整個 series 收工了, 那不是它壞掉: 造兵即時, 所以那是軍隊配置湊不到兵營的一半, 要人進遊戲改. 實測過一次是限時活動結束, 活動兵從已儲存的隊伍裡消失, 只剩 20/340. 抓一張軍隊畫面附在回報裡, 讓使用者知道要改什麼
- 連續打完但每輪 `skipped` 都是幾十: 門檻對現在的獎盃區間來說太高了, 值得跟使用者提一句
- 打完了但**入庫的進帳遠小於 `attacked`**: 進攻打不動人家, 這是 watch-and-fix 的題目, 這裡只負責報告. 看的是這個落差而不是 `attacked` 自己大不大 —— 那個數字只說對手**擺出**多少 (見下面「數字從哪來, 不准編」), 所以它小可能只是配到一串窮對手, 或者門檻設得太低
- log 裡出現重新登入 / 重開遊戲 (`The session was dropped`): `ui/runner.py` 的 `restart_game` 自己會處理, 會回到村莊, 不用管. 閒置斷線跟 連線已中斷 兩張對話框都走這條. 但如果一直重複發生, 那是要查的
- log 裡出現 `waiting for the server rather than tapping`: 遊戲卡在載入畫面, 通常是伺服器那邊的事. 迴圈自己會等, 最多 45 分鐘, 每次載入只等一次 (重開遊戲算新的載入), 等到了就接著打; 等不到的那一輪 `outcome` 是 `server_loading` (等滿 45 分鐘) 或 `server_flapping` (載入完又掉回去). 這時候**不要**去重開遊戲或模擬器: 實測兩次都是它自己回來的, 重開沒有縮短過任何一次. 連續兩輪都是這兩種之一再停下來講
- log 裡出現 `The camera was not at the far zoom`: 那一輪多半是白打的, 因為這個專案每一個座標都是在最遠的 zoom 量的, 鏡頭飄掉就全部落空. 迴圈每場自己會 pinch 回去, 所以偶爾一條不用管, 連著出現就去看畫面. 手動修法是 `ai_coc view --zoom out`, 但要先把迴圈停掉. **這條只在主村會出現**: 那個高度是拿主村量的, 建築大師基地地圖比較小, 在同一個 zoom 下每一張都讀得比它短, 所以夜世界不做這個判斷 —— 夜世界沒有這條, 不代表那邊的鏡頭一定是對的

## 倉庫滿了: 預設就收工, 他開口才花

**預設情況下倉庫滿了就是終點.** 使用者 2026-09-15 的常設交代, 原話是「默認就是打到設定的值, 除非我有特地說 打資源跟升級牆壁之類的」. 所以他只說「幫我打資源」的那一趟, 任務就到兩個世界都打到 `stop_at` 為止: 讀結束水位, 把工人狀況附在報告裡, 交報告, 收工. **工人那一項用 `ai_coc worker`, 不要用 `ai_coc builders`** —— 後者是主村的指令, 停在夜世界的時候會自己坐船回主村 (`GameRunner._home` 讀到夜世界就 `cross`), 白花一趟船還把遊戲留在錯的世界. `worker` 不切世界, 答的是當下站著的那個村莊, 而且連每個工人在蓋什麼都讀出來. 要一次交代完就用 `ai_coc status`, 它把工人、實驗室、倉庫跟護盾一起讀, 一樣不切世界. **不要自己接下去花**, 也不要因為看到工人閒著或者某棟很划算就動手 —— 覺得值得花的就寫成選項讓他挑, 規矩在下面「要他拍板的事情用選擇題問」.

**他開口了才有下面這一圈**: 打到滿 → 把資源花掉 → 回來繼續打, 繞到花不掉為止. 開口的意思是他在交辦的時候就講了要花 —— 「打完順便刷牆」「把資源花掉」「打資源跟升級牆壁」 —— 而不是你判斷出來的. **底下這一整節都只在那種情況下適用.**

**第一步是問 `ai_coc world`, 沒有例外.** 夜世界一樣會 `stock_full`, 而花資源的三個指令**一個都不看世界**: `walls` / `upgrade` / `hero` 走的 `_home` 讀到夜世界就直接坐船回主村, log 只留一行 warning, 然後花掉的是**主村**的資源跟**主村**的工人. 所以在夜世界打滿之後照這一節做, 結果是主村的工人被綁走好幾天, 而夜世界那個真的滿了的倉庫一動也沒動 —— 「花不掉才停手」永遠到不了, 於是繞回去繼續打一個已經滿了的村莊.

**夜世界打滿了要做的是換去打日世界**, 因為兩邊的倉庫互不相通. 夜世界自己的出口 (它的建築跟牆) 沒有任何指令做得到, 那是 `spend-loot` 用眼睛做的事, 而且值不值得做是使用者的決定. 兩個世界都滿了才是真的要通知他.

**底下這一整節講的都是日世界.**

**這個圈是你在接的, 程式碼裡沒有它.** `ai_coc attack --repeat 0` 只知道「倉庫滿了就停」, `stock_full` 是 true 的那一刻對它來說就是結束, 對你來說是換下一步. 沒有旗標可以讓它自己繞. 中間也不要拖: 打滿的村莊正是別人最想打的那一種, 而唯一減少暴露的動作就是趕快把資源花掉, 讓倉庫不再是滿的.

**背景那輪跑完的通知進來, 就自己接下一步, 不要回頭問.** 他交辦的是「打到花不掉為止」, 所以那個通知是接縫不是終點, 停在那裡問「接下來要做什麼」等於把他花錢請你避開的那段等待又放回去. 只有兩種情況不接 —— 他自己說過停 (見 `references/running.md` 的「中止」), 或者剩下的那一步需要他拍板 (牆, 英雄). **他沒開口要花的那一趟, 這條只是不往「花」那一步接, 不是整條停用.** 該打的世界還沒打完之前, 通知一樣是接縫: 讀完最後一輪確認是 `stock_full`, 就自己開下一個世界, 不要回頭問 —— 上面「兩邊都打滿是一個你要接的序列」那段記著的那次實測 (一個 session 打完夜世界之後就停在原地) 正是這樣來的. 都打到 `stop_at` 之後才是終點, 那時候交報告收工, 再「接下一步」就會變成花掉他沒授權的東西.

**怎麼花是 `spend-loot` 的事** —— 三個入口各自怎麼找目標, 陷阱在哪, 全部在那份 skill 裡. 這裡只有三件事要你判斷.

**一, 授權.** 這一整節的前提是他已經開口要花了. 在那之上, 建築照他那句話做就好, 城牆要他指名到「牆」, 英雄要他指名到是哪一個.

- **城牆要使用者指名, 預設不刷.** 這是使用者 2026-09-15 給的常設交代, 原話是「默認是不升級牆壁, 除非我說」, 而他要的是被通知: 「待會不要升級牆壁 通知我就好」. 他沒有講理由, 所以**不要替他補一個**, 也不要因為這一趟看起來特別划算就自己判斷. 一句籠統的「把資源花掉」不算指名到牆. 牆本身的性質沒有變 —— 付錢的當下就升好, 不跑計時器, 工人立刻還回來, 資源再打就有 —— 那是它值得在通知裡被列成一個選項的原因, 不是它可以自己跑掉的理由
- **建築不用問, 但要有工人閒著**: `ai_coc builders` 說真的有. 倉庫滿了而工人在發呆是雙重浪費 —— 打回來的資源進不了滿倉直接被丟掉, 而工人這段時間什麼都沒蓋. **這一條是這份 skill 從「只有刷牆不用問」改過來的**, 因為那條規則讓每一次倉庫打滿都停在等使用者回話, 而他不在. 它以前還有第二個前置條件「牆已經證明吸不掉」, 那是牆還會自己跑的時候寫的; 牆現在預設不跑, 那個條件永遠不會成立, 留著等於把建築這個出口也一起關掉
- **英雄要使用者指名.** 升級中的英雄不能上場, 卡片直接從隊伍列消失, 所以升一個英雄是拿接下來幾天的進攻火力去換, 而這個 skill 的主線正是打資源. `ai_coc hero` 不給 `--upgrade` 只讀不動, 讀出價格回報給他, 讓他挑 (用選擇題問, 見下面「要他拍板的事情用選擇題問」)

**二, 順序: 使用者指名要刷牆的那一趟, `walls` 先, `upgrade` 後.** 兩個出口搶同一個工人, 而它們借走的長度差好幾天 —— 牆借一瞬間, 建築借好幾天. 而 `ai_coc upgrade` 會把**每一個**閒置工人都派出去, 所以先跑它就是先把牆這個出口關掉, 然後花兩分鐘讓 `walls` 去撞「所有建築工人都在忙碌中」. 反過來也不會虧: 牆買完還有剩, 或者牆被大本營等級卡住, 那兩種情況工人都還閒著, `upgrade` 照樣接得上. (牆因為工人全忙才買不動的那一種是例外, 那時候 `upgrade` 同樣派不出人, 見下面.) 他要花但沒指名到牆的那一趟就沒有順序問題, 只有 `upgrade` 會跑.

**而那一趟的 `upgrade` 會把牆這個出口關掉好幾天, 通知救不回來.** 刷牆要有一個工人閒著, `0/N` 一片都買不了, 而 `ai_coc upgrade` 會把**每一個**閒置工人都派出去 —— 所以倉庫滿了而工人閒著的時候, 牆跟建築在搶同一個工人, 而一句籠統的「把資源花掉」會把他派去蓋建築, 一綁好幾天.

**通知照樣先發, 牆列成其中一個選項, 但要在通知裡講明那個選項會在 `upgrade` 跑下去之後過期.** 把通知排在前面並不會留下任何一個工人, 而上面「不要回頭問」那條說的就是不要停在那裡等他回話; 使用者多半不在, 這個 skill 又多半是 subagent 在跑, 題目還要轉一手給主 session, 所以他的回覆幾乎一定落在工人已經被借走之後. 寫成「已經幫你問過了」是假的. 誠實的寫法是讓他知道: 要刷牆的話, 得等下一個工人空出來再說一次.

**三, 兩個出口關掉的方式不一樣, 下一步也不一樣.**

- **牆需要有一個工人閒著.** 升一片牆要用掉一個空閒工人, 只是付錢的當下就完成, 工人立刻還回來, 所以有一個閒著就能連續買一整排, 而 `0/N` 一片都買不了. 實測在 0/5 的村莊每一批都確認了然後沒被扣錢, 遊戲回一句「所有建築工人都在忙碌中」再附一顆寶石按鈕, 一片牆跟八片牆一樣退 —— 一片跟八片一樣退, 正是排除掉批次大小跟錢的那個證據. **這一種卡法 `upgrade` 也接不上**, 因為它同樣要工人
- **牆被大本營的等級卡住.** 看 `WallReport.outcome` 而不是看句子: `cannot_afford` 跟 `builders_busy` 是真的講出原因的兩種, 而 **`nothing_bought` 是它自己也說不上來**, 最可能的意思是牆到頂了 —— 那時候升級開出來的是一張要你先升大本營的告示, 而這個迴圈結構上只按得下綠色的確定, 所以它撞到什麼自己讀不出來. **這一種正是 `upgrade` 該接手的地方**: 工人還閒著, 只是牆沒得買. 撞到一次之後這一整趟都不用再跑 `walls`, 那個出口要等大本營升上去才會重開, 而那是使用者的決定

**他開口要花的那一趟, 停手的條件不是「倉庫滿了」而是「資源花不掉了」**: 工人全忙或者沒有值得升的建築, 牆沒指名到所以不刷 (指名了的話就是牆也刷不動, 兩種卡法見上面), 而剩下的只有要他拍板的英雄. 那時候就交報告收工. 那一趟倉庫滿了就交報告是把一圈當成全部. **他沒開口的那一趟剛好相反**, 倉庫滿了就是終點, 見這一節開頭.

**黑水只有升英雄能消化.** 牆吃金幣跟聖水不吃黑水, 所以黑水滿了而使用者沒指名英雄, 那一項就是停在那裡, 回報的時候要講出來.

通知的時候一起附上工人的狀況. `ai_coc builders` 說每個工人在蓋什麼、最快的一個還要多久, 那決定了通知裡要不要叫使用者等; 只想知道閒著幾個的話, 一張主村畫面丟 `uv run ai_coc read <png>` 看 `builders` 就有.

**其他停手的理由**: 遊戲一直回不到村莊, 同一個錯誤連續發生三次以上, 一輪也沒打成過, **連續三輪都是 `模擬器沒有回應：…`** (log 會說 `The emulator has not answered for 3 rounds`; 那是模擬器不理人而不是遊戲的問題, 先去看它還活著沒有), 或者排程重開模擬器之後村莊沒回來 (log 會說 `The village never came back after the restart`, 整個 series 就停在那裡, 手上那幾輪還是算數的). 這些都停下來講, 不要一直重試. 這個 repo 的原則是失敗要吵, 不是安靜地繼續.

## 停手之後就真的停手

**打完不要再留著什麼東西跑.** 這裡以前有一個 `ai_coc online`, 每兩分鐘拖一下畫面, 為的是「部落衝突不會讓人攻擊一個主人正在線上的村莊」. **那條規則在現在的版本已經不成立了** —— 帳號的主人實測過, 現在有沒有人在看畫面都照樣被打, 所以那個指令買不到任何東西, 已經整個刪掉.

真正還在保護村莊的是**遊戲自己在你被打之後給的護盾** —— 實測那一晚, keepalive 隨著模擬器一起死掉之後村莊連吃兩發, 然後就掛著一張 4 小時 20 分的護盾 —— 它不需要這邊跑任何東西. 所以資源花不掉的時候就交報告、停手, 不要為了「讓它有事做」而留一個迴圈在背景.

## 順手做的事

`collect` 很便宜, 是這個專案裡最值得常跑的指令: 採集器裝滿就停工, 沒人去收的村莊多數時間是在發呆. 開跑前跑一次, 每過一段時間再跑一次, 花不到幾秒.

`donate` 也幾乎沒成本, 沒人開口要兵的話只花一次點擊跟一張截圖, 而且捐兵有回饋. 想跑就跑, **但它在夜世界會先坐船回主村**, 所以開跑前要跑的話先問過 `ai_coc world` 再跑, 理由在上面「順序」那段.

`upgrade` 跟 `hero` **不要在打到一半的時候插進去**: 它們要先停迴圈才跑得了, 而且倉庫還沒滿的時候 `upgrade` 挑得到的比打滿之後差. 它們的位置是倉庫滿了那個接縫, 授權跟順序見上一節.

使用者開口指名要升某一樣東西的時候, 換 `spend-loot`. `ai_coc upgrade` 不給 `--only` 只會挑「最貴而且買得起的」, 指定不了是哪一棟, 而怎麼指定寫在那份 skill 的「三個入口」那節.

## 途中撞到 bug

**停下來把它寫清楚, 不要自己動手改.** 這個 skill 常常交給比較弱的模型跑, 而讓它一邊打一邊改程式碼正是要避開的事: 動程式碼要先量測, 要跑測試, 要開 PR, 那一整套判斷寫在 `watch-and-fix` 裡, 這裡沒有.

撞到的時候把三件事寫進回報: 哪一輪, `run.log` 裡的哪幾行, 以及你當下看到的畫面. 那份回報就是 `watch-and-fix` 接手的起點. 繞過去而且不寫才是真的損失, 因為下一次還是會撞上同一個.

要看活的畫面才判斷得出來的時候, 就自己把迴圈停掉, 看完自己開回去 —— 規矩在 `references/running.md` 的「你自己要用畫面」那節.

## 任務報告

**任務達成才交完整報告, 而達成的定義跟著他有沒有開口要花走.**

- **他只說打資源**: 該打的世界都到 `stop_at` 就是達成. 那一趟不花任何資源, 所以不要為了湊出一個「花不掉了」的結論去跑 `walls` 或 `upgrade` —— 那正是這條規矩擋掉的事
- **他開口要花**: 達成的意思是**資源花不掉了** (倉庫滿了, 工人全忙或者沒有值得升的建築, 牆沒指名到所以不刷). 那一趟「倉庫滿了」只是一圈的一半, 上面那個圈跑完幾次都算同一個任務, 中間那幾次「打滿了」只值一句進度 —— 一圈交一次報告會把同一件事拆成四五份, 而他要的是「這一段總共賺了多少、花掉多少」

使用者指定的輪數跑完也是達成. 不管哪一種, 那都是一個明確的時刻, 報告放在那裡才有份量.

**沒達成就不要交報告**, 給一段話講清楚三件事就好: 跑到哪, 為什麼停下來, 要不要繼續. 中途被中斷, 遊戲一直回不了村莊, 一輪也沒打成, 這些都屬於這一類. 對一個半路夭折的跑交一份完整格式的報告, 只是把壞消息包裝得很漂亮.

**交報告之前先確認沒有東西留在背景**, 而且是去查而不是回想 —— 沒有 `ai_coc` 程序, 沒有 shell 還在輪詢, `state.json` 回到 `idle`. 規矩跟那次三十五小時的實測在 `references/running.md` 的「等待要有出口, 收尾要清乾淨」那節. 報告裡要講結果, 刻意留著的也要講是哪一個.

報告印在對話裡, 同時寫一份到這次執行自己的目錄 (`~/.ai_coc/logs/<run>/report.md`), 跟它的 log 和畫面放在一起. 檔案那份是給以後翻的跟拿來跟上次比的, 對話那份是給現在看的, 內容一樣.

**樣板不要改.** 使用者會拿這次跟上次對照, 每次換一種寫法就比不了.

**兩個世界都打了就各報一份.** 「資源」跟「戰績」這兩節各出現兩次, 標題寫成 `## 資源（主村）` 跟 `## 資源（夜世界）`, 其他幾節共用. 不加總, 理由跟基準那節一樣. 夜世界那兩節的欄位本來就不一樣, 照著填會填出一堆空格:

- **對手擺出來的總量沒有**: 那個數字是從偵察畫面讀的, 而夜世界沒有偵察畫面, 所以 `attacked` 是 `null`. 那一行寫「無此欄位」, 不要留空讓人以為是零
- **戰績看 `phases`**: 那是這一場出了幾次兵 (第二階段算第二次), 不是輪數. 也沒有對手可以跳過, 所以跳過那行不用寫
- **聖水要另外算推車**: 夜世界的聖水是入推車不是入庫, 迴圈每三場去領一次. 倉庫水位的差額會漏掉還在推車裡的那些, 所以收工前先跑一次 `uv run ai_coc collect`: 倉庫還有空間它會把推車倒進去; 打滿收工的時候倉庫是滿的, 它回 `locked_holding` 並附上車上存的 `held` 跟 `capacity`, 那筆也是夜世界的聖水, 報告裡跟倉庫分開寫 (倉庫 X + 推車 Y)

### 開跑前先記下基準

進帳算不出來是因為沒有起點. 所以**開跑之前一定先跑一次 `uv run ai_coc stock`**, 把它印出來的數字記下來; 結束之後再跑一次. 這兩次讀取合起來才是「這次賺了多少」的唯一可信來源.

它回的是**當下這個世界**的水位、容量, 跟每一項的百分比. 百分比才是真正在用的那個數字, 因為 `stop_at` 就是一個百分比; 而容量會在工人升完倉庫之後變大, 所以不要把容量記在腦子裡或抄進筆記, 每次問它就好.

**它不會自己切世界, 這是刻意的.** 要看另一邊就先 `ai_coc world --go`, 再問一次 `stock`. 兩個指令湊起來就是「兩邊各多少」, 沒有第三個指令要記.

**這一步不是可有可無的.** 它存在之前唯一的辦法是 `capture` 加 `read`, 而 `capture` 刻意不動畫面: 儲量條沒填滿的那一段是半透明的, 所以數字背後透出來的是鏡頭當下對著的東西, 而夠亮的背景會把數字**之間的縫**填掉 —— 實測在一個拉近的鏡頭上, 七個平移位置有一個讓 `10 779 278` 的 `779` 連成一段 55 px 的東西, 判讀器認不出那是什麼, 整排回 None, 而那張圖上三個數字用眼睛看都是清楚的. `stock` 走 `_settle_game`, 鏡頭是放好的.

**兩個世界都要打的話, 兩邊各讀各的, 而且不准混.** `stock` 只答當下這個世界, 所以另一邊是 `ai_coc world --go` 之後再問一次; 它回的 `world` 欄位說這份數字是哪一個村莊的. 那是兩組完全分開的倉庫, 容量差十倍, 所以「金幣 + 金幣」是一個沒有意義的數字. 順序上先讀要先打的那個世界, 因為切世界要坐船, 而船開過去之後另一邊的水位還是原本那個.

### 樣板

```markdown
# 任務報告

**目標**: <這次要達成什麼>
**結果**: 達成
**一句話**: <賺到了嗎, 現在輪到使用者做什麼嗎>

## 資源
|      | 開跑 | 結束 | 進帳 |
| ---- | ---- | ---- | ---- |
| 金幣 |      |      |      |
| 聖水 |      |      |      |
| 黑水 |      |      |      |

對手擺出來的總量: 金 / 聖水 / 黑水
平均一場: ...    每小時約: ...

## 戰績
跑了 <時長>, <N> 輪, <M> 輪開打, <K> 輪空手 (<理由>)
跳過 <X> 個對手
最好的一場 / 最差的一場

## 花掉的
刷牆 <N> 片, 金幣 -<X>, 聖水 -<Y>
(沒花的話寫沒花, 以及為什麼)

## 為什麼停
<停手的理由>
工人 <閒著幾個>/<總共幾個>

## 需要你決定的
<沒有就寫沒有>
```

### 數字從哪來, 不准編

- **開跑 / 結束 / 進帳**: 上面那兩次 `ai_coc stock`. 這是真的入庫的量

- **對手擺出來的總量**: `result.json` 裡每輪 `AttackReport.attacked` 的加總. **那是偵察畫面上對手擺出來的可搶量, 不是帶回家的量** —— 欄位的 docstring 就是這樣寫的, 所以別把它讀成戰利品. 它跟入庫的進帳一定對不上, 而且原因有三個, 方向不一樣:

    - **一場只帶回打下來的那一份**, 這是常態而且通常是三者裡最大的一項. 打得爛就差得多 —— `CLAUDE.md` 記著一場結算讀 `戰敗, 32%, 你獲得了 0` 的實測, 那一場的 `attacked` 照樣是滿滿一排數字
    - **倉庫滿了之後搶到的進不去被丟掉**, 所以入庫又更少. 打到 `stop_at` 的那一趟最後幾場都是這樣
    - **星星獎勵是另外加在上面的**, 偵察畫面上看不到, 所以這一項往回加

    真正入庫的只有前後兩次 `stock` 的差額, 沒有第二個來源. 兩個都列出來, 差很多本身就是資訊. **差額存在是正常的, 不要當成查不出原因的怪事寫進報告** (實測 2026-09-16 就有一趟是這樣報的), 但**差額比平常大得多是要往上報的訊號** —— 那是進攻打不動人家, 見上面「值得警覺的樣態」, 而這份 skill 只負責報告

- **輪數 / 開打 / 空手 / 跳過**: `AttackSeries` 數出來, 空手的理由看那一輪的 `outcome`

- **刷牆**: `WallReport.walls` 跟 `paid("gold")` / `paid("elixir")` 說買了多少, `WallReport.outcome` 說為什麼停 —— 那才是「發生了什麼」的欄位, 見上面停手那節

- **工人**: 一張主村畫面丟 `ai_coc read`, 看 `builders`

- **時長**: `run.log` 第一行跟最後一行的時間戳. 那個格式只有時分秒沒有日期, 所以跨午夜的跑會算出負數, 日期要看目錄名

**量不到的就寫量不到, 不要估.** 這個專案的規矩是寧可顯示破折號也不猜一個數字, 報告一樣適用.

### 那一句話怎麼寫

使用者多半只看這一句, 所以它要同時回答「賺到了嗎」跟「現在輪到我做什麼嗎」:

- `兩邊都打滿了. 主村金幣聖水都到 26M 上限, 夜世界也滿, 沒花任何資源; 工人 2/6 閒著, 要花什麼跟我說.`
- `打滿了但花不掉. 金幣卡在上限, 工人 0/6 全忙, 牆你沒開口所以沒刷, 多出來的資源會一直被丟掉.`

### 要他拍板的事情用選擇題問

**寫進「需要你決定的」的每一項, 都要同時用選擇題問出去.** 報告是一段文字, 使用者要打開對話才看得到; 選擇題會推一則通知到他手機上, 而「打滿了但花不掉」這種時刻正好是他不在電腦前的時候 —— 這是他自己交代要這樣問的. 選項就是他真正的那幾條路, 每一條附上價格或代價, 再加一條「先不要動」. **不要替他推薦哪一個**: 升哪個英雄是村莊怎麼玩的取捨, 價格答不了, 而一個被標成推薦的選項就是替他決定了. 沒有東西要他決定就不要問, 那只是多一則通知.

**問不到人的時候就把題目交出去.** 這個 skill 多半是主 session 派一個 subagent 來跑的, 而 subagent 問不到使用者. 那種情況不要硬問: 把題目跟選項照樣寫進回報, 並且明講這是要用選擇題問出去的, 讓主 session 去問.

### 他交辦裡有「通知我」的時候

**推播不一定送得出去, 而且失敗是安靜的.** 它吃使用者自己的通知設定, 關掉的時候只回一句 not sent 就沒了 —— 交辦裡的「打滿後通知我」於是變成一則沒有人收到的通知, 他要自己打開對話才會發現. 實測 2026-09-17, 一趟打滿的報告就是這樣掉的, 而那一趟的使用者正是因為要通知才不在電腦前.

**選擇題看起來是另一條路, 但那還沒有量過.** 使用者說他看過選擇題推來的通知, 上一節也是照他的交代寫的 —— 可是**沒有人試過推播被關掉的時候選擇題還送不送得到**, 這個 repo 裡沒有任何一筆量測. 所以它是一個有根據的假設而不是已知, 而這份 skill 自己的規矩是量不到的就寫量不到: 「通知我」這種交辦**兩條都發**, 不要因為這一節就把推播那一路收掉. 哪一天真的量到了就把結果寫回這裡, 這一段可以收成一句話.

**而打滿的那一刻多半有東西可以問** —— 繼續打, 把資源花掉, 還是收工 —— 所以這通常不是替通知硬湊一個題目. 但那是判斷不是通則, 見下一條.

**上一節那條「沒有東西要他決定就不要問」沒有被這一段取消.** 真的沒有題目的時候就是沒有: 倉庫滿了而工人全忙, 三條花錢的路都要工人所以連「把資源花掉」都選不了, 而「繼續打」搶回來的進不了滿倉, 「收工」本來就是預設. 那時候誠實的做法是把狀況寫進報告並且講明推播沒送到, 而不是編一個他選了也做不到的題目讓通知有藉口發出去.

**subagent 兩條都發不出來.** 這份 skill 多半是主 session 派來的 subagent 在跑 (上一節末尾那條), 而它既推不出通知也問不出選擇題. 所以交辦裡有「通知我」的時候, **那件事本身要跟題目一起往上交**: 在回報裡明講使用者要求過通知, 不然主 session 收到的只是一份普通報告, 那則通知還是沒有人發.

**推播回 not sent 就要在回覆裡講出來**, 不要當成發成功了. 那一句是這條管道唯一的回音, 而使用者看不到工具輸出.

## 沒達成的時候講什麼

不套樣板, 不寫檔案, 就一段話:

- 跑到哪 (幾輪, 進帳多少, 能講多少講多少)
- 為什麼停 (被中止 / 一輪也沒打成 / 回不了村莊 / 同一個錯誤重複發生)
- 要不要繼續, 以及繼續之前有沒有東西該先處理

被砍掉的跑 `result.json` 會是空的, 走 `uv run ai_coc stop` 停的不會. 空的那時候 `run.log` 是唯一的紀錄, 從裡面數得出多少就寫多少, 並且註明是從 log 數的. 被砍掉的那種 `state.json` 也會停在 `running`, 因為沒有人把它寫回去 —— 那是殘留而不是有東西在跑, 拿裡面的 `pid` 查一下就知道.

## 中途被問進度

報當下的資源跟輪數就好, 而且**不要停下迴圈**. 報告留到任務真的達成再交.
