# farm

代替使用者顧兩個村莊. 開跑, 盯著, 判斷, 回報. 這個 skill 不改程式碼.

## 做完的樣子

最後交給使用者的是下面三種之一, 看任務走到哪:

- **任務達成** (他只說打資源: 該打的世界都到 `stop_at`; 他要打到有空閒: 確認有工人或實驗室空出來了; 他開口要花: 資源花不掉了; 他指定輪數: 輪數跑完): 照「樣板」: 一句打完沒跟花多久, 一張每個世界一列的表 (幾場, 進帳, 現在的水位), 一行工人跟護盾. 印在對話裡, 不寫檔案, 同時發一則推播; 要他決定的事接在報告後面, 一條一個編號 (「通知跟要他拍板的事」). 交之前查過背景沒有殘留. 細節全在「任務報告」
- **沒達成** (還沒達成就停了, 不管為什麼: 被中止, 「其他停手的理由」, `army_short`、`other_village` 或 `session_taken` 收掉整個 series, 「一輪就要停下來的」那種, 途中撞到 bug): 不套樣板, 兩三句話, 見「沒達成的時候講什麼」. 各自要附的東西跟著那一條走, 例如 `army_short` 附軍隊畫面, 撞到 bug 附「途中撞到 bug」那三件事; 你是 subagent 而那個停不是你下的, 還要寫停在哪, 見 `references/running.md` 的「中止」
- **中途被問進度**: 當下的資源跟輪數, 迴圈照跑, 見「中途被問進度」

另外, 你看過而且拿來下判斷的每一張圖都發給使用者 (見「怎麼盯」). 你是 subagent 的話, 上面這些交回給派你的 session, 要問的題目跟要推播的那一行在回報裡寫明, 讓它去發.

## 三份文件的分工

- **程式碼**說現在是什麼: 旗標看 `src/ai_coc/cli.py` 的 `_parser()`, 指令做什麼看 `src/ai_coc/commands.py` 對應的函式, 回報欄位看 `src/ai_coc/models.py` 的 `AttackReport` / `AttackSeries` / `WallReport`
- **`AGENTS.md` 跟常數旁邊的註解**說為什麼
- **這份 skill** 說怎麼判斷: 什麼時候介入, 什麼時候停手

不要憑記憶下參數, 開跑前讀上面三個程式碼位置.

## 開跑之前

**讀 `~/.ai_coc/config.json`** (視窗跟終端機共用):

- `thresholds`: 打誰的門檻. 太高會一直跳過
- `stop_at`: 停手的倉庫水位百分比, **主村跟夜世界共用**, 容量迴圈自己去遊戲讀. **每一項都滿過這個百分比才停**, 不是任何一項到頂就停. `0` 是永遠不收工; 讀不到容量的那一項不列入計算
- `adb_serial`: 打的是哪一台模擬器 (MuMu 或雷電), 寫 `adb devices` 列出來的名字. 空的話第一次執行會自己挑一台寫進來. **兩台登的是同一個帳號**, 一台開遊戲就把另一台踢下線, 所以只打設定的那一台, 要換台先改這一格 (或在視窗的模擬器清單選), 不要兩台輪流開

使用者沒交代就照設定檔跑. `--min-gold` 之類只在他明講要放寬時用, `0` 跟不給是兩件事 (見 `LootOverrides` 的 docstring). `--stop-at` 是**測試**用的: 對著剛打滿的村莊打一場來驗東西時給 `0`; 打資源不要用, 滿倉搶回來的進不去.

**碰模擬器之前先讀 `~/.ai_coc/state.json`, 而且每個指令都帶 `--yield`**: 有別人在跑就排隊等它跑完, 不會把它停掉; 別人要用時你的 run 是被借走, 開回去的指令會自己等到還回來. 查法在 `references/running.md` 的「絕對不要同時跑兩個」跟「被借走」. **例外是別人已經在打資源**: 開工時佔著的是別的 agent 帶 `--yield` 的 run (`yields` 是 `true`, `caller` 不是你), 或者檔案上有一筆還沒結束的借用 (`loan.ended` 是 null) 而 `lender` 不是你, 就不要排在它後面, 兩個迴圈會在指令之間輪流搶到模擬器, 各自的 `world --go` 把對方下一輪的 `attack` 帶到錯的村莊. 不開跑, 回報誰 (`caller`) 在跑哪一個 (`command`, `log`).

**開跑前不用先讀倉庫**: `attack` 每一輪開打前自己讀一次, 寫成 `run.log` 的 `Village holds …` (夜世界 `Builder base holds …`), 進帳就從這些行算 (「數字從哪來, 不准編」). 已經滿了的世界, 開跑第一輪就會收工, 不是壞掉.

**不用自己開模擬器或遊戲**: 會操作畫面的指令 (`stock`、`attack`、`world --go` …) 走 `commands._controller()`, 它會 `ensure_coc`. 不帶 `--go` 的 `world` 跟 `capture` 只看不開, 模擬器沒開就報錯; 遊戲沒畫面時 `world` 回 `no_display`, `capture` 直接報錯. 那時先 `ai_coc launch`.

**這個遊戲有兩個村莊, 而遊戲會開在上次離開的那一個**: 日世界 (主村) 跟夜世界 (建築大師基地), 靠一艘船來回. `ai_coc world` 答現在在哪個世界, 不點任何東西; `ai_coc world --go day|night` 坐船切過去, 已經在那邊就什麼都不做.

**沒有指令會自己換村莊, 每一個都做遊戲當下停著的那一個.** 先 `world --go` 再開 `attack`. `world --go` 回的不是那個村莊 (`crossing_failed`) 就不要開, 先去看畫面. 開跑後對一下 `run.log` 打的是哪一邊: 每一輪開頭 `Attack run starts` 是主村, `Builder base attack run starts` 是夜世界 (沒給 `--plan` 的那批第一輪前面還有一行 `Playing the day village, the one the game is on` (或 night); 給了 `--plan` 就打戰術檔寫的那個村莊, 沒有這行). 兩邊容量差十倍, 打錯世界「還差多少」就全錯. 打到一半遊戲被換到另一個村莊 (例如使用者自己切), 那一輪回 `other_village`, 整批收工, 不會自己坐船回去.

**沒特別交代就兩個世界都打完.** 不用先問哪邊有空間: 滿的世界第一輪就 `stock_full` (主村在付搜尋費前, 夜世界在進配對前), 代價只是幾秒. 他指定了一個才只打那一個. 夜世界是同一個指令, 多帶平鋪戰術 (為什麼見下面「夜世界不一樣的地方」):

```bash
uv run ai_coc world --go night --yield
uv run ai_coc attack --repeat 0 --plan src/ai_coc/plans/night_flat.json --yield
```

**順序: 他指定了照他的, 沒指定就先打當下所在的那個.** 「當下所在」是開跑前第一件事用 `ai_coc world` 問到的答案, 記下來. 切畫面就是他指定順序的方式 (想先打夜世界他會自己切過去), 不要推翻.

**一次只跑一個世界, 而「兩邊都打滿」是一個你要接的序列, 不是一個指令.** 同時開會搶同一個畫面. 最後一輪的 `AttackReport.stock_full` 是 `true` 就是這個世界打完了 (`result.json` 是陣列, 讀法在 `references/running.md`), 但那只是一半: 通知進來, 讀最後一輪確認是 `stock_full`, 就 `world --go` 換另一個, 開一樣的 `attack`, 它也 `stock_full` 才算達成 (日世界那半還要接「倉庫滿了」). 怎麼開才叫得醒你 (shell 層 detach 叫不醒), 通知進來看什麼, 在 `references/running.md` 的「開跑」跟「盯」. 哪幾種滿了、水位多少不在報告上: grep `run.log` 的 `Storage limit reached`, 主村整行像 `Storage limit reached (金幣/聖水/黑水); farming stops with 金幣 …／聖水 …／黑水 …` (括號裡是讀得到容量而且都滿過 `stop_at` 的那幾項, 夜世界沒有黑水), 夜世界前面還有一行 `the cart held X of Y N battle(s) ago`; 不要從 `attacked` 推.

**一個世界打不動就先去打另一個**, 為什麼卡住不重要: 耗在那邊等於另一個整晚沒打. 看進帳斜率而不是輪數: 主村 `Village holds gold=… elixir=… dark=…`, 夜世界 `Builder base holds gold=… elixir=…`, 連續幾輪幾乎沒動就是打不動. **夜世界倉庫滿了之後那行本來就不動** (在填聖水車), 看每五場一次的 `holding X of Y` 有沒有在長.

**這種 run 不會自己結束** (到不了百分比就沒有 `stock_full`), 所以換世界要先 `uv run ai_coc stop`, 等背景指令結束再 `world --go … --yield`: 帶 `--yield` 的指令不請任何人收工, 你自己那一輪也一樣, 只會排隊等它. 停止在打完手上那一場才生效, 可能好幾分鐘; `result.json` 寫出來或 `state.json` 的 `status` 回到 `idle` 就是退出了.

**兩邊都不等兵營**, 造兵是即時的; 夜世界的時間幾乎都在等真人配對.

**開跑後先估時間.** 一輪抓四到五分鐘; 什麼都沒打成的那輪會等 `IDLE_REST`. 第一輪的 `run.log` 有現在水位 (`Village holds …`) 跟容量 (`Storage ceilings read as …`), 兩者算出到 `stop_at`% 的距離, 除以一場的平均收穫, 就是大概要跑多久. 好幾個小時就先跟使用者講一聲. 實測速率 (2026-09-01, TH15 / 建築大師基地 10 級左右):

- **主村一場約 +1.1M 金幣、+1.1M 聖水**, 一輪 2 到 3 分鐘. 幾乎空的倉庫打到 24M 的 90% 大概 20 場、一個多小時
- **夜世界一場約 +100k 到 130k 金幣**; 聖水進推車, 一場 6 萬到 22 萬, 平均 12 萬左右 (2026-09-25 量的). 一輪 2 到 5 分鐘. 聖水是瓶頸, 5.1M 的聖水倉庫從三成打到九成約二十五場

夜世界不一樣的地方:

- **沒有門檻**: 沒有偵察畫面, 贏拿金幣輸拿聖水, 沒東西好跳過
- **打資源用平鋪戰術, 不叫 AI** (使用者 2026-09-26 的交代): 贏輸都有進帳, 兩樣倉庫都要填, 挑哪一邊打差別不大, AI 規劃卻每個 stage 要 10 到 15 秒 (慢的時候 40 秒以上, 逾時一樣退回平鋪). 用 `--plan src/ai_coc/plans/night_flat.json` 蓋過它就好. **AI 規劃留在程式裡, 不要拿掉**, 兩個世界的邏輯要一樣; 主村照舊讓 AI 規劃. 使用者說主村也用平鋪 (例如「幫我打日夜世界資源, 全部用平鋪就好」), 主村就帶 `--plan src/ai_coc/plans/flat.json`, 只管那一趟
- **搜尋要等真人** (量過四秒到五分半). 搜尋中 log 不寫東西, 最久兩分半 (`SEARCH_PATIENCE`) 會有一行 `No opponent in 150s; cancelling and searching again`, 重搜 `SEARCH_ATTEMPTS` 次都沒配到才回 `no_opponent`
- **容量一整趟只讀一次** (`AttackRunner._settle_ceilings`), 只讀兩排 (沒有黑水, 第三排是寶石, 不點)
- **聖水車也算一個倉庫.** 迴圈開跑第一輪跟之後每 `CART_EVERY` (五) 場去一次車子: 倉庫有空間就倒進去, 倉庫滿了就讀車上存多少. 倉庫滿了**而且**最近一次讀到車子也過同一個百分比才 `stock_full`, 所以車子剛滿之後最多還會多打四場. 同一趟看三次都讀不到車子, 就退回只看倉庫. 手動領是在夜世界跑 `uv run ai_coc collect`; 車子容量會跟著村莊長大 (現在 160 萬). 打完一輪記得確認有領到
- **`CartReport.outcome` 有九種**, 收集鈕灰的三種在下一條: `collected` 領到了; `empty` 按了收集而儲量沒動; `not_found` 三個候選點都沒點開; `wrong_world` 不在夜世界; `not_parked` 鏡頭沒停好所以沒去找; `unreadable` 領了但有一邊的儲量條讀不到
- **收集鈕灰的三種**: `locked_holding` 車上有東西領不出來 (`held` 車上的數字, `capacity` 上限), 幾乎一定是聖水倉庫滿了, 車子在當額外倉庫, **車子也滿了才是這個村莊不再賺了**; `locked_empty` 車上本來就空, 沒事; `locked` 按鈕灰而車上數字讀不到, 要自己去看

## 怎麼跑

**主 session 背景跑, subagent 前景分段阻塞.** 前景會把主 session 卡住幾十分鐘, 使用者也插不了話; subagent 反過來, 把指令丟到背景再結束回合就再也醒不過來. 兩種各怎麼做, 目錄佈局, 以及每個指令都要帶的 `--agent`、`--session`、`--mission` 跟 subagent 要用的 `uv run --no-sync`, 都在 `references/running.md` 的「為什麼一定要背景跑」跟「開跑」; 這份 skill 裡的指令為了好讀都省略了.

**預設 `--repeat 0`**: 倉庫滿了迴圈自己會 break, 正是「打到資源滿」. 使用者指定輪數就照他的.

**要不要留畫面是派工的人決定.** `--debug` 存迴圈讀的每一張 (log 也記到 DEBUG), `--shot-every` 加一條固定心跳; 一張 PNG 平均兩 MB 多 (`AGENTS.md` 量過 11 456 張佔 27.2 GB).

- **你是 subagent**: 交辦寫了 `--debug` / `--shot-every` 就帶, 沒寫就不帶, 一個都不要自己加或拿掉. 圖是派你的那一邊要看的, 你不用打開, 專心打資源, 回報列出執行目錄就好
- **你是派工的那一邊, 或者沒人派你**: 有人要找問題 (盯著 subagent 的行為、查 bug、驗證剛修好的東西) 就開 `--debug`, 問題跟戰鬥過程有關 (兵怎麼走、法術什麼時候下) 再加 `--shot-every`, 單純打資源就不開. 交辦裡一律寫明開還是不開, 圖由你看

## 怎麼盯

**log 跟畫面都能用, 自己判斷**, log 講不清楚就截一張, 那很便宜.

- **`run.log`** 便宜, 答「走到哪, 這輪結果是什麼」. 跨好幾次找同一個症狀用 `grep -r ~/.ai_coc/logs/*/run.log`
- **`plans.jsonl`** (`attack` 的目錄才有, 一場一行帶輪數) 答那一場照什麼戰術打: AI 規劃的, 或 `--plan` 交進去的那份. 一輪打得爛先看它, 再對 `run.log` 的實際發生: 對不上是迴圈的問題, 對得上是戰術的問題
- **畫面**答 log 答不了的: 畫面長什麼樣, 兵有沒有在打, 判讀器讀的跟眼睛看的一不一樣. 迴圈在跑的時候看 `--debug` 留下的 `frames/`: 存下的每一張, `run.log` 都有一行 `Saved frame <檔名>`, 它前後的 log 就是讀這張的那一步. 迴圈自己沒在拍 (卡在某個畫面不動、沒開 `--debug`) 才用 `uv run ai_coc capture --count N` (`--label` 取名)、`repair-emulator` 的 `scripts/look.py` 截 (兩個都只截圖, 不佔 `state.json`, 但存在別的地方, 時間也對不上這輪的 log). `uv run ai_coc read <png>` 不碰模擬器, 隨時能跑, 看每個 parser 讀到什麼

**看過的圖發一份給使用者.** 只要你看了並據此下判斷, 就用檔案傳送機制發出去, 不要只留路徑; 他看不到你的工具輸出. 你是 subagent 而發不出去, 就把路徑跟它說明了什麼寫進回報, 讓主 session 發.

**幾分鐘看一次就夠**, 不要每幾秒讀一次, 也不要掛東西在 log 上等新行 (見 `references/running.md` 的「盯」). 空檔拿去做別的事.

**每一輪結束有一行 `Attack finished:`**, 但判斷看 `result.json` 那一輪的 **`AttackReport.outcome`**, 不要比對 log 的句子. 十八種, 分成兩組, 加上兩組都可能的 `session_taken` (見「一輪就要停下來的」).

**打了一場的五種**, 差別就是下一步往哪走:

- `took_loot`: 打完回營, 戰鬥中的戰利品面板比偵察時少了 (有搶到東西). 正常的一輪, **只有主村會出現**; 入庫多少照樣只看前後兩行 `Village holds`
- `deployed`: **夜世界的正常一輪**. 不保證倉庫動了, 看進帳就比對前後兩行 `Builder base holds`
- `loot_unread`: 整場讀不到戰利品面板, **無從判斷**, 不是失敗也不是成功
- `no_loot`: 兵出去了而戰利品面板整場沒動 (一點都沒搶到), **戰術**的問題, 歸 watch-and-fix
- `nothing_deployed`: 一張卡都沒出去, **迴圈**的問題, 也歸 watch-and-fix, 查的地方完全不同

**沒打到的十二種**:

- `army_short`: 軍隊不到兵營的一半, 沒付搜尋費就退, **整個 series 到此為止**: 造兵即時, 這種軍隊不會自己變好, 要人進遊戲改配置. 抓一張軍隊畫面附在回報裡
- `stock_full`: 倉庫都滿過設定的百分比, 整個 series 到此為止. 夜世界還要車子也滿, 除非三次都讀不到 —— 那時 `run.log` 前面有一行 `the storages decide alone`, 回報就不能說車子滿了
- `builder_free` / `lab_free`: 只有帶 `--until-idle` 才會有, 這個村莊有工人或實驗室空出來, 整個 series 到此為止. 接法見「打到有空閒」
- `other_village`: 遊戲停在這一批沒在打的村莊, 整個 series 到此為止, 多半是有人切過; 要換就 `world --go`
- `server_loading` / `server_flapping`: 伺服器的事, 見下面
- `no_opponent` / `all_skipped` (跳過的都未達門檻) / `stopped` / `no_attack_menu` / `emulator_silent`

`forced` 是這一場被倒數逼開而不是戰利品達標, `skipped` 是這一輪跳過幾個對手, `world` 是這一輪打哪個世界 (讀到村莊之前就結束的是 `null`). 一輪算不算真的開打, 最穩看 `attacked` 是不是 `None`; 夜世界沒有偵察畫面, `attacked` 一律是 `null`, 看 `phases` (這一場出了幾次兵).

**值得警覺的樣態**, 連續幾輪才算:

- 每輪 `skipped` 都是幾十: 門檻對現在的獎盃區間太高, 提一句
- **入庫的進帳遠小於 `attacked`**: 進攻打不動人家, 是 watch-and-fix 的題目, 這裡只報告. 看落差而不是 `attacked` 大不大 (它只說對手**擺出**多少, 見「數字從哪來, 不准編」)
- `The session was dropped`: `ui/runner.py` 的 `relogin` 自己會點對話框的按鈕重新登入回到村莊, 點了沒用才重開遊戲 (閒置斷線跟 連線已中斷 都是; log 有 `did not clear it; restarting the game` 就是重開了). 一直重複才要查
- `waiting for the server rather than tapping`: 卡在載入畫面, 伺服器的事. 迴圈每次載入最多等 45 分鐘; 等不到的那輪是 `server_loading` (等滿) 或 `server_flapping` (載入完又掉回去). **不要**重開遊戲或模擬器, 量過兩次都是自己回來的. 連續兩輪都是這兩種再停下來講
- `The camera was not at the far zoom` (**只在主村**): 那一輪多半白打. 迴圈每場自己會 pinch 回去, 連著出現才去看畫面; 手動修是先停迴圈再 `ai_coc view --zoom out`. 夜世界不做這個判斷, 沒這條不代表那邊的鏡頭是對的

**一輪就要停下來的**: `session_taken`, 另一部裝置 (多半是他的手機, 另一台模擬器也算) 登入了這個帳號, 在兩輪之間或打到一半都會有. 迴圈沒有把登入搶回來, 整個 series 自己收掉, log 有一行 `Another device has logged in to this account`. 使用者的交代 (2026-10-09): 被搶登就停手通知他, 他臨時上線一定是有事要做, 不小心的也會回來叫你繼續. 所以照「沒達成」交回報並發推播, 推播那一行講明是被登入擠掉、打資源停了, 等他說可以. **這段時間一個 `ai_coc` 指令都不要下**, `stock`、`status` 也算: 每個指令開跑時的 `ensure_coc` 都會重新登入, 把他踢下線 (2026-10-09 量過). 他說可以了, 照同一個世界同一組旗標開回去, 第一個指令就會重新登入. 別的指令 (`walls`、`stock`, 還有剛開跑就遇到的 `attack`) 遇到它也不重開遊戲, `result.json` 只有一句 `另一部裝置登入了這個帳號,沒有把登入搶回來`, exit code 不是 0, 一樣照這條處理.

## 倉庫滿了: 預設就收工, 他開口才花

**預設情況下倉庫滿了就是終點.** 使用者 2026-09-15 的常設交代, 原話是「默認就是打到設定的值, 除非我有特地說 打資源跟升級牆壁之類的」. 他只說「幫我打資源」的那一趟, 任務就到兩個世界都打到 `stop_at`: 讀結束水位, 附上工人狀況, 交報告, 收工. **工人用 `ai_coc worker`, 不要用 `ai_coc builders`** (後者只讀主村, 在夜世界回 `builder_base`); 一次讀工人、實驗室、倉庫跟護盾用 `ai_coc status`, 兩個都不切世界. **不要自己接下去花**, 工人閒著或某棟很划算也一樣; 值得花就寫成選項讓他挑 (「通知跟要他拍板的事」).

**他開口了才有下面這一圈**: 打到滿 → 花掉 → 回來繼續打, 繞到花不掉為止. 開口是他交辦時就講了要花 (「打完順便刷牆」「把資源花掉」「打資源跟升級牆壁」), 不是你判斷出來的. **底下這一整節都只在那種情況下適用.**

**第一步是問 `ai_coc world`, 沒有例外.** `walls` / `upgrade` / `hero` 在夜世界回 `builder_base`, 那是站錯村莊不是花不掉. 要花主村的先 `world --go day`. **夜世界打滿了就換去打日世界**, 兩邊倉庫不相通; 夜世界的出口 (建築跟牆) 沒有指令做得到, 那是 `spend-loot` 用眼睛做的事, 值不值得是使用者的決定. 兩個世界都滿了才通知他.

**底下這一整節講的都是日世界.**

**這個圈是你在接的**, `attack` 在 `stock_full` 就結束, 沒有旗標讓它自己繞. 中間不要拖: 打滿的村莊是別人最想打的, 趕快花掉是唯一減少暴露的動作.

**背景那輪跑完的通知進來, 就自己接下一步, 不要回頭問.** 只有兩種情況不接: 他說過停 (見 `references/running.md` 的「中止」), 或者剩下那一步要他拍板 (牆, 英雄). **他沒開口要花的那一趟也一樣, 只是不往「花」接**: 還有世界沒打完, 確認 `stock_full` 就自己開下一個世界. 都打到 `stop_at` 才是終點, 再接下去就是花他沒授權的東西.

**怎麼花是 `spend-loot` 的事**, 這裡只有三件事要你判斷.

**一, 授權.** 建築照他那句話做, 城牆要他指名到「牆」, 英雄要他指名到哪一個.

- **城牆要使用者指名, 預設不刷.** 使用者 2026-09-15 的常設交代, 原話是「默認是不升級牆壁, 除非我說」, 而他要的是被通知: 「待會不要升級牆壁 通知我就好」. 他沒講理由, **不要替他補一個**, 也不要因為這一趟划算就自己判斷. 籠統的「把資源花掉」不算指名到牆. 牆付錢當下就升好、工人立刻還回來, 那是它值得列成通知選項的原因, 不是可以自己跑的理由
- **建築不用問, 但要有工人閒著** (`ai_coc worker` 的 `free` 說真的有): 倉庫滿了而工人發呆, 資源被丟掉, 工人也沒蓋東西
- **英雄要使用者指名.** 升級中的英雄不能上場, 升一個是拿幾天的進攻火力去換. `ai_coc hero` 不給 `--upgrade` 只讀不動, 讀出價格讓他挑 (「通知跟要他拍板的事」)

**二, 順序: 他指名要刷牆的那一趟, `walls` 先, `upgrade` 後.** 兩個搶同一個工人, 而 `ai_coc upgrade` 會把**每一個**閒置工人派去蓋好幾天的建築, 先跑它 `walls` 就只會撞「所有建築工人都在忙碌中」. 反過來不虧: 牆買完還有剩或被大本營卡住, 工人都還閒著, `upgrade` 接得上. 要花但沒指名到牆的那一趟只有 `upgrade` 會跑, 而它一跑牆這個出口就關好幾天: **通知照樣先發, 牆列成一個選項, 但講明它會在 `upgrade` 跑下去之後過期, 然後照樣跑 `upgrade`, 不要停下來等他回話** (「不要回頭問」那條, 先發通知也留不住任何一個工人). 他多半不在, 題目還常要經主 session 轉一手, 回覆幾乎一定落在工人被借走之後; 不要寫「已經幫你問過了」, 要寫: 要刷牆得等下一個工人空出來再說一次.

**三, 兩個出口關掉的方式不一樣, 下一步也不一樣.**

- **牆需要有一個工人閒著.** 一個閒著就能連買一整排, `0/N` 一片都買不了 (遊戲回「所有建築工人都在忙碌中」加一顆寶石按鈕). **這一種 `upgrade` 也接不上**, 它同樣要工人
- **牆被大本營的等級卡住.** 看 `WallReport.outcome`: `cannot_afford` 跟 `builders_busy` 講得出原因, **`nothing_bought` 是它自己也說不上來**, 最可能是牆到頂了. **這一種正是 `upgrade` 該接手的地方**, 工人還閒著. 撞到一次這一趟就不用再跑 `walls`, 要等大本營升上去, 那是使用者的決定

**他開口要花的那一趟, 停手的條件不是「倉庫滿了」而是「資源花不掉了」**: 工人全忙或者沒有值得升的建築, 牆沒指名到所以不刷 (指名了就是牆也刷不動: `builders_busy` 或 `nothing_bought`), 剩下的只有要他拍板的英雄. 那時交報告收工. **`walls` 回 `cannot_afford` 或 `bought` 不是花不掉**: 前者是倉庫花到買不起下一批了, 後者是找到的牆都買了, 都是回去打的時候. 不交報告, 直接開下一輪 `attack` (倉庫還滿著的話它第一輪就 `stock_full`, 再刷一次). **他沒開口的那一趟剛好相反**, 倉庫滿了就是終點.

**牆有指名而工人閒著, 這一圈就幾乎不會自己停** (要刷到大本營的上限); 他指名刷牆時加的「循環到我說停」「打到早上」就是這一圈, 沒指名牆的那幾個字不授權刷牆. **這一圈 `walls` 之後不跑 `upgrade`**, 除非是 `nothing_bought`: 「二, 順序」的「買完還有剩」在這裡是回去打, 因為 `upgrade` 會把閒著的工人全派出去, 下一圈 `walls` 就 `builders_busy`, 圈也就斷了. 一跑就是好幾個小時, 照 `references/running.md` 的「跑好幾個小時的圈」開.

**黑水只有升英雄能消化.** 黑水滿了而使用者沒指名英雄, 那一項就停在那裡, 回報要講出來.

通知時附上工人狀況: `ai_coc worker` 說每個工人在蓋什麼 (`jobs` 的 `name`, 沒有 API key 時是空的) 跟各還要多久 (`remaining` 秒, 最快的自己取最小), 決定要不要叫他等; 手上已經有一張主村畫面而只要知道閒著幾個, 丟 `uv run ai_coc read <png>` 看 `builders`.

**其他停手的理由**: 遊戲一直回不到村莊, 同一個錯誤連續三次以上, 一輪也沒打成過, **連續三輪 `emulator_silent`** (log 說 `The emulator has not answered for 3 rounds`, 先看模擬器還活著沒有), **連續 `MENU_FAILURES` 輪 `no_attack_menu`** (現在是 5 輪, 比一整場戰鬥長, 所以留在畫面上的那場打完不會誤判; log 說 `The attack menu has not opened for 5 rounds in a row; ending the series`, 迴圈自己收工. 原因看每一輪自己的 log: 蓋住遊戲的畫面 (活動的劇情對話框), 一直掉線, 或有人在手機上玩, 先看畫面). 這些都停下來講, 不要一直重試: 失敗要吵.

## 打到有空閒

**他把終點放在工人或實驗室上的那一趟** (「打日世界資源, 打到有空閒的通知我」「直到有工人空出來通知我」), 每個 `attack` 多帶 `--until-idle`. 他講「有空閒」或沒說是哪個, 就只給旗標, 工人跟實驗室都看; 只講工人就帶 `--until-idle builder`, 只講實驗室就帶 `--until-idle lab`, 沒講的那塊不看 (活動多給的研究格沒在用時, 實驗室會一直閒著, 只等工人的那一趟不能被它攔下來). 沒這樣講就不帶, 終點還是倉庫滿. 這一趟跟上面不一樣的只有下面幾條.

- **只打一個村莊, 看那邊的牌子.** 迴圈、`worker` 跟 `lab` 都只看得到遊戲當下停著的那個村莊, 兩個世界各算各的. 他指定了就打那邊; 沒指定就打開跑時所在的那個 (切畫面就是他選的方式), 不照「兩個世界都打完」, 回報講明看的是哪邊
- **迴圈自己看牌子, 只看左邊的閒置數** (`0/5` 的 `0`). 總數會跟著活動變 (多一個哥布林工人, 多一格研究, 活動結束又收回去), 不看. 每一輪付搜尋費 (夜世界進配對) 之前, 從讀倉庫的同一張畫面讀它要看的牌子, 閒置數大於 0 就回 `builder_free` 或 `lab_free`. 所以開跑時就閒著的, 第一輪就收, 那就是答案, 馬上講; 跑到一半活動多給一個閒著的也算. 讀不到那一輪照打, `run.log` 留一行 `The builder plate would not read` (或 `lab`)
- **開跑前先跑一次 `uv run ai_coc status`**, 為的是工人跟實驗室的倒數 (他要看的那幾塊, `builder.jobs`、`lab.jobs` 的 `remaining` 取最小, 秒). 拿它估要打多久, 跟倉庫打滿要多久比; 收工那次也用它. 它讀到他要看的那塊已經有閒著的, 就不用開跑, 直接當達成講
- **回來先確認**, 迴圈只讀了一次牌子: `builder_free` 跑 `ai_coc worker`, `lab_free` 跑 `ai_coc lab`. `free` 大於 0, 而且面板上在跑的列數 (`jobs` 有幾個) 等於 `total - free` (或 `outcome` 是 `idle`), 兩種讀法對得上才算; 這裡的總數只拿來對兩種讀法, 不拿來判斷有沒有空. `free` 是 0 就是迴圈那次讀錯, 同一組旗標開回去; 兩種讀法對不上就照「途中撞到 bug」停下來, 附 `--debug` 的畫面
- **倒數過了還沒收工就查.** 開跑時讀到的最快倒數再過一場的時間, 迴圈還在打, 就跑 `ai_coc status` (會借走你自己那一輪, 規矩在 `references/running.md` 的「你自己要用畫面」). 真的空出來了, 是牌子在迴圈裡沒觸發 (夜世界還沒在真的畫面上讀過有人閒著的牌子), 照「途中撞到 bug」回報; 沒有就照同一組旗標開回去. 藥水會讓倒數提早結束, 這條管不到, 迴圈每一輪讀牌子才管得到
- **`stock_full` 照樣收工, 但不是終點.** 倉庫滿了再打也進不了倉; 還沒有空出來的, 這一趟就還沒完: 照 `watch-upgrades` 的「算出時間, 不要輪詢」睡到他要看的那幾塊最快的倒數, 醒來 `status` 讀到那幾塊空出來才算達成. 等的時候背景不留迴圈. 你是 subagent 就睡不了, 把倒數寫進回報交回去
- **達成之後照「任務報告」交**, 表下面那一行先講哪個世界的工人還是實驗室空出來. 拿它做什麼是他拍板的事, 照「通知跟要他拍板的事」發推播並列出選項: 工人是升建築、刷牆、繼續打到倉庫滿、先不要動 (有價格就附); 實驗室沒有指令能研究, 選項是他自己進遊戲研究、繼續打到倉庫滿、先不要動. **他沒開口要花就不要自己花**, 「倉庫滿了」那節的授權照舊

## 停手之後就真的停手

**打完不要留任何東西在背景跑**, 包括為了讓村莊「有人在線上」: 現在有沒有人看畫面都照樣被打, 保護村莊的是被打之後遊戲自己給的護盾. 資源花不掉就交報告、停手.

## 順手做的事

`collect` 很便宜 (幾秒), 最值得常跑: 採集器裝滿就停工. 開跑前跑一次, 隔一段時間再跑.

`donate` 也幾乎沒成本, 想跑就跑, 但只做主村 (夜世界回 `builder_base`).

這兩個一樣**不跟背景那輪同時跑** (`references/running.md` 的「絕對不要同時跑兩個」): 等接縫 (換世界前, 收工前) 再跑, 或者先停迴圈, 跑完照同一個世界同一組旗標開回去 (停跟開回去的規矩在同一份的「你自己要用畫面」).

`upgrade` 跟 `hero` **不要在打到一半插進去**: 要先停迴圈, 而且倉庫沒滿時 `upgrade` 挑得到的比較差. 它們的位置是倉庫滿了那個接縫, 授權跟順序見上一節.

使用者指名要升某一樣東西, 換 `spend-loot`: `ai_coc upgrade` 不給 `--only` 只挑最貴而且買得起的, 怎麼指定在那份 skill 的「三個入口」那節.

## 途中撞到 bug

**停下來寫清楚, 不要自己動手改.** 動程式碼要量測、跑測試、開 PR, 那套在 `watch-and-fix`, 這裡沒有.

回報裡寫三件事: 哪一輪, `run.log` 的哪幾行, 你當下看到的畫面. 那是 `watch-and-fix` 接手的起點; 繞過去不寫, 下一次還會撞上.

要看活的畫面才判斷得出來: 只截圖看用 `look.py` 就好 (見「怎麼盯」), 迴圈不用停; 要動到遊戲或跑別的 `ai_coc` 指令才自己停迴圈 (`ai_coc stop`, 等它退出), 用完同一組旗標 (帶 `--yield`) 開回去.

## 任務報告

**任務達成才交回報, 達成的定義跟著他有沒有開口要花走.**

- **他只說打資源**: 該打的世界都到 `stop_at` 就是達成. 不要為了湊「花不掉了」去跑 `walls` 或 `upgrade`
- **他要打到有空閒**: 確認有工人或實驗室空出來才是達成, 倉庫先滿了不算, 見「打到有空閒」
- **他開口要花**: **資源花不掉了**才是達成. 圈跑幾次都是同一個任務, 中間的「打滿了」跟「刷到買不起」只值一句進度, 他要的是這一段總共賺了多少、花掉多少

使用者指定的輪數跑完也是達成. **沒達成就照「沒達成的時候講什麼」講兩三句.**

**回報只回答四件事: 打完沒, 打了多少, 花多久, 現在的資源狀態.** 使用者的交代: 2026-09-27 嫌以前的報告太長太複雜, 也不需要 `report.md`; 2026-09-28 又嫌縮成幾行純文字之後很難看懂. 所以是**一句結論, 一張每個世界一列的小表, 一行工人跟護盾**, 印在對話裡, 不寫檔案, 不加章節.

**交之前先確認沒有東西留在背景**, 去查而不是回想: 沒有 `ai_coc` 程序, 沒有 shell 還在輪詢, `state.json` 回到 `idle`. 規矩在 `references/running.md` 的「等待要有出口, 收工要清乾淨」. 查過沒事不用講; 刻意留著在跑的才講是哪一個.

### 進帳從 `run.log` 算

**不要為了算進帳下 `ai_coc stock`, 開跑前跟收工後都一樣.** 迴圈每一輪開打前自己讀一次倉庫, 寫成 `Village holds gold=… elixir=… dark=…` (夜世界 `Builder base holds gold=… elixir=…`), 相鄰兩行的差就是中間真的入庫的量. 一個執行目錄的進帳是它最後一行減第一行; 被借走或換世界而重開過的, 每個目錄各算各的再加起來, 使用者在兩次之間花掉的才不會被扣成負的進帳. **兩個世界各算各的, 不准混**: 兩組倉庫容量差十倍, 「金幣 + 金幣」沒有意義.

**最後一行有沒有算到最後一場, 看它在不在最後一場打完之後**, 也就是最後一個真的開打的輪次那行 `Attack finished:` 的後面. 打到 `stock_full` 收工的一定在 (迴圈就是靠這一行看出滿了), 下一輪讀完倉庫才 `army_short` 或在搜尋中被叫停的也在; 不在的 (打完一場就被叫停, 輪數跑完) 少算最後一場.

某一輪讀不出倉庫就沒有那一行; 一個目錄一行都沒有, 那一段的進帳寫「量不到」.

### 樣板

```markdown
兩邊都打滿了, 花了 2 小時 50 分.

| 世界   | 場數 | 金幣                 | 聖水                 | 黑水                |
| ------ | ---- | -------------------- | -------------------- | ------------------- |
| 日世界 | 2    | +76 萬 → 2700 萬 (滿) | +87 萬 → 2700 萬 (滿) | +0.6 萬 → 44 萬 (滿) |
| 夜世界 | 70   | +568 萬 → 600 萬 (滿) | +497 萬 → 510 萬 (滿) | —                   |
| 聖水車 |      |                      | 123 萬 → 160 萬 (滿)  |                     |

工人: 日世界 0/6 (最快 1 天 2 小時), 夜世界 0/3 (最快 13 小時 55 分); 日世界沒有護盾.
```

- **第一行**: 打完沒, 總共花多久. 只打一個世界就講那一個
- **表**: 直接印成 markdown 表格, 不要包在程式碼區塊裡. 每個打了的世界一列, 不加總; 每一格是「進帳 → 現在的水位」, 滿了加 (滿), 夜世界沒有黑水寫 —. 沒打的世界不列. 夜世界的聖水車自己一列, 寫開跑跟收工時車上各有多少 (X → Y): 收工前跑一次 `uv run ai_coc collect`, 倉庫滿時它在 `cart` 底下回 `locked_holding` 附 `held` 跟 `capacity`; 回 `locked`, `not_found`, `not_parked` 或 `wrong_world` 都是**沒讀到**, 寫「聖水車讀不到」, 不准寫成滿, 理由同上面 `stock_full` 那條
- **表下面一行**: 兩個世界的工人 (閒幾個/總共幾個, 最快那個還要多久), 日世界護盾剩多久 (讀不到就說讀不到)
- **他開口要花的那一趟表下面多一行**: 刷了幾片牆, 升了什麼, 各花多少
- 數字用「萬」; 不到一萬的 (多半是黑水) 留一位小數
- 要他決定的事接在報告後面, 一條一個編號 (見「通知跟要他拍板的事」)

### 數字從哪來, 不准編

- **進帳**: `run.log` 的 `holds` 那幾行, 算法見「進帳從 `run.log` 算」. **不是**每輪 `AttackReport.attacked` 的加總: 那是偵察畫面上對手擺出來的可搶量, 跟入庫一定對不上 (比平常大得多的落差是要往上報的訊號, 見「值得警覺的樣態」)
- **現在的水位**: 那個世界最後一行 `holds`; 收工時跑的 `ai_coc status` 讀的是同一個世界的話, 用它的 `stock`, 那份比較新
- **場數**: `AttackSeries` 裡真的開打的輪數; 主村看 `attacked` 不是 `None` (`jq '[.[] | select(.attacked != null)] | length' result.json`), 夜世界看 `phases` 大於 0 (`select(.phases > 0)`). 不是 `Attack finished` 的行數, 沒開打的那一輪 (例如最後那一輪 `stock_full`) 也有這一行
- **花掉的**: 刷牆看 `walls` 的 `result.json`, 只有 `upgrades` (每批的 `unit` 單價、`count` 片數、`resource` 付哪一種) 跟 `outcome`. 片數是 `count` 的和, 各資源花多少是 `unit × count` 的和 (`WallReport.walls` 跟 `paid()` 算的就是這個, 但它們不寫進檔案); `run.log` 的 `Walls: … (金幣 X／聖水 Y)` 那行是現成的. 升建築跟英雄看花之前跟花之後兩次讀到的倉庫差額
- **工人跟護盾**: `ai_coc status` (或 `worker`), 答的是當下站著的那個村莊 (見「倉庫滿了」開頭); 夜世界沒有護盾
- **時長**: `run.log` 第一行跟最後一行的時間戳; 沒有日期, 跨午夜看目錄名

**量不到的就寫量不到, 不要估.**

### 通知跟要他拍板的事

**交報告的時候發一則推播通知**, 達成跟沒達成都一樣: 一趟打資源動輒幾個小時, 他多半不在電腦前, 推播才到得了他手機. 使用者 2026-10-06 把推播打開之後交代「改成真正的通知, 而不是出選項來給我選」. 一行就好, 先講他會想動手的那件事 (「日世界打滿了, 工人全忙」比「任務完成」有用), 表跟選項留在回覆裡. 中途的進度不發; 例外是等到交報告就過期的題目 (他開口要花而沒指名牆, 牆的選項在 `upgrade` 跑之前就要發, 見「倉庫滿了」), 當下就發推播, 選項寫在回覆裡.

**推播回 not sent 不一定是壞了**: 他人就在終端機前的時候, runtime 認為回覆已經到得了他, 不會重複推 (2026-10-06 量過). 所以內容一律也寫在回覆裡; 他交辦裡講了「通知我」而推播沒送出, 在回覆裡講一聲. runtime 沒有推播的話, 就只有回覆.

**要他決定的事寫在回覆裡, 接在報告後面, 一條一個編號**, 不用選擇題選單. 選項是他真正的那幾條路, 每一條附價格或代價, 再加一條「先不要動」. **不要替他推薦哪一個**, 標成推薦就是替他決定. 有題目的時候, 推播那一行要講有事等他決定. 打滿的那一刻多半有題目可問 (繼續打, 把資源花掉, 還是收工), 但**沒有題目就不要編一個**: 例如倉庫滿了而工人全忙, 花不了, 繼續打也進不了倉, 收工本來就是預設, 樣板那份回報就是全部.

**你是 subagent 就發不了推播, 也問不到他**: 把要推播的那一行、題目跟選項寫進回報, 讓主 session 發.

## 沒達成的時候講什麼

不套樣板, 兩三句話:

- 跑到哪 (幾輪, 最後一行 `holds` 的水位; 它在最後一場之前讀的就註明)
- 為什麼停 (被中止 / 一輪也沒打成 / 回不了村莊 / 同一個錯誤重複發生)
- 要不要繼續, 以及繼續之前有沒有東西該先處理

**使用者叫停就是他要接手**: 他說停, 或者 `references/running.md` 的「被借走」判定為真的叫停. 之後**一個 `ai_coc` 指令都不要下**, 只讀倉庫的 `stock`、`status`、`worker` 也算: 它們一樣會佔用模擬器操作畫面, 他在手機上玩的話 `ensure_coc` 會把登入搶回來, 把他踢下線. 回報也不算進帳, 數字全從 `run.log` 讀.

被砍掉的跑沒有 `result.json` (走 `uv run ai_coc stop` 停的會有), 那時從 `run.log` 數得出多少寫多少, 註明是從 log 數的. 它的 `state.json` 也會停在 `running`, 那是殘留, 拿 `pid` 查一下就知道.

## 中途被問進度

報當下的資源跟輪數就好, **不要停下迴圈**. 報告留到任務真的達成再交.

數字從那次的 `run.log` 讀: 最近一行 `Village holds …` (夜世界 `Builder base holds …`) 跟 `Round N of`. **不要為了這個下 `ai_coc stock`**: 迴圈在跑的時候, 會操作畫面的指令不帶 `--yield` 就是把它借走, 帶了就排在它後面等到它收工 (`references/running.md` 的「絕對不要同時跑兩個」).
