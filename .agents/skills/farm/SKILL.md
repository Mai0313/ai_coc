# farm

代替使用者顧這個村莊. 開跑, 盯著, 判斷, 回報. 這個 skill 不改程式碼.

## 三份文件的分工

- **程式碼**說「現在是什麼」: 有哪些指令, 旗標叫什麼, 報告有哪些欄位
- **`CLAUDE.md`** 說「為什麼是這樣」: 每個常數背後的實測, 每個設計的代價
- **這份 skill** 說「怎麼判斷」: 什麼時候該介入, 什麼時候該停手

所以不要憑記憶下參數, skill 裡沒有一份參數表, 因為那種表一定會過期. 開跑前先讀這三個地方:

- `src/ai_coc/cli.py` 的 `_parser()` 是旗標的唯一真相
- `src/ai_coc/commands.py` 裡對應的函式說那個指令實際做什麼, docstring 通常已經把設計理由講完了
- `src/ai_coc/models.py` 的 `AttackReport` / `AttackSeries` / `WallReport` 說回報的欄位是什麼意思

## 開跑之前

**讀 `~/.ai_coc/config.json`.** 這份檔案是視窗跟終端機共用的, 兩邊會跑出一樣的結果. 三件事要看:

- `thresholds` 是打誰的門檻. 訂太高會一直跳過, 一輪搜幾十個對手還開不了打
- `stop_at` 是停手的倉庫水位, 一個百分比, **主村跟夜世界共用**. 容量是迴圈自己去遊戲讀的 (點一下儲量條, 遊戲會寫 `最大儲存量`), 所以同一個 90% 在兩邊代表不同的數字, 而且倉庫升級之後不用改設定. **每一項都滿過那個百分比才停**, 不是任何一項到頂就走 —— 一場仗帶回來三種資源, 一個倉庫到頂不足以放棄另外兩種還在賺的. `0` 是永遠不收工; 容量讀不到的那一項不列入計算
- `restart_every` 是每打幾場重開一次模擬器, 算的是真的打完的場次而不是輪數. 這是全檔唯一一個不是實測出來的數字, 因為掉幀是模擬器的毛病, 程式這邊量不到; 看畫面的人才知道該多久重開一次. 掛整晚的跑一定會遇到它, 而且它也是一個結束理由, 見下面停手那節

如果使用者沒特別交代, 就照設定檔跑, 那是他調過的值. `--min-gold` 之類的旗標只在他明講要放寬時才用, 而且 `0` 跟不給是兩件事, 讀 `LootOverrides` 的 docstring.

**不用自己開模擬器或遊戲.** `commands._controller()` 會找 MuMu instance 並 `ensure_coc`, 遊戲沒開它自己會開.

**這個遊戲有兩個村莊, 而遊戲會開在上次離開的那一個.** 日世界 (主村) 跟夜世界 (建築大師基地) 是兩張完全不同的地圖, 中間只有一艘船可以來回. 所以「遊戲開起來了」不等於「站在你要的那個村莊上」.

- `ai_coc world` 回答現在在哪個世界, 不動畫面也不點任何東西, 所以隨時可以問
- `ai_coc world --go day|night` 坐船切過去, 已經在那邊就什麼都不做

**不指定的指令會做在當下所在的世界, 不會自己切.** `ai_coc attack` 沒有 `--world` 的時候打的是眼前那個村莊, 所以要打哪個就寫出來: `--world day` 或 `--world night`, 它會先確認並且需要的話坐船過去. 這一條很重要, 因為遊戲留在夜世界的時候, 一個以為自己在打主村的 session 會安靜地打了夜世界 —— 兩邊的倉庫容量差了十倍, 所以「還差多少才滿」的答案完全不同.

**沒有特別交代的話, 兩個世界的資源都要打完.** 夜世界是同一個指令:

```bash
uv run ai_coc attack --world night --repeat 0
```

**一次只跑一個世界, 跑完再跑下一個.** 兩個指令同時開會搶同一個畫面, 兩邊都會壞掉. 判斷「這個世界打完了」看最後一輪的 `AttackReport.stock_full`: 那是 `true` 的時候 series 自己就結束了, 訊息會說哪幾種資源都滿過設定的百分比. 那一刻就換下一個世界, 指令一模一樣只是 `--world` 換掉, 它會自己坐船過去.

**順序沒有規定, 但有兩個實際的考量.** 省一趟船就先打當下所在的那個 (`ai_coc world` 問, 不動畫面). 另外主村那邊會等兵營, 夜世界不會 —— 那邊一場打完軍隊立刻補滿, 所以夜世界的時間幾乎全花在等真人配對上, 而主村是花在練兵上, 兩種等待不一樣.

**一個世界打不動不要卡著, 先去打另一個.** 兩個都要打, 而且它們互不影響 —— 一個世界的水位卡住不會讓另一個跟著卡住, 所以耗在打不動的那個等於另一個一整晚沒打. 為什麼卡住不重要, 卡住了就換. 判斷方式是看進帳的斜率而不是輪數 —— 連續幾輪的水位幾乎沒動就是打不動了. **那一行在兩個世界叫不同名字**: 主村是 `Village holds gold=… elixir=… dark=…`, 夜世界是 `Builder base holds gold=… elixir=…`, 因為那邊只有兩排要讀.

**而這種情況下前一個 run 不會自己結束**, 所以要換世界就得停掉它: 那個世界永遠到不了百分比, 就永遠不會 `stock_full`, `--repeat 0` 會一直打下去. 停法是 `uv run ai_coc stop`, **而且要等它真的退出再開下一個**. 直接接著開不行, 因為 `attack` 開頭就會把停止旗標清掉 —— 等於把前一個 run 還沒讀到的那個停止請求刪掉, 然後兩個 run 一起搶畫面. 旗標最慢是在打完手上這一場之後才讀到, 所以那個等待可能要好幾分鐘, 看 `result.json` 有沒有寫出來最準.

實測的速率, 拿來估時間用 (2026-09-01, TH15 / 建築大師基地 10 級左右):

- **主村一場約 +1.1M 金幣、+1.1M 聖水**, 一輪連搜尋帶回營約 2 到 3 分鐘. 從幾乎空的倉庫打到 24M 的 90%, 大概 20 場、一個多小時
- **夜世界一場約 +100k 金幣**, 聖水不入庫要看推車, 每三場領一次約 116k. 一輪約 2 到 5 分鐘, 大部分是配對在等真人. 所以那邊的聖水是瓶頸, 從三成打到九成要三十幾場

夜世界跟日世界有幾個地方不一樣, 判斷的時候要記得:

- **沒有門檻可以設, 也不需要設.** 沒有偵察畫面, 對手是配對給的, 而且贏了拿金幣輸了拿聖水, 兩種結果都有收穫, 所以沒有東西好跳過
- **搜尋要等真人.** 那邊是即時對戰, 實測過一次搜了五分半, 也有四秒就配到的. 迴圈自己會在 `SEARCH_PATIENCE` 之後取消重搜, 所以看到 log 停在 searching 一兩分鐘是正常的, 不是卡住
- **倉庫水位跟主村共用同一個設定.** 設定檔裡只有一個 `stop_at` (百分比), 因為容量是迴圈自己去遊戲讀的: 每一輪開打前它會點一下儲量條, 讀 `最大儲存量`, 再拿現在的水位去比. 判斷方式跟主村一模一樣 (**每一項都滿過那個百分比才停**), 所以 `--repeat 0` 在夜世界一樣會因為倉庫滿了而收工. 夜世界只讀兩排 —— 那邊沒有黑水, 第三排是寶石而且點下去會開商店, 所以它根本不點; 讀不到容量的資源不列入計算, 不會把另外兩項卡住
- **聖水在推車裡, 不會直接入庫.** 迴圈每 `CART_EVERY` 場會自己去領一次; 手動領是在夜世界跑 `uv run ai_coc collect`. 實測一次領到 30 萬聖水, 推車滿了是 100 萬, 所以打完一輪記得確認有領到
- **報告的欄位不一樣**: 夜世界那幾輪的 `attacked` 是 `null` (沒有偵察畫面就沒有戰利品可報), 要看的是 `phases`, 那是這一場出了幾次兵. `world` 欄位說這一輪打的是哪個世界

**先估時間再開跑.** 一輪是搜尋加上最多三分鐘的戰鬥, 加上回營, 抓四到五分鐘. 軍隊沒練好的那輪會等 `IDLE_REST` 再來. 從現在的倉庫水位到容量的 `stop_at`% 的距離, 除以一場的平均收穫, 大概就是要跑多久. 如果算出來是好幾個小時, 先跟使用者講一聲.

## 怎麼跑

**背景跑.** 前景跑會把整個 session 卡住幾十分鐘, 中間你什麼都做不了, 使用者也插不了話. 機制跟目錄佈局讀 `references/running.md`.

**預設 `--repeat 0`.** 那不是無限: 倉庫滿了迴圈自己會 break, 這正是「打到資源滿」要的語義. 使用者指定輪數就照他的.

**要不要留畫面自己決定.** `--record` 存的是迴圈自己讀的每一張, `--shot-every` 再加一條固定心跳. 留了就有東西可以事後翻, 代價是空間, 一張 PNG 一兩百 KB, 一場加起來幾十 MB. 覺得這批會有東西要查就開著, 覺得只是單純掛機就不開, 臨時想看現況隨時可以 `uv run ai_coc capture` 抓幾張.

## 怎麼盯

**log 跟畫面兩種手段都可以用, 用哪個你自己判斷.**

**log** 便宜, 適合回答「現在走到哪一步, 這輪結果是什麼」. 看這次執行自己的 `run.log`. 沒有第二份把所有執行混在一起的檔案了; 要跨好幾次找同一個症狀就 `grep -r ~/.ai_coc/logs/*/run.log`, 那樣還會順便告訴你每一筆是哪一次跑出來的.

**`plans.jsonl` 是第三種, 而且它回答的問題前兩種都答不了**: 那一場的 AI 到底叫部隊往哪打. 每次執行的目錄底下都有一份, 不用開任何旗標, 一場一行, 帶著自己的輪數. 一輪打得爛的時候它是最快的第一步 —— 先看那一行說要打哪一側、幾秒放法術、每個英雄下在哪, 再去對 `run.log` 說實際發生什麼. 兩邊對不上就是迴圈的問題, 對得上就是這份戰術本身的問題, 那是兩個完全不同的方向.

**畫面**貴一點但能回答 log 回答不了的問題: 畫面上現在到底長什麼樣, 兵有沒有真的在打, 判讀器讀到的跟眼睛看到的一不一樣. `uv run ai_coc capture <dir> --count N` 從活著的遊戲抓, `uv run ai_coc read <png>` 把一張圖丟給所有 parser 看它們各自讀到什麼.

沒有規定的順序. log 看得出來就不用截圖, log 講不清楚就去看圖, 一開始就想看圖也可以. 有疑問而 log 沒回答到, 截一張就是了, 那很便宜.

**看過的圖順手發一份給使用者.** 只要你看了它並且據此下判斷, 就用檔案傳送機制發出去, 不要只留一個路徑. 使用者看不到你的工具輸出, 而你在圖上看到的東西他多半也想看一眼.

**盯的頻率**: 一輪四五分鐘, 所以幾分鐘看一次就夠, 不要每幾秒去 tail 一次. 中間的空檔拿去做別的事.

**每一輪結束會有一行 `Attack finished: <message>`.** 那個 message 就是 `AttackReport.message`, 它自己會講清楚這輪發生什麼事. 常見的幾種語義:

- 打完回營了, 附帶搶到的三種資源
- 兵力不足, 沒付搜尋費就退出來. 這是設計好的行為, 不是錯誤
- 倉庫都滿過設定的百分比, 整個 series 到此為止
- 畫面不在主村, 沒開成攻擊選單. 這輪什麼都沒做
- 等不到對手畫面

不要去背這些字串, 它們會改. 要判斷一輪算不算成功就看 `AttackReport.attacked` 是不是 `None`.

**值得警覺的樣態**, 不是單一輪而是連續幾輪:

- 連續三輪以上 `attacked=None` 而理由都是兵力不足: 兵營可能根本沒在練, 或者軍隊配置被改過. 去看一眼再回報
- 連續打完但每輪 `skipped` 都是幾十: 門檻對現在的獎盃區間來說太高了, 值得跟使用者提一句
- 打完了但 `attacked` 的數字很小: 進攻打不動人家, 這是 tune-attack 的題目, 這裡只負責報告
- log 裡出現重新登入 / 重開遊戲: `ui/runner.py` 的 `restart_game` 自己會處理, 會回到村莊, 不用管. 但如果一直重複發生, 那是要查的
- log 裡出現 `The camera was not at the far zoom`: 那一輪多半是白打的, 因為這個專案每一個座標都是在最遠的 zoom 量的, 鏡頭飄掉就全部落空. 迴圈每場自己會 pinch 回去, 所以偶爾一條不用管, 連著出現就去看畫面. 手動修法是 `ai_coc view --zoom out`, 但要先把迴圈停掉

## 倉庫滿了: 把資源花掉, 再回來打

**倉庫滿不是終點, 花不掉才是.** 一圈長這樣: 打到滿 → 把資源花掉 → 回來繼續打, 繞到花不掉為止.

**第一步是問 `ai_coc world`, 沒有例外.** 夜世界一樣會 `stock_full`, 而花資源的三個指令**一個都不看世界**: `walls` / `upgrade` / `hero` 走的 `_home` 讀到夜世界就直接坐船回主村, log 只留一行 warning, 然後花掉的是**主村**的資源跟**主村**的工人. 所以在夜世界打滿之後照這一節做, 結果是主村的工人被綁走好幾天, 而夜世界那個真的滿了的倉庫一動也沒動 —— 「花不掉才停手」永遠到不了, 於是繞回去繼續打一個已經滿了的村莊.

**夜世界打滿了要做的是換去打日世界**, 因為兩邊的倉庫互不相通. 夜世界自己的出口 (它的建築跟牆) 沒有任何指令做得到, 那是 `spend-loot` 用眼睛做的事, 而且值不值得做是使用者的決定. 兩個世界都滿了才是真的要通知他.

**底下這一整節講的都是日世界.**

**這個圈是你在接的, 程式碼裡沒有它.** `ai_coc attack --repeat 0` 只知道「倉庫滿了就停」, `stock_full` 是 true 的那一刻對它來說就是結束, 對你來說是換下一步. 沒有旗標可以讓它自己繞. 中間也不要讓遊戲閒著: 剛打滿的村莊是最好的目標, 護盾多半也正好在這時候到期.

**背景那輪跑完的通知進來, 就自己接下一步, 不要回頭問.** 那個通知是接縫不是終點: 使用者交辦的是「打到花不掉為止」, 停在那裡問「接下來要做什麼」等於把他花錢請你避開的那段等待又放回去. 只有兩種情況不接 —— 他自己說過停 (見 `references/running.md` 的「中止」), 或者剩下的那一步需要他拍板 (英雄).

**怎麼花是 `spend-loot` 的事** —— 三個入口各自怎麼找目標, 陷阱在哪, 全部在那份 skill 裡. 這裡只有三件事要你判斷.

**一, 授權.** 城牆跟建築這個 session 自己可以做, 英雄要使用者指名.

- **城牆**付錢的當下就升好, 不跑計時器, 工人立刻還回來, 資源再打就有, 所以它一直都不用問
- **建築也不用問, 但有前置條件**: 牆已經證明吸不掉 (見下面「順序」), 而且 `ai_coc builders` 說真的有工人閒著. 倉庫滿了而工人在發呆是雙重浪費 —— 打回來的資源進不了滿倉直接被丟掉, 而工人這段時間什麼都沒蓋. **這一條是這份 skill 從「只有刷牆不用問」改過來的**, 因為那條規則讓每一次倉庫打滿都停在等使用者回話, 而他不在
- **英雄要使用者指名.** 升級中的英雄不能上場, 卡片直接從隊伍列消失, 所以升一個英雄是拿接下來幾天的進攻火力去換, 而這個 skill 的主線正是打資源. `ai_coc hero` 不給 `--upgrade` 只讀不動, 讀出價格回報給他, 讓他挑

**二, 順序: `walls` 先, `upgrade` 後.** 兩個出口搶同一個工人, 而它們借走的長度差好幾天 —— 牆借一瞬間, 建築借好幾天. 而 `ai_coc upgrade` 會把**每一個**閒置工人都派出去, 所以先跑它就是先把牆這個出口關掉, 然後花兩分鐘讓 `walls` 去撞「所有建築工人都在忙碌中」. 反過來也不會虧: 牆買完還有剩, 或者牆被大本營等級卡住, 那兩種情況工人都還閒著, `upgrade` 照樣接得上. (牆因為工人全忙才買不動的那一種是例外, 那時候 `upgrade` 同樣派不出人, 見下面.)

**三, 兩個出口關掉的方式不一樣, 下一步也不一樣.**

- **牆需要有一個工人閒著.** 升一片牆要用掉一個空閒工人, 只是付錢的當下就完成, 工人立刻還回來, 所以有一個閒著就能連續買一整排, 而 `0/N` 一片都買不了. 實測在 0/5 的村莊每一批都確認了然後沒被扣錢, 遊戲回一句「所有建築工人都在忙碌中」再附一顆寶石按鈕, 一片牆跟八片牆一樣退 —— 一片跟八片一樣退, 正是排除掉批次大小跟錢的那個證據. **這一種卡法 `upgrade` 也接不上**, 因為它同樣要工人
- **牆被大本營的等級卡住.** `WallReport.message` 只有「剩下的資源買不起下一批城牆」跟「工人都在忙」是真的講出原因的; 落到「每一個位置都沒有買成」是它自己也說不上來, 而最可能的意思是牆到頂了 —— 那時候升級開出來的是一張要你先升大本營的告示, 而這個迴圈結構上只按得下綠色的確定, 所以它撞到什麼自己讀不出來. **這一種正是 `upgrade` 該接手的地方**: 工人還閒著, 只是牆沒得買. 撞到一次之後這一整趟都不用再跑 `walls`, 那個出口要等大本營升上去才會重開, 而那是使用者的決定

**停手的條件因此不是「倉庫滿了」而是「資源花不掉了」**: 工人全忙, 牆也刷不動, 而剩下的只有要使用者拍板的英雄. 那時候才交報告並掛上線. 倉庫滿了就交報告是把一圈當成全部.

**黑水只有升英雄能消化.** 牆吃金幣跟聖水不吃黑水, 所以黑水滿了而使用者沒指名英雄, 那一項就是停在那裡, 回報的時候要講出來.

通知的時候一起附上工人的狀況. `ai_coc builders` 說每個工人在蓋什麼、最快的一個還要多久, 那決定了通知裡要不要叫使用者等; 只想知道閒著幾個的話, 一張主村畫面丟 `uv run ai_coc read <png>` 看 `builders` 就有.

**其他停手的理由**: 遊戲一直回不到村莊, 同一個錯誤連續發生三次以上, 一輪也沒打成過, 或者排程重開模擬器之後村莊沒回來 (log 會說 `The village never came back after the restart`, 整個 series 就停在那裡, 手上那幾輪還是算數的). 這些都停下來講, 不要一直重試. 這個 repo 的原則是失敗要吵, 不是安靜地繼續.

## 停手之後掛著上線

**打完不要就這樣離開.** 部落衝突不會讓人攻擊一個主人正在線上的村莊, 而剛打滿的村莊是最好的目標 —— 護盾多半也在這時候到期. `uv run ai_coc online` 把連線撐著, 只送一個來回的短拖曳, 不做任何實質操作, 聽的是同一個 `ai_coc stop`.

值得掛的時機不只是「打完了」, 而是**任何一件事都做不下去的時候**: 倉庫滿了打不動, 工人全忙升不了也刷不了牆, 而下一個工人還要幾小時. 那段時間本來就是空的, 掛著上線的成本是每兩分鐘一次 swipe, 換到的是村莊不會被洗掉.

要動遊戲之前先 `ai_coc stop` 把它停掉, 不然兩邊會搶同一個畫面.

## 順手做的事

`collect` 很便宜, 是這個專案裡最值得常跑的指令: 採集器裝滿就停工, 沒人去收的村莊多數時間是在發呆. 開跑前跑一次, 每過一段時間再跑一次, 花不到幾秒.

`donate` 也幾乎沒成本, 沒人開口要兵的話只花一次點擊跟一張截圖, 而且捐兵有回饋. 想跑就跑.

`upgrade` 跟 `hero` **不要在打到一半的時候插進去**: 它們要先停迴圈才跑得了, 而且倉庫還沒滿的時候 `upgrade` 挑得到的比打滿之後差. 它們的位置是倉庫滿了那個接縫, 授權跟順序見上一節.

使用者開口指名要升某一樣東西的時候, 換 `spend-loot`. `ai_coc upgrade` 不給 `--only` 只會挑「最貴而且買得起的」, 指定不了是哪一棟, 而怎麼指定寫在那份 skill 的「三個入口」那節.

## 途中撞到 bug

**修掉, 不要繞過.** 這個 skill 的主線是跑迴圈而不是改程式碼, 但迴圈跑不動的原因如果是程式碼裡的錯, 繞過去只是把它留給下一次撞上. 流程照 `CLAUDE.md` 的 `## Development flow`, **這段不用另外問使用者.**

修的時候讓迴圈繼續在背景跑. 要動到活的遊戲才驗得了的, 就自己把它停掉, 驗完自己開回去 —— 規矩在 `references/running.md` 的「你自己要用畫面」那節.

## 任務報告

**任務達成才交完整報告.** 達成的意思是**資源花不掉了** (倉庫滿了, 牆刷不動, 工人也全忙), 或者使用者指定的輪數跑完. 那是一個明確的時刻, 報告放在那裡才有份量.

**倉庫滿了不是達成, 那只是一圈的一半.** 上面那個圈跑完幾次都算同一個任務, 所以中間那幾次「打滿了」只值一句進度, 報告等到真的花不掉再交. 一圈交一次報告會把同一件事拆成四五份, 而使用者要的是「這一段總共賺了多少、花掉多少」.

**沒達成就不要交報告**, 給一段話講清楚三件事就好: 跑到哪, 為什麼停下來, 要不要繼續. 中途被中斷, 遊戲一直回不了村莊, 一輪也沒打成, 這些都屬於這一類. 對一個半路夭折的跑交一份完整格式的報告, 只是把壞消息包裝得很漂亮.

報告印在對話裡, 同時寫一份到這次執行自己的目錄 (`~/.ai_coc/logs/<run>/report.md`), 跟它的 log 和畫面放在一起. 檔案那份是給以後翻的跟拿來跟上次比的, 對話那份是給現在看的, 內容一樣.

**樣板不要改.** 使用者會拿這次跟上次對照, 每次換一種寫法就比不了.

**兩個世界都打了就各報一份.** 「資源」跟「戰績」這兩節各出現兩次, 標題寫成 `## 資源（主村）` 跟 `## 資源（夜世界）`, 其他幾節共用. 不加總, 理由跟基準那節一樣. 夜世界那兩節的欄位本來就不一樣, 照著填會填出一堆空格:

- **搶到的總量沒有**: 沒有偵察畫面就沒有戰利品可報, `attacked` 是 `null`. 那一行寫「無此欄位」, 不要留空讓人以為是零
- **戰績看 `phases`**: 那是這一場出了幾次兵 (第二階段算第二次), 不是輪數. 也沒有對手可以跳過, 所以跳過那行不用寫
- **聖水要另外算推車**: 夜世界的聖水是入推車不是入庫, 迴圈每三場去領一次. 倉庫水位的差額會漏掉還在推車裡的那些, 所以收工前先跑一次 `uv run ai_coc collect` 把推車清乾淨再讀結束水位

### 開跑前先記下基準

進帳算不出來是因為沒有起點. 所以**開跑之前先讀一次倉庫水位**: `uv run ai_coc capture` 抓一張主村畫面, `uv run ai_coc read` 看 `stock` 欄位, 把三個數字記下來. 結束之後再讀一次. 這兩次讀取合起來才是「這次賺了多少」的唯一可信來源.

**兩個世界都要打的話, 兩邊各讀各的, 而且不准混.** 主村是 `stock` 三排, 夜世界要 `read_builder_stock` 讀兩排 (`ai_coc read` 的 `stock` 在那邊第三個數字是寶石被誤讀的). 那是兩組完全分開的倉庫, 容量差十倍, 所以「金幣 + 金幣」是一個沒有意義的數字. 順序上先讀要先打的那個世界, 因為切世界要坐船, 而船開過去之後另一邊的水位還是原本那個.

### 樣板

```markdown
# 任務報告

**目標**: <這次要達成什麼>
**結果**: 達成
**一句話**: <賺到了嗎, 現在輪到使用者做什麼嗎>

## 資源
|      | 開跑 | 結束 | 進帳 |
| ---- | ---- | ---- | ---- |
| 金幣 |      |      |      |
| 聖水 |      |      |      |
| 黑水 |      |      |      |

搶到的總量: 金 / 聖水 / 黑水
平均一場: ...    每小時約: ...

## 戰績
跑了 <時長>, <N> 輪, <M> 輪開打, <K> 輪空手 (<理由>)
跳過 <X> 個對手
最好的一場 / 最差的一場

## 花掉的
刷牆 <N> 片, 金幣 -<X>, 聖水 -<Y>
(沒花的話寫沒花, 以及為什麼)

## 為什麼停
<停手的理由>
工人 <閒著幾個>/<總共幾個>

## 需要你決定的
<沒有就寫沒有>
```

### 數字從哪來, 不准編

- **開跑 / 結束 / 進帳**: 上面那兩次 `read_stock`. 這是真的入庫的量
- **搶到的總量**: `result.json` 裡每輪 `AttackReport.attacked` 的加總. 這跟入庫的量**會不一樣**, 因為倉庫滿了之後搶到的會被丟掉. 兩個都列出來, 差很多本身就是資訊
- **輪數 / 開打 / 空手 / 跳過**: `AttackSeries` 數出來, 空手的理由看那一輪的 `message`
- **刷牆**: `WallReport.walls` 跟 `paid("gold")` / `paid("elixir")`
- **工人**: 一張主村畫面丟 `ai_coc read`, 看 `builders`
- **時長**: `run.log` 第一行跟最後一行的時間戳. 那個格式只有時分秒沒有日期, 所以跨午夜的跑會算出負數, 日期要看目錄名

**量不到的就寫量不到, 不要估.** 這個專案的規矩是寧可顯示破折號也不猜一個數字, 報告一樣適用.

### 那一句話怎麼寫

使用者多半只看這一句, 所以它要同時回答「賺到了嗎」跟「現在輪到我做什麼嗎」:

- `打滿了. 金幣聖水都到 15M 上限, 中間刷掉 34 片牆, 現在沒事要你處理.`
- `打滿了但花不掉. 金幣卡在上限, 牆也刷不動了 (剩下的不夠下一批 210k), 工人 0/6 全忙, 多出來的資源會一直被丟掉.`

## 沒達成的時候講什麼

不套樣板, 不寫檔案, 就一段話:

- 跑到哪 (幾輪, 進帳多少, 能講多少講多少)
- 為什麼停 (被中止 / 一輪也沒打成 / 回不了村莊 / 同一個錯誤重複發生)
- 要不要繼續, 以及繼續之前有沒有東西該先處理

被砍掉的跑 `result.json` 會是空的, 走 `uv run ai_coc stop` 停的不會. 空的那時候 `run.log` 是唯一的紀錄, 從裡面數得出多少就寫多少, 並且註明是從 log 數的.

## 中途被問進度

報當下的資源跟輪數就好, 而且**不要停下迴圈**. 報告留到任務真的達成再交.
