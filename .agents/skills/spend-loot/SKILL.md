# spend-loot

把打回來的資源變成村莊的進度. 三種出口: **城牆**, **建築**, **英雄**.

**三種都有指令, 而且指令自己會找目標.** 你的眼睛是它們失手時的退路, 不是第一步 —— 這一點跟這個 skill 以前的寫法相反, 因為那時候還沒有 `_spotted`.

`farm` 那個圈的另外半邊在這裡: 打到滿 → 花掉 → 回去打. 圈本身的規則 (什麼時候該花, 什麼時候該停手通知人) 寫在 `.agents/skills/farm/SKILL.md`, 這裡只講怎麼花.

**動手之前先確認沒有別的迴圈在跑.** 這裡每一個指令都在驅動同一個模擬器的同一個 display, 兩個一起跑就是兩隻手搶同一張畫面, 而且沒有任何機制會發現. 怎麼停跟停完怎麼開回去在 `.agents/skills/farm/references/running.md`.

## 先確認在哪個村莊

這個遊戲有兩張地圖, 日世界 (主村) 跟夜世界 (建築大師基地), 而**遊戲會開在上次離開的那一個**. 兩邊的建築完全不同名也不同用, 所以「找儲金罐」在錯的村莊上是找不到而不是找錯, 而你會花好幾張截圖才發現.

```bash
uv run ai_coc world                       # 回 day / night, 不動畫面也不點東西
uv run ai_coc world --go day              # 坐船切過去, 已經在那邊就什麼都不做
```

用指令問比用眼睛猜快, 而且它是同一個判讀器 (看最上面那排面板伸到多開 —— 主村多了護盾那格所以更寬, 遊戲的動畫蓋掉一格也不會讀錯).

## 想知道村莊裡有什麼, 不必用截圖猜

```bash
uv run ai_coc export --last --table       # 上一次取出來的整個村莊, 不碰遊戲
uv run ai_coc export --table              # 重新取一次再看, 會操作遊戲選單
```

遊戲自己會把整個村莊寫成 JSON, `export` 就是去按那幾個鍵再把結果對照成名稱. 出來的是**每一棟建築、每一個兵種、每一個英雄的等級跟數量**, 兩個世界一起 (`buildings` 是主村, `buildings2` 是夜世界), 這是任何截圖都看不到的完整帳. 決定「哪一棟該升」的時候先看它, 比一張一張點開建築快得多.

兩件要知道的事: 它是**當下的快照**, 升完東西要重跑才會變; 而且對照表收的是建築跟兵種, 所以英雄裝備、外觀、裝飾品、障礙物那幾段的 `name` 是空的 (實測 226 筆裡有 65 筆), 只有編號跟等級. 你會用到的建築跟兵種都有名字.

## 三個入口

```bash
uv run ai_coc walls                       # 把儲量換成城牆, 不佔工人
uv run ai_coc upgrade                     # 把閒著的工人派去升最貴而且買得起的建築
uv run ai_coc upgrade --only 儲金罐        # 只升名字含這幾個字的那一棟
uv run ai_coc hero                        # 六個英雄各自的下一級要多少, 只讀不動
uv run ai_coc hero --upgrade duke         # 真的派一個工人去升這一個
```

**找目標是同一套機制** (`GameRunner._spotted`): 把一張村莊畫面丟給 Gemini, 要回一批座標, 而**每一個座標都點開驗過才算數** —— `walls` 驗開出來的是不是城牆選單, `upgrade` 驗有沒有一個帶價格的升級鍵, `hero` 驗開出來的是不是英雄殿堂. 猜錯的代價是一次點擊加一次截圖, 所以它問回來的點比實際需要的多是刻意的.

實測過兩次: 12 個城牆座標一次開出 9 個選單, 另一次 12 個全中; 14 個建築座標有 9 個真的有升級可以按; 英雄殿堂第一個猜測就開到. 對照組是 `_sweep` 鋪網格撞運氣, 找一次英雄殿堂兩分半, 而且村莊大半根本在格子外.

**`--at` 是你手上剛好已經有截圖時的捷徑**, 不是常態. 城牆跟建築的 `--at` 可以給很多次, 而且**要給很多次**: `_pick` 的整個價值就在比價, 只給一個座標等於沒得比 —— 實測那樣花 9 000 000 買下一片牆, 而同一個村莊裡站著 4 000 000 的.

**`--only` 是包含比對** (標籤上帶著等級), 而且**名字讀不出來的建築一律不匹配**. 名字是遊戲寫在按鈕列正上方那條帶子, 裁下來丟給便宜的模型 (`gemini` 設定的 `lite` tier) 讀的; 工人很稀缺, 這個過濾器存在的意義就是不要把它花在猜的東西上.

**代價是它會安靜地什麼都不升.** 沒設模型, 或者那條帶子這次讀不出來, `--only 儲金罐` 回報的「沒有找到可以升的」就有兩種意思: 真的沒有, 還是名字全部讀不出來. 分辨的方法是看報告裡每個候選的名稱欄位 —— 全空就是後者, 那時候改成自己看畫面找到座標再 `--at`. 順帶一提那個欄位有時候會夾著模型自言自語 (實測 11 個標籤裡 4 個), 那不影響 `--only` 的包含比對, 只是讀起來難看.

## 花的順序: 牆先, 工人的活後

**底下每一個跑到 `walls` 的步驟都要使用者開口過.** 牆預設不刷 (見下面「哪些不用問, 哪些要」), 這一節講的是牆在場的時候怎麼排順序, 不是牆會自己出現. 他沒指名牆的那一趟只有 `upgrade` 會跑, 沒有順序問題 —— 但要知道跑下去就把牆這個出口關掉好幾天, 理由就是底下這一段.

**兩個出口搶同一個工人, 而它們借走的長度差好幾天.** 一片牆付錢的當下就升好, 工人立刻還回來, 所以有一個閒著就能連續買一整排; 建築升級不一樣, 那個工人被綁住好幾天. 所以:

1. `ai_coc walls` 先把儲量吃掉. 它每一批挑**剩得多**的那邊付, 停在兩邊都買不起最便宜的一批; 兩種資源的牆價一樣, 所以哪邊先用完不影響總共買幾片
2. **牆吸不掉的時候才輪到 `ai_coc upgrade`.** 吸不掉有兩種: 牆被大本營等級卡住 (回報「每一個位置都沒有買成」而村裡的牆都到頂), 或者買完還有剩. 這個前置條件只在牆真的跑了的時候才成立 —— 他沒指名牆的那一趟牆根本不跑, 那個條件永遠驗不出來, 所以那時候 `upgrade` 看的是「有沒有工人閒著」而不是這一條

**不能顛倒, 而且理由在程式碼裡.** `ai_coc upgrade` 會把**每一個**閒置工人都派出去 (`ui/upkeep.py` 的 `while offers and len(report.started) < builders[0]`), 而 `walls` 在 `0/N` 的村莊一片都買不了 —— 實測每一批都確認了然後沒被扣錢, 遊戲回一句「所有建築工人都在忙碌中」再附一顆寶石按鈕, 一片牆跟八片牆一樣退. 先跑 `upgrade` 就是先把牆這個出口關掉, 然後花兩分鐘讓 `walls` 去撞它.

**使用者指名了要升什麼的時候是第三種順序**, 因為那時候價格是讀得到的:

1. 點開那棟讀出價錢
2. **他也開口要刷牆的話**, `uv run ai_coc walls --keep-gold <留這麼多> --keep-elixir <留這麼多>` 把多的刷成牆. 只指名了建築就跳過這一步 —— 沒被指名就刷牆正是預設要擋掉的事, 而多出來的資源留在倉庫裡不會怎麼樣
3. 回來按升級

**除了這個例外之外 `--keep-*` 就讓它是 0.** 現在的 Clash of Clans 練兵不用錢, 留下來的聖水沒有任何用途, 而牆吃金幣也吃聖水. 實測照舊寫法留了聖水, 金幣買完兩片就停在「買不起下一批」, 而旁邊躺著 610 萬聖水買得起第三片.

## 哪些不用問, 哪些要

- **城牆: 要使用者指名, 預設不刷.** 使用者 2026-09-15 的常設交代, 原話是「默認是不升級牆壁, 除非我說」. 牆的性質沒變 —— 付錢的當下就升好, 不跑計時器, 工人立刻還回來, 資源再打就有 —— 但那是它值得被列成一個選項的原因, 不是自己跑掉的理由. 他開口了才跑, 而那正是這份 skill 的主線
- **建築: 工人閒著的時候不用問.** 倉庫滿了而工人在發呆是雙重浪費 —— 打回來的資源進不了滿倉直接被丟掉, 而工人這段時間什麼都沒蓋. 前置條件是 `ai_coc builders` 說真的有工人閒著. **要知道它挑得沒有你準**: `_pick` 的 docstring 自己寫著 which building is worth raising is a judgement about the base rather than about the price, 而 finder 實測 14 個點裡 9 個有升級可按. 所以使用者指名的時候一定要用 `--only`; 沒指名的時候「最貴而且買得起的」是能拿到的最好的預設, 不是最好的答案
- **英雄: 要使用者指名.** `hero` 不給 `--upgrade` 就只讀不動, 那是刻意的. **升級中的英雄不能上場**, 卡片直接從隊伍列消失, 所以升一個英雄是拿接下來幾天的進攻火力去換; 而這個專案的主線是打資源, 所以那是使用者對村莊怎麼玩的取捨, 價格答不了. 讀出價格回報給他, 讓他挑, 而且用選擇題問 —— 規矩在 `farm` 的「要他拍板的事情用選擇題問」

寶石跟現金在任何情況下都不碰, 見下面「絕對不要點的兩個東西」.

**這些條件只擋最後那一次點擊, 不擋前面任何一步.** 找到目標跟讀出它的價格都不花任何東西, 而價格是點開選單才看得到的 —— 所以工人 `0/N` 全忙也照樣把價格讀回來回報, 那本身就是使用者要的答案. 一開頭就因為沒工人收工, 等於把唯一能帶回去的資訊也丟掉了. 使用者只是問「那東西多少錢」的時候, 授權這一整節根本用不上.

**但沒工人的時候這一步只能用眼睛做.** `ai_coc upgrade` 在零個閒置工人的時候直接返回 —— `ui/upkeep.py` 讀到 `builders[0] == 0` 就回「N 個工人都在忙，沒有可以派的」, 連 finder 都還沒跑, 一個價格都讀不到. 所以那是換成自己看的第五種情況.

錢跟工人怎麼讀: `uv run ai_coc worker` 說閒著幾個、每個在蓋什麼、最快的一個還要多久, 而且不切世界; 資源是 `uv run ai_coc stock`, 它答當下這個世界的水位、容量跟百分比, 而且鏡頭是它自己放好的. 手上已經有一張圖才用 `uv run ai_coc read <png>` 讀 `stock`, 那條路的鏡頭是碰運氣的.

## 什麼時候換成你自己看

四種情況, 前三種是指令先失手:

1. **指令說找不到.** `upgrade` 沒找到可以升的, `hero` 找不到英雄殿堂, 或者 `walls` 回報「每一個位置都沒有買成」而牆其實還沒到頂
2. **`--only` 對不上.** 名字讀不出來的建築一律不匹配, 而那條帶子讀不讀得到不是你能控制的
3. **問題本來就不是升級.** 「這棟是什麼」「儲金罐在哪」「畫面上有沒有 X」
4. **人在夜世界.** 那邊沒有任何指令做得了升級, 見下一節
5. **工人全忙而使用者只是想知道價錢.** `ai_coc upgrade` 那時候連找都不找就返回了, 理由在下面「哪些不用問」

**為什麼眼睛還有用.** 這個專案的規矩是「讀遊戲畫在上面的 UI, 不讀底下的美術」, 因為每一級都會重畫建築, 模板比對認不出來. **那條規矩約束的是判讀器, 不是你** —— 「這棟是儲金罐」是看一眼就知道的事, 而且遊戲會把答案寫在選單標題上, 那行中文只有你讀得懂. 分工是: 要跑幾百次的重複動作交給腳本, 一次性的辨認交給眼睛.

## 夜世界只能自己看

**在夜世界跑主村的指令不是「什麼都不做」, 是坐船回主村然後做主村的.** `walls` / `upgrade` / `hero` / `donate` / `builders` 五個全是 `GameRunner` 的子類別, 而 `GameRunner._home` 讀到夜世界就 `cross(..., "day")`, 因為它底下每一個判讀器都是主村的. 這五個沒有一個有 `--world` 可以擋, log 裡也只有一行 warning. 所以在夜世界下 `ai_coc upgrade` 是**沒問過就切世界**, 花掉主村的資源, 綁走主村的工人; 連純讀的 `ai_coc builders` 都會白花一趟船, 而且把遊戲留在錯的世界, 下一個 `attack --world night` 得再坐回來 (**純讀工人改用 `ai_coc worker`**, 它讀的是當下那個村莊, 不切世界). 動手之前先問 `ai_coc world`. (**`ai_coc collect` 是唯一自己先問世界的**, 它在夜世界改去收聖水推車. 船只坐一次, 沒成功就 `return None` 收工.)

夜世界看圖的方法完全不用改, 而且比主村好用: 拉到最遠的時候整個基地擠在畫面中間大約 x 520 到 1080, y 170 到 540 的一塊裡, 不用拖鏡頭, 也沒有主村那個「下面三分之一掃不到」的問題. 選單也長得一模一樣: 標題寫建築名稱跟等級, 下面一排按鈕左起是 `資訊`, 然後是 `升級` 帶著價格跟資源圖示.

實測過的四個差別:

- **升級是交叉付款的.** 主村的建築多半用自己那種資源升級, 夜世界不是: 儲金罐要 **80 萬聖水**, 建築大師大本營要 **224 萬金幣**. 不要看到金色建築就以為它吃金幣, 讀選單上的圖示
- **藍色底板那條規則照樣適用.** 儲金罐選單上的 `填滿` 就坐在藍色底板上, 那是花寶石的
- **工人的總數跟主村不一樣** (夜世界實測是 3, 主村目前是 6, 而且兩個都會隨帳號成長, 所以不要背), 而且 `ai_coc builders` 在夜世界**不會回 `null`, 它會坐船回主村**再回報主村的那一排 (`UpkeepRunner.builders()` 第一件事就是 `_home`). 要知道夜世界的工人忙不忙就跑 `ai_coc worker`, 它讀的正是畫面最上面那格, 不切世界, 連在蓋什麼都答
- **只有金幣跟聖水兩種資源**, 沒有黑水. 要知道那邊剩多少就跑 `uv run ai_coc stock`, 它會自己挑對的判讀器並且把百分比一起算好. 拿一張圖去讀的時候才要小心: `ai_coc read` 的 `stock` 欄位在夜世界第三個數字是寶石條被誤讀的 (實測 10 152 寶石讀成 `dark=410152`), 該看的是 `builder_stock`, 而 `world` 欄位說該信哪一個

## 原語

`ai_coc` 沒有「點這裡然後給我看」這種指令, 每個都是一整套迴圈. 這個 skill 自己帶一個:

```bash
uv run python .agents/skills/spend-loot/scripts/eye.py shot <out.png>
uv run python .agents/skills/spend-loot/scripts/eye.py tap <x,y> <out.png>
uv run python .agents/skills/spend-loot/scripts/eye.py zoom <in.png> <l,t,r,b> <out.png>
```

`tap` 點完會等選單滑出來再截.

`zoom` 不碰遊戲, 只是把存下來的圖裁一塊放大 —— 1600x900 整張讀進對話裡, 一棟建築只剩幾十像素, 不放大認不出來, 這步不要省. 四個數字是**原圖的像素座標**, 左上右下. 畫面永遠是 1600x900. 它會印出放大倍率, **記下來**: 在放大圖上量到的位置要除以倍率再加回裁切框的左上角, 才是可以拿去 `tap` 的座標. 這個換算是整個流程的核心動作, 算錯就點到隔壁那棟.

**遊戲沒開不用管**, 腳本走 `commands._controller()`, 它會自己 `ensure_coc`.

**每一張你看過的圖都發一份給使用者.** 這個 skill 的 fallback 從頭到尾就是在看圖, 而使用者看不到你的工具輸出 —— 你說「這棟是儲金罐」的時候, 他要能看到你看到的那張才判斷得出你有沒有看錯. 用檔案傳送機制發出去, 不要只留路徑.

## 找

1. `shot` 一張村莊畫面
2. 讀進來看. 認不出來就 `zoom` 分區放大, 一次一塊
3. 挑出候選, 記下座標

**第一張拍到的不一定是村莊.** 上一次跑留下的選單可能還開著. 選單要關掉就 `tap` 一塊空地 (畫面邊緣的樹林或水面), **不要按 back** —— 在村莊上按 back 跳出來的是「確定退出遊戲嗎」, 那個對話框的綠色「確定」跟升級的確認鍵長得一模一樣, 在同樣的位置. 如果畫面根本不是村莊而是戰鬥或某個全螢幕頁面, 停下來告訴使用者, 不要亂點.

**縮小範圍的線索全都是位置跟關係, 不是長相.** 每一級都會重畫建築, 所以記住某樣東西長什麼樣一定會過期, 但這些不會:

- **採集器在村莊最外圈**, 而且頭上浮著收集標記 (金幣 / 紫水滴 / 黑泡泡). 金礦, 聖水收集器, 黑水鑽井都在那一圈, 它們跟同名的儲存罐是不同的東西
- **儲存罐體積大一號, 而且成排擺在一起**, 通常在防禦圈裡面
- **大本營是全村最大最顯眼的那棟**, 而且只有一棟
- **正在升級的建築頭上有一條綠色進度條跟剩餘時間**. 那些點開也沒有升級按鈕
- **牆是連成線的格子**, 認不錯
- **浮在建築上方的標籤是提示不是建築** ——「請求增援」是部落城堡的, 「已滿!」是某樣東西滿了. 它們會蓋住底下的東西, 別把標籤的座標當成建築的座標

**這一步不要猜到底.** 放大兩三塊還認不出來, 直接點一個最像的看選單 —— 點錯的代價只是一次截圖, 比繼續盯著圖猜便宜得多. 遊戲會把答案寫在選單標題上.

**認不出來就問使用者.** 他認得自己的村莊, 而且一張縮圖就講完了. 這比放大十塊區域快, 也比點錯五次誠實.

**村莊下緣正好是腳本掃不到而你看得到的地方.** `_sweep` 的網格最下面一列停在 y 500, 再往下的格點直接跳過, 因為一格點下去開出來的按鈕列會蓋住螢幕下緣. 村莊的下面三分之一沒有任何一趟掃描到得了 —— 所以那一帶不是這個 skill 的死角, 是它最有價值的地方.

**重開遊戲或模擬器之後, 之前記下來的每一個座標都作廢.** 實測: 一次 `launch --restart emulator` 之後村莊整個偏到畫面右下, 幾分鐘前還能一次點中儲金罐的 (1157, 500) 變成一片空地. 重開過就重新截一張重新找, 不要拿舊座標賭.

**但鏡頭不用你操心.** `ai_coc launch` 每一種 `--restart` 最後都走 `_settle_game`: 輪詢到村莊真的畫出來, 然後 pinch 拉遠, **再把鏡頭滑到地圖角落停好**. 那是兩件事: pinch 只管縮放, 實測它一點都不移動鏡頭, 真正讓位置可重現的是地圖邊緣把鏡頭夾住. 村莊畫面上也一直在校正, `_settle_zoom` 掛在 `_home` 認出來的第一張村莊上, 而且是在讀儲量條**之前** —— 鏡頭飄掉的時候儲量條本身就讀不出來, 所以拿它當條件的話, 唯一能把鏡頭救回來的那一步永遠不會執行. 要自己補一次的只有一種情況 —— 不是透過 `ai_coc launch` 重開的 (譬如自己去 MuMu 按重啟), 那就先跑 `uv run ai_coc view --zoom out`. **它現在會滑鏡頭而不只是 pinch**, 所以只在畫面確實是村莊的時候才停鏡頭; 戰鬥中它只縮放不滑, 因為選著卡片時滑動會變成沿路出兵. **`--zoom in` 也一樣不停鏡頭**: 那一滑有沒有到位只有在最遠的 zoom 讀得出來, 拉近之後鏡頭會滑出村莊外, 實測滑十四下還在動 —— 所以那條路只縮放, 並且照實說沒有定位.

**剛載入的遊戲, 右上角那三個資源數字是會動的.** 儲量條從 0 跑上去要幾秒, 中途讀到的是假的: 同一次重啟實測讀到 12.4M 金幣, 而真正的值是 19.7M. 要拿資源數字做決定就等畫面靜下來再讀一次.

## 點開, 然後確認點對了

```bash
uv run python .agents/skills/spend-loot/scripts/eye.py tap 1157,500 pick.png
```

**選單標題會寫建築名稱跟等級**, 像「儲金罐(14級)」「英雄殿堂(10級)」. 這是驗證的唯一可靠依據, 而且它是中文 —— 這正是腳本做不到而你做得到的那件事. 每次點完都讀一次標題再往下走.

**點錯很正常, 建築會重疊.** 一個座標壓在兩棟建築上的時候, 連續點會在它們之間輪替: 實測在 (990, 430) 連點三次, 依序開出英雄殿堂, 旁邊的箭塔, 又是英雄殿堂. 所以點錯就再點一次同一個點, 或者偏移個二三十像素. `ui/hero.py` 的 `AT_TRIES` 就是為這件事存在的.

## 按下去

選單下方那排按鈕裡有一個「升級」, 上面寫著價格跟資源圖示. 點它, 通常會跳出一個全螢幕的確認頁 (「將金礦升至10級？」), 上面有綠色的「確認」; 城牆是一個小對話框. 點下去, 然後**再截一張看資源真的少了** —— 被遊戲吞掉的點擊不會有任何提示, 光看對話框關掉是分不出來的. 這個專案裡每一個花錢的迴圈都是這樣驗的.

**價格是紅色代表買不起, 但那個數字本身是對的.** 紅色是遊戲在說「你現在付不出來」, 不是在說這個數字有問題 —— 照樣讀出來回報, 那往往正是使用者要的答案. 紅色改變的只有一件事: 不要點下去, 因為遊戲照樣讓你點, 然後給你一個寶石購買畫面.

**有價格也不等於按得下去.** 被英雄殿堂等級卡住的英雄, 價格照樣讀得出來, 死掉的是按鈕: 底盤變成純灰. 實測飛龍公爵 15 級要 220 000 黑水, 村莊剛好握著 220 000, 按下去什麼都沒發生; `hero --upgrade` 這時候回的是「升級按鈕是停用的，多半是英雄殿堂的等級擋住了」. 那不是 bug, 是這一級要先把殿堂升上去.

**絕對不要點的兩個東西, 它們都長得像正常按鈕:**

- **藍色底盤的按鈕**. 那是花寶石或魔法物品的 (加速所有同類項目, 城牆之戒). 這個專案的授權原則是寶石在結構上就碰不到, 你也一樣
- **綠色的寶石數字**, 畫面右上角那個, 以及任何確認頁上寫著寶石的按鈕. 英雄殿堂裡「立即完成」佔的正好是「升級」的位置, 而它旁邊的數字是寶石

看到確認頁上要的是寶石而不是資源, 退出來, 告訴使用者為什麼.

## 收尾: 把選單關掉

**不管有沒有升級, 走之前都要讓畫面回到乾淨的村莊.** 方法跟上面一樣, `tap` 一塊空地, 然後截一張確認. 這不是禮貌問題: 留在畫面上的選單會蓋住村莊中間, 下一個跑起來的迴圈第一件事就是讀倉庫條, 讀不到就開始按 back 找路回家, 而 back 在村莊上會叫出「確定退出遊戲嗎」. 你省下的一次點擊, 下一個人要花好幾十秒繞出來.

## 花完了就回去打

**這個 skill 被叫來多半是因為倉庫滿了, 而花掉剛好把它清出空間 —— 空的倉庫是可以再打滿的.** 所以做完就回 `farm`, 那邊的「什麼時候停手」寫了完整的圈. 重點是**這個圈沒有寫在程式碼裡**: `ai_coc attack --repeat 0` 倉庫一滿就結束, 它不知道還有下一步, 所以交接是你在做的. 使用者要的是打到花不掉為止, 不是打到滿為止.

**真的花不掉的時候才停手通知使用者**, 而三種卡法各自的下一步不一樣 (工人全忙 / 牆被大本營卡住 / 黑水只有英雄能消化). 那一段判斷在 `farm` 的「倉庫滿了」那節, 這裡不重複.

## 回報

一句話講完就好: 升了什麼, 花了多少, 現在剩多少. 沒升成的話講清楚是卡在工人, 卡在錢, 還是找不到東西 —— 這三種使用者的下一步完全不同.

**不要編數字.** 花了多少以升級前後兩次讀到的倉庫差額為準, 不是選單上的標價 —— 兩者不一樣就是有事發生, 那本身就是要回報的資訊.
