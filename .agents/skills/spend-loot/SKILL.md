# spend-loot

把打回來的資源變成村莊的進度, 出口有三種: **城牆**, **建築**, **英雄**. **三種都有指令, 而且指令自己會找目標**, 你的眼睛是它們失手時的退路, 不是第一步.

這裡是 `farm` 那個圈 (打到滿 → 花掉 → 回去打) 的另外半邊; 什麼時候該花, 什麼時候停手通知人, 在 `.agents/skills/farm/SKILL.md`.

**動手之前先確認沒有別的迴圈在跑**: 有的話, 你的指令會借走它, 等它打完手上那一場才開始, 花完要 `uv run ai_coc giveback` 它才會接著打; 不是你要的就不要下. 怎麼借, 怎麼還, 還有 `walls` / `upgrade` / `hero` 這種會跑好幾分鐘的怎麼送到背景, 在 `.agents/skills/farm/references/running.md`.

每個 `ai_coc` 指令都帶 `--agent`、`--session`、`--mission` (`AGENTS.md` 的 Say who is driving), 下面的例子為了好讀省略了; `eye.py` 不收這幾個旗標.

## 做完的樣子

使用者最後拿到的是**一句話的回報, 加上你看過的每一張圖**. 回報照他問的是什麼:

- **只問在哪, 是什麼, 升這個要多少**: 答案本身. 名稱跟等級照選單標題讀, 價格連同是哪一種資源; 紅色的 (買不起) 照讀, 工人全忙也照讀 (建築跟牆的價格用眼睛讀, 見「什麼時候換成你自己看」). 什麼都不花
- **要升, 升成了**: 升了什麼, 花了多少, 現在剩多少
- **要升, 沒升成**: 卡在工人, 卡在錢, 還是找不到東西, 這三種的下一步完全不同, 要講是哪一種. 按鈕是停用的 (英雄殿堂等級擋住), 或者確認頁要寶石而退出來的, 照實講為什麼
- **英雄他沒指名是哪一個**: 讀出來的價格列給他挑, 不替他挑 (見「哪些不用問, 哪些要」)

**不要編數字**: 花了多少以升級前後兩次讀到的倉庫差額為準, 不是選單上的標價; 兩者不一樣就是有事發生, 那本身就要回報.

**每一張你看過的圖都發一份給使用者**, 用檔案傳送機制, 不要只留路徑: 他要看到你看的那張, 才判斷得出你有沒有認錯.

**畫面要停在乾淨的村莊**, 有沒有升都一樣, 見「收尾: 把選單關掉」.

**從 `farm` 那一圈接過來的** (他開口要打到花不掉), 這裡花掉的寫進 `farm` 回報裡花費那一行; 做完接回去打, 見「花完了就回去打」.

## 先確認在哪個村莊

遊戲會開在上次離開的那一個村莊, 而日世界 (主村) 跟夜世界 (建築大師基地) 的建築完全不同, 在錯的那邊是找不到而不是找錯. 用指令問:

```bash
uv run ai_coc world                       # 回 day / night, 不動畫面也不點東西
uv run ai_coc world --go day              # 坐船切過去, 已經在那邊就什麼都不做
```

## 想知道村莊裡有什麼, 不必用截圖猜

```bash
uv run ai_coc export --last --table       # 上一次取出來的整個村莊, 不碰遊戲
uv run ai_coc export --table              # 重新取一次再看, 會操作遊戲選單
```

兩個世界每一棟建築, 兵種, 英雄的等級跟數量都在裡面 (`buildings` 是主村, `buildings2` 是夜世界), 挑哪一棟該升先看它. 它是**當下的快照**, 升完要重跑; 英雄裝備, 外觀, 裝飾品, 障礙物那幾段的 `name` 是空的.

## 三個入口

```bash
uv run ai_coc walls                       # 把儲量換成城牆, 不綁住工人 (但要有一個閒著)
uv run ai_coc upgrade                     # 把閒著的工人派去升最貴而且買得起的建築
uv run ai_coc upgrade --only 儲金罐        # 只升名字含這幾個字的那一棟
uv run ai_coc hero                        # 六個英雄各自的下一級要多少, 只讀不動
uv run ai_coc hero --upgrade duke         # 真的派一個工人去升這一個
```

**找目標共用 `GameRunner._spotted`**: Gemini 回一批座標, **每一個都點開驗過才算數**, 所以回來的點比需要的多是刻意的.

**`--at` 是手上剛好已經有截圖時的捷徑**, 不是常態. 城牆跟建築的 `--at` **要給很多次**, 因為 `_pick` 靠比價挑, 只給一個座標等於沒得比. **那張截圖要在鏡頭停好之後拍**, 先 `uv run ai_coc view --zoom out` 再 `shot`: 指令開跑會先把鏡頭拉遠停好 (`GameRunner._settle_zoom`, 它的 docstring 把 `--at` 算在內), 而坐船 (`world --go`) 之後的鏡頭是遊戲給的, 在沒停好的畫面上量的點, 指令一停鏡頭就偏了. 偏了在 `walls`, `hero` 跟帶 `--only` 的 `upgrade` 只是那一點驗不過; **不帶 `--only` 的 `upgrade --at` 會把偏到的那一棟照樣比價, 買得起就買** (`_offer` 不核對打開的是不是瞄準的那棟), 所以指名的建築一定帶 `--only`.

**`--only` 是包含比對** (標籤帶著等級), 而且**名字讀不出來的建築一律不匹配**, 因為工人稀缺, 不能花在猜的東西上. 名字由 `gemini` 設定的 `lite` tier 從按鈕列正上方那條帶子讀出來.

**代價是它會安靜地什麼都不升**: 沒設模型或帶子讀不出來時, `--only 儲金罐` 回 `only_no_match` 可能是真的沒有, 名字對上了但買不起, 也可能是名字全讀不出來. 報告裡沒有候選的名字, 要看 `run.log` 的 `Upgrade at (x, y): <名稱> asking …` 那幾行: 名稱全是 `?` 就是讀不出來, 改成自己看畫面找座標再 `--at`. 名稱裡夾著模型自言自語不影響比對.

## 花的順序: 牆先, 工人的活後

**跑到 `walls` 的每一步都要使用者開口過** (見「哪些不用問, 哪些要」). 沒指名牆的那一趟只跑 `upgrade`, 沒有順序問題, 但要知道那會把牆這個出口關掉好幾天; 那則通知怎麼寫 (牆列成會過期的選項, `upgrade` 照樣跑) 在 farm 的「倉庫滿了」那節.

**兩個出口搶同一個工人**: 牆付錢的當下就升好, 工人立刻還回來; 建築升級把工人綁住好幾天. 所以:

1. `ai_coc walls` 先吃掉儲量. 每一批挑**剩得多**的那邊付, 兩邊都買不起最便宜的一批才停
2. **牆吸不掉才輪到 `ai_coc upgrade`**: 牆被大本營等級卡住 (`WallReport.outcome` 是 `nothing_bought` 而村裡的牆都到頂), 或者買完還有剩 (`farm` 那一圈裡不算, 那裡買完還有剩是回去打, 見它的「倉庫滿了」). 這個條件只在牆真的跑了才驗得出來; 沒指名牆的那一趟, `upgrade` 看的是有沒有工人閒著

**不能顛倒**: `ai_coc upgrade` 會把**每一個**閒置工人都派出去 (`ui/upkeep.py` 的 `while offers and len(report.started) < builders[0]`), 而 `walls` 在 `0/N` 的村莊一片都買不了 (遊戲回「所有建築工人都在忙碌中」, 不扣錢), 只會白撞兩分鐘.

**使用者指名了要升什麼, 是第三種順序**, 因為價格讀得到:

1. 點開那棟讀出價錢
2. **他也開口要刷牆的話**, `uv run ai_coc walls --keep-gold <留這麼多> --keep-elixir <留這麼多>` 把多的刷成牆; 只指名了建築就跳過, 沒被指名就刷牆正是預設要擋掉的事
3. 回來按升級

**除了這個例外, `--keep-*` 一律是 0**: 練兵不用錢, 留下來的聖水沒有用途, 而牆吃金幣也吃聖水; 留了聖水, 金幣用完就停在 `cannot_afford`.

## 哪些不用問, 哪些要

**這一節的前提是他這一趟開口要花**, 開口是他講的, 不是你判斷出來的 (farm 的「倉庫滿了」那節). 只問在哪, 是什麼, 多少錢的, 什麼都不花.

- **城牆: 要使用者指名, 預設不刷.** 使用者 2026-09-15 的常設交代, 原話是「默認是不升級牆壁, 除非我說」. 籠統的「把資源花掉」不算指名到牆. 牆要一個閒著的工人但買完立刻還回來, 那不是自己跑的理由
- **建築: 工人閒著 (`ai_coc worker` 說的) 就不用問**, 因為滿倉加上發呆的工人是雙重浪費. 但**它挑得沒有你準** (`_pick` 的 docstring: which building is worth raising is a judgement about the base rather than about the price): 使用者指名的時候一定用 `--only`, 沒指名時「最貴而且買得起的」只是能拿到的最好預設
- **英雄: 要使用者指名.** `hero` 不給 `--upgrade` 只讀不動是刻意的: **升級中的英雄不能上場**, 升一個是拿接下來幾天的進攻火力去換, 而這個專案的主線是打資源, 所以那是使用者的取捨, 價格答不了. 讀出價格列給他挑 (規矩在 `farm` 的「通知跟要他拍板的事」)

寶石跟現金在任何情況下都不碰, 見「按下去」.

**這些條件只擋最後那一次點擊.** 找目標跟讀價格都不花東西, 所以工人 `0/N` 全忙也不要收工, 照樣把價格讀回來回報, 那本身就是使用者要的答案. 工人全忙時**建築**的價格只能用眼睛讀: `ai_coc upgrade` 讀到 `builders[0] == 0` 就回 `BuildReport.outcome` 是 `builders_busy` (`ui/upkeep.py`), 連 finder 都還沒跑. 英雄的不受影響: `ai_coc hero` 不給 `--upgrade` 照樣進殿堂讀, 工人全忙只擋 `--upgrade` (`ui/hero.py`).

錢跟工人怎麼讀:

- `uv run ai_coc worker`: 閒著幾個 (`free`/`total`), 每一個在蓋什麼 (`jobs`, 每列帶 `name` 跟 `remaining` 秒數), 不切世界. 最快的還要多久要自己對 `remaining` 取最小, 答案裡沒有那一句, `run.log` 裡才有
- `uv run ai_coc stock`: 當下這個世界的水位, 容量跟百分比, 鏡頭它自己放好
- `uv run ai_coc read <png>` 的 `stock`: 手上已經有一張圖才用, 那條路的鏡頭是碰運氣的

## 什麼時候換成你自己看

1. **指令說找不到**: `upgrade` 回 `nothing_found`, `hero` 回 `hall_not_found`, `walls` 回 `no_walls_found`, 或者 `walls` 回 `nothing_bought` 而牆其實還沒到頂
2. **`--only` 對不上**, 見「三個入口」
3. **問題本來就不是升級**: 「這棟是什麼」「儲金罐在哪」「畫面上有沒有 X」, 還有建築或牆的「升這個要多少」: `upgrade` 跟 `walls` 沒有只讀不花的模式, 跑下去就是買 (英雄的價格 `ai_coc hero` 不給 `--upgrade` 讀得到)
4. **人在夜世界**, 見下一節
5. **要升而工人全忙**, 建築的價格還是要讀回來, 見「哪些不用問, 哪些要」

「讀 UI 不讀美術」這條規矩約束的是判讀器, 不是你: 一次性的辨認看一眼就知道, 而且遊戲把答案寫在選單標題的中文上.

## 夜世界只能自己看

**主村的指令在夜世界什麼都不做, 也不會坐船**: `walls` / `upgrade` / `hero` / `donate` / `builders` 回 `builder_base` 就結束, 遊戲留在原地. 要花主村的就先 `ai_coc world --go day`. 夜世界的工人用 `ai_coc worker` 讀, 連在蓋什麼都答; `ai_coc collect` 在那邊收的是聖水推車.

看圖反而更好找: `uv run ai_coc view --zoom out` 停好鏡頭後整個基地在畫面中間, 大約 x 360 到 1410, y 110 到 870 (2026-10-07 量的), 不用拖鏡頭, 下緣也看得到. 選單一樣是標題寫名稱跟等級, 按鈕列左起 `資訊`, 然後是帶價格跟資源圖示的 `升級`. 差別是:

- **升級是交叉付款的**: 儲金罐要 **80 萬聖水**, 建築大師大本營要 **224 萬金幣** (同一天讀的, 只說明誰付哪一種, 價格每次照選單讀). 讀選單上的圖示, 不要看建築的顏色猜
- **藍色底板照樣是花寶石的**: 儲金罐選單上的 `填滿` 就坐在藍色底板上
- **工人總數跟主村不一樣, 而且會隨帳號成長, 不要背**
- **只有金幣跟聖水**. 剩多少跑 `uv run ai_coc stock`; 拿圖去 `ai_coc read` 的時候看 `builder_stock` 而不是 `stock` (後者第三個數字是寶石條誤讀的), `world` 欄位說該信哪一個

## 原語

`ai_coc` 沒有「點這裡然後給我看」這種指令, 這個 skill 自己帶一個:

```bash
uv run python .agents/skills/spend-loot/scripts/eye.py shot <out.png>
uv run python .agents/skills/spend-loot/scripts/eye.py tap <x,y> <out.png>
uv run python .agents/skills/spend-loot/scripts/eye.py zoom <in.png> <l,t,r,b> <out.png>
```

`tap` 點完會等選單滑出來再截. `zoom` 不碰遊戲, 只把存下來的圖裁一塊放大; **這步不要省**, 整張 1600x900 裡一棟建築只剩幾十像素. 四個數字是**原圖的像素座標**, 左上右下. 它會印出放大倍率: 放大圖上量到的位置要除以倍率再加回裁切框的左上角, 才是可以拿去 `tap` 的座標, 算錯就點到隔壁那棟.

**遊戲沒開不用管**, 腳本走 `commands._controller()`, 它會自己 `ensure_coc`. **但它不碰 `state.json`, 迴圈在跑的時候 `tap` 會跟迴圈搶同一個畫面**: 先用會 claim 的指令借到模擬器再用, 做法在 `running.md` 的「你自己要用畫面」.

## 找

1. `shot` 一張村莊畫面
2. 讀進來看. 認不出來就 `zoom` 分區放大, 一次一塊
3. 挑出候選, 記下座標

**第一張拍到的不一定是村莊.** 上一次留下的選單要關就 `tap` 一塊空地 (畫面邊緣的樹林或水面), **不要按 back**: 在村莊上按 back 會跳出「確定退出遊戲嗎」, 它的綠色「確定」跟升級的確認鍵長得一樣, 位置也一樣. 畫面是戰鬥或某個全螢幕頁面的話, 停下來告訴使用者, 不要亂點.

**縮小範圍靠位置跟關係, 不靠長相**, 因為每一級都會重畫建築:

- **採集器在村莊最外圈**, 頭上浮著收集標記 (金幣 / 紫水滴 / 黑泡泡), 跟同名的儲存罐是不同的東西
- **儲存罐體積大一號, 成排擺在一起**, 通常在防禦圈裡面
- **大本營是全村最大最顯眼的那棟**, 只有一棟
- **正在升級的建築頭上有綠色進度條跟剩餘時間**, 點開也沒有升級按鈕
- **牆是連成線的格子**
- **浮在建築上方的標籤不是建築** (「請求增援」是部落城堡的, 「已滿!」是某樣東西滿了), 別把標籤的座標當成建築的座標

**這一步不要猜到底**: 放大兩三塊還認不出來, 就點一個最像的看選單標題, 點錯只花一次截圖. **還認不出來就問使用者**, 他認得自己的村莊.

**村莊的下面三分之一最值得你看**: `_sweep` 的網格最下面一列停在 y 500 (`hero` 第二趟錯開的網格到 y 560), Gemini 回的點低於 y 620 也會被丟掉 (`SWEEP_LIMIT`, 那裡是上一次選取留下的按鈕列), 指令到不了.

**重開遊戲或模擬器之後, 之前記下的每一個座標都作廢**, 重新截一張重新找. **指令自己的鏡頭不用你操心**: `ai_coc launch` 每一種 `--restart` 最後都走 `_settle_game` 把鏡頭拉遠並停好, `walls` / `upgrade` / `hero` 每次開跑也先用 `_settle_zoom` 停一次. 只有不是透過 `ai_coc launch` 重開的 (譬如自己去 MuMu 按重啟) 要先跑 `uv run ai_coc view --zoom out`; 它只在畫面確實是村莊時才停鏡頭, `--zoom in` 只縮放不定位. 要拿去給 `--at` 的那張另有規矩, 見「三個入口」.

**剛載入的遊戲, 資源數字是會動的**: 儲量條從 0 跑上去要幾秒, 中途讀到的是假的, 要拿它做決定就等畫面靜下來再讀一次.

## 點開, 然後確認點對了

```bash
uv run python .agents/skills/spend-loot/scripts/eye.py tap 1157,500 pick.png
```

**選單標題會寫建築名稱跟等級**, 像「儲金罐(14級)」「英雄殿堂(10級)」. 這是驗證的唯一可靠依據, 每次點完都讀一次標題再往下走.

**點錯很正常, 建築會重疊**: 一個座標壓在兩棟上時, 連點會在它們之間輪替 (`ui/hero.py` 的 `AT_TRIES` 就是為這件事存在的). 點錯就再點一次同一個點, 或者偏移個二三十像素.

## 按下去

按鈕列裡的「升級」寫著價格跟資源圖示. 點它, 通常跳出全螢幕確認頁 (「將金礦升至10級？」) 帶綠色的「確認」, 城牆是一個小對話框. 點下去, 然後**再截一張看資源真的少了**: 被遊戲吞掉的點擊沒有任何提示, 光看對話框關掉分不出來.

**價格是紅色代表買不起, 但數字本身是對的**, 照樣讀出來回報. 只是不要點下去: 遊戲會照樣讓你點, 然後給你寶石購買畫面.

**有價格也不等於按得下去**: 被英雄殿堂等級卡住的英雄照樣讀得出價格, 但按鈕底盤是純灰, 按下去不會升級, 遊戲只跳一行紅字要你先升英雄殿堂; `hero --upgrade` 這時候回 `HeroReport.outcome` 是 `button_dead`, 那是要先把殿堂升上去.

**絕對不要點的兩個東西, 它們都長得像正常按鈕:**

- **藍色底盤的按鈕**: 花寶石或魔法物品的 (加速所有同類項目, 城牆之戒). 這個專案的寶石在結構上就碰不到, 你也一樣
- **綠色的寶石數字**, 畫面右上角那個, 以及任何確認頁上寫著寶石的按鈕. 英雄殿堂裡「立即完成」佔的正好是「升級」的位置, 旁邊的數字是寶石

確認頁上要的是寶石而不是資源, 就退出來, 告訴使用者為什麼.

## 收尾: 把選單關掉

**不管有沒有升級, 走之前都要讓畫面回到乾淨的村莊**: 普通的建築選單 `tap` 一塊空地, 再截一張確認. 全螢幕的頁面 (確認頁, 兵營, 實驗室一類) 點空地關不掉, 它蓋住倉庫條, 下一個迴圈讀不到就開始按 back 繞路回家; 這種跑一次 `uv run ai_coc stock`, 它讀不到村莊時走 `uncovered`, 只在不是村莊也不是戰鬥的畫面上按 back, 順便把花完之後的倉庫讀回來.

## 花完了就回去打

**從 `farm` 那一圈接過來的, 做完就回 `farm`**: 空的倉庫可以再打滿, 而他開口要花的那一趟, 要的是打到花不掉為止, 不是打到滿為止. 這個圈**沒有寫在程式碼裡**: `ai_coc attack --repeat 0` 倉庫一滿就結束, 交接是你在做的. 他直接叫你升某一樣東西的那一趟沒有這一步, 交回報就好; 從背景那輪借來的模擬器照樣 `giveback`.

**真的花不掉的時候才停手通知使用者.** `walls` 回 `cannot_afford` 或 `bought` 是花完了, 不是花不掉. 三種卡法 (工人全忙 / 牆被大本營卡住 / 黑水只有英雄能消化) 各自的下一步在 `farm` 的「倉庫滿了」那節.
