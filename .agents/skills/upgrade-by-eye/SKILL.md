# upgrade-by-eye

在村莊裡找到一樣東西並且升級它. 找的部分靠眼睛, 不靠腳本.

## 為什麼不用腳本找

`ui/runner.py` 的 `_sweep` 是這個專案裡唯一一個「在村莊上找東西」的機制, 它的做法是
在畫面上鋪一個 160x120 的網格, 每一格點下去, 看開出什麼選單. 建築只有 70 到 120 px
寬, 所以格點之間本來就漏得過去 —— `CLAUDE.md` 自己記著英雄殿堂離最近的格點 86 px,
整整兩趟掃描從它旁邊走過去沒點到, 後來才補上「錯開半格再掃一遍」的第二趟.

那不是精準, 那是撒兩次網. 實測: 找一次英雄殿堂花了兩分半, 中間點開又退出十幾個
不相干的建築; 同一個村莊用眼睛找儲金罐, 第一次點就中.

**腳本不得已這樣做, 是因為它沒有視覺.** 專案的規矩是「讀遊戲畫在上面的 UI, 不讀
底下的美術」, 因為每一級都會重畫建築, 模板比對認不出來. 那條規矩約束的是判讀器,
不是你. 「這棟是儲金罐」是看一眼就知道的事, 而且遊戲還會把答案寫在選單標題上.

所以分工是: **要跑幾百次的重複動作交給腳本, 一次性的辨認交給眼睛.**

## 原語

`ai_coc` 沒有「點這裡然後給我看」這種指令, 每個都是一整套迴圈. 這個 skill 自己帶
一個:

```bash
uv run python .agents/skills/upgrade-by-eye/scripts/eye.py shot <out.png>
uv run python .agents/skills/upgrade-by-eye/scripts/eye.py tap <x,y> <out.png>
uv run python .agents/skills/upgrade-by-eye/scripts/eye.py zoom <in.png> <l,t,r,b> <out.png>
```

`tap` 點完會等選單滑出來再截.

`zoom` 不碰遊戲, 只是把存下來的圖裁一塊放大 —— 1600x900 整張讀進對話裡, 一棟建築
只剩幾十像素, 不放大認不出來, 這步不要省. 四個數字是**原圖的像素座標**, 左上右下.
畫面永遠是 1600x900. 它會印出放大倍率, **記下來**: 在放大圖上量到的位置要除以倍率
再加回裁切框的左上角, 才是可以拿去 `tap` 的座標. 這個換算是整個流程的核心動作,
算錯就點到隔壁那棟.

**遊戲沒開不用管**, 腳本走 `commands._controller()`, 它會自己 `ensure_coc`.

**每一張你看過的圖都發一份給使用者.** 這個 skill 從頭到尾就是在看圖, 而使用者看不到你的工具輸出 —— 你說「這棟是儲金罐」的時候, 他要能看到你看到的那張才判斷得出你有沒有看錯. 用檔案傳送機制發出去, 不要只留路徑.

## 花得掉才按, 但看不用錢

**這兩個條件只擋最後那一次點擊, 不擋前面任何一步.** 找到目標跟讀出它的價格都不花
任何東西, 而價格是點開選單才看得到的 —— 所以工人是 0/5 也照樣走完整條流程, 停在
「升級要多少」那裡回報, 那本身就是使用者要的答案. 一開頭就因為沒工人收工, 等於
把唯一能帶回去的資訊也丟掉了.

**工人.** `uv run ai_coc builders` 說閒著幾個, 以及最快的一個還要多久. 城牆以外的
每一種升級都要一個工人. 城牆不佔工人, 但遊戲一樣會在工人全忙的時候把整批退掉 ——
一片牆跟八片牆一樣退, 所以那不是批次大小的問題, 詳見 `CLAUDE.md` 的 wall loop 那段.

**錢.** 截一張主村畫面, 右上角三條就是金幣 / 聖水 / 黑水. 或者 `uv run ai_coc read <png>` 讀 `stock`.

**先讀還是邊做邊讀都可以**, 只要在按下升級之前這兩個數字是新的. 使用者只是問
「那東西多少錢」的時候, 這一節整段跳過.

## 找

1. `shot` 一張主村畫面
2. 讀進來看. 認不出來就 `zoom` 分區放大, 一次一塊
3. 挑出候選, 記下座標

**第一張拍到的不一定是村莊.** 上一次跑留下的選單可能還開著. 選單要關掉就 `tap`
一塊空地 (畫面邊緣的樹林或水面), **不要按 back** —— 在村莊上按 back 跳出來的是
「確定退出遊戲嗎」, 那個對話框的綠色「確定」跟升級的確認鍵長得一模一樣, 在同樣的
位置. 如果畫面根本不是村莊而是戰鬥或某個全螢幕頁面, 停下來告訴使用者, 不要亂點.

**縮小範圍的線索, 全都是位置跟關係, 不是長相.** 每一級都會重畫建築, 所以記住某樣
東西長什麼樣一定會過期, 但這些不會:

- **採集器在村莊最外圈**, 而且頭上浮著收集標記 (金幣 / 紫水滴 / 黑泡泡). 金礦,
    聖水收集器, 黑水鑽井都在那一圈, 它們跟同名的儲存罐是不同的東西
- **儲存罐體積大一號, 而且成排擺在一起**, 通常在防禦圈裡面
- **大本營是全村最大最顯眼的那棟**, 而且只有一棟
- **正在升級的建築頭上有一條綠色進度條跟剩餘時間**. 那些點開也沒有升級按鈕
- **牆是連成線的格子**, 認不錯
- **浮在建築上方的標籤是提示不是建築** ——「請求增援」是部落城堡的, 「已滿!」是
    某樣東西滿了. 它們會蓋住底下的東西, 別把標籤的座標當成建築的座標

**這一步不要猜到底.** 放大兩三塊還認不出來, 直接點一個最像的看選單 —— 點錯的代價
只是一次截圖, 比繼續盯著圖猜便宜得多. 遊戲會把答案寫在選單標題上.

**認不出來就問使用者.** 他認得自己的村莊, 而且一張縮圖就講完了. 這比放大十塊區域
快, 也比點錯五次誠實.

**村莊下緣可能被卡片列擋住.** 遊戲已經在最遠的鏡頭 (`ai_coc view --zoom out` 是回到
那個位置, 不能再拉遠), 所以底下那一條真的看不到. 要看得先拖鏡頭, 而拖完之後所有
座標都變了, 前面存的圖就不能用了.

**重開之後鏡頭還會拉近**, 所以連比例都不一樣了, 不只是位置偏掉. `uv run ai_coc view --zoom out` 是回到所有座標量測時的那個視野, 拉過頭沒有副作用, 所以重開過就先跑一次
再開始找.

**重開遊戲或模擬器之後, 之前記下來的每一個座標都作廢.** 實測: 一次
`launch --restart emulator` 之後村莊整個偏到畫面右下, 幾分鐘前還能一次點中儲金罐的
(1157, 500) 變成一片空地. 遊戲不保證回到同一個鏡頭位置, 而且沒有指令可以把村莊挪
回正中間 —— 只有進攻迴圈自己會在戰鬥畫面上校正鏡頭, 村莊畫面不會. 所以重開過就
重新截一張重新找, 不要拿舊座標賭.

**剛載入的遊戲, 右上角那三個資源數字是會動的.** 儲量條從 0 跑上去要幾秒, 中途讀到
的是假的: 同一次重啟實測讀到 12.4M 金幣, 而真正的值是 19.7M. 要拿資源數字做決定
(算留多少, 判斷買不買得起) 就等畫面靜下來再讀一次, 不然會以為村莊被洗了.

## 點開, 然後確認點對了

```bash
uv run python .../eye.py tap 1157,500 pick.png
```

**選單標題會寫建築名稱跟等級**, 像「儲金罐(14級)」「英雄殿堂(10級)」. 這是驗證的
唯一可靠依據, 而且它是中文 —— 這正是腳本做不到而你做得到的那件事. 每次點完都讀
一次標題再往下走.

**點錯很正常, 建築會重疊.** 一個座標壓在兩棟建築上的時候, 連續點會在它們之間輪替:
實測在 (990, 430) 連點三次, 依序開出英雄殿堂, 旁邊的箭塔, 又是英雄殿堂. 所以點錯
就再點一次同一個點, 或者偏移個二三十像素. `ui/hero.py` 的 `AT_TRIES` 就是為這件事
存在的.

## 按之前先想: 多的資源要不要先花掉

**工人全忙的時候刷不了牆, 所以倉庫會一直卡在滿的**, 而那是雙重浪費: 打回來的資源
進不了滿倉直接被丟掉, 偏偏牆這個唯一不佔工人的出口這時候也用不了。所以工人一放出
來, 第一件事往往不是升級, 是**先把多餘的資源刷成牆**, 只留下剛好夠付眼前這幾個
升級的量, 然後才去按升級。

1. 每個目標各點開一次, 把價格讀出來
2. 加總, 那是要留下來的
3. 多的拿去 `uv run ai_coc walls --keep-gold <留這麼多> --keep-elixir <留這麼多>`
4. 回來按升級

**順序不能顛倒.** 先升級的話, 扣完錢剩下的多半湊不滿一批牆, 而且從升級到刷牆之間
倉庫還是滿的, 那段時間打回來的照樣被丟掉。

**牆吃金幣跟聖水, 不吃黑水.** 所以黑水的目標 (英雄幾乎都是) 不用留也花不掉 ——
黑水滿了就是滿了, 只有升英雄能消化它。

## 升級

選單下方那排按鈕裡有一個「升級」, 上面寫著價格跟資源圖示. 點它, 通常會跳出一個
全螢幕的確認頁 (「將金礦升至10級？」), 上面有綠色的「確認」; 城牆是一個小對話框.
點下去, 然後**再截一張看資源真的少了** —— 被遊戲吞掉的點擊不會有任何提示, 光看
對話框關掉是分不出來的. 這個專案裡每一個花錢的迴圈都是這樣驗的.

**價格是紅色代表買不起, 但那個數字本身是對的.** 紅色是遊戲在說「你現在付不出來」,
不是在說這個數字有問題 —— 照樣讀出來回報, 那往往正是使用者要的答案. 紅色改變的
只有一件事: 不要點下去, 因為遊戲照樣讓你點, 然後給你一個寶石購買畫面.

**絕對不要點的兩個東西, 它們都長得像正常按鈕:**

- **藍色底盤的按鈕**. 那是花寶石或魔法物品的 (加速所有同類項目, 城牆之戒). 這個
    專案的授權原則是寶石在結構上就碰不到, 你也一樣
- **綠色的寶石數字**, 畫面右上角那個, 以及任何確認頁上寫著寶石的按鈕

看到確認頁上要的是寶石而不是資源, 退出來, 告訴使用者為什麼.

## 收尾: 把選單關掉

**不管有沒有升級, 走之前都要讓畫面回到乾淨的村莊.** 方法跟上面一樣, `tap` 一塊
空地, 然後截一張確認. 這不是禮貌問題: 留在畫面上的選單會蓋住村莊中間, 下一個
跑起來的迴圈第一件事就是讀倉庫條, 讀不到就開始按 back 找路回家, 而 back 在村莊上
會叫出「確定退出遊戲嗎」. 你省下的一次點擊, 下一個人要花好幾十秒繞出來.

## 三種目標

**建築**: 全程照上面走. `ai_coc upgrade` 幫不上忙 —— 它挑的是「最貴而且買得起的」,
沒有辦法指定是哪一棟, 也沒有 `--at`.

**城牆**: 找到一面牆之後, 把座標交給 `uv run ai_coc walls --at <x>,<y>`, 它會從那裡
開始一批一批買下去. 這是腳本該做的事: 買幾十片牆是重複動作, 而且它讀價格比你可靠.
你省掉的是它開場那趟掃描. 城牆的按鈕列是從畫面中間往外排的, 位置會隨按鈕數量整個
平移, 所以不要自己去點城牆選單上的東西, 交給 `walls`.

**英雄**: `uv run ai_coc hero` 讀得到六個英雄各自的下一級價格, 而且它靠卡片橫幅的
純色辨識, 那是 UI 不是美術, 可靠. 要升就 `--upgrade <hero>`. 你的眼睛在這裡的用處
是省掉找英雄殿堂那趟掃描: 找到殿堂之後給 `--at <x>,<y>`. 正在升級中的英雄沒有價格,
`hero` 會報成「升級中」.

## 回報

一句話講完就好: 升了什麼, 花了多少, 現在剩多少. 沒升成的話講清楚是卡在工人, 卡在
錢, 還是找不到東西 —— 這三種使用者的下一步完全不同.

**不要編數字.** 花了多少以升級前後兩次讀到的倉庫差額為準, 不是選單上的標價 ——
兩者不一樣就是有事發生, 那本身就是要回報的資訊.
