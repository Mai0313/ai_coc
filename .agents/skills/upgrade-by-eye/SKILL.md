# upgrade-by-eye

在村莊裡找到一樣東西並且升級它. 找的部分靠眼睛, 不靠腳本.

## 為什麼不用腳本找

`ui/runner.py` 的 `_sweep` 是這個專案裡唯一一個「在村莊上找東西」的機制, 它的做法是
在畫面上鋪一個 160x120 的網格, 每一格點下去, 看開出什麼選單. 建築只有 70 到 120 px
寬, 所以格點之間本來就漏得過去 —— `CLAUDE.md` 自己記著英雄殿堂離最近的格點 86 px,
整整兩趟掃描從它旁邊走過去沒點到, 後來才補上「錯開半格再掃一遍」的第二趟.

那不是精準, 那是撒兩次網. 實測: 找一次英雄殿堂花了兩分半, 中間點開又退出十幾個
不相干的建築; 同一個村莊用眼睛找儲金罐, 第一次點就中.

**腳本不得已這樣做, 是因為它沒有視覺.** 專案的規矩是「讀遊戲畫在上面的 UI, 不讀
底下的美術」, 因為每一級都會重畫建築, 模板比對認不出來. 那條規矩約束的是判讀器,
不是你. 「這棟是儲金罐」是看一眼就知道的事, 而且遊戲還會把答案寫在選單標題上.

所以分工是: **要跑幾百次的重複動作交給腳本, 一次性的辨認交給眼睛.**

## 先確認自己站在哪個村莊

這個遊戲有兩張地圖, 日世界 (主村) 跟夜世界 (建築大師基地), 而**遊戲會開在上次離開的那一個**. 兩邊的建築完全不同名也不同用, 所以「找儲金罐」在錯的村莊上是找不到而不是找錯, 而你會花好幾張截圖才發現.

第一張截圖下去之前先問一句, 它不動畫面也不點東西:

```bash
uv run ai_coc world                       # 回 day / night
uv run ai_coc world --go day              # 切過去, 已經在那邊就什麼都不做
```

看圖也分得出來: 主村是白天的草地, 夜世界是夜晚的深色岩地, 而且畫面最上面那排面板主村有三格 (增益, 工人, 護盾), 夜世界只有兩格. 但用指令問比用眼睛猜快, 而且它是同一個判讀器.

**不指定世界的指令做的是當下所在的那一個, 不會自己切.** 使用者說「升級儲金罐」的時候心裡想的通常是主村, 但遊戲可能停在夜世界, 所以先問一次再動手.

## 夜世界怎麼升級

**這個 skill 是夜世界唯一的升級手段.** `ai_coc upgrade` / `hero` / `walls` 全部只做日世界 —— 它們在夜世界不會做錯事 (`_home` 發現站錯會自己坐船回主村), 但也什麼都不會做. 所以那邊只能靠眼睛.

好消息是**方法完全不用改, 而且比主村還好用**:

- **整個基地一眼看得完.** 拉到最遠的時候所有建築擠在畫面中間大約 x 520 到 1080, y 170 到 540 的一塊裡, 不用拖鏡頭, 也沒有主村那個「下面三分之一掃不到」的問題
- **選單長得一模一樣**: 標題寫建築名稱跟等級, 下面一排按鈕左起是 `資訊`, 然後是 `升級` 帶著價格跟資源圖示, 再來才是那棟建築自己的東西. 價格是紅色就是買不起, 跟主村同一套

要注意的差別有四個, 都是實測的:

- **升級是交叉付款的.** 主村的建築多半用自己那種資源升級, 夜世界不是: 儲金罐要 **80 萬聖水**, 建築大師大本營要 **224 萬金幣**. 所以不要看到金色建築就以為它吃金幣, 讀選單上的圖示
- **藍色底板那條規則照樣適用.** 儲金罐選單上的 `填滿` 就坐在藍色底板上, 那是花寶石的. `CLAUDE.md` 搜 `blue plate`
- **工人是 0/3 不是 0/5**, 而且 `ai_coc builders` 讀的是主村的工人面板, 在夜世界回 `null`. 要知道工人忙不忙只能看畫面最上面那格
- **只有金幣跟聖水兩種資源**, 沒有黑水. `ai_coc read` 的 `stock` 欄位在那邊第三個數字是寶石被誤讀的, 不能用; 要讀夜世界的儲量用 `read_builder_stock`

**點一下儲量條可以看到容量.** 遊戲會跳一個小框寫 `最大儲存量` 跟 `每小時產量` —— 實測這個基地是金幣 2 050 000 / 聖水 2 450 000, 主村是金幣跟聖水各 24 000 000 / 黑水 370 000. 那是判斷「還差多少才滿」最快的方法, 兩個世界都有效. 那個小框是 toggle: 點一下開, 再點一下關, 而且開著的時候點任何一條都只是把它關掉. 進攻迴圈就是這樣讀的, 判讀器是 `storage_capacity(png, row)`; 夜世界第三排不要點, 那是寶石而且旁邊的綠色 `+` 會開商店.

## 原語

`ai_coc` 沒有「點這裡然後給我看」這種指令, 每個都是一整套迴圈. 這個 skill 自己帶
一個:

```bash
uv run python .agents/skills/upgrade-by-eye/scripts/eye.py shot <out.png>
uv run python .agents/skills/upgrade-by-eye/scripts/eye.py tap <x,y> <out.png>
uv run python .agents/skills/upgrade-by-eye/scripts/eye.py zoom <in.png> <l,t,r,b> <out.png>
```

`tap` 點完會等選單滑出來再截.

`zoom` 不碰遊戲, 只是把存下來的圖裁一塊放大 —— 1600x900 整張讀進對話裡, 一棟建築
只剩幾十像素, 不放大認不出來, 這步不要省. 四個數字是**原圖的像素座標**, 左上右下.
畫面永遠是 1600x900. 它會印出放大倍率, **記下來**: 在放大圖上量到的位置要除以倍率
再加回裁切框的左上角, 才是可以拿去 `tap` 的座標. 這個換算是整個流程的核心動作,
算錯就點到隔壁那棟.

**遊戲沒開不用管**, 腳本走 `commands._controller()`, 它會自己 `ensure_coc`.

**每一張你看過的圖都發一份給使用者.** 這個 skill 從頭到尾就是在看圖, 而使用者看不到你的工具輸出 —— 你說「這棟是儲金罐」的時候, 他要能看到你看到的那張才判斷得出你有沒有看錯. 用檔案傳送機制發出去, 不要只留路徑.

## 花得掉才按, 但看不用錢

**這兩個條件只擋最後那一次點擊, 不擋前面任何一步.** 找到目標跟讀出它的價格都不花
任何東西, 而價格是點開選單才看得到的 —— 所以工人是 0/5 也照樣走完整條流程, 停在
「升級要多少」那裡回報, 那本身就是使用者要的答案. 一開頭就因為沒工人收工, 等於
把唯一能帶回去的資訊也丟掉了.

**工人.** `uv run ai_coc builders` 說閒著幾個, 以及最快的一個還要多久. 城牆以外的
每一種升級都要一個工人, 城牆也不例外. 差別只在城牆付錢的當下就升好, 工人立刻還
回來, 所以有一個閒著就能連續買一整排, 而工人 `0/N` 的時候一片都買不了. 詳見
`CLAUDE.md` 的 wall loop 那段.

**錢.** 截一張主村畫面, 右上角三條就是金幣 / 聖水 / 黑水. 或者 `uv run ai_coc read <png>` 讀 `stock`.

**先讀還是邊做邊讀都可以**, 只要在按下升級之前這兩個數字是新的. 使用者只是問
「那東西多少錢」的時候, 這一節整段跳過.

## 找

1. `shot` 一張主村畫面
2. 讀進來看. 認不出來就 `zoom` 分區放大, 一次一塊
3. 挑出候選, 記下座標

**第一張拍到的不一定是村莊.** 上一次跑留下的選單可能還開著. 選單要關掉就 `tap`
一塊空地 (畫面邊緣的樹林或水面), **不要按 back** —— 在村莊上按 back 跳出來的是
「確定退出遊戲嗎」, 那個對話框的綠色「確定」跟升級的確認鍵長得一模一樣, 在同樣的
位置. 如果畫面根本不是村莊而是戰鬥或某個全螢幕頁面, 停下來告訴使用者, 不要亂點.

**縮小範圍的線索, 全都是位置跟關係, 不是長相.** 每一級都會重畫建築, 所以記住某樣
東西長什麼樣一定會過期, 但這些不會:

- **採集器在村莊最外圈**, 而且頭上浮著收集標記 (金幣 / 紫水滴 / 黑泡泡). 金礦,
    聖水收集器, 黑水鑽井都在那一圈, 它們跟同名的儲存罐是不同的東西
- **儲存罐體積大一號, 而且成排擺在一起**, 通常在防禦圈裡面
- **大本營是全村最大最顯眼的那棟**, 而且只有一棟
- **正在升級的建築頭上有一條綠色進度條跟剩餘時間**. 那些點開也沒有升級按鈕
- **牆是連成線的格子**, 認不錯
- **浮在建築上方的標籤是提示不是建築** ——「請求增援」是部落城堡的, 「已滿!」是
    某樣東西滿了. 它們會蓋住底下的東西, 別把標籤的座標當成建築的座標

**這一步不要猜到底.** 放大兩三塊還認不出來, 直接點一個最像的看選單 —— 點錯的代價
只是一次截圖, 比繼續盯著圖猜便宜得多. 遊戲會把答案寫在選單標題上.

**認不出來就問使用者.** 他認得自己的村莊, 而且一張縮圖就講完了. 這比放大十塊區域
快, 也比點錯五次誠實.

**村莊下緣正好是腳本掃不到而你看得到的地方.** 卡片列是戰鬥畫面的東西, 村莊畫面上
根本沒有那一列; 底下那一排是攻擊, 商店那些常駐按鈕, 下緣的建築本身看得一清二楚.
掃不到是腳本自己的限制: `_sweep` 的網格最下面一列停在 y 500 (`SWEEP_Y`), 再往下的
格點直接跳過 (`SWEEP_LIMIT` 的 620), 因為一格點下去開出來的按鈕列會蓋住螢幕下緣,
繼續往下點就是在按上一次點擊自己的按鈕. `CLAUDE.md` 的說法是村莊的下面三分之一
沒有任何一趟掃描到得了 —— 所以那一帶不是這個 skill 的死角, 是它最有價值的地方.

**重開遊戲或模擬器之後, 之前記下來的每一個座標都作廢.** 實測: 一次
`launch --restart emulator` 之後村莊整個偏到畫面右下, 幾分鐘前還能一次點中儲金罐的
(1157, 500) 變成一片空地. 所以重開過就重新截一張重新找, 不要拿舊座標賭.

**但鏡頭不用你操心, `ai_coc launch` 收尾就擺好了.** 每一種 `--restart` 最後都走
`_settle_game`: 輪詢到村莊真的畫出來, 然後 pinch 拉遠, `LaunchReport.at_village` 就是
它到底有沒有走到的回報欄位. 而**拉到最遠順便就把村莊帶回中央** —— 地圖會在自己的
邊緣把鏡頭夾住, 所以在最遠的 zoom 村莊自己填滿畫面, 中心落在螢幕中心 20 px 以內,
不需要先「找到村莊」才擺得正. 村莊畫面上也一直在校正: `GameRunner._settle_zoom` 掛
在 `_home` 讀到的第一張村莊上, 所以 `walls`, `collect`, `upgrade`, `hero`, `donate`
每一個動手之前都先把鏡頭拉回去. 要自己補一次的只有一種情況 —— 不是透過
`ai_coc launch` 重開的 (譬如自己去 MuMu 按重啟), 那就先跑
`uv run ai_coc view --zoom out`, 它送的是同一個 pinch, 拉過頭沒有副作用.

**剛載入的遊戲, 右上角那三個資源數字是會動的.** 儲量條從 0 跑上去要幾秒, 中途讀到
的是假的: 同一次重啟實測讀到 12.4M 金幣, 而真正的值是 19.7M. 要拿資源數字做決定
(算留多少, 判斷買不買得起) 就等畫面靜下來再讀一次, 不然會以為村莊被洗了.

## 點開, 然後確認點對了

```bash
uv run python .../eye.py tap 1157,500 pick.png
```

**選單標題會寫建築名稱跟等級**, 像「儲金罐(14級)」「英雄殿堂(10級)」. 這是驗證的
唯一可靠依據, 而且它是中文 —— 這正是腳本做不到而你做得到的那件事. 每次點完都讀
一次標題再往下走.

**點錯很正常, 建築會重疊.** 一個座標壓在兩棟建築上的時候, 連續點會在它們之間輪替:
實測在 (990, 430) 連點三次, 依序開出英雄殿堂, 旁邊的箭塔, 又是英雄殿堂. 所以點錯
就再點一次同一個點, 或者偏移個二三十像素. `ui/hero.py` 的 `AT_TRIES` 就是為這件事
存在的.

## 按之前先想: 多的資源要不要先花掉

**工人全忙的時候刷不了牆, 所以倉庫會一直卡在滿的**, 而那是雙重浪費: 打回來的資源
進不了滿倉直接被丟掉, 偏偏牆這個唯一不佔工人的出口這時候也用不了。所以工人一放出
來, 第一件事往往不是升級, 是**先把多餘的資源刷成牆**, 只留下剛好夠付眼前這幾個
升級的量, 然後才去按升級。

1. 每個目標各點開一次, 把價格讀出來
2. 加總, 那是要留下來的
3. 多的拿去 `uv run ai_coc walls --keep-gold <留這麼多> --keep-elixir <留這麼多>`
4. 回來按升級

**順序不能顛倒.** 先升級的話, 扣完錢剩下的多半湊不滿一批牆, 而且從升級到刷牆之間
倉庫還是滿的, 那段時間打回來的照樣被丟掉。

**`walls` 回報「每一個位置都沒有買成」不是牆刷完了, 是城牆被大本營等級卡住了.**
實測在大本營 15 級的村莊, 全村的牆都到頂升不動, 每一批確認下去都開出一張叫你先把
大本營升上去的頁面, 一趟花掉約兩分鐘而一片牆都沒買到. 那句話讀起來像「牆刷完了」,
之前就被誤讀過一次. 讀到它就代表多出來的金幣跟聖水現在沒有出口, 上面那整套順序不
成立, 第 3 步跳過, 直接去升建築.

**牆吃金幣跟聖水, 不吃黑水.** 所以黑水的目標 (英雄幾乎都是) 不用留也花不掉 ——
黑水滿了就是滿了, 只有升英雄能消化它。

## 升級

選單下方那排按鈕裡有一個「升級」, 上面寫著價格跟資源圖示. 點它, 通常會跳出一個
全螢幕的確認頁 (「將金礦升至10級？」), 上面有綠色的「確認」; 城牆是一個小對話框.
點下去, 然後**再截一張看資源真的少了** —— 被遊戲吞掉的點擊不會有任何提示, 光看
對話框關掉是分不出來的. 這個專案裡每一個花錢的迴圈都是這樣驗的.

**價格是紅色代表買不起, 但那個數字本身是對的.** 紅色是遊戲在說「你現在付不出來」,
不是在說這個數字有問題 —— 照樣讀出來回報, 那往往正是使用者要的答案. 紅色改變的
只有一件事: 不要點下去, 因為遊戲照樣讓你點, 然後給你一個寶石購買畫面.

**絕對不要點的兩個東西, 它們都長得像正常按鈕:**

- **藍色底盤的按鈕**. 那是花寶石或魔法物品的 (加速所有同類項目, 城牆之戒). 這個
    專案的授權原則是寶石在結構上就碰不到, 你也一樣
- **綠色的寶石數字**, 畫面右上角那個, 以及任何確認頁上寫著寶石的按鈕

看到確認頁上要的是寶石而不是資源, 退出來, 告訴使用者為什麼.

## 收尾: 把選單關掉

**不管有沒有升級, 走之前都要讓畫面回到乾淨的村莊.** 方法跟上面一樣, `tap` 一塊
空地, 然後截一張確認. 這不是禮貌問題: 留在畫面上的選單會蓋住村莊中間, 下一個
跑起來的迴圈第一件事就是讀倉庫條, 讀不到就開始按 back 找路回家, 而 back 在村莊上
會叫出「確定退出遊戲嗎」. 你省下的一次點擊, 下一個人要花好幾十秒繞出來.

## 三種目標

**建築**: `ai_coc upgrade` 現在也會自己問 Gemini 建築在哪, 每個座標都點開驗過價格才
算數, 所以「把資源花在建築上」不用你先看圖. 它挑的是**最貴而且買得起的** —— 因為這裡
稀缺的是工人不是錢.

實測值得知道: 它問回來的 14 個點有 9 個真的有升級可以按, 而**那九個裡只有兩個落在
`_sweep` 網格點 45 px 以內**（網格停在 x 1220 / y 500, 村莊大半在格子外）. 所以這不只
是比較快, 是掃描根本到不了那些地方.

**但它還是不知道自己在升什麼.** 選單上沒有任何東西說得出建築名字, 那行中文只有你讀得
懂. 所以「幫我升儲金罐」這種指名的要求還是走下面整套: 你看圖找到它, 用 `--at <x>,<y>`
把座標交給它.

**城牆**: 你多半不用找. 不給 `--at` 的時候 `walls` 會自己問 Gemini 牆在哪, 而牆是
全村最好認的東西 —— 數量最多、長得最一致, 而且每個座標都會點開選單驗過才算數, 所以
猜錯的成本是一次點擊加一次截圖:

```bash
uv run ai_coc walls
```

**要自己挑的時機是你手上已經有一張截圖了**, 那就省掉那次 API 呼叫. 找**好幾片**便宜
的牆 —— 顏色最舊的那一種, 一片一個 `--at`:

```bash
uv run ai_coc walls --at 250,400 --at 300,430 --at 350,460
```

腳本會把每一片的價格讀出來, 挑最便宜的那片 (最便宜就是等級最低, 也就是該優先升
的), 然後一批一批買下去. 開不出城牆選單的那些會被丟掉並且說出來 —— 那代表你是在
一格已經過期的畫面上找到它的, 而任何把遊戲拉到前景的動作都會移動鏡頭.

**只給一片是最貴的用法.** `_pick` 的整個價值就在比價, 只給一個座標等於沒得比. 這條
指示以前寫的是「省掉開場那趟掃描」, 而它實際做的是「用最貴的價格買」: 實測那樣花了
9 000 000 買一片, 而同一個村莊裡站著 4 000 000 的.

**找這一段已經不是你的事了.** 以前是, 因為另一個選擇是 `_sweep` 鋪網格撞運氣; 現在
`walls` 自己會問 Gemini, 實測一個村莊 12 個座標中了 9 個, 找加驗 23 秒. 你的眼睛在
這裡剩下的用處是「手上剛好已經有截圖」跟「Gemini 找歪了要接手」這兩種情況.

**買一直都是腳本的事.** 幾十片牆是重複動作, 它讀價格比你可靠 (金幣跟聖水兩個價格
要相等才算數 —— 那也正是它辨認城牆的方式, 因為全遊戲只有牆可以用兩種資源升級),
成交與否看倉庫真的少了沒, 而且它只點從聖水滴**往左**推導出來的座標, 所以城牆之戒
跟寶石按鈕在構造上就按不到. 城牆的按鈕列是從畫面中間往外排的, 位置會隨
按鈕數量整個平移, 所以不要自己去點城牆選單上的東西, 交給 `walls`.

**英雄**: `uv run ai_coc hero` 讀得到六個英雄各自的下一級價格, 而且它靠卡片橫幅的
純色辨識, 那是 UI 不是美術, 可靠. 要升就 `--upgrade <hero>`. 找英雄殿堂它也會自己問
Gemini 了, 實測第一個猜測就開到 —— 對照組是網格第一趟會**整個跨過**這棟建築, 得跑第
二趟偏移半格的, 那是好幾分鐘. 你手上剛好有截圖的話 `--at <x>,<y>` 還是最快. 正在升級中的英雄沒有價格,
`hero` 會報成「升級中」.

**但有價格不等於按得下去.** 被英雄殿堂等級卡住的英雄, 價格照樣讀得出來, 死掉的是
按鈕: 底盤變成純灰, `--upgrade` 回的是「X 的升級按鈕是停用的，多半是英雄殿堂的等級
擋住了（要 N 資源）」. 那不是 bug, 是這一級要先把殿堂升上去, 使用者說「把飛龍公爵
升上去」拿到的就是這句話. `HeroCard.upgradable` 就是為這件事存在的, 而且它排在買不
買得起前面 —— 實測飛龍公爵 15 級要 220 000 黑水, 村莊剛好握著 220 000, 按下去什麼
都沒發生.

## 回報

一句話講完就好: 升了什麼, 花了多少, 現在剩多少. 沒升成的話講清楚是卡在工人, 卡在
錢, 還是找不到東西 —— 這三種使用者的下一步完全不同.

**不要編數字.** 花了多少以升級前後兩次讀到的倉庫差額為準, 不是選單上的標價 ——
兩者不一樣就是有事發生, 那本身就是要回報的資訊.

**花完了就回去打.** 這個 skill 被叫來多半是因為倉庫滿了, 而升級剛好把它清出空間 ——
空的倉庫是可以再打滿的, 所以做完就回 `farm`, 那邊的「什麼時候停手」那節寫了完整的
圈. 重點是**這個圈沒有寫在程式碼裡**: `ai_coc attack --repeat 0` 倉庫一滿就結束,
它不知道還有下一步, 所以交接是你在做的. 使用者要的是打到花不掉為止, 不是打到滿為止.
