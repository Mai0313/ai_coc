# 打一趟資源

給派打資源的那一邊: `takeover` 每一種要打資源的終點, 都照這一份派一趟. 迴圈交給一個 subagent, 它照同一個資料夾的 `runner.md` 跑; 這份是派它的 session 的: 開跑前的判斷、派工、回報進來怎麼判、一趟的報告. 打資源本身不花任何東西, 不改程式碼.

旗標看 `src/ai_coc/cli.py` 的 `_parser()`, 回報欄位看 `src/ai_coc/models.py` 的 `AttackReport` / `AttackSeries`, 不要憑記憶下參數. 下面的指令都省略了每個指令都要帶的 `--agent`、`--session`、`--mission` (`AGENTS.md` 的 Say who is driving).

## 開跑之前

**讀 `~/.ai_coc/config.json`** (裡面的 Gemini key 讀到也沒關係, 不用先遮掉):

- `thresholds`: 打誰的門檻, 三項都要過. 太高會一直跳過. 已經滿過 `stop_at` 的倉庫, 迴圈每一輪自己把它的門檻當 `0`, 跟收工一樣把它當成滿了
- `stop_at`: 停手的倉庫水位百分比, **主村跟夜世界共用**, 容量迴圈自己去遊戲讀. **每一項都滿過這個百分比才停**, 不是任何一項到頂就停. `0` 是永遠不收工; 讀不到容量的那一項不列入計算
- `adb_serial`: 打的是哪一台模擬器 (MuMu 或雷電), 寫 `adb devices` 列出來的名字. 空的話第一次執行會自己挑一台寫進來. **兩台登的是同一個帳號**, 一台開遊戲就把另一台踢下線, 所以只打設定的那一台, 要換台先改這一格, 不要兩台輪流開

**門檻由你定**, 每一趟開跑前看 `status` 的倉庫 (只讀得到遊戲停著的那個世界, 另一個照設定檔或上一次讀到的): 缺得最兇的那一項給門檻 (例如黑水見底就 `--min-dark` 5000 到 1 萬), 其他沒滿的看情況放寬或照設定檔, 滿的不用管. 每輪跳過幾十個就往下調. 使用者交代過的照他的. 定好的旗標寫進交辦, subagent 不會自己加或改. `0` 跟不給是兩件事 (見 `LootOverrides` 的 docstring). `--stop-at` 是**測試**用的: 對著剛打滿的村莊打一場來驗東西時給 `0`; 打資源不要用, 滿倉搶回來的進不去.

**碰模擬器之前先讀 `~/.ai_coc/state.json`** (`share-emulator` 的「開工先讀 `state.json`」). **別人已經在打資源就不開**: `emulator` 那一塊佔著的是別的 session 帶 `--yield` 的 run (`yields` 是 `true`), 或者那一塊有一筆還沒結束的借用 (`loan.ended` 是 null) 而出借的是別的 session, 或者 `watch` 那一塊是別的 session 用寫著「全天候託管」的 `--mission` 開的 (託管睡在兩趟打資源之間). 兩個帶 `--yield` 的迴圈會在指令之間輪流搶到模擬器, 各自的 `world --go` 把對方下一輪的 `attack` 帶到錯的村莊. 不派, 回報誰 (`caller`) 在跑哪一個 (`command`, `log`). 你自己的 session id 加 `-farm` 後綴的是你自己派的 subagent, 不是別人.

**這個遊戲有兩個村莊, 而遊戲會開在上次離開的那一個**: 日世界 (主村) 跟夜世界 (建築大師基地), 靠一艘船來回. `ai_coc world` 答現在在哪個世界, 不點任何東西; `ai_coc world --go day|night` 坐船切過去. **沒有指令會自己換村莊, 每一個都做遊戲當下停著的那一個**, 所以 subagent 先 `world --go` 再開 `attack`. 遊戲沒畫面時 `world` 回 `no_display`, 先 `ai_coc launch` (`share-emulator` 的「遊戲卡住, 或者根本沒開」). 開跑後對一下 `run.log` 打的是哪一邊: 每一輪開頭 `Attack run starts` 是主村, `Builder base attack run starts` 是夜世界. 兩邊容量差十倍, 打錯世界「還差多少」就全錯.

**沒特別交代就兩個世界都打完.** 不用先問哪邊有空間: 滿的世界第一輪就 `stock_full` (主村在付搜尋費前, 夜世界在進配對前), 代價只是幾秒. 他指定了一個才只打那一個. **順序: 他指定了照他的, 沒指定就先打當下所在的那個.** 「當下所在」是開跑前第一件事用 `ai_coc world` 問到的答案. 切畫面就是他指定順序的方式 (想先打夜世界他會自己切過去), 不要推翻.

**兩個世界都用平鋪, 不叫 AI**: 日世界帶 `--plan src/ai_coc/plans/flat.json`, 夜世界帶 `--plan src/ai_coc/plans/night_flat.json`. **AI 規劃留在程式裡, 不要拿掉**, 兩個世界的邏輯要一樣; 他明講要 AI 規劃的那一趟才不帶 `--plan`. 夜世界用平鋪是因為贏輸都有進帳, 挑哪一邊打差別不大, AI 規劃卻每個 stage 要 10 到 15 秒 (慢的時候 40 秒以上).

**開跑後先估時間.** 一輪抓四到五分鐘. 第一輪的 `run.log` 有現在水位 (`Village holds …`) 跟容量 (`Storage ceilings read as …`), 兩者算出到 `stop_at`% 的距離, 除以一場的平均收穫, 就是大概要跑多久. 好幾個小時就先跟使用者講一聲. 量過的速率 (TH15 / 建築大師基地 10 級左右): 主村一場約 +1.1M 金幣、+1.1M 聖水; 夜世界一場約 +100k 到 130k 金幣, 聖水進推車, 平均一場 12 萬左右, 聖水是瓶頸.

夜世界不一樣的地方:

- **沒有門檻**: 沒有偵察畫面, 贏拿金幣輸拿聖水, 沒東西好跳過
- **搜尋要等真人** (量過四秒到五分半). 搜尋中 log 不寫東西, 最久兩分半會有一行 `No opponent in 150s; cancelling and searching again`, 重搜幾次都沒配到才回 `no_opponent`
- **聖水車也算一個倉庫.** 迴圈開跑第一輪跟之後每五場去一次車子: 倉庫有空間就倒進去, 倉庫滿了就讀車上存多少. 倉庫滿了**而且**最近一次讀到車子也過同一個百分比才 `stock_full`, 所以車子剛滿之後最多還會多打四場. 同一趟看三次都讀不到車子, 就退回只看倉庫, `run.log` 前面有一行 `the storages decide alone`, 回報就不能說車子滿了. **倉庫滿了之後 `Builder base holds` 那行本來就不動** (在填聖水車), 看每五場一次的 `holding X of Y` 有沒有在長

## 派工

**迴圈交給一個 farm subagent 跑**: 在背景跑, 取一個名字讓你傳得到訊息, **模型比你低一級, 不再更低**, thinking budget 用 runtime 給得出的最低那一級. 交辦裡告訴它它是 subagent, 照 `.agents/skills/takeover/references/runner.md` 跑; 那一份是每一趟都一樣的那一半, 這一趟才有的寫進交辦. **分工是判斷對上跑腿**: subagent 是為了讓指令的輸出不進主 thread, 它又快又便宜是因為它什麼都不判斷. 要判斷的 (門檻、花不花、畫面上是什麼、一個結果算不算 bug) 都留在你這裡; 它照交辦跑, 碰到交辦以外的第一件事就回報. 所以它不花任何東西 (買東西要看建造面板), 打到 `stock_full` 就回報. **最低那一級 budget 還在試行** (#548): subagent 沒回報就停了, 或回報的跟 `state.json`、`result.json`、`runs.jsonl` 對不上, 就到那張 issue 留一則; 第二則就把 budget 調高一級. 它每個指令都帶 `--yield`, 所以 live test 是借走它而不是停掉它, 它也從不把測試請下來. **使用者在模擬器上玩, 或說過不要控制遊戲, 就一個都不派**, 他說可以之前什麼都不開.

runtime 沒有 subagent 的話, 你自己照 `runner.md` 跑; 指令照 `share-emulator` 的「背景跑」送背景, 通知進來照 `runner.md` 的「讀結果」接下一步.

**交辦**, 照這個骨架填, 每一格都寫, 沒有的寫「不要」:

```text
你是打資源的 subagent, 照 .agents/skills/takeover/references/runner.md 跑, 不載入其他 skill.
session: <你的 session id>-farm
先打: <day|night>, 再打: <另一個|不打>
日世界: attack --repeat 0 --plan src/ai_coc/plans/flat.json <門檻旗標>
夜世界: attack --repeat 0 --plan src/ai_coc/plans/night_flat.json
label 前綴: <這一趟的代號, 例如 t3>
--debug / --shot-every: <不要 | 要, 為了什麼>
終點: 兩個世界各打到 stock_full (或: 各打 N 輪)
收尾 (只在正常收工時): <world --go day | 不要>; <每個世界 stock_full 後 ai_coc capture 一張 | 不要>
暫存檔: <你的暫存資料夾路徑>
```

兩個 `--plan` 都要寫: 交辦沒寫的 `--plan` 它不會自己補, 日世界那個漏寫了, 每場就去問 AI (託管曾經漏了兩天).

**交給 subagent 的每一趟都要有終點, 不要叫它「跑到叫停為止」**: 一個被交代跑到早上的 subagent 打了 3 圈 (約 2 小時 20 分), 在一次刷牆跑完時結束了回合, 沒有回報, 之後傳給它的訊息也叫不醒, 模擬器閒了 40 分鐘才被發現; 改成每個只跑 3 圈之後, 接手的每一個都跑完回報了. 步驟之間不結束回合、每一步各自一次呼叫、跑完讀 `state.json`、被叫停就回報, 都在 `runner.md` 裡. **那一趟會跑好幾個小時的, 留一個心跳**: 背景等大約一小時 (runtime 管的那種, 等完會叫醒你), 醒來讀 `state.json` 跟最新的執行目錄. 跟上次看比沒有往前走, 又沒收到回報, 就是它默默停了: 結束掉它, 派下一個. 默默結束回合的 subagent 什麼都不會送出來, 只有心跳抓得到; 每次醒來就再開一個, 直到那一趟收工.

**要不要留畫面是你決定.** 有人要找問題 (盯著 subagent 的行為、查 bug、驗證剛修好的東西) 就開 `--debug`, 問題跟戰鬥過程有關 (兵怎麼走、法術什麼時候下) 再加 `--shot-every`, 單純打資源就不開. 圖由你看, subagent 不打開.

## 回報進來怎麼判

**一個世界打不動就先去打另一個**, 為什麼卡住不重要: 耗在那邊等於另一個整晚沒打. 看進帳斜率而不是輪數: 主村 `Village holds gold=… elixir=… dark=…`, 夜世界 `Builder base holds gold=… elixir=…`, 連續幾輪幾乎沒動就是打不動. 這種 run 不會自己結束, 所以換世界要先 `ai_coc stop emulator` (不帶 `emulator` 會連盯升級一起停), 等 subagent 回報它停了, 再照「派工」派一趟, 先打另一個世界.

**log 跟畫面都能用, 自己判斷**, log 講不清楚就截一張, 那很便宜. `run.log` 答「走到哪, 這輪結果是什麼」; 畫面答 log 答不了的: 畫面長什麼樣, 兵有沒有在打, 判讀器讀的跟眼睛看的一不一樣. 迴圈在跑的時候看 `--debug` 留下的 `frames/`: 存下的每一張, `run.log` 都有一行 `Saved frame <檔名>`, 它前後的 log 就是讀這張的那一步. 迴圈自己沒在拍才用 `ai_coc capture --count N` 或 `repair-emulator` 的 `scripts/look.py` 截 (兩個都只截圖, 不佔 `state.json`, 但存在別的地方, 時間也對不上這輪的 log). `ai_coc read <png>` 不碰模擬器, 隨時能跑, 看每個 parser 讀到什麼.

**判斷看 `result.json` 每一輪的 `AttackReport.outcome`**, 不要比對 log 的句子. 每一種是什麼在 `models.py` 的 `AttackOutcome` 上面那段註解; subagent 照 `runner.md` 決定續或停, 這裡是你要判斷的那幾種:

- `no_loot` (兵出去了而戰利品整場沒動) 是**戰術**的問題, `nothing_deployed` (一張卡都沒出去) 是**迴圈**的問題, 都歸 `watch-and-fix`, 查的地方完全不同
- `army_short`: 軍隊不到兵營的一半, 整個 series 到此為止. 造兵是即時的, 這種軍隊不會自己變好, 要人進遊戲改配置. 抓一張軍隊畫面附在回報裡
- `other_village`: 遊戲停在這一批沒在打的村莊, 多半是有人切過, 例如使用者在手機上玩

**值得警覺的樣態**, 連續幾輪才算:

- 每輪 `skipped` 都是幾十: 門檻對現在的獎盃區間太高, 調低再派
- **入庫的進帳遠小於 `attacked`**: 進攻打不動人家, 是 `watch-and-fix` 的題目, 這裡只報告. 看落差而不是 `attacked` 大不大 (它只說對手**擺出**多少)
- `The session was dropped`: 迴圈自己會點對話框的按鈕重新登入, 點了沒用才重開遊戲 (log 有 `did not clear it; restarting the game` 就是重開了). 一直重複才要查
- `waiting for the server rather than tapping`: 卡在載入畫面, 伺服器的事. 迴圈每次載入最多等 45 分鐘; 等不到的那輪是 `server_loading` 或 `server_flapping`. **不要**重開遊戲或模擬器, 量過兩次都是自己回來的. 連續兩輪都是這兩種再停下來講
- `The camera was not at the far zoom` (**只在主村**): 只是回報, 迴圈每場自己會 pinch 回去. 連著出現才去看畫面

**被搶登** (`session_taken`): 另一部裝置 (多半是他的手機, 另一台模擬器也算) 登入了這個帳號, 迴圈沒有把登入搶回來就收工. 託管裡照 `SKILL.md` 的「停」: 五分鐘後自己登入回去; 不是託管派的這一趟 (例如查問題時派的) 就停手通知他, 等他說可以. 兩種都一樣, 那之前一個 `ai_coc` 指令都不要下, `stock`、`status` 也算: 每個指令開跑時都會重新登入, 把他踢下線. 登入回去後同一個世界同一組旗標再派. 夜世界被擠掉之後有幾分鐘配不到對手, 開回去頭幾輪 `No opponent in 150s` 甚至 `no_opponent` 是這個, 不是卡住.

**其他停手的理由**: 遊戲一直回不到村莊, 同一個錯誤連續三次以上, 一輪也沒打成過, 連續三輪 `emulator_silent` (先看模擬器還活著沒有), 連續五輪 `no_attack_menu` (原因看每一輪自己的 log: 蓋住遊戲的畫面, 一直掉線, 或有人在手機上玩, 先看畫面). 這些都停下來講, 不要一直重試: 失敗要吵.

**撞到 bug 或模擬器起不來**: subagent 停下來回報哪一輪、`run.log` 的哪幾行跟執行目錄, 什麼都不改也不修. 接不接進 `watch-and-fix`、`repair-emulator` 或 `game-update` 是你判斷 (`SKILL.md` 的「停」說託管時不等他), 打資源本身不改程式碼. 交給使用者的話寫三件事: 哪一輪, `run.log` 的哪幾行, 你看到的畫面.

## 報告

**預設倉庫滿了就是終點**: 他只說「幫我打資源」的那一趟, 任務就到該打的世界都打到 `stop_at`. **不要自己接下去花**, 工人閒著或某棟很划算也一樣; 值得花就寫成選項讓他挑.

**打完不要留任何東西在背景跑**, 包括為了讓村莊「有人在線上」: 有沒有人看畫面都照樣被打, 保護村莊的是被打之後遊戲自己給的護盾. 盯升級的 `ai_coc watch` 也不是這一趟留的: 使用者要過 farm 預設留一個, 討論完自己收回 (每個在做事的 session 都會派 farm, 而一次只有一個 watch, 預設留就會把別人睡著的那個請掉), 不要再加回這裡. **交之前先確認沒有東西留在背景**, 去查而不是回想 (`AGENTS.md` 的 Check what subagents leave behind yourself); 查到 `ai_coc` 程序還在跑也不要砍它 (`share-emulator` 的「停」).

`collect` 不在流程裡跑, 他開口才跑: 收集器產出不多, 倉庫多半又是滿的收不進去; 聖水車不受影響, 進攻迴圈自己會去倒. `donate` 想跑就跑, 但只做主村. 這兩個一樣不跟迴圈同時跑, 等接縫 (換世界前, 收工前) 再跑.

**回報只回答四件事: 打完沒, 打了多少, 花多久, 現在的資源狀態.** 一句結論, 每個打了的世界一張一種資源一列的小表加一行工人, 印在對話裡, 不寫檔案, 不加章節. 講給他聽時說「打資源」, 不說「農場」.

```markdown
兩邊都打滿了, 花了 2 小時 50 分.

日世界: 2 場

| 資源 | 進帳    | 現在         |
| ---- | ------- | ------------ |
| 金幣 | +76 萬  | 2700 萬 (滿) |
| 聖水 | +87 萬  | 2700 萬 (滿) |
| 黑水 | +0.6 萬 | 44 萬 (滿)   |

工人 0/6, 最快今天 20:21 好.

夜世界: 70 場

| 資源   | 進帳    | 現在        |
| ------ | ------- | ----------- |
| 金幣   | +568 萬 | 600 萬 (滿) |
| 聖水   | +497 萬 | 510 萬 (滿) |
| 聖水車 | +37 萬  | 160 萬 (滿) |

工人最快 10/13 05:34 好.
```

- **第一行**: 打完沒, 總共花多久. 只打一個世界就講那一個
- **每個打了的世界一段**, 日世界在前: 一行「X世界: N 場」, 一張表, 一行工人. 沒打的世界不列
- **表**直接印成 markdown 表格, 不要包在程式碼區塊裡. 一種資源一列, 不加總; 夜世界沒有黑水那一列, 聖水車是它的最後一列
- **工人那一行**: 那個世界的工人最快幾點好 (收工時跑的 `ai_coc status` 表上那個世界「誰」是工人的第一列), 遊戲停著的那個世界再加閒幾個/總共幾個 (`status` 那個世界那一行的工人數) (另一個世界的計數讀不到, 不為它開船). 沒打的世界沒有那一段, 它的工人最快幾點好寫成最後一行
- 這一趟有花東西的話, 那個世界的工人那一行下面多一行: 刷了幾片牆, 升了什麼, 各花多少
- 數字用「萬」; 不到一萬的 (多半是黑水) 留一位小數
- 推播一行就好, 先講他會想動手的那件事 (「日世界打滿了, 工人全忙」比「任務完成」有用)

**數字從哪來, 量不到就寫量不到, 不要估:**

- **進帳**: 不要為了算進帳下 `ai_coc stock`. 迴圈每一輪開打前自己讀一次倉庫, 寫成 `Village holds …` (夜世界 `Builder base holds …`), 一個執行目錄的進帳是它最後一行減第一行; 被借走或換世界而重開過的, 每個目錄各算各的再加起來, 使用者在兩次之間花掉的才不會被扣成負的進帳. **兩個世界各算各的, 不准混**. 最後一行有沒有算到最後一場, 看它在不在最後一個真的開打的輪次那行 `Attack finished:` 的後面; 打到 `stock_full` 收工的一定在, 不在的少算最後一場. 一個目錄一行都沒有, 那一段寫「量不到」. 目錄已經刪了的話, 同樣的數字在 `~/.ai_coc/runs.jsonl` 那次執行每一行 `round` 的 `holding`. **不是** `AttackReport.attacked` 的加總: 那是偵察畫面上對手擺出來的可搶量
- **現在的水位**: 那個世界最後一行 `holds`; 收工時的 `ai_coc status` 讀的是同一個世界的話, 用它那一行的倉庫, 那份比較新. **倉庫讀到超過上限是真的** (例如 153%): 儲值送的資源會超過上限, 不是讀錯, `stop_at` 照樣把它當滿. 哪幾種滿了看 `run.log` 的 `Storage limit reached`, 不要從 `attacked` 推
- **聖水車**: 讀 `runs.jsonl` 裡夜世界那趟第一輪跟最後一輪 `round` 那行的 `cart`, 不另外跑 `collect`. 倉庫滿時是 `locked_holding` 附 `held` 跟 `capacity`; `collected` 是車子倒進了倉庫, 「進帳」寫「倒了 N」, 倒完車上算 0; `locked_empty` 是車上本來就空, 寫 0; `empty` 是按了收集而儲量沒動, 車上寫 0; `unreadable` 是領了但有一邊的儲量條讀不到, 「進帳」寫「讀不到」; 沒有 `cart`, 或是 `locked`, `not_found`, `not_parked`, `wrong_world`, 都是沒讀到, 兩格都寫「讀不到」, 不准寫成滿
- **場數**: 真的開打的輪數; 主村看 `attacked` 不是 `None`, 夜世界看 `phases` 大於 0. 不是 `Attack finished` 的行數
- **花掉的**: 看花之前跟花之後兩次讀到的倉庫差額, 片數是每批「城牆(N級)xK」的 K 加起來
- **時長**: `run.log` 第一行跟最後一行的時間戳; 沒有日期, 跨午夜看目錄名

## 沒達成, 或中途被問

**沒達成**不套樣板, 兩三句話: 跑到哪 (幾輪, 最後一行 `holds` 的水位; 它在最後一場之前讀的就註明), 為什麼停 (被中止 / 一輪也沒打成 / 回不了村莊 / 同一個錯誤重複發生), 要不要繼續以及繼續之前有沒有東西該先處理. 一樣發推播.

**使用者叫停就是他要接手**: 之後碰模擬器的 `ai_coc` 指令一個都不要下, 只讀倉庫的 `stock`、`status` 也算; 只讀檔案的 (`status --last` 這類) 照樣能跑 (`share-emulator` 的「停」). 回報的數字全從 `run.log` 讀. 被砍掉的跑沒有 `result.json`, 從 `run.log` 數得出多少寫多少, 註明是從 log 數的.

**中途被問進度**: 報當下的資源跟輪數就好, **不要停下迴圈**. 數字從那次的 `run.log` 讀: 最近一行 `Village holds …` (夜世界 `Builder base holds …`) 跟 `Round N of`. **不要為了這個下 `ai_coc stock`**: 迴圈在跑的時候, 會操作畫面的指令就是把它借走.
