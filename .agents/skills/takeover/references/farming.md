# 打一趟資源

給派打資源的那一邊: `takeover` 每一種要打資源的終點, 都照這一份派一趟. 迴圈交給一個 subagent, 它照同一個資料夾的 `runner.md` 跑; 這份是派它的 session 的: 開跑前的判斷、派工、回報進來怎麼判、一趟的報告. 打資源本身不花任何東西, 不改程式碼.

旗標看 `ai_coc <指令> -h` (開頭一行說那個指令做什麼), 回報欄位看 `src/ai_coc/models.py` 的 `AttackRun` (整個 series 怎麼收工的 `SeriesEnding` 加上每一輪) / `AttackReport`, 不要憑記憶下參數. 下面的指令都省略了每個指令都要帶的 `--agent`、`--session`、`--mission` (`AGENTS.md` 的 Say who is driving).

## 開跑之前

**讀 `~/.ai_coc/config.json`** (裡面的 Gemini key 讀到也沒關係, 不用先遮掉):

- `thresholds`: 打誰的門檻, 三項都要過. 太高會一直跳過. 已經滿過 `stop_at` 的倉庫, 迴圈每一輪自己把它的門檻當 `0`, 跟收工一樣把它當成滿了
- `stop_at`: 停手的倉庫水位百分比, **主村跟夜世界共用**, 容量迴圈自己去遊戲讀. **每一項都滿過這個百分比才停**, 不是任何一項到頂就停. `0` 是永遠不收工; 讀不到容量的那一項不列入計算
- `adb_serial`: 打的是哪一台模擬器 (MuMu 或雷電), 寫 `adb devices` 列出來的名字. 空的話第一次執行會自己挑一台寫進來. **兩台登的是同一個帳號**, 一台開遊戲就把另一台踢下線, 所以只打設定的那一台, 要換台先改這一格, 不要兩台輪流開

**門檻由你定**, 每一趟開跑前看 `status` 的倉庫 (只讀得到遊戲停著的那個世界, 另一個照設定檔或上一次讀到的): 缺得最兇的那一項給門檻 (例如黑水見底就 `--min-dark` 5000 到 1 萬), 其他沒滿的看情況放寬或照設定檔, 滿的不用管. 每輪跳過幾十個就往下調. 使用者交代過的照他的. 定好的旗標寫進交辦, subagent 不會自己加或改. `0` 跟不給是兩件事 (見 `LootOverrides` 的 docstring). `--stop-at` 是**測試**用的: 對著剛打滿的村莊打一場來驗東西時給 `0`; 打資源不要用, 滿倉搶回來的進不去.

**碰模擬器之前先讀 `~/.ai_coc/state.json`** (`share-emulator` 的「開工先讀 `state.json`」). **別人已經在打資源就不開**: `emulator` 那一塊佔著的是別的 session 帶 `--yield` 的 run (`yields` 是 `true`), 或者那一塊有一筆還沒結束的借用 (`loan.ended` 是 null) 而出借的是別的 session, 或者 `watch` 那一塊是別的 session 的、`status` 是 `running` 而 `farms` 是 `true` (託管睡在兩趟打資源之間, 開 watch 時帶了 `--farms`). 兩個帶 `--yield` 的迴圈會在指令之間輪流搶到模擬器, 各自的 `world --day` / `--night` 把對方下一輪的 `attack` 帶到錯的村莊. 不派, 回報誰 (`caller`) 在跑哪一個 (`command`, `log`). 你自己的 session id 加 `-farm` 後綴的是你自己派的 subagent, 不是別人.

**這個遊戲有兩個村莊, 而遊戲會開在上次離開的那一個**: 日世界 (主村) 跟夜世界 (建築大師基地), 靠一艘船來回. `ai_coc world` 答現在在哪個世界, 不點任何東西; `ai_coc world --day|--night` 坐船切過去. **沒有指令會自己換村莊, 每一個都做遊戲當下停著的那一個**, 所以 subagent 先 `world --day` / `--night` 再開 `attack`. 遊戲沒畫面時 `world` 回 `no_display`, 先 `ai_coc launch` (`share-emulator` 的「遊戲卡住, 或者根本沒開」). 開跑後對一下 `run.log` 打的是哪一邊: 每一輪開頭 `Attack run starts` 是主村, `Builder base attack run starts` 是夜世界. 兩邊容量差十倍, 打錯世界「還差多少」就全錯.

**沒特別交代就兩個世界都打完.** 不用先問哪邊有空間: 滿的世界第一輪就 `stock_full` (主村在付搜尋費前, 夜世界在進配對前), 代價只是幾秒. 他指定了一個才只打那一個. **順序: 他指定了照他的, 沒指定就先打當下所在的那個.** 「當下所在」是開跑前第一件事用 `ai_coc world` 問到的答案. 切畫面就是他指定順序的方式 (想先打夜世界他會自己切過去), 不要推翻.

**兩個世界都用平鋪, 不叫 AI**: 兩個 `attack` 都帶 `--plan flat`, 它照遊戲停著的那個村莊用那一份 (日世界 `flat.json`, 夜世界 `night_flat.json`). **AI 規劃留在程式裡, 不要拿掉**, 兩個世界的邏輯要一樣; 他明講要 AI 規劃的那一趟才不帶 `--plan`. 夜世界用平鋪是因為贏輸都有進帳, 挑哪一邊打差別不大, AI 規劃卻每個 stage 要 10 到 15 秒 (慢的時候 40 秒以上).

**開跑後先估時間.** 一輪抓四到五分鐘. 打完頭幾場跑一次 `ai_coc farmed` (見「報告」): 「現在」那一欄的百分比離 `stop_at`% 還差多少, 除以一場的平均進帳, 就是大概要跑多久. 好幾個小時就先跟使用者講一聲. 量過的速率 (TH15 / 建築大師基地 10 級左右): 主村一場約 +1.1M 金幣、+1.1M 聖水; 夜世界一場約 +100k 到 130k 金幣, 聖水進推車, 平均一場 12 萬左右, 聖水是瓶頸.

夜世界不一樣的地方:

- **沒有門檻**: 沒有偵察畫面, 贏拿金幣輸拿聖水, 沒東西好跳過
- **搜尋要等真人** (量過四秒到五分半). 搜尋中 log 不寫東西, 最久兩分半會有一行 `No opponent in 150s; cancelling and searching again`, 重搜幾次都沒配到才回 `no_opponent`
- **聖水車也算一個倉庫.** 迴圈開跑第一輪跟之後每五場去一次車子: 倉庫有空間就倒進去, 倉庫滿了就讀車上存多少. 倉庫滿了**而且**最近一次讀到車子也過同一個百分比才 `stock_full`, 所以車子剛滿之後最多還會多打四場. 同一趟看三次都讀不到車子, 就退回只看倉庫, `run.log` 前面有一行 `the storages decide alone`, 回報就不能說車子滿了. **倉庫滿了之後倉庫的進帳本來就不動** (在填聖水車), 看 `farmed` 的聖水車那一列有沒有在長

## 派工

**迴圈交給一個 farm subagent 跑**: 在背景跑, 取一個名字讓你傳得到訊息, **模型跟 thinking budget 都從 runtime 給得出的最低那一級開始**. 交辦裡告訴它它是 subagent, 照 `.agents/skills/takeover/references/runner.md` 跑; 那一份是每一趟都一樣的那一半, 這一趟才有的寫進交辦. **分工是判斷對上跑腿**: subagent 是為了讓指令的輸出不進主 thread, 它又快又便宜是因為它什麼都不判斷. 要判斷的 (門檻、花不花、畫面上是什麼、一個結果算不算 bug) 都留在你這裡; 它照交辦跑, 碰到交辦以外的第一件事就回報. 所以它不花任何東西 (買東西要看建造面板), 打到 `stock_full` 就回報. **它沒照交辦跑才往上調, 一次一格**: 沒回報就停了, 回報的跟 `state.json`、`result.json`、`runs.jsonl` 對不上, 或者改了、併了、跳了交辦裡的步驟, 下一個就把 budget 調高一級, budget 到頂了再換高一級的模型, 調上去的那一級用到這個 session 結束. 每一次都到 #548 留一則 (哪個 session, 模型跟 budget, 它說的跟檔案上的); 第二則就把這裡的起點調高一格, 照 #548 記下現在在哪一格. 最低那一級跑得穩, 靠的是交辦把每一步寫成完整的指令 (下面的「交辦」). 它佔模擬器的指令都帶 `--yield`, 所以 live test 是借走它而不是停掉它, 它也從不把測試請下來. **使用者在模擬器上玩, 或說過不要控制遊戲, 就一個都不派**, 他說可以之前什麼都不開.

runtime 沒有 subagent 的話, 你自己照 `runner.md` 跑; 指令照 `share-emulator` 的「背景跑」送背景, 通知進來照 `runner.md` 的「讀結果」接下一步.

**交辦把每一步寫成完整的一行指令**, 照順序編號, 它照抄不加不改. 照這個骨架填 (先打日世界的那一種): 先打夜世界就把兩段對調, 只打一個世界就刪掉另一段, `--debug` / `--shot-every` 加在 `attack` 那一行, 不截圖或不回日世界就刪掉那一行. 不打滿而打 N 輪的, 把 `--repeat 0` 換成 `--repeat N`, 「收工在 stock_full」換成「收工在 repeat_done」.

```text
你是打資源的 subagent. 先用讀檔工具完整讀一遍 <主 checkout>/.agents/skills/takeover/references/runner.md, 照它跑, 不載入其他 skill. 你不判斷任何事, 只照下面的清單一步一步跑, 碰到 runner.md 說要停下來的狀況或清單以外的事, 就停下來回報.
工作目錄: <主 checkout> (不切分支; git pull 跟 uv sync 只在 runner.md 說的時候)
暫存檔: <你的暫存資料夾路徑>

每一行最後都加上這一段 (下面寫成 <身分>): --agent <runtime 的名字> --session <你的 session id>-farm --mission "<這一趟為了什麼>"
每一個 world 都等它跑完、讀完它的結果, 確認到了該到的世界才下一步, 不跟下一步放在同一次執行裡.

1. uv run --no-sync ai_coc world --day --yield --label <代號>-d-w1 <身分>
2. uv run --no-sync ai_coc attack --repeat 0 --plan flat <門檻旗標> --yield --label <代號>-d-a1 <身分>
3. 日世界的 attack 收工在 stock_full (wait 回的 run_outcome) 之後: uv run --no-sync ai_coc capture --label <代號>-d-cap <身分> (capture 不帶 --yield)
4. uv run --no-sync ai_coc world --night --yield --label <代號>-n-w1 <身分>
5. uv run --no-sync ai_coc attack --repeat 0 --plan flat --yield --label <代號>-n-a1 <身分>
6. 夜世界的 attack 收工在 stock_full 之後: uv run --no-sync ai_coc capture --label <代號>-n-cap <身分>
7. uv run --no-sync ai_coc world --day --yield --label <代號>-d-w2 <身分>
然後回報.

被借走時照 runner.md「被叫停, 被借走」: 是借走就開回被借走時在打的那個世界, 同一組旗標, 先 world 再 attack, label 的數字往下編 (日世界第二次是 <代號>-d-w3 跟 <代號>-d-a2, 夜世界第二次是 <代號>-n-w2 跟 <代號>-n-a2). 是真的叫停就不開回去, 回報.
回報照 runner.md「回報」, 用中文寫, 每一個執行目錄都列, 各附那次 attack 印的那一段照貼. 被借走過的寫借了幾次、每次多久接回去.
```

兩個 `attack` 都要寫 `--plan flat`: 交辦沒寫的它不會自己補, 漏寫了每場就去問 AI (託管曾經漏了兩天).

**交給 subagent 的每一趟都要有終點, 不要叫它「跑到叫停為止」**: 一個被交代跑到早上的 subagent 打了 3 圈 (約 2 小時 20 分), 在一次刷牆跑完時結束了回合, 沒有回報, 之後傳給它的訊息也叫不醒, 模擬器閒了 40 分鐘才被發現; 改成每個只跑 3 圈之後, 接手的每一個都跑完回報了. 步驟之間不結束回合、每一步各自一次呼叫、跑完讀 `state.json`、被叫停就回報, 都在 `runner.md` 裡. **那一趟會跑好幾個小時的, 留一個心跳**: 背景等大約一小時 (runtime 管的那種, 等完會叫醒你), 醒來讀 `state.json` 跟最新的執行目錄. 跟上次看比沒有往前走, 又沒收到回報, 就是它默默停了: 結束掉它, 派下一個. 默默結束回合的 subagent 什麼都不會送出來, 只有心跳抓得到; 每次醒來就再開一個, 直到那一趟收工.

**要不要留畫面是你決定.** 有人要找問題 (盯著 subagent 的行為、查 bug、驗證剛修好的東西) 就開 `--debug`, 問題跟戰鬥過程有關 (兵怎麼走、法術什麼時候下) 再加 `--shot-every`, 單純打資源就不開. 圖由你看, subagent 不打開.

## 回報進來怎麼判

**一個世界打不動就先去打另一個**, 為什麼卡住不重要: 耗在那邊等於另一個整晚沒打. 看進帳斜率而不是輪數: 隔一段時間各跑一次 `ai_coc farmed`, 幾場下來進帳幾乎沒動就是打不動. 這種 run 不會自己結束, 所以換世界要先 `ai_coc stop emulator` (不帶 `emulator` 會連盯升級一起停), 等 subagent 回報它停了, 再照「派工」派一趟, 先打另一個世界.

**log 跟畫面都能用, 自己判斷**, log 講不清楚就截一張, 那很便宜. `run.log` 答「走到哪, 這輪結果是什麼」; 畫面答 log 答不了的: 畫面長什麼樣, 兵有沒有在打, 判讀器讀的跟眼睛看的一不一樣. 迴圈在跑的時候看 `--debug` 留下的 `frames/`: 存下的每一張, `run.log` 都有一行 `Saved frame <檔名>`, 它前後的 log 就是讀這張的那一步. 迴圈自己沒在拍才用 `ai_coc capture --count N` 或 `repair-emulator` 的 `scripts/look.py` 截 (兩個都只截圖, 不佔 `state.json`, 但存在別的地方, 時間也對不上這輪的 log). `ai_coc read <png>` 不碰模擬器, 隨時能跑, 看每個 parser 讀到什麼.

**判斷看 `result.json` 的 `ending` (整個 series 怎麼收工) 跟每一輪的 `AttackReport.outcome`**, 不要比對 log 的句子. 每一種是什麼在 `models.py` 的 `SeriesEnding` 跟 `AttackOutcome` 上面那段註解; subagent 照 `runner.md` 決定續或停, 這裡是你要判斷的那幾種:

- `no_loot` (兵出去了而戰利品整場沒動) 是**戰術**的問題, `nothing_deployed` (一張卡都沒出去) 是**迴圈**的問題, 都歸 `watch-and-fix`, 查的地方完全不同
- `army_short`: 軍隊不到兵營的一半, 整個 series 到此為止. 造兵是即時的, 這種軍隊不會自己變好, 要人進遊戲改配置. 抓一張軍隊畫面附在回報裡
- `other_village`: 遊戲停在這一批沒在打的村莊, 多半是有人切過, 例如使用者在手機上玩

**值得警覺的樣態**, 連續幾輪才算:

- 每輪 `skipped` 都是幾十: 門檻對現在的獎盃區間太高, 調低再派
- **入庫的進帳遠小於 `attacked`**: 進攻打不動人家, 是 `watch-and-fix` 的題目, 這裡只報告. 看落差而不是 `attacked` 大不大 (它只說對手**擺出**多少)
- `The session was dropped`: 迴圈自己會點對話框的按鈕重新登入, 點了沒用才重開遊戲 (log 有 `did not clear it; restarting the game` 就是重開了). 一直重複才要查
- `waiting for the server rather than tapping`: 卡在載入畫面, 伺服器的事. 迴圈每次載入最多等 45 分鐘; 等不到的那輪是 `server_loading` 或 `server_flapping`. **不要**重開遊戲或模擬器, 量過兩次都是自己回來的. 連續兩輪都是這兩種再停下來講
- `The camera was not at the far zoom` (**只在主村**): 只是回報, 迴圈每場自己會 pinch 回去. 連著出現才去看畫面

**被搶登** (`session_taken`): 另一部裝置 (多半是他的手機, 另一台模擬器也算) 登入了這個帳號, 迴圈沒有把登入搶回來就收工. 託管裡照 `SKILL.md` 的「停」: 五分鐘後自己登入回去; 不是託管派的這一趟 (例如查問題時派的) 就停手通知他, 等他說可以. 兩種都一樣, 那之前一個 `ai_coc` 指令都不要下, `stock`、`status` 也算: 每個指令開跑時都會重新登入, 把他踢下線. 登入回去後同一個世界同一組旗標再派. 夜世界被擠掉之後有幾分鐘配不到對手, 開回去頭幾輪 `No opponent in 150s` 甚至 `no_opponent` 是這個, 不是卡住.

**其他停手的理由**: 遊戲一直回不到村莊, 同一個錯誤連續三次以上, 一輪也沒打成過, series 收工在 `emulator_silent` (連續三輪沒回應, 先看模擬器還活著沒有) 或 `no_attack_menu` (連續五輪打不開攻擊選單, 原因看每一輪自己的 log: 蓋住遊戲的畫面, 一直掉線, 或有人在手機上玩, 先看畫面). 這些都停下來講, 不要一直重試: 失敗要吵.

**撞到 bug 或模擬器起不來**: subagent 停下來回報哪一輪、`run.log` 的哪幾行跟執行目錄, 什麼都不改也不修. 接不接進 `watch-and-fix`、`repair-emulator` 或 `game-update` 是你判斷 (`SKILL.md` 的「停」說託管時不等他), 打資源本身不改程式碼. 交給使用者的話寫三件事: 哪一輪, `run.log` 的哪幾行, 你看到的畫面.

## 報告

**預設倉庫滿了就是終點**: 他只說「幫我打資源」的那一趟, 任務就到該打的世界都打到 `stop_at`. **不要自己接下去花**, 工人閒著或某棟很划算也一樣; 值得花就寫成選項讓他挑.

**打完不要留任何東西在背景跑**, 包括為了讓村莊「有人在線上」: 有沒有人看畫面都照樣被打, 保護村莊的是被打之後遊戲自己給的護盾. 盯升級的 `ai_coc watch` 也不是這一趟留的: 使用者要過 farm 預設留一個, 討論完自己收回 (每個在做事的 session 都會派 farm, 而一次只有一個 watch, 預設留就會把別人睡著的那個請掉), 不要再加回這裡. **交之前先確認沒有東西留在背景**, 去查而不是回想 (`AGENTS.md` 的 Check what subagents leave behind yourself); 查到 `ai_coc` 程序還在跑也不要砍它 (`share-emulator` 的「停」).

`collect` 不在流程裡跑, 他開口才跑: 收集器產出不多, 倉庫多半又是滿的收不進去; 聖水車不受影響, 進攻迴圈自己會去倒. `donate` 想跑就跑, 但只做主村. 這兩個一樣不跟迴圈同時跑, 等接縫 (換世界前, 收工前) 再跑.

**回報只回答四件事: 打完沒, 打了多少, 花多久, 現在的資源狀態.** 數字全從 `ai_coc farmed --by <你的 session id>-farm --since <派這一趟的時間>` 來: 它只讀 `~/.ai_coc/runs.jsonl`, 不碰模擬器也不佔鎖, 隨時能跑, 被叫停之後也能; 這一趟被借走、換世界而重開過的每一次都加在一起, 兩個世界各算一段, 每次各算各的 (使用者在兩次之間花掉的不會被扣成負的進帳). 不要為了算數字下 `ai_coc stock`, 也不要自己翻 `run.log` 或加總每次 `attack` 印的那一段. 一句結論, 每個打了的世界貼它印的那一段再加一行工人, 印在對話裡, 不寫檔案, 不加章節, 不包程式碼區塊. 講給他聽時說「打資源」, 不說「農場」.

```markdown
兩邊都打滿了, 花了 1 小時 31 分鐘.

日世界: 18 場, 倉庫都滿過設定的百分比

| 資源 | 進帳 | 現在 |
| --- | --- | --- |
| 金幣 | -5 萬 | 4365 萬 (150%) |
| 聖水 | +1920 萬 | 2900 萬 (100%) |
| 黑水 | +0 萬 | 47 萬 (100%) |

工人 0/7, 最快明天 06:29 好.

夜世界: 21 場, 倉庫都滿過設定的百分比

| 資源 | 進帳 | 現在 |
| --- | --- | --- |
| 金幣 | +0 萬 | 1328 萬 (204%) |
| 聖水 | +31 萬 | 650 萬 (100%) |
| 聖水車 | +82 萬 | 160 萬 / 160 萬 |

有 3 場打完之後沒讀到倉庫, 沒算進進帳

工人最快明天 05:00 好.
```

- **第一行**: 打完沒, 總共花多久 (`farmed` 第一行的時長). 只打一個世界就講那一個
- **每個打了的世界一段, 照貼 `farmed` 印的**: 一行場數跟最後那一次怎麼收工 (還在打的沒有這一句), 一張表 (現在附滿了幾成; 夜世界的聖水車那一列, 進帳是車上多存的, 倒進倉庫的已經算在倉庫裡); 「有 N 場…沒算進進帳」那幾行照留, 那是量不到的場數, 不准估. 沒打的世界它不列. 金幣讀到負的是倉庫滿著只付了搜尋費
- **工人那一行**: 那個世界的工人最快幾點好 (收工時跑的 `ai_coc status` 表上那個世界「目標」是工人的第一列, 哥布林的也算), 遊戲停著的那個世界再加閒幾個/總共幾個 (`status` 那個世界那一行的工人數; 另一個世界的讀不到, 不為它開船). 沒打的世界沒有那一段, 它的工人最快幾點好寫成最後一行
- 這一趟有花東西的話, 那個世界的工人那一行下面多一行: 刷了幾片牆, 升了什麼, 各花多少 (花之前跟花之後兩次讀到的倉庫差額, 片數是每批「城牆(N級)xK」的 K 加起來)
- **倉庫讀到超過 100% 是真的**: 儲值送的資源會超過上限, 不是讀錯, `stop_at` 照樣把它當滿
- 推播一行就好, 先講他會想動手的那件事 (「日世界打滿了, 工人全忙」比「任務完成」有用)

## 沒達成, 或中途被問

**沒達成**不套樣板, 兩三句話: 跑到哪 (`ai_coc farmed` 印的那一段: 幾場、現在的倉庫跟沒算進進帳的場數), 為什麼停 (被中止 / 一輪也沒打成 / 回不了村莊 / 同一個錯誤重複發生), 要不要繼續以及繼續之前有沒有東西該先處理. 一樣發推播.

**使用者叫停就是他要接手**: 之後碰模擬器的 `ai_coc` 指令一個都不要下, 只讀倉庫的 `stock`、`status` 也算; 只讀檔案的 (`status --last`、`farmed` 這類) 照樣能跑 (`share-emulator` 的「停」). 回報的數字從 `ai_coc farmed` 讀, 被砍掉的那一次打完的每一輪也在裡面.

**中途被問進度**: 報當下的資源跟場數就好, **不要停下迴圈**. 數字從 `ai_coc farmed` 讀: 它照每一輪寫下的紀錄算到剛打完的那一輪, 第一行寫「還在打」. **不要為了這個下 `ai_coc stock`**: 迴圈在跑的時候, 會操作畫面的指令就是把它借走.
