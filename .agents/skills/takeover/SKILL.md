# takeover

代替他打資源跟顧村莊, 唯一會睡、會醒、會接下一步的 skill: 一趟打資源, 或一個圈一直跑到他給的終點. 他能交代的只有兩處: **跑到什麼時候** (「跑到什麼時候」那一節), **打不打資源** (預設打). 打資源照 `references/farming.md` 派一個 subagent, 它照 `references/runner.md` 跑; 升級怎麼點照 `upgrades`. 這裡寫圈本身跟託管才有的規矩. 講給他聽時說「打資源」, 不說「農場」.

## 他交代了什麼

**他事先交代的照他的**: 某一件好了要改升什麼 (例如「雪怪升級完升級地震」), 照他說的, 不照「到點的那一件」的預設. 「到點前五分鐘備好」也一樣: 開的是他要改升的那一列或分頁, 按下去的也只有那一件, 不讓到點的英雄、研究或戰寵視窗刷新成下一級就按, 也不點到點那一棟的「升級」. 交代的用 `ai_coc note add <day|night> "<一條交代>"` 記進 `state.json` 的 `notes`, 一條一項, 改升的那一件開始升了就 `ai_coc note done <day|night> <第幾條>` 刪掉; 接手的 session 或別的 agent 看不到這次對話, 只看得到 `state.json`. 「這一級升完」跟「滿級以後」照他的原話寫進去, 兩者不同 (沒特別講就是這一級升完). `notes` 由這個 session 寫跟讀, 打資源的 subagent 不碰; `--about` 只寫這個 watch 在等什麼. 還在跑 `notes` 加進來之前的程式的迴圈或 watch, 下一次寫 `state.json` 就會把 `notes` 整段丟掉, 所以先照 `share-emulator` 的「merge 進來的修正, 迴圈怎麼用上」讓它們用上新程式, 再寫交代.

**託管是他的常設授權**: 到點的那一件續升, 滿級了照表挑, 英雄、研究、戰寵都包括在內. 城牆照舊要他指名才刷 (`upgrades` 的「哪些不用問, 哪些要」), 託管不算指名. 「每次升工人之前先刷牆」擬過, 他擔心每次升級都要先查牆會拖慢, 擱在 #448; 不要再提, 也不要列成待他決定的事.

**護盾不盯**: 不為它讀、不為它醒來、也不為它開船.

## 圈

1. **開始**: 照 `AGENTS.md` 的 Look before driving 先看 `state.json`; 這一趟要打資源而別人已經在打資源, 就不開 (`references/farming.md` 的「開跑之前」), 跟他講. 跑一次 `status` (`upgrades` 的「讀一次」), 照「講什麼」交開始的那一份, 再照 `references/farming.md` 的「派工」派打資源 (不打資源的不派). 第一次讀就看到他要看的那塊已經有人閒著, 或鐘塔現在就能開, 當下就處理, 不用排. 讀到升完就到頂的, 等第 2 步掛好 watch 再問他 (「到點的那一件」)
2. **睡**: 派完打資源就睡, 不等它打完: 打資源要好幾個小時, 中間有升級到點也要有人醒. 只掛一個 `ai_coc watch`: `uv run --no-sync ai_coc watch --next <醒來的時間, ISO> --about "<在等什麼>"`, 用 runtime 自己管的背景執行開, 背景指令跑完叫不醒你的 runtime 另外照 `share-emulator` 的「背景跑」設一個排程. 醒來的時間取下一件 `done_at` 的五分鐘前 (見「到點前五分鐘備好」), 鐘塔的 `ready_at`, 終點是某個時間的那個時間, 跟現在起三小時後 (每三小時上去看一眼, 資源沒滿就補), 最早的那一個; 不打資源的那一趟不取三小時. `--about` 寫上各在等什麼, `--mission` 寫明這一趟的終點, 要打資源的再寫明「全天候託管」: 別的 session 讀到它就不開打資源的 (`references/farming.md` 的「開跑之前」); 不打資源的不寫, 免得擋住別人打資源. 計時放在 `ai_coc watch` 而不是 runtime 自己的排程: `ai_coc stop` 停得到它, 別的 session 也看得到有人在顧. 不管多遠都睡; 不要每十分鐘戳一次: 等待是算術不是觀察. 升級的完成時間不另存成檔案, 每一趟從 `status` 讀
3. **醒來**: 先看它的輸出 (`WatchReport`, 跟那次的 `result.json` 是同一份), 見下面. `due` 的話先照 `AGENTS.md` 的 Look before driving 看 `state.json`, **再重跑 `status`** (借到打資源的就讀完 `giveback`, 五分鐘內有升級到點的例外, 見「到點前五分鐘備好」), 照新的讀數決定: 他中途可能玩過, 加速或自己升了東西不一定會講. 讀數跟上一次對不上 (那一件提早好了、時間突然變長、等級跳了一級) 多半是他自己上線動過, 照新的讀數排, 不當成 bug. 有升級五分鐘內到點就照「到點前五分鐘備好」做, 挑哪一件照「到點的那一件」; **每升完一件就重跑一次 `status`** (升級本身改了時間), 照新的讀數再排. 然後打資源的那一趟照 `references/farming.md` 再派一趟, 兩個世界都打: 倉庫還滿著的話第一輪就 `stock_full`, 這就是「看一眼」. `state.json` 上打資源還在跑就不再開一個; 這一次醒來就是 `references/farming.md` 的「派工」說的心跳, 照那裡看它有沒有往前走, 不另外掛一小時的心跳
4. 照最新的讀數回到第 2 步

**之前讀到的時間不沿用**: 他講了在遊戲裡動過什麼 (加速、開藥水、自己升了東西), 不等醒來, 當下就重跑 `status`, 照新的讀數重掛 watch. 他拿模擬器或手機玩過, 也算動過.

**夜世界沒花東西也照樣去打那一趟**: 立刻升好的牆不留計時, 他在夜世界自己花了也讀不出來. 「沒花就跳過夜世界」他否決過, 不要再提.

**醒來的輸出**: `outcome` 是 `due` 就是時間到了. 是 `stopped` 就是有人叫停或接手了, `stop_by` 是誰、他的 `mission` 是為什麼: 不要默默收工, 跟他講託管被誰中斷了, 他以為還在跑; 有設排程的話也刪掉. 託管就是停了: 照「講什麼」交停下來的那一份, 他說要繼續再從第 1 步開始. 例外是 `stop_by.session` 是你自己的: 你剛下過 `ai_coc stop` 就是你自己停的, 照「停」收尾; 不然是你重讀時間後開的新 watch 接手了舊的, 照常等新的那個. 輸出只有一行說 `state.json` 不在 (exit code 不是 0) 的話, 它根本沒睡: 先跑一個會操作模擬器的指令 (例如 `status`) 再開一次.

**開始前先看 `state.json` 的 `watch` 那一塊**: `status` 是 `running` 而它的 pid 還活著, 就是有人在盯. 你被交辦了就照樣開: `ai_coc watch` 會先請那一個收工、把你記成 `stop_by` 再接手, 所以一次只有一個在盯. **它在等的那一件就變成你的**: 那一邊醒來不會講話, 你不帶著它, 那一件就沒人盯了. 它的 `about` 寫著在等什麼; 拿你自己讀到的 `status` 表對回那一件, 跟你自己要看的一起排, 已經好了或對不上就當下跟他講. 之後每次開 `ai_coc watch`, `--about` 都把它一起寫上, 直到講完. 到時候講明這一件原本是誰在盯的 (`caller`); 它講完之前你不收工. 回報講一聲接手了誰、它在等什麼.

**打資源的每一趟兩個世界都正常收工 (`stock_full`), 最後 `world --go day` 回日世界**: 夜世界不會被打掉資源, 主村會, 停在主村他上線一眼就看得到, 下一次 `status` 讀到的計數也是主村的. 這一步寫進交辦的收尾; 被擠掉、被叫停、或停下來回報的那一趟不開船, 開船會把遊戲登入回來, 把手機上的他踢掉 (`references/runner.md` 只在正常收工時做收尾).

盯時間跟升級是這個 session 的事: 打資源的 subagent 卡在 `attack` 裡, 看不到時間也發不了通知, 只管打資源. 每一次讀 `status` 都會借走它 (它帶 `--yield`), 讀完就 `giveback`, 不然它要等 30 分鐘才接回去.

## 到點前五分鐘備好

從到點到按下確認的每一分鐘, 那個工人都閒著, 開著工人藥水時一分鐘就是十分鐘的工時. 醒在到點那一刻的話, 到按下確認量過要兩分多鐘, 一半花在 `status`, 碰上打資源在打仗還要先等那一場打完. 所以醒在 `done_at` 的五分鐘前, 到點以前做得完的都先做完:

1. 照第 3 步看 `state.json`, 重跑 `status`. 那一件的 `done_at` 變了 (他可能加速過) 就照新的排, 五分鐘內還是會到點才往下做
2. **這時不 `giveback`**: `status` 借到的模擬器留著, 到點以前打資源不會插進來. 借用從你最後一個指令跑完起算三十分鐘才失效, 等五分鐘夠
3. 那一件在另一個世界就先 `world --go`. 照 `upgrades` 的「面板」`tap`「建造」(點完回來那張就是開工那張, 讀寶石數), 切到那一件的分頁 (工人、實驗室或戰寵). **主村的英雄、研究跟戰寵再 `tap` 它正在升級的那一列**, 開出「正在將X升至N級」放著: 倒數到 0 時它自己變成「將X升至N+1級？」, 不用回面板找 (量過從到點到按下確認十五秒, 戰寵十三秒). **建築也 `tap` 那一列**: 鏡頭移過去把那一棟選起來, 記下它在圖上的位置; 到 0 時那一排自己收掉, 面板上那一列也移走 (量過四十二秒). 夜世界的英雄開著面板就好: 到 0 時它移到「建議升級」, 點那一列直接跳「是否提升至N+1級？」 (量過二十九秒). 哥布林那格做的也一樣備好: 那格做完要再聘一次哥布林才續升得了, 按下確認跳出聘請的視窗就照 `upgrades` 的「哥布林」付. 續升前照 `upgrades` 的「先確認在哪個村莊, 有沒有空」看空閒數
4. 背景開 `ai_coc watch --next <done_at>` 睡到點, 帶同一個 `--session`, 中間不下別的指令. 背景指令跑完叫不醒你的 runtime, 這幾分鐘就在前景跑它
5. 醒來先照第 3 步讀它的輸出: `stopped` 就照那裡處理, 什麼都不再點. `due` 才往下. **選著建築的不先 `capture`**, 直接 `tap` 地圖上的那一棟 (位置照選起來時那張圖), 讀回來的那一張: 那一排上方的名字是剛升完的那一棟、等級是新的一級 (例如「地獄之塔(7級)」), 那一排又有「升級」, 才讀它印的價格, 接著下 `tap`「升級」跟 `confirm --price <那個價格> --item "<那一棟> <新的一級加一>"` (要買的那一級), 中間不讀圖. 先對名字是因為 `confirm` 只核對確認鈕上的價格跟資源, 點到隔壁那棟或城牆時, 價格是從同一排讀的, 它照樣會按. 那一排還是「立即完成」(差幾秒還沒升完), 就隔一兩秒再 `tap` 那一棟; 選到別的或什麼都沒選到, 照下面「圖上兩者都不是」處理. 其他的先 `capture` 一張新的圖. 開著英雄、研究或戰寵視窗的: 標題變成「將X升至N+1級？」就照 `upgrades` 讀價格、`confirm`; 還是「正在將…」(差幾秒, 或他加速改過時間) 就再 `capture` 一次, 變了才按. 開著面板的: 剛升完的通常在「建議升級」, 不在就往下捲; 那一列還在正在升級那區, 就關掉面板重開一次. 圖上兩者都不是 (例如閒置斷線的對話框), 就 `ai_coc launch` 回到村莊, 再從 `tap`「建造」重來. 照 `upgrades` 點下去, `confirm`. 三種都一樣, 按完照「收尾」, `giveback`, 再接第 3 步剩下的 (重讀 `status`, 補打)

**視窗跟面板最多提早五分鐘開, 兩件接得近也一樣**: 遊戲沒人碰太久會閒置斷線 (量過五分二十秒沒事, 十二分四十八秒斷線), 到點時才從斷線登入回來, 那一次從到點到按下確認拖到八十九秒. 前一件照本節第 5 步做完之後, 後一件還要超過五分鐘才到點, 就照「圈」第 2 步睡到它的五分鐘前, 再從本節第 1 步做起, 不先把它的視窗或面板開著等. 中間閒著斷線不要緊: 醒來的 `status` 自己會登入回來, 那時還沒到點. 後一件快到了的話, 前一件之後的補打可以先不派, 等後一件也按完再一起打回來, 派不派由你判斷.

## 到點的那一件

**預設再升同一件, 不問**: 工人、實驗室、戰寵小屋都一樣, 英雄也算, 哥布林那格也算 (見下面「活動的哥布林那格」). 時間到不代表有空格, 續升前照 `upgrades` 的「先確認在哪個村莊, 有沒有空」看空閒數.

**升完就到頂的, 開始時先問他, 到點不等他**: 第 1 步讀的 `status` (開始, 或他說繼續再從第 1 步開始) 裡在升的, 升完就是下面「同一件升不了」那三種的, 照第 2 步掛好 `ai_coc watch` 之後, 照 `AGENTS.md` 的 Putting a decision to the user 問他那一格到時改升什麼: 一則推播, 編號清單一項一件那一格到時照下表 (日世界的工人照它的順序) 會挑的那一組 (實驗室是「建議升級」那幾項, 不是每一項研究), 附價格 (面板上讀的或 `ai_coc search` 的牌價), 一項先不要動, 不標推薦. 他回了就照「他交代了什麼」記成 note, 到點照它做. 到點還沒回就照下面「同一件升不了」挑, 不讓工人、實驗室或戰寵小屋空著等他回話. 每一件只問一次, 醒來不再問. 那一格不會照表補的不問: 不續升的那一趟 (「打到有空閒通知我」), 要留給 X 的 (「到時候幫我升 X」).

**同一件升不了** (滿級了、被大本營或殿堂卡住、`upgrades` 的「哪些不用問, 哪些要」裡停在某一級的; 前兩種看 `status` 表上那一列「項目」的括號: 升到的等級等於滿級 (`10/10`), 或等於後面寫的上限 (`8/9, 上限 8`)), 或開始時就閒著、沒有剛好好的那一件可續: 不問, 照下表挑一件 (升完就到頂的開始時先問過, 他回了照他的, 見上一段); 他想先被問, 講一句就記成 note. 這是使用者定的順序, 也是他的常設授權, 託管的每一種終點都適用 (打資源順便花掉跟只盯升級是他另外確認過的), 英雄、研究、戰寵都包括在內:

| 好了的是              | 同一件滿級時改升                                                               |
| --------------------- | ------------------------------------------------------------------------------ |
| 實驗室                | 「建議升級」裡任一項                                                           |
| 戰寵小屋              | 「已指派」的寵物優先                                                           |
| 工人 (英雄跟建築共用) | 別的英雄優先, 英雄之間挑升級時間最短的; 沒有英雄能升才挑建築, 一樣挑時間最短的 |

**升級時間照那份匯出比**: 每一列的 `next.time` 是下一級要的秒數, 是遊戲表上的牌價時間, 活動可能讓實際的短一些, 拿來排誰最短就夠, 不用一列一列開面板讀; `next` 是 `null` 或 `next.lvl` 大於 `limited_lvl` 的升不了, 不算候選. 不用自己翻那份檔案: `ai_coc search --section heroes` 一次印出每個英雄下一級的牌價跟時間, 被殿堂卡住的會註明 (`next`、`limited_lvl` 在那次執行的 `result.json`), 建築照遊戲裡的名字查 (`ai_coc search 地獄之塔 --all`, 每一棟各一列), 不碰模擬器也不佔鎖; 上面看同一件升不升得了也一樣用它.

`upgrades` 的「哪些不用問, 哪些要」裡不升或已經停在上限的 (時光鐘樓, 兩個世界的聖水收集器、金礦、暗黑重油提煉井, 18 級的日世界儲金罐跟聖水瓶, 12 級的暗黑重油罐, 暫停中的超級蓄能) 都不是候選, 時間再短也不挑.

**日世界的工人另有順序**: 英雄一律續升, 建築也先續升同一棟; 沒有英雄或那一棟能續升的空工人 (好了的那一棟升滿了、英雄升滿了、開始時就閒著都算), 照這個順序挑, 每一組裡挑升級時間最短的:

1. 地獄塔
2. 地獄塔都升滿了, 才換箭塔、法師塔、防空火箭、空氣炮. 地獄塔還沒滿但每一座都在升, 這個工人就挑這第二組, 不空著, 也不去升兩組以外的

兩組都升滿了才照上表的工人那一列挑. 夜世界的工人照舊照上表.

**活動的哥布林那格 (工人或研究員) 預設要用, 一樣照這裡挑, 挑好了才看寶石** (使用者 2026-11-11 定的): 那格做的那一件做完而還沒到頂, 就再聘一次哥布林續升; 到頂了照上面挑別的, `notes` 跟順序一樣管. 寶石照 `upgrades` 的「哥布林」, 上限內直接付, 超過就問他, 託管也不例外; 不要為了壓在上限內改挑別的.

**錢不夠不算升不了** (這裡的升不了都是滿級): `confirm` 回 `cannot_afford`, 打資源的那一趟就先派一趟打到滿, 再回來升; **不打資源的那一趟不去打**, 跟他講哪一件差多少, 照下一件排.

**鐘塔到了就開, 不問**: 睡到 `ready_at` 再開, 不照上面提早五分鐘 (五分鐘前醒來就改睡到 `ready_at`), 因為能開的標記到點才出現. 怎麼開照 `upgrades` 的「開鐘塔」. 開成了 (`boosted`) 先重跑 `status`, 照新的讀數排下一次醒來: 加速讓夜世界每個工人跟實驗室的工作都跑快, `done_at` 跟著提早 (2026-11-11 量過: 建築大師訓練營從 17:46 提早到 17:34, 戰爭機器從隔天 09:30 提早到 05:00), 照開之前讀的時間睡, 會醒在那一件做完之後. 開不成而講過之後就不再算進醒來的時間, 直到之後讀到鐘塔那一列又不是「現在」.

## 跑到什麼時候

| 他講的               | 終點                                       | 打資源       | 收的時候                                                 |
| -------------------- | ------------------------------------------ | ------------ | -------------------------------------------------------- |
| 打資源               | 該打的世界都到 `stop_at`, 或他給的輪數跑完 | 打           | `references/farming.md` 的報告                           |
| 託管 (預設)          | 他叫停                                     | 打           | 「講什麼」的停下來那一份                                 |
| 打資源順便花掉       | 倉庫滿了而且沒有東西花得下去               | 打           | `references/farming.md` 的報告, 工人那一行下面加花了什麼 |
| 打到早上、跑到幾點   | 那個時間                                   | 打           | 停下來那一份                                             |
| 打到有空閒通知我     | 他要看的那一塊空出來                       | 打           | 通知他, 列選項                                           |
| 到時候幫我升 X       | X 開始升了                                 | 他說要打才打 | 升了什麼、花了多少                                       |
| 只盯升級、不用打資源 | 他叫停, 或沒有東西可等了                   | 不打         | 停下來那一份                                             |

只講打資源, 沒講要花、時間或空閒的, 是打一趟; 其他沒講終點的是託管. 打一趟以外的每一種都照「圈」跑, 下面只寫各自不一樣的地方. 他講的終點跟打不打資源寫進 watch 的 `--mission`. 終點是某個時間、某一塊空出來或 X 開始升了的, 到了而背景還有打資源在跑, 就 `ai_coc stop emulator` 停下它 (等 subagent 回報它停了), 讀完報告要的 `status` 跟價格, 再交「收的時候」那一份. 這不是他叫停, 收尾要讀的照讀.

**不打資源的那一趟**: 不派打資源, 不補打, 醒來的時間不取三小時; 錢不夠就跟他講, 不去打. 其餘一樣.

### 打資源 (一趟)

照 `references/farming.md` 派一趟, 終點到了就照它的「報告」交, 收工. **只打不花**: 倉庫滿了就是終點, 工人閒著或某棟很划算也一樣, 值得花就寫成選項讓他挑. 這一趟不睡著等升級: 不掛 `ai_coc watch` (被搶登的那五分鐘例外), 不續升, 不補打; 等 subagent 回報的時候照 `farming.md` 的心跳. 背景已經有一趟在跑而他問進度, 照 `farming.md` 的「沒達成, 或中途被問」, 迴圈照跑.

### 打資源順便花掉

打到滿 → 花掉 → 回去打, 繞到花不掉為止. 他交辦時講了要花 (「打完順便刷牆」「把資源花掉」「打資源跟升級牆壁」) 才是這一趟, 不是你判斷出來的. 每一趟打資源照 `references/farming.md` 派, subagent 打到 `stock_full` 回報, 你花完再派下一趟, 同一份交辦. 回報說它在半路停手, 就照那份回報處理, 不要再派: 那些停手的理由換一個 subagent 一樣成立, 使用者在手機上玩的話, 每派一個就把他踢下線一次. 背景那輪跑完就自己接下一步, 不要回頭問; 中間不要拖: 打滿的村莊是別人最想打的, 趕快花掉是唯一減少暴露的動作.

**第一步是問 `ai_coc world`, 沒有例外.** 面板上列的是遊戲停著那一邊的建築跟牆, 站錯村莊花的就是另一邊的倉庫. 要花主村的先 `world --go day`. **夜世界打滿了就換去打日世界**, 兩邊倉庫不相通; 夜世界的建築跟牆一樣走 `upgrades` 的面板, 牆值不值得刷是使用者的決定. 兩個世界都滿了才通知他. **底下講的都是日世界.**

**一, 授權.** 城牆要他指名到「牆」; 閒著的工人、實驗室、戰寵小屋照「到點的那一件」的表跟日世界工人的順序挑 (英雄、研究、戰寵都在裡面), 不用問.

- **城牆要使用者指名, 預設不刷.** 他要的是被通知; 他沒講理由, **不要替他補一個**, 也不要因為這一趟划算就自己判斷. 籠統的「把資源花掉」不算指名到牆. 牆付錢當下就升好、工人立刻還回來, 那是它值得列成通知選項的原因, 不是可以自己跑的理由
- **建築不用問, 但要有工人閒著** (`status` 那個世界那一行的「工人 閒/總」說真的有, 只有遊戲停著那個世界有這一行): 倉庫滿了而工人發呆, 資源被丟掉, 工人也沒蓋東西

**二, 順序: 他指名要刷牆的那一趟, 牆先刷, 建築後升**, 刷之前先把建築要的那一筆留下來 (`upgrades` 的「城牆」講怎麼留; 循環刷牆的那一圈不留, 因為它不升建築). 兩個搶同一個工人, 而升建築會把閒著的工人派去蓋好幾天, 先升建築, 刷牆就只會撞「所有建築工人都在忙碌中」. 要花但沒指名到牆的那一趟只會升建築, 而工人一派出去牆這個出口就關好幾天: **通知照樣先發, 牆列成一個選項, 但講明它會在建築升下去之後過期, 然後照樣升建築, 不要停下來等他回話.** 不要寫「已經幫你問過了」, 要寫: 要刷牆得等下一個工人空出來再說一次.

**三, 兩個出口關掉的方式不一樣.** 牆需要有一個工人閒著, `0/N` 一片都買不了, 這一種升建築也接不上. 牆被大本營的等級卡住 (面板上沒有城牆那一列, 或者 `confirm --pay` 回 `no_confirmation` 而圖上是確認鈕灰掉的視窗), 正是升建築該接手的地方, 工人還閒著; 撞到一次這一趟就不用再刷牆.

**停手的條件是「資源花不掉了」**: 工人全忙或者沒有值得升的建築, 牆沒指名到所以不刷 (指名了就是牆也刷不動: 工人全忙或牆到頂). **刷到升級鈕變紅字不是花不掉**: 是倉庫花到買不起下一批了, 回去打. **牆有指名而工人閒著, 這一圈就幾乎不會自己停**; 他指名刷牆時加的「循環到我說停」「打到早上」就是這一圈, 沒指名牆的那幾個字不授權刷牆. **這一圈刷完牆不升建築**, 除非是牆到頂了: 升建築會把閒著的工人派出去, 下一圈刷牆就撞工人全忙, 圈也就斷了.

**黑水只有升英雄能消化.** 英雄在表上都升著或都滿級, 黑水就停在那裡, 回報要講出來.

### 打到有空閒通知我

他把終點放在工人或實驗室上 (「直到有工人空出來通知我」): 兩個世界照常都打, 醒來的時間多取他要看的那幾塊 (`status` 表上「目標」是工人或實驗室的那幾列; 他只講工人就只看工人, 只講實驗室就只看實驗室, 講「有空閒」或沒說是哪個就兩個都看) 最早的「時間」, **不提早五分鐘**. 醒來 `status` 讀到那一件已經不在表上 (做完了) 才算達成; 那個世界是遊戲停著的, 再看那一行那一塊的閒置數大於 0 (另一個世界的計數讀不到, 不為它開船). 還沒有就照新的讀數再睡. 他中途自己加速的, 要到下一次醒來才知道. 有哥布林活動時, 空出來的那一格可能是要寶石聘請的哥布林, 回報時講明.

**這一趟不續升**: 空出來就是他要的那一刻, 續升會把那個空位又派出去. 達成就照 `references/farming.md` 的報告交, 空出來的那個世界的工人那一行先講是工人還是實驗室空出來, 發推播並列出選項 (`AGENTS.md` 的 Putting a decision to the user): 工人是升建築、刷牆、繼續打到倉庫滿、先不要動 (有價格就附); 實驗室是研究 (照 `upgrades` 的「面板」開實驗室那個分頁, 有價格就附)、繼續打到倉庫滿、先不要動. **他沒開口要花就不要自己花.**

### 到時候幫我升 X

他叫你升 X 而工人 (或實驗室、戰寵小屋) 全忙, 回答幾點空出來時問過要不要到時候替他升, 他說要: 把「X 空出來就升」用 `ai_coc note` 記下來, 照「圈」睡到那一塊最早的 `done_at` 的五分鐘前, 照「到點前五分鐘備好」先開好面板上 X 那個分頁, 到點照 `upgrades` 找 X 那一列升下去. X 開始升了就收, 刪掉那條 note, 講升了什麼、花了多少. 他沒說要打資源就不打.

## 講什麼

開始跟停下來各交一份, 中間只在有事時講: 升了什麼 (挑的那一件講為什麼是它)、花了多少, 鐘塔開了 (或為什麼沒開成), 工人學徒跟實驗室助手能派了 (`status` 印的「助手」那一行, 順口一句), 卡住了. 每三小時的補打不交一趟的報告. 要他決定的事照 `AGENTS.md` 的 Putting a decision to the user; runtime 只能用發問工具而它會讓整個回合停住的, 先把下一件的 `ai_coc watch` 丟到背景、借來的模擬器 `giveback`、要回去打的資源先派出去, 再問. 兩份都直接印在回覆裡, 不包程式碼區塊.

**開始**: 第 1 步的 `status` 讀完就交, 不等打資源. 第一行你寫, 底下是 `status` 印的, 照貼, 每張表再加一欄「後續」由你填.

```markdown

村莊匯出: 今天 17:41
```

- 「助手」那一行講過了就刪, 等它下一次冷卻完再講

- **每次升級**: 升之前面板上那一列跟確認視窗, 升完收尾後一張, 鐘塔加速也一樣
- **每次發圖都再附一次升級的表** (使用者 2026-11-11 要的), 跟開始那份一樣四欄 (時間、目標、項目、後續), 印在同一則回覆裡: 前三欄照最近一次 `status` 印的 (升級跟鐘塔之後本來就重跑了 `status`; 打資源打完用 `status --last`, 不為它借模擬器), 「後續」照開始那份的規矩由你填
- **發完就把那些 `frames/` 刪掉**, `run.log` 跟 `result.json` 照留. 出了問題要拿去修的那幾張例外, 修完再刪

## 停

- **他叫停**: 下 `ai_coc stop`, 一次停掉 watch 跟模擬器上的指令, 有設排程的話一起刪掉; 你剛好借著模擬器的話, 照 `share-emulator` 的「停」等指令停了再下一次, 才取消借用. 打資源的 subagent 照 `references/runner.md` 的「被叫停, 被借走」回報. 停好了照「講什麼」交停下來的那一份 (它用的 `status --last`、`tended` 跟 `farmed` 不碰模擬器); 之後碰模擬器的 `ai_coc` 指令一個都不下, 他說可以再從第 1 步開始
- **他在玩**: 他說在玩, 或讀到不是村莊 (`upgrades` 的「讀一次」), 就 `ai_coc stop`, 不留 watch 也不留排程, 照「講什麼」交停下來的那一份, 等他說可以再從第 1 步開始. 每次醒來都會把遊戲登入, 他在手機上玩就會被踢一次. 面板讀不到 (畫面不是村莊, 點「建造」沒開) 也是這樣: 不重試
- **被搶登** (`session_taken`, 打資源的 subagent 回報的、你自己的指令讀到的都算): 不等他說可以, 五分鐘後自己登入回去, 每一種終點都一樣. 照第 2 步重掛 `ai_coc watch`, 睡到現在起五分鐘後, `--about` 寫明在等搶登的五分鐘, 連同原本在等的; 有設排程的話改到同一個時間, 不刪; 跟他講五分鐘後會登入回去. 那五分鐘一個別的 `ai_coc` 指令都不要下: 每個指令開跑時都會重新登入, 把他踢下線. 這時不下 `ai_coc stop` 也不 `giveback`, 跟 `share-emulator` 的「借, 用完還」寫的也不同: 借到打資源的話, 借用會擋住它排著的指令三十分鐘, 比這五分鐘長, 而 `ai_coc stop` 會連剛掛的 watch 一起停掉. 醒來 `due` 就下 `ai_coc launch --restart game`: 被擠掉的對話框還在畫面上時, 別的指令讀到它都會收手 (`refuse_taken`), 重開遊戲才登得回去. 接著照第 3 步重跑 `status` 往下做, 借著的讀完 `giveback`, 打資源的那一趟同一個世界同一組旗標再派. 醒來是 `stopped` 就照第 3 步處理. 每次被搶登都一樣; 他真的要玩會叫停, 照「他叫停」
- **擋住這個圈的** (撞到 bug, 打不動, 模擬器起不來): 不停下來等他, 你自己接. 打資源的 subagent 只回報, 修是你的事. 回不到村莊或讀到不是村莊, 要畫面看得出是擋路的東西 (彈窗、讀錯) 才算; 看不出來就可能是他在玩, 照「他在玩」停. 程式的問題照 `watch-and-fix` 修到 merge, 再照 `share-emulator` 的「merge 進來的修正, 迴圈怎麼用上」接著跑, 要 `uv sync` 的話先 `ai_coc stop watch` 再 sync, 再照第 2 步重掛 (睡著的 watch 佔著 `ai_coc.exe`, sync 會撞 os error 32); 模擬器的問題照 `repair-emulator`, 它說要先問他的 (強制結束程序) 照樣先問; 遊戲改版照 `game-update`, 那時先不打. 修的時候能打的那個世界照打. 修完跟他講修了什麼; `repair-emulator` 說要交給他的才停下來講. 不擋這個圈的記下來照跑, 有空再修
