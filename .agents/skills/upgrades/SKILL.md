# upgrades

升級分兩半: **盯** (工人、實驗室、鐘塔幾點好, 快到時間回來講) 跟 **花** (建築、英雄、研究、戰寵、城牆). 盯的那一趟只讀, 只有好了的那一件預設再升同一件; 這個續升、他交辦時就開口要花, 或者盯到時間問他而他挑了要升的, 才走「花掉資源」那一半.

每個 `ai_coc` 指令都帶 `--agent`、`--session`、`--mission` (`AGENTS.md` 的 Say who is driving), 下面的例子為了好讀省略了.

# 盯著升級

## 這一趟在做什麼

**護盾不盯**: 使用者 2026-10-10 說護盾時間不重要, 不為它讀、不為它醒來、也不為它開船.

## 做完的樣子

使用者收到的是一句回報 (好了的那一件又升下去了) 或一個問題 (同一件升不了, 或是鐘塔), 見「講給使用者聽」, 加上回覆裡一段具體的話. 只在下面幾個時刻出現:

- **他要看的那件事五分鐘後就到**: 睡到它的五分鐘前就問, 不再讀一次時間 (提早講是使用者 2026-10-10 要的; 時間是算好的, 他也說打到一半不會去開藥水). 那一段他拿模擬器或手機玩過的話例外, 見下面「每一趟都從一次新的讀數開始」
- **第一次讀就看到他要看的那塊已經有人閒著, 或鐘塔現在就能開**: 當下就講, 不用排
- **最快的那件超過他交代的範圍**: 直接講還要多久, 不排鬧鐘
- **讀到不是村莊**: 停下來問他玩完了沒 (見「什麼時候收工」)

這一趟只花在一個地方: 好了的那一件再升同一件 (「講給使用者聽」); 其他的要不要花是給他選的題目, 不是你接著做的事. **講完不收工**: 照同一份讀數接著睡下一件, 一路循環到他叫停 (使用者 2026-10-16: 「問完照樣接著盯下一件，一路循環到我叫停」); 什麼時候才收工見「什麼時候收工」.

## 每一趟都從一次新的讀數開始

**之前讀到的時間不沿用** (使用者 2026-10-10 的交代): 他在遊戲裡用寶石加速、開藥水或開了新的升級, 不一定會講. 每一趟開始都重讀; 他講了在遊戲裡動過什麼, 也再讀一次, 排好的計時全部換掉. **他拿模擬器或手機玩過, 就算當作動過**: 醒來先重讀 `status` 再問, 不沿用他玩之前的讀數 (2026-10-15: 神盾勇者他玩的時候就加速好了, 照舊讀數問他那一件, 他得自己指出來).

**開始前先看 `state.json` 的 `watch` 那一塊**: `status` 是 `running` 而它的 pid 還活著, 就是有人在盯. 你被交辦了就照樣開: `ai_coc watch` 會先請那一個收工、把你記成 `stop_by` 再接手, 那一邊醒來讀到是你就收工, 所以一次只有一個在盯, 他不會收到兩份一樣的問題. **它在等的那一件就變成你的** (使用者 2026-10-16 選的, #437): 那一邊醒來不會講話, 你不帶著它, 那一件就沒人盯了. 它的 `about` 寫著在等什麼; 拿你這一趟自己讀到的 `timers` 跟 `clock_tower` 對回那一件, 跟你自己要看的一起排, 醒的時間取最早的, 已經好了或對不上就當下跟他講. 你之後每次開 `ai_coc watch`, `--about` 都把它一起寫上, 直到講完: 下一個接手你的人也只看得到 `about`. 到時候講明這一件原本是誰在盯的 (`caller`); 它講完之前你不收工. 回報講一聲接手了誰、它在等什麼.

## 讀一次

```bash
uv run --no-sync ai_coc status --label watch --agent <名字> --session <session id> --mission "盯升級"
```

它從遊戲自己的村莊匯出 (設定頁那一份) 讀兩個世界每件在跑的升級, 把在跑的藥水跟鐘塔算進去; 遊戲停著的那個世界, 另外讀右下角計數的閒置數字跟倉庫. **不切世界, 不問 Gemini.** `result.json` 的欄位:

- **先看 `export`**: `exported` 才有 `timers` 跟 `clock_tower`. `no_village` 照「什麼時候收工」的不是村莊處理; 其他的 (`settings_shut`、`row_not_found`、`nothing_copied` 之類) 是設定頁那一趟沒走完, 過幾分鐘再讀. 沒讀到的時候 `timers` 是空的, 不能拿來說沒東西在跑
- **`timers`** 由早到晚. `world` 是哪個世界; `role` 是 `builder` (工人)、`lab` (實驗室, 活動多給的研究格也算) 或 `pet` (寵物小屋, 他問才講), `null` 是還沒看過帶時間的那一區, 沒算加速, 回報時講明. `done_at` 是實際幾點好, `seconds` 是從匯出那一刻起還要幾秒, `timer` 是遊戲畫面上寫的正常速度倒數. `name` 是社群對照表的英文名 (沒有的是 `null`), 講給他聽時換成遊戲裡的中文
- **`clock_tower`**: `ready_in` 是 0 就是現在能開, `ready_at` 是幾點能開, `boosting` 是正在跑的那一次還剩幾秒. `null` 是匯出裡沒有鐘塔, 或鐘塔正在升級
- **`builder` / `lab`** 是遊戲停著那個世界右下角計數的數字, 另一個世界的讀不到, 不為它開船. `outcome`: `counted` 讀到了; `unread` 數字讀不到, 過幾分鐘再讀; `not_a_village` 畫面不是村莊, 兩個都是就見「什麼時候收工」
- **工人學徒跟研究助手會讓掛著它們的那件比 `done_at` 早好, 目前不算** (使用者 2026-10-10 決定先跳過)

## 算出時間, 不要輪詢

他要看的每一件 (`timers` 裡 `world` 跟 `role` 對得上的) 跟鐘塔取**最早**的. 睡到它的**五分鐘前**, 醒來就講. **不管多遠都睡**, 跟著打資源來的也一樣 (使用者 2026-10-16 拿掉了只睡八小時內的限制: 「你是完全可以自己安排打資源 自己安排升級 自己借用模擬器 升級完繼續打資源之類的」). 睡超過八小時的, 跟他講一聲這台電腦跟這個 session 要一直開著: 斷了 `ai_coc watch` 就不會叫醒任何人. **鐘塔每次都盯**, 不用他交代 (使用者 2026-10-10 要的, 鐘塔每天能開一次, 以後要做成自動開); 講過「現在能開」之後就不再算進最早的那一個, 直到之後的讀數又是 `ready_in` 大於 0. 講完就照同一份讀數排下一件, 不用重讀.

**睡在 `ai_coc watch` 上, 它就是計時器**: `uv run --no-sync ai_coc watch --next <醒來的時間, ISO> --about "<在等什麼>"` (帶 `--agent`、`--session`、`--mission`), 用 runtime 自己管的背景執行開 (`.agents/skills/farm/references/running.md` 的「開跑」). 它睡到 `--next` 才結束, 結束的通知就是叫醒你的那一下; 睡的時候它記在 `state.json` 的 `watch` 那一塊, 別的 agent 看得到有人在盯, `ai_coc stop` 也停得到它. 它不碰模擬器. 不要另外排 sleep 或排程: 以前記錄跟計時是兩件事, 2026-10-11、10-12 都有 agent 只記了一筆就結束回合, 到點沒有人回來.

**醒來先看它的輸出** (`WatchReport`, 跟那次的 `result.json` 是同一份): `outcome` 是 `due` 就是時間到了; 是 `stopped` 就是有人叫停或接手了, `stop_by` 是誰、他的 `mission` 是為什麼, 什麼都不講, 直接收工. 例外是 `stop_by.session` 是你自己的: 那是你重讀時間後開的新 watch 接手了舊的, 照常等新的那個. 另一個例外是它睡著是為了花他交辦的東西 (見「講給使用者聽」): 那一筆還沒花, 回覆裡講一聲沒花成、是誰接手的. 輸出只有一行說 `state.json` 不在 (exit code 不是 0) 的話, 它根本沒睡: 先跑一個會操作模擬器的指令 (例如 `status`) 再開一次.

要再讀之前 (讀不到要重來, 或他說動過遊戲) 照 `AGENTS.md` 的 Look before driving 先看 `state.json`: 模擬器上可能已經有別的 run 在跑, 這時下 `status` 會借走它 (它帶 `--yield` 的話), 讀完馬上 `uv run --no-sync ai_coc giveback` (使用者叫停時例外, 見 `.agents/skills/farm/references/running.md` 的「用完一定要還」), 不然它要等 30 分鐘才接回去 (見 `.agents/skills/farm/references/running.md` 的「絕對不要同時跑兩個」).

**不要每十分鐘戳一次**, 這是使用者自己否掉 `--watch` 的理由: 等待是算術不是觀察, 而 `--watch` 那種在程序裡睡的迴圈佔住的是模擬器那一塊, 讓別的 session 以為模擬器在忙 (`ai_coc watch` 睡在自己那一塊, 不佔模擬器). 一整晚一次讀取, 不是四十八次; 只有讀不到的時候 (上一節說過要再讀的那幾種) 過幾分鐘再讀.

## 講給使用者聽

**要他選的時候發問, 不只推播** (使用者 2026-10-11: 有些 agent, 例如 Antigravity, 只有發問才彈得出通知): 用 runtime 自己問使用者的工具. 有些 runtime 發問時整個回合停在那裡等回答, 所以先把下一件的 `ai_coc watch` 丟到背景、借來的模擬器 `giveback`, 再問.

問法:

- **到點的那一件預設就再升同一件, 不問** (使用者 2026-10-16: 「默認用 繼續升級 例如，女皇升級完了，可以直接繼續升級女皇 如果要升級別的我會另外跟妳說」; 他說這跟打資源、刷牆、打資源那個圈是同一回事, 只是升得久): 工人、實驗室、戰寵小屋都一樣, 英雄也算他指名過. **`farm` 的「打到有空閒」那一趟不續升**: 他要的是空出來的那一刻的通知, 續升會把那個空位又派出去. 五分鐘前醒來時那一件還沒好, 所以把 `ai_coc watch` 改睡到它的 `done_at`, 醒來照「花掉資源」在面板上找同一件升下去, 升完講一聲升了什麼、花了多少, 再回去打資源 (「花完了就回去打」). 他另外講了要升別的, 照他講的
- **同一件升不了才問** (到頂了、被大本營卡住、紅字買不起、面板上找不到它), 第一次讀就看到有人閒著 (沒有剛好的那一件可續) 也是這樣問, **工人、實驗室、戰寵小屋**: 打開「建造」面板那個分頁讀「建議升級」(怎麼開、怎麼讀見「面板」), 每一列 (名字、價錢、資源) 列成一個選項, 再加「其他 (自己填名字)」跟「先不要動」. 讀完先把面板關掉、`giveback`, 再問. 他填了名字, 就到同一個分頁往下捲找那一列, 找不到 (或是鎖著的) 再回來問他. 要好的是另一個世界的就不開船去讀, 只問要不要現在處理, 問題裡講明為什麼沒有清單
- **鐘塔**: 還沒有能替他做的事, 選項只放一個「知道了」, 這一問是為了把通知彈出來
- **面板讀不到** (畫面不是村莊, 點「建造」沒開): 他可能正拿手機在玩, 不重試, 不列清單照樣問, 問題裡講明. 是另一部裝置登入的話照 `AGENTS.md` 的 Driving the game, 他說可以之前什麼都不再跑

他挑了要升的, 照「花掉資源」那一半做. 工人還沒空出來的話, 睡到那一件的 `done_at` 再花. 同一時間只有一個 `ai_coc watch` (新開的會把舊的請下來, 你自己開的也一樣), 所以不要另外開一個: 把排好的那一個換成 `--next` 取這個 `done_at` 跟下一件該醒的時間較早的那一個, 醒來先做到點的那一件. 花完重跑一次 `status` (升級本身就改了時間), 照新的讀數排下一個.

問題裡要具體: 哪個世界、什麼幾點好、到時會空出幾個. 遊戲停著的那個世界講得出閒幾個 (`free` 加上這次要好的件數) 跟倉庫多滿 (`stock`); 另一個世界只講這次要好幾件, 不為它開船. 鐘塔就講幾點能開.

**runtime 沒有發問的工具才改發推播**: 推播回 not sent 多半是他就在終端機前, 所以要講的也一定寫在回覆裡 (規矩在 farm 的「通知跟要他拍板的事」).

## 什麼時候收工

- **問完、升完都不收工**, 接著睡下一件 (「做完的樣子」). 沒有東西可等了才收工: 他要看的那幾塊沒有一件在跑, 鐘塔也講過了. `farm` 的「打到有空閒」那一趟例外: 空出來講完就是終點
- 他說停: 下 `ai_coc stop`, 一次就停掉你睡著的那個 `ai_coc watch`, 連同模擬器上在跑的指令; 你剛好借著模擬器 (在讀 `status`) 的話, 照 `.agents/skills/farm/references/running.md` 的「中止」等指令停了再下一次, 才取消借用
- **讀到一次不是村莊就停**: `export` 是 `no_village`, 或兩個計數的 `outcome` 都是 `not_a_village`. 常見的原因是使用者正在手機上玩, 模擬器那邊被登出了, 而每跑一次 `ai_coc status` 都會經過 `ensure_coc` 把遊戲搶回來, 等於把他從手機上踢掉 (`AGENTS.md` 的 Driving the game). 所以不重試: 停下來, 問他玩完了沒 (見「講給使用者聽」), 他說可以了再讀. 看欄位不要看句子, 那句話只在 `run.log` 裡
- **另一部裝置登入了**: `status` 兩種都不回, exit code 不是 0, `result.json` 只有一句 `另一部裝置登入了這個帳號,沒有把登入搶回來`. 一樣停下來告訴他, 他說可以之前一個 `ai_coc` 指令都不要下 (`AGENTS.md` 的 Driving the game)

# 花掉資源

把打回來的資源變成村莊的進度. **建築、英雄、研究、戰寵都走右下角的「建造」面板**: 你自己看圖找到那一列, 點下去跳出確認視窗, 最後那一下交給 `ai_coc confirm`. **城牆也從面板進去**, 付錢交給 `ai_coc confirm --pay` (見「城牆」); 牆都升滿時面板上不會列牆.

這裡是 `farm` 那個圈 (打到滿 → 花掉 → 回去打) 的另外半邊; 什麼時候該花, 什麼時候停手通知人, 在 `.agents/skills/farm/SKILL.md`.

## 做完的樣子

使用者最後拿到的是**一句話的回報, 加上你看過的每一張圖**. 回報照他問的是什麼:

- **只問多少錢, 建議升級有哪些**: 答案本身, 名稱、等級、價格連同是哪一種資源; 紅色的 (買不起) 照讀. 什麼都不花
- **要升, 升成了**: 升了什麼, 花了多少, 現在剩多少
- **要升, 沒升成**: 卡在工人 (或實驗室、戰寵小屋) 全忙, 卡在錢, 還是面板上找不到那一列, 這三種的下一步完全不同, 要講是哪一種
- **英雄他沒指名是哪一個**: 讀出來的價格列給他挑, 不替他挑 (見「哪些不用問, 哪些要」)

**不要編數字**: 花了多少以前後兩次看到的倉庫差額為準, 不是標價. 差額跟標價對不上, 或者你沒動手倉庫卻少了, 多半是使用者自己在遊戲裡花的, 照實寫進回報就好, 不要為它問他: 金幣、聖水、黑水打得回來, 沒有成本 (使用者 2026-10-15 的交代).

**要盯的是寶石, 那是真錢.** 開工那張圖 (`view --zoom out` 之後的 `capture`) 跟收尾時 `view --zoom out` 之後、`giveback` 之前 `capture` 的一張 (還了之後打資源的迴圈馬上開打, 寶石數就被蓋住了), 各讀一次右上角的寶石數. 少了就停手, 不再點任何東西, 馬上回報, 附那兩張圖.

**每一張你看過的圖都發一份給使用者**, 用檔案傳送機制, 不要只留路徑.

**畫面要停在乾淨的村莊**: 面板跟確認視窗都關掉, 見「收尾」.

**從 `farm` 那一圈接過來的** (他開口要打到花不掉), 這裡花掉的寫進 `farm` 回報裡花費那一行; 做完接回去打, 見「花完了就回去打」.

## 先確認在哪個村莊, 有沒有空

```bash
uv run --no-sync ai_coc world      # 回 day / night, 不點東西
uv run --no-sync ai_coc status     # 兩個世界每件升級幾點好, 加上這個世界閒著幾個
```

兩個世界的建築、兵種、英雄完全不同, 要升的在另一邊就先 `world --go`. **工人、實驗室、戰寵小屋各自要有空才買得了**: 全忙的時候遊戲照樣讓你打開確認視窗, 按下去它跳「所有建築工人都在忙碌中！」跟一顆寶石按鈕 (2026-10-15 在夜世界量到), `confirm` 回 `unexpected` 不再按任何東西. 所以先看計數: 面板每個分頁上就寫著空閒數/總數, 開了面板看那個就夠, 不用另外跑 `status`; 計數只算遊戲停著的那個世界. 沒空就不要走到 `confirm`. 讀價格不受這個限制, 全忙也照樣開面板讀回來. 他直接要升的東西卡在全忙, 就講幾點空出來, 問他要不要到時候替他升 (要的話睡在 `ai_coc watch` 上, 醒來照這一節做).

## 面板

```bash
uv run --no-sync ai_coc view --zoom out       # 先借到模擬器, 鏡頭停好
uv run --no-sync ai_coc capture               # 一張現在的畫面
uv run --no-sync ai_coc tap 1495 800          # 「建造」, 回一張點完的圖
uv run --no-sync ai_coc swipe 1385 740 1385 240   # 面板往下捲大約一頁 (7 列)
uv run --no-sync ai_coc confirm --price 10800 # 確認鈕上的價格要是這個才按
```

**每個指令都帶同一個 `--session`** (還有 `--agent`、`--mission`): 少帶一次, 那一步一結束就把借用還回去, 打資源的迴圈會在你兩步之間插進來.

**`view --zoom out` 是第一步**: 背景有打資源的迴圈時, 它會等迴圈打完手上那一場再借走模擬器, 所以座標要從它之後截的圖 (`capture`) 量, 不要從借到之前的畫面量. 之後的 `tap`、`swipe`、`confirm` 都在這次借用裡, 不會再等. 用完照 `.agents/skills/farm/references/running.md` 的「你自己要用畫面」`giveback`.

**`tap` 跟 `swipe` 每次都回一張點完的圖** (`result.json` 的 `frame`), 下一步看那張決定, **永遠照最新那張圖上的位置點**: 面板捲過、視窗開關過, 舊圖上的座標就不準了. 它們會拒絕幾種會花錢或毀掉東西的點法 (`outcome`): 確認視窗開著時只准點它右上角的 X; 遊戲對話框只准按取消; 商店跟加號那排不點 (面板開著時那排往左移, 一樣不點); 面板上正在升級的列不點; 大顆的綠色按鈕不點 (確認、立即完成、寶石補位都是綠的; 面板沒開時整個畫面都算, 開著時算面板左邊); 建築選單那一排只要有「立即完成」就整排不點 (旁邊的「取消」會把在升的取消掉); 戰鬥中什麼都不點. 被拒絕的那張圖就是當下的畫面.

**面板長這樣** (2026-10 改版之後): 主村底下四個分頁, 從左到右「建築和英雄」(工人, 約 1222, 850)、「軍隊升級」(實驗室, 約 1330, 850)、「英雄裝備」(鐵匠鋪, 用礦石, 不碰)、「英雄戰寵」(約 1547, 850); 夜世界只有工人 (約 1277, 850) 跟實驗室 (約 1492, 850) 兩個. 面板打開時停在上一次看的分頁, 看圖上哪一個是亮的, 不是要的就點它. 每個分頁上寫著空閒數/總數. 分頁上方由上往下:

1. **正在升級的列**: 整列是綠色進度條加倒數. **絕對不要點** (`tap` 也會拒絕): 主村的英雄跟戰寵會跳「正在將X升至N級」, 綠色按鈕是用寶石的「立即完成」; 夜世界的建築會被選起來, 跳出資訊、取消、立即完成那一排
2. **建議升級**: 遊戲挑的幾列, 每列有名字、時間、價格跟資源圖示. 剛升完的英雄常出現在這裡, 但不保證
3. **其他升級**: 其餘每一樣能升的, 先黑水再聖水再金幣, 各自由貴到便宜. 標了 `x N` 的是同等級的 N 棟, 點下去開其中一棟. 最後面帶鎖頭的是還不能升的 (寫著要先升什麼)

往下捲一次大約七列; 捲完的圖跟上一張一模一樣就是到底了. 建築和英雄分頁大約要捲九次, 軍隊升級七次, 戰寵兩次.

## 點那一列, 然後按下去

1. 在最新那張圖上找到那一列, `tap` 它的名字
2. 回來的圖是確認視窗, **先讀標題**: 主村是「將X升至N級？」, 夜世界是「是否提升至N級？」加上視窗裡的建築名 (英雄的視窗沒寫名字, 畫的是英雄本人, 確認鈕在右下). 不是要的那個, 或者是「正在將…」, 就 `tap` 右上角的 X (主村約 1413, 70; 夜世界約 1340, 57) 關掉, 回面板重找. 這一步什麼都不花
3. 讀確認鈕上的價格, 應該跟那一列寫的一樣. 有折扣時是黃字, 下面劃掉的是原價; 列上寫的也是折扣後的價錢, 給 `confirm` 的就是這一個
4. `ai_coc confirm --price <那一列的價格>`. 它自己再讀一次按鈕: 是金幣、聖水或黑水的圖示, 價格一模一樣, 不是紅字, 才按, 而且只按一次

`confirm` 的 `outcome`:

- `confirmed`: 按了, 視窗關了. 看它回的圖: 面板會回來, 那一項出現在正在升級的列裡, 左邊倉庫條的數字少了 (面板開著時倉庫條整排往左移)
- `price_mismatch`: 按鈕上的價格跟你給的不一樣 (`offer` 是它讀到的), 什麼都沒按. 多半是點錯列, 回第 2 步
- `not_a_resource`: 按鈕不是資源價格, 是寶石 (點到正在升級的列) 或讀不出來, 什麼都沒按
- `cannot_afford`: 紅字, 資源不夠, 什麼都沒按. 按下去遊戲會叫你用寶石補差額
- `no_sheet`: 畫面上沒有確認視窗
- `refused_by_game`: 按了之後遊戲跳兩顆按鈕的對話框, 它已經按了取消; 看回來的圖還剩什麼, 照「收尾」收乾淨
- `unexpected`: 按了之後出現別的畫面, 它沒有再按. 最常見的是「所有建築工人都在忙碌中！」跟一顆寶石按鈕: `tap` 它右上角的 X 關掉 (寶石按鈕 `tap` 會拒絕), 回報卡在工人全忙
- `sheet_stayed`: 按了但確認視窗沒關, 沒有再按. 看圖, 不懂就停下來給使用者看
- `no_wall_menu` (只有 `--pay`): 面板左邊沒有選著城牆的選單, 或已經有視窗、對話框蓋著, 什麼都沒按. 你自己先 `tap` 了升級鈕的話, 確認視窗已經開著, 改用不帶 `--pay` 的 `confirm`
- `sheet_disagrees` (只有 `--pay`): 按了城牆的升級鈕, 跳出的確認視窗價格或資源跟按鈕不一樣, 視窗留著沒按: `tap` 它的 X, 重讀選單
- `no_confirmation` (只有 `--pay`): 按了城牆的升級鈕卻沒跳出確認. 看圖: 牆到了大本營的上限時, 遊戲跳的視窗確認鈕是灰的, `tap` 它的 X, 這種牆要等大本營升上去

帶 `--pay` 時 `price_mismatch` 跟 `cannot_afford` 說的是城牆選單上那顆升級鈕 (`wall`), 它也一樣沒按.

借用要留到畫面收乾淨才還: 還了之後打資源的迴圈會接著跑, 留著的視窗會擋住它.

**確認鈕永遠只用 `confirm` 按, 不要用 `tap` 點它**, `tap` 也會拒絕. 確認視窗左邊另一顆「確認」是用魔法道具 (建築之錘、戰鬥之錘、英雄之錘) 付的, 任何情況都不點.

## 收尾

升完或不升都把畫面收乾淨: 確認視窗 `tap` 它的 X, 面板 `tap` 右上角的紅色 X (約 1572, 30). 面板關了那棟 (或那面牆) 還是選著的, 畫面下方留著它的選單; 先 `tap` 一塊空地 (不是建築、不是按鈕) 取消選取, 看回來的圖那排選單不見了, 才 `ai_coc view --zoom out` 把鏡頭停回去 (點一列會把鏡頭移到那棟建築): 選著的時候 `view` 只拉遠不停鏡頭, 回 `selected`: 它的拖曳會從選單的按鈕上開始而拖不動鏡頭 (2026-10-15 在夜世界量到), 剛好從選著的建築上開始的話, 可能會把它拖到別處 (沒量過, 不要試). 最後 `giveback`, 自己一步.

## 哪些不用問, 哪些要

**這一節的前提是他這一趟開口要花, 或者是好了的那一件預設續升** (「講給使用者聽」), 開口是他講的, 不是你判斷出來的 (farm 的「倉庫滿了」那節). 只問多少錢、有哪些的, 什麼都不花.

- **城牆: 要使用者指名, 預設不刷.** 使用者 2026-09-15 的常設交代, 原話是「默認是不升級牆壁, 除非我說」. 籠統的「把資源花掉」不算指名到牆
- **建築: 工人閒著就不用問**, 滿倉加上發呆的工人是雙重浪費. 他沒指名的時候, 挑「建議升級」裡買得起的, 回報講挑了什麼
- **英雄、研究、戰寵: 要使用者指名.** 升級中的英雄不能上場, 升一個是拿接下來幾天的進攻火力去換; 研究跟戰寵挑哪個也是他的取捨. 讀出價格列給他挑 (規矩在 `farm` 的「通知跟要他拍板的事」)

**寶石跟現金在任何情況下都不碰**, 魔法道具也不碰.

## 城牆

**兩個世界都從面板進去** (使用者 2026-10-15 要的). 在夜世界量過; 他的日世界牆都升滿了, 照他說的先假設日世界一樣.

1. 工人分頁 (主村的「建築和英雄」) 的「其他升級」裡有一列「城牆 x N」, 寫著一面的價格. 這一列標的是金幣還是聖水會變 (2026-10-15 夜世界聖水多的時候排在聖水區, 金幣多了之後換到金幣區), 兩區都要找. `tap` 它, 鏡頭跳到一面那個等級的牆並選起來, 面板不關; 再點一次會換一面同等級的牆
2. 面板左邊出現城牆的選單: 「資訊」「整排選取」「升級更多」跟兩顆升級鈕, 左邊金幣、右邊聖水, 價格一樣. 有時分兩排 (升級鈕在下排), 有時五顆排成一排, `confirm --pay` 兩種都認
3. 只升一面就跳到第 4 步. 錢夠買好幾面就用批次, 不要一面一面升 (使用者要的). 一次升好幾面: `tap`「升級更多」, 前三顆變成「移除城牆」「新增城牆」, 每按一次「新增城牆」多一面同等級的牆, 升級鈕上的價格跟著加上去 (兩面就是兩倍). 先算好要加幾面 (一面的價格乘上面數, 不要超過倉庫); 價格變紅字就是加過頭了, `tap` 面板上城牆那一列重新選一面, 少加一面重來
4. `ai_coc confirm --price <升級鈕上的價格> --pay gold` (或 `elixir`). 它自己讀那顆鈕, 價格一模一樣、不是紅字才按; 一面的會跳確認視窗, 它再對一次價格才按; 好幾面的會跳「升級城牆／是否確定要花費…」的對話框, 它按確定. **升級鈕不要自己 `tap`**: 那樣跳出來的對話框它不會按, `tap` 也只准按取消
5. 看它回的圖, 要再升就從第 1 步再點一次城牆那一列

**「整排選取」不是升級**, 是搬移城牆的模式, 進去之後只有一顆「整排旋轉」, 按下去會把整排牆轉向, 改到村莊的佈局. 兩顆都不要點; 不小心進去了, `tap` 面板上城牆那一列就會退出來.

**牆跟建築搶同一個工人**: 牆付錢當下就升好、工人立刻還回來, 建築把工人綁住好幾天, 所以他指名要刷牆的那一趟, 牆先刷, 刷不動了才升建築. 全忙的時候一面都買不了, 按下去遊戲跳「所有建築工人都在忙碌中！」跟寶石按鈕, 跟建築一樣是 `unexpected`, `tap` 它的 X.

**牆先刷, 但先把下一件要升的錢留下來**, 不然牆會把它吃光 (使用者 2026-10-16 定的流程). 牆刷完要接著升東西的那一趟才留; `farm` 那個循環刷牆到他說停的圈, 刷完牆本來就不升建築, 不留:

1. 刷之前先在面板讀下一件要升的東西要多少、哪一種資源, 那一筆不動. 他沒說是哪一件, 就是剛升完、空出工人的那一件的下一級 (2026-10-16 戰爭機器剛好, 就留它下一級的 2 240 000 聖水); 不知道剛升完的是哪一件 (從 `farm` 接過來的多半不知道), 就是第 4 步照「哪些不用問, 哪些要」會挑的那一列
2. 扣掉預留, 剩下的金幣跟聖水拿去刷牆, 兩種各算各的: 一種能刷幾面是它可用的量除以一面的價格
3. 夜世界接著領聖水車: 先照「收尾」關面板、取消選取 (牆還選著的話, `collect` 停鏡頭的拖曳會從選單上開始而拖不動), 再 `ai_coc collect`, 倉庫有空它就倒進來. 一樣留著預留, 多出來的再刷一批. 日世界對應的是去部落城堡拿資源, 還沒做, 先跳過
4. 最後升那一件. 要不要升照「哪些不用問, 哪些要」: 建築工人閒著就升, 英雄要他指名

「升級更多」之後的按鈕數會變: 同等級的牆還很多時多一顆「新增城牆 +10」(2026-10-16 剩 14 面時有, 剩 10 面時沒有), 後面每顆都往右挪. 每按一下都照它回的那張圖找「+1」.

## 花完了就回去打

**從 `farm` 那一圈接過來的, 做完就回 `farm`**: 空的倉庫可以再打滿, 而他開口要花的那一趟, 要的是打到花不掉為止. 這個圈**沒有寫在程式碼裡**, 交接是你在做的. **升完一樣回去打** (使用者 2026-10-16: 「升級完畢要繼續幫我打資源」), 他直接叫你升某一樣東西的那一趟、好了再升同一件的那一趟都算: 交回報, 借來的模擬器 `giveback`, 打資源照 `farm` 開回去.

**真的花不掉的時候才停手通知使用者.** `confirm` 回 `cannot_afford` 是錢花完了, 不是花不掉. 三種卡法 (工人全忙 / 牆被大本營卡住 / 黑水只有英雄能消化) 各自的下一步在 `farm` 的「倉庫滿了」那節.
