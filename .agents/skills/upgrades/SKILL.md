# upgrades

一次性的升級: 答他問的升級狀況, 把他指名的東西升下去, 或開鐘塔, 做完就結束, 不睡著等時間到. 每個 `ai_coc` 指令都帶 `--agent`、`--session`、`--mission` (`AGENTS.md` 的 Say who is driving), 下面的例子為了好讀省略了.

## 做完的樣子

使用者拿到的是一段回覆, 照他問的是什麼:

- **問升級狀況**: 照「問狀況」的表
- **只問多少錢, 還能升的有哪些**: 答案本身, 名稱、等級、價格連同是哪一種資源. 從 `ai_coc search` 答 (「問狀況」的最後一段), 講明那是牌價; 他要今天實際的價格才開面板讀, 紅色的 (買不起) 照讀. 什麼都不花
- **要升, 升成了**: 升了什麼, 花了多少, 現在剩多少
- **要升, 沒升成**: 卡在工人 (或實驗室、戰寵小屋) 全忙, 卡在錢, 還是面板上找不到那一列, 這三種的下一步完全不同, 要講是哪一種. 全忙的講幾點空出來 (`status` 的 `done_at`), 並問他要不要到時候替他升; 他要的話那是一趟跨時間的事, 這份不睡著等
- **英雄、研究、戰寵他沒指名是哪一個**: 讀出來的價格列給他挑, 不替他挑 (見「哪些不用問, 哪些要」)

**不要編數字**: 花了多少以前後兩次看到的倉庫差額為準, 不是標價. 差額跟標價對不上, 或者你沒動手倉庫卻少了, 多半是使用者自己在遊戲裡花的, 照實寫進回報就好, 不要為它問他: 金幣、聖水、黑水打得回來, 沒有成本.

**要盯的是寶石, 那是真錢.** `tap`「建造」之前跟收尾之後、`giveback` 之前 (還了之後打資源的迴圈馬上開打), 各讀一次寶石數: `ai_coc stock` 的 `gems`, 或 `status` 在遊戲停著那個世界那一行印的「寶石 N」 (動手前剛跑過 `status` 就用它). 是 null 或那一行沒印, 就是那一刻右上角讀不到, 再跑一次 `stock`. 少了就停手, 不再點任何東西, 馬上回報兩次讀到的數; 這一趟照「哥布林」付過寶石的, 少的要剛好是付的那個數, 多少了才算.

**畫面停在乾淨的村莊**, 借來的模擬器還回去: 見「收尾」.

## 問狀況

**升級狀況不主動列, 他問了才列.** 不借模擬器重讀: `ai_coc status --last` 從最新那份村莊匯出 (`~/.ai_coc/account_json/` 裡, 每次 `status` 跟 `export` 都存當天那份) 印兩個世界每件在升的, 不碰模擬器也不佔鎖, 照貼就是答案: 每個世界一張表, 欄位是時間、目標 (工人、實驗室、戰寵, 哥布林那格加「(哥布林)」)、項目 (遊戲的中文名, 括號裡是正在升到的等級/滿級, 被大本營或殿堂卡在滿級以下的再寫上限), 鐘塔是夜世界的一列. 表上只有事實; 他問到好了以後能不能再升、會接著升什麼, 從括號裡的等級跟這份 skill 的規矩自己判斷再講. 時間照現在算, 匯出之後已經好了的那一列寫「(已過)」; 沒算加速的那一列寫「(沒算加速)」, 沒算助手的寫「(沒算助手)」, 回報時講明. 那份匯出之後他說在遊戲裡動過, 或拿模擬器、手機玩過, 才照「讀一次」重讀. 他只問某一樣 (「多人箭塔幾點好」), 照下面「他問某一樣」那段用 `ai_coc search` 就好, 不用列整張表.

**他問一段時間裡升了什麼** (例如「這個月升了哪些」): `ai_coc growth --start-date <YYYY-MM-DD> --end-date <YYYY-MM-DD>`, 兩個日期不給就是存下的最舊跟最新那份; 它只讀 `~/.ai_coc/account_json/` 裡一天一份的匯出, 不碰模擬器, 列的是工人跟實驗室升的 (戰寵、英雄裝備不算), 名字是遊戲裡的中文. 要新到這一分鐘就先跑一次 `status`.

**他問升級從到點到按下確認花了多久**: `ai_coc turnaround [--since <時間>]` (跟 `tended`、`farmed` 一樣是 ISO, 只給日期就從那天零點), 依王、實驗室、建築、戰寵印次數、中位數、平均跟最近十次, 哥布林那格跟城牆不算; 只讀 `runs.jsonl` 跟各次的 `run.log`, 不碰模擬器. 他問了才跑, 不放進任何流程.

**他問某一樣現在怎樣、滿級是幾級、能不能再升、下一級要多少錢多久**: `ai_coc search <中文名或英文名的一段, 或 data_id>`, 不碰模擬器也不佔鎖, 只讀存下的遊戲表跟最新那份村莊匯出 (上一次 `status` 或 `export` 存的; 要新到這一分鐘就先 `status`). 名字對得上的全部列出, 現在能升的照下一級的牌價時間由短到長排前面, 其他的村莊裡有的在前, 村莊還沒有的也查得到. 名字是遊戲自己的寫法, 不是平常的叫法 (地獄之塔, 「地獄塔」查不到), 對不上就給短一點的一段 (`地獄`). 它印的是中文摘要, 下面這些欄位在那次執行的 `result.json`. 每一種的 `max_lvl` 是遊戲的滿級; `owned` 是各幾級幾個, `upgrading` 是哪幾個在升、`done_at` 幾點好、`extra` 是不是哥布林那格; `limited_lvl` 是現在大本營 (或實驗室、英雄殿堂這些, 等級在匯出檔頂上的 `halls`) 最多讓它升到幾級, `next` 是各個下一級, 幾個等級不同的就各一個 (`lvl`、`cost`、`time` 是要的秒數; `ready` 是現在就能開工的有幾個, `waiting` 是正在升、要等它做完才輪到的有幾個, 卡在上限的兩個都是 0; 滿級的沒有). `next.lvl` 大於 `limited_lvl` 就是被殿堂卡住, 印出來的那一行會寫「上限 N 級」. `levels` 是遊戲表上每一級的 `needs`、`cost`、`time`, 買到那一級要的; 兵種、攻城機器跟法術的第一級是解鎖的, 不是研究的, 它的 `needs` 是訓練它的那一棟 (訓練營、闇黑訓練營、攻城機器工坊、法術工廠、闇黑法術工廠、建築大師訓練營) 要幾級, 之後每一級才是實驗室. 村莊還沒有的, 印出來那一行寫解鎖要哪一棟幾級、村莊裡現在幾級 (`unlock`). 超級兵種跟活動兵種的解鎖條件讀到的表裡沒有 (超級兵種看的是它的基本兵種幾級), 所以只印「村莊裡沒有」: 那只是最新那份匯出沒有它, 不代表他還沒解鎖. 同一種好幾棟、等級跟完成時間各不同, 加 `--rows` 每一列分開列. 回 `no_tables` 是還沒存過遊戲表: 先跑 `ai_coc gamedata`, 只從模擬器讀遊戲檔, 不碰畫面也不佔鎖. 價格跟時間都是遊戲表上的牌價, 活動跟金券會打折, 實際可能只要一部分, 真要買照面板上寫的那個價格給 `confirm` (「點那一列」第 3 步).

**他問還能升的有哪些, 或你要挑一件來升**: 不給名字, 給 `--section` 就列村莊裡有的, 照建造面板的分法: `builder` 是工人升的 (建築、英雄、陷阱、守護者), `lab` 是實驗室研究的 (兵種、法術、攻城機器), `pets` 戰寵, `equipment` 英雄裝備 (用礦石), `helpers` 助手 (用寶石), `all` 每一類. 印出來日世界、夜世界各一段, 每段照分類排, 每一類裡現在能升的照下一級的牌價時間由短到長排在前面; `--day` 或 `--night` 只留一個世界, `--skip-max-lvl` 不列已經升到遊戲滿級的 (被大本營或殿堂卡住的照列, 註明上限), 再給名字就在裡面找, 這幾個可以任意搭:

```bash
uv run --no-sync ai_coc search --section builder --day --skip-max-lvl   # 日世界工人那一格還能升的
uv run --no-sync ai_coc search --section all --night                    # 夜世界的每一類
```

能升的是「下一次」那一行寫著「現在能升 N 個」的, N 是現在就能開工的有幾個; 寫「上限 N 級」的被大本營或殿堂卡住, 只寫「要等手上的升級做完」的正在升. 每一種那一行寫著它是哪一類 (英雄、建築、兵種…), 分類名跟旗標 `ai_coc search -h` 都列著.

## 讀一次

```bash
uv run --no-sync ai_coc status --label watch
```

它從遊戲自己的村莊匯出 (設定頁那一份) 讀兩個世界每件在跑的升級, 把在跑的藥水跟鐘塔算進去; 遊戲停著的那個世界, 另外讀右下角計數的閒置數字跟倉庫. **不切世界, 不問 Gemini.** 先照 `share-emulator` 的「開工先讀 `state.json`」: 背景有帶 `--yield` 的迴圈在跑時, `status` 會借走它, 讀完馬上 `ai_coc giveback` (自己一步; 使用者叫停時例外, 見 `share-emulator` 的「借, 用完還」), 不然它要等 30 分鐘才接回去.

它印的就是 `takeover` 報告跟上面「問狀況」要的那一段, 欄位在那次的 `result.json` (加 `--json` 就印成 JSON):

- **第一行是村莊匯出**: 讀到了寫匯出的時刻; 寫「村莊匯出沒讀到」的是設定頁那一趟沒走完 (`result.json` 的 `export` 不是 `exported`), 底下就沒有表, 不能拿來說沒東西在跑, 過幾分鐘再讀
- **每個世界一段**, 日世界在前. 遊戲停著的那個世界那一行是倉庫 (括號裡是容量的百分比, 超過 100% 是真的, 儲值送的會超過上限)、寶石數跟右下角計數的「閒幾個/總共幾個」, 日世界再加護盾 (不用講, 見 `takeover` 的「護盾不盯」), 讀不到的寫讀不到; 另一個世界寫遊戲停在哪邊、這次沒讀, 不為它開船
- **表**由早到晚: 「時間」是實際幾點好 (`done_at`, 藥水跟正在做的助手算進去了), 「目標」是工人、實驗室 (活動多給的研究格也算) 或戰寵, 哥布林那格 (`extra`) 加「(哥布林)」, 工人學徒或實驗助手正在做的那件加「(建築工人學徒幫到今天 18:36)」, 是它這一趟做到幾點; 「項目」是遊戲自己的中文名 (`zh`), 同一種同一級同一種格子幾分鐘內先後好的併成一列 ×N, 括號裡是正在升到的等級/遊戲的滿級 (`max_lvl`), 現在大本營或殿堂最多讓它升到的 (`limited_lvl`) 比滿級低就寫「上限 N」. 名字是 `#` 加數字的, 是遊戲的表沒讀到, 不要自己翻, 看一張面板的圖. 好了以後能不能再升不印, 由你看括號判斷: 升到的等級等於滿級或上限就不能. 鐘塔那一列是幾點能開 (`clock_tower.ready_at`), 「現在」就是現在能開; 鐘塔在升級或匯出裡沒有鐘塔就沒有這一列. `result.json` 另外有 `seconds` (從匯出那一刻起還要幾秒)、`timer` (遊戲畫面上寫的正常速度倒數)、`next` (這一級升完之後的下一級跟牌價)
- **「助手」那一行**: 建築工人學徒跟實驗助手各一項, 寫「現在能派」或幾點能派. 現在能派的就在下一次回話裡順口講一句, 講過就不再重講, 等它下一次冷卻完; 不幫他派, 也不為它推播
- **主村工人的總數 5、6、7 都正常, 實驗室 1 或 2 也是**: 工人常駐 5 個, 夜世界的巴布控制台解鎖之後常駐 6 個 (第六個是普通工人, 不用寶石; 使用者的帳號已經解鎖), 活動的哥布林工人再多 1 個; 實驗室常駐 1 格, 活動的哥布林研究員再多 1 格. 總數不拿來判斷有沒有空, 只看閒置數 (哥布林那格要寶石, 見「哥布林」)
- **工人學徒跟實驗助手正在做的那件, `done_at` 已經算進去**: 倍率是 `status` 自己照它的等級從遊戲的表讀的, 不用你查 (2026-11-12 量過: 學徒 8 級讓藥水的 10 倍變 18 倍, 助手 12 級讓 24 倍變 36 倍). 只算它這一趟還剩的時間; 冷卻完它會再回到同一件 (`helper_recurrent`), 但幾點回去對不準, 不算, 所以它回去之後那件會比讀到的 `done_at` 早好, 那時重讀 `status` 就對了. 寫「(沒算助手)」的是改版前存的匯出, 助手在做卻沒算進去, 重讀一次 `status` 就好
- **匯出只寫加速還剩幾秒, 不寫倍率**, `status` 把每一種加速都照 `parsers/village.py` 的 `SPEED_UPS` 算 (工人是藥水的 10 倍). 遊戲也有只把工人加速兩倍的特殊道具, 匯出裡怎麼寫還沒量過; 跟藥水寫在同一格的話, 算出來的 `done_at` 會偏早, 照新的讀數再算就好, 不是讀錯. 照舊當 10 倍算, 使用者的決定

**讀到不是村莊, 收掉再讀一次, 不停下來問**: 第一行寫「村莊匯出沒讀到: 遊戲沒有回到村莊畫面」, 或兩個世界那一行都寫「畫面不是村莊」. 畫面上多半是沒收掉的視窗或彈窗; 他在手機上玩的話遊戲會跳被擠掉的對話框, 指令回的是下面的 `session_taken`, 不是這個. `status` 讀到不是村莊時自己已經按過幾次返回, 所以先 `ai_coc capture` 留一張 (它不佔模擬器), 圖上看得到 X 就 `tap` 它, 看不到就 `ai_coc launch --restart game` (不帶 `--restart` 的不按它不認得的視窗), 再讀一次, 回報時附那張圖講一句 (使用者 2026-11-12: 「下次遇到這種問題可以直接繼續操作嗎 不要停下來問我」). 還是不是村莊才停下來跟他講. **另一部裝置登入了**: `status` 兩種都不回, exit code 1, 印出的跟 `result.json` 都只有 `outcome` 是 `session_taken`; 這才停下來告訴他, 他說可以之前一個 `ai_coc` 指令都不要下.

## 開鐘塔

鐘塔的免費加速 (`status` 表上鐘塔那一列寫「現在」才能開; 能開的標記到點才出現):

1. `world --night` 到夜世界
2. `view --zoom out` 停好鏡頭: `boost` 自己不拉遠, 而標記的大小跟點它下方多遠都是在最遠的鏡頭量的; 開船不會替靠岸的那邊拉遠
3. `ai_coc boost`. 它只在遊戲浮在鐘塔上那個能開的時鐘標記下, 按帶著時鐘、沒標價的那顆免費加速; 冷卻中同一顆要寶石, 它不按
4. 照「收尾」取消選取 (它把鐘塔留在選著的狀態); 原本在日世界的就開回去 (`world --day` / `--night` 自己會停鏡頭, 不用先 `view`)

回 `boosted` 就講一聲開了; 其他的照它的 `outcome` 講為什麼沒開成 (到點了還 `not_ready`, 多半是他自己先開了, 或標記被別的東西擋住), 附它留下的圖.

## 先確認在哪個村莊, 有沒有空

```bash
uv run --no-sync ai_coc world      # 回 day / night, 不點東西
uv run --no-sync ai_coc status     # 兩個世界每件升級幾點好, 加上這個世界閒著幾個
```

兩個世界的建築、兵種、英雄完全不同, 要升的在另一邊就先 `world --day` / `--night`. **工人、實驗室、戰寵小屋各自要有空才買得了**: 全忙的時候遊戲照樣讓你打開確認視窗, 按下去它跳「所有建築工人都在忙碌中！」跟一顆寶石按鈕 (量過), `confirm` 回 `unexpected` 不再按任何東西. **有哥布林活動時, 跳的可能是聘請哥布林的視窗** (工人或研究員, 兩種都量過), `confirm` 回 `goblin_offered`, 視窗的 X 在右上 (約 1430, 193). 計數讀到有閒著的而按下去跳的是它, 那個閒著的就是哥布林那格. 付不付照「哥布林」那一節. 所以先看計數: 面板每個分頁上就寫著空閒數/總數, 開了面板看那個就夠, 不用另外跑 `status`; 計數只算遊戲停著的那個世界. 沒空就不要走到 `confirm`. 讀價格不受這個限制, 全忙也照樣開面板讀回來.

**剛好的那一件要再升 (續升) 之前, 看那個分頁的空閒數**: 活動多給的哥布林格 (工人或研究) 做完那一件就收回, 續升要再聘一次 (「哥布林」), 所以時間到不代表有空格. 空閒數是 0 就不升. 之前讀的 `status` 是那一件還佔著格子時讀的, 它那一行的閒置數本來就是 0, 不能拿來判斷.

## 面板

```bash
uv run --no-sync ai_coc tap 1495 800          # 「建造」: 先借到模擬器, 回一張點完的圖
uv run --no-sync ai_coc swipe 1385 740 1385 240   # 面板往下捲大約一頁 (7 列)
uv run --no-sync ai_coc confirm --price 10800 --item "加農炮 12 級" # 確認鈕上的價格要是這個才按
```

**每個指令都帶同一個 `--session`** (還有 `--agent`、`--mission`): 借到的那個指令沒帶的話, 它一跑完就把借用還回去, 打資源的迴圈會在你兩步之間插進來 (`share-emulator` 的「借, 用完還」).

**`tap`「建造」是第一步, 不用先 `view --zoom out`**: 面板、視窗跟它們的按鈕畫在固定的位置, 鏡頭在哪都一樣, 點建築那一列遊戲自己會把鏡頭移過去 (一次 `view` 要二十幾秒). 背景有打資源的迴圈時, 這一下會等迴圈打完手上那一場再借走模擬器, 所以座標從它回來的那張圖量, 不要從借到之前截的圖量. 之後的 `tap`、`swipe`、`confirm` 都在這次借用裡, 不會再等. 用完照 `share-emulator` 的「借, 用完還」`giveback`.

**`tap` 跟 `swipe` 每次都回一張點完的圖** (`result.json` 的 `frame`), 下一步看那張決定, **永遠照最新那張圖上的位置點**: 面板捲過、視窗開關過, 舊圖上的座標就不準了. 它們會拒絕幾種會花錢或毀掉東西的點法 (`outcome`): 確認視窗開著時只准點它右上角的 X; 遊戲對話框只准按取消; 商店跟加號那排不點 (面板開著時那排往左移, 一樣不點); 大顆的綠色按鈕不點 (確認、立即完成、寶石補位都是綠的; 面板沒開時整個畫面都算, 開著時算面板左邊); 建築選單那一排只要有「立即完成」就整排不點 (旁邊的「取消」會把在升的取消掉); 戰鬥中什麼都不點. 被拒絕的那張圖就是當下的畫面.

**面板長這樣**: 主村底下四個分頁, 從左到右「建築和英雄」(工人, 約 1222, 850)、「軍隊升級」(實驗室, 約 1330, 850)、「英雄裝備」(鐵匠鋪, 用礦石, 不碰)、「英雄戰寵」(約 1547, 850); 夜世界只有工人 (約 1277, 850) 跟實驗室 (約 1492, 850) 兩個. 面板打開時停在上一次看的分頁, 看圖上哪一個是亮的, 不是要的就點它. 每個分頁上寫著空閒數/總數. 分頁上方由上往下:

1. **正在升級的列**: 整列是綠色進度條加倒數. 點下去不花錢, 花錢的在它開出來的東西上, 那些 `tap` 會拒絕: 主村的英雄、戰寵跟實驗室的研究跳「正在將X升至N級」, 綠色的「立即完成」用寶石, 它左邊那顆 (英雄是藍色的「英雄之書」, 研究是「戰鬥之書」) 用魔法道具, 只能點 X; 建築 (兩個村莊都是) 會把鏡頭移過去選起那一棟, 跳出資訊、取消、立即完成那一排, 整排不點; 夜世界的英雄也是這樣, 選起地圖上的它, 那一排多一顆「更換造型」. **英雄、研究跟戰寵的這個視窗開著等到倒數到 0, 會自己變成「將X升至N+1級？」**, 不用關掉重找 (量過). **建築到 0 時那一排自己收掉**, 面板上那一列也移走; 這時 `tap` 地圖上的那一棟, 跳出來的那一排就有「升級」 (量過). 夜世界的英雄到 0 時那一排一樣收掉, 面板上那一列移到「建議升級」, 點它直接跳「是否提升至N+1級？」 (量過)
2. **建議升級**: 遊戲挑的幾列, 每列有名字、時間、價格跟資源圖示. 剛升完的英雄常出現在這裡, 但不保證. 要升哪一件不從這一區挑 (「沒人指名時挑哪一件」)
3. **其他升級**: 其餘每一樣能升的, 先黑水再聖水再金幣, 各自由貴到便宜. 標了 `x N` 的是同等級的 N 棟, 點下去開其中一棟. 最後面帶鎖頭的是還不能升的 (寫著要先升什麼)

往下捲一次大約七列; 捲完的圖跟上一張一模一樣就是到底了. 建築和英雄分頁大約要捲九次, 軍隊升級七次, 戰寵兩次.

## 點那一列, 然後按下去

1. 在最新那張圖上找到那一列, `tap` 它的名字
2. 回來的圖是確認視窗, **先讀標題**: 主村是「將X升至N級？」, 夜世界是「是否提升至N級？」加上視窗裡的建築名 (英雄的視窗沒寫名字, 畫的是英雄本人, 確認鈕在右下). 不是要的那個, 或者是「正在將…」, 就 `tap` 右上角的 X (主村約 1413, 70; 夜世界約 1340, 57) 關掉, 回面板重找. 這一步什麼都不花
3. 讀確認鈕上的價格, 應該跟那一列寫的一樣. 有折扣時是活動的顏色 (黃字, 半價時綠字), 下面劃掉的是原價; 列上寫的也是折扣後的價錢, 給 `confirm` 的就是這一個. 價格是選單今天寫的, 不是固定的表: 金券跟活動任務會打折, 同一級這週跟上週可能不一樣, 跟之前讀到的或 wiki 不同不算讀錯; 懷疑讀錯就裁一塊按鈕的圖來看, 不拿記得的價格比
4. `ai_coc confirm --price <那一列的價格> --item "<那一件> <升到的等級>"`. 它自己再讀一次按鈕: 是金幣、聖水或黑水的圖示, 價格一模一樣, 不是紅字, 才按, 而且只按一次. `--item` 寫第 2 步標題上讀到的那一件跟升到幾級 (例如 `雷電飛龍 8 級`), 記進紀錄: 確認鈕以外的字 `confirm` 讀不出來, `ai_coc tended` 列升了什麼就照它; `--goblin`、`--pay` 也一樣帶

`confirm` 的 `outcome`:

- `confirmed`: 按了, 視窗關了. 看它回的圖: 面板會回來, 那一項出現在正在升級的列裡, 左邊倉庫條的數字少了 (面板開著時倉庫條整排往左移). 夜世界的研究例外: 遊戲接著開「升級部隊」視窗, 最上面那條淺綠色的就是剛開始研究的那一項跟倒數, 確認是它之後 `tap` 視窗的 X (約 1318, 62) 回到面板; 視窗上的寶石「立即完成」跟研究藥水 `tap` 都會拒絕. 主村的研究跟戰寵也不關視窗: 開始以後, 確認視窗直接變成「正在將X升至N級」, 按鈕換成寶石的「立即完成」, `tap` 它的 X (約 1413, 70) 回到面板 (量過)
- `price_mismatch`: 按鈕上的價格跟你給的不一樣 (`offer` 是它讀到的), 什麼都沒按. 多半是點錯列, 回第 2 步. 標題對而 `offer` 只差一兩位數 (夜世界放大的數字讀成 `2 400 800` 這種), 是讀錯不是點錯, 停下來回報, 附那張圖
- `not_a_resource`: 按鈕不是資源價格, 是寶石 (點到正在升級的列) 或讀不出來, 什麼都沒按
- `cannot_afford`: 紅字, 資源不夠, 什麼都沒按. 按下去遊戲會叫你用寶石補差額
- `no_sheet`: 畫面上沒有確認視窗
- `refused_by_game`: 按了之後遊戲跳兩顆按鈕的對話框, 它已經按了取消; 看回來的圖還剩什麼, 照「收尾」收乾淨
- `unexpected`: 按了之後出現別的畫面, 它沒有再按. 最常見的是「所有建築工人都在忙碌中！」跟一顆寶石按鈕: `tap` 它右上角的 X 關掉 (寶石按鈕 `tap` 會拒絕), 回報卡在工人全忙
- `goblin_offered`: 按了之後跳出聘請哥布林的視窗 (工人或研究員), 它沒有再按, 視窗留著. `goblin.gems` 是聘請鈕上的寶石數, 付不付照「哥布林」那一節; `goblin` 是 null 就是寶石數讀不出來, 照那一節第 4 步
- `sheet_stayed`: 按了但確認視窗沒關, 沒有再按. 看圖, 不懂就停下來給使用者看
- `no_wall_menu` (只有 `--pay`): 面板左邊沒有選著城牆的選單, 或已經有視窗、對話框蓋著, 什麼都沒按. 你自己先 `tap` 了升級鈕的話, 確認視窗已經開著, 改用不帶 `--pay` 的 `confirm`
- `sheet_disagrees` (只有 `--pay`): 按了城牆的升級鈕, 跳出的確認視窗價格或資源跟按鈕不一樣, 視窗留著沒按: `tap` 它的 X, 重讀選單
- `no_confirmation` (只有 `--pay`): 按了城牆的升級鈕卻沒跳出確認. 看圖: 牆到了大本營的上限時, 遊戲跳的視窗確認鈕是灰的, `tap` 它的 X, 這種牆要等大本營升上去

帶 `--pay` 時 `price_mismatch` 跟 `cannot_afford` 說的是城牆選單上那顆升級鈕 (`wall`), 它也一樣沒按.

借用要留到畫面收乾淨才還: 還了之後打資源的迴圈會接著跑, 留著的視窗會擋住它.

**確認鈕永遠只用 `confirm` 按, 不要用 `tap` 點它**, `tap` 也會拒絕. 確認視窗左邊另一顆「確認」是用魔法道具 (建築之錘、戰鬥之錘、英雄之錘) 付的, 任何情況都不點.

## 收尾

升完或不升都把畫面收乾淨, 每一下都照上一張回來的圖點: `confirm` 按成之後確認視窗多半已經自己關了, 這時再點 X 的位置會點到後面面板上的那一列, 確認視窗還在才 `tap` 它的 X. 面板 `tap` 右上角的紅色 X (約 1572, 30). 面板關了那棟 (或那面牆) 還是選著的, 畫面下方留著它的選單: 先 `ai_coc view --zoom out` (選著的時候它只拉遠, 回 `selected`; 回 `parked` 就是沒有選著的, 到這裡就收好了, 不要再點: 停好的鏡頭每次差到一百多像素, 下面那一點在停好的鏡頭上量過落在城牆上, 把牆選了起來), 回 `selected` 才 `tap` 村莊圍牆外的場景取消選取 (日世界現在的場景量過 1200, 560), 看回來的圖那排選單不見了才算. 不要在拉近的鏡頭上找空地點: 村莊排得密, 量過連三次分別點到城牆、看不見的陷阱跟收集器. 這一步不能省: 之後停鏡頭的指令 (`collect`、`world --day` / `--night`、`view`) 都用拖曳, 選著的時候拖曳會從選單的按鈕上開始而拖不動鏡頭 (量過), 剛好從選著的建築上開始的話, 可能會把它拖到別處 (沒量過, 不要試). 取消選取之後不用再停鏡頭, 要點地圖的指令都會自己停. 最後 `giveback`, 自己一步.

## 哪些不用問, 哪些要

**這一節管他開口要花而沒說升哪一件的時候** (「這些錢幫我花在建築上」), 跟好了的那一件再升同一件. 開口是他講的, 不是你判斷出來的; 他另外給過授權的照他的 (`takeover` 的常設授權). 只問多少錢、有哪些的, 什麼都不花. 不用問的挑哪一件, 照下一節「沒人指名時挑哪一件」.

- **城牆: 要使用者指名, 預設不刷.** 使用者的常設交代. 籠統的「把資源花掉」不算指名到牆
- **建築: 工人閒著就不用問**, 滿倉加上發呆的工人是雙重浪費. 他沒指名的時候照下一節挑; 回報講挑了什麼
- **夜世界的時光鐘樓不主動升**, 續升跟託管都不挑它, 他說要升才升. 之前停在 9 級是為了好找出來加速, 但 `boost` 找的是它頭上的時鐘標記, 不是面板. 升到 10 級之後的第一次 `boost` 要看它留下的圖: 點標記下方多遠 (`CLOCK_TOWER_BELOW`) 是在 9 級的鐘塔上量的, 換了造型可能點不中 (點不中什麼都不按, 只是沒開成)
- **聖水收集器、金礦、闇黑重油提煉井 (只有日世界有) 兩個世界都不升**, 續升跟託管都一樣: 好了的那一件是它們就當它滿級, 別的挑選也不挑它們, 問他要升什麼的選項裡也不列 (使用者要永遠記得的交代). 他自己指名要升才升
- **日世界的儲金罐跟聖水瓶只升到 18 級, 闇黑重油罐只升到 12 級**, 到了就當它滿級, 同上
- **超級蓄能暫時一律不升**, 續升跟託管都一樣: 已經滿級的建築上的超級蓄能不挑, 好了的那一件是超級蓄能也不續升. 他自己指名或說恢復才升
- **英雄、研究、戰寵: 要使用者指名**, 他給過常設授權照下一節挑的除外 (跨時間顧著村莊的時候). 升級中的英雄不能上場, 升一個是拿接下來幾天的進攻火力去換; 研究跟戰寵挑哪個也是他的取捨. 讀出價格列給他挑 (`AGENTS.md` 的 Putting a decision to the user)

上面的名字是遊戲的寫法, `ai_coc search` 照這個找得到 (超級蓄能不是一樣東西, 查不到).

**寶石跟現金不碰, 只有聘請哥布林照「哥布林」那一節付**, 魔法道具也不碰.

## 沒人指名時挑哪一件

**挑法只寫在這裡**: 託管的常設授權 (`takeover` 的「到點的那一件」: 同一件升不了、開始時就閒著、開始時問他的那幾項) 跟他開口要花而沒說升哪一件的 (上一節) 都照這一節挑. 他指名的跟 `notes` 永遠優先.

**候選從 `ai_coc search` 來, 不從面板的「建議升級」來** (使用者 2026-11-12 定的; 那一區是遊戲挑的, 不照他的順序). 照「問狀況」最後一段列: `--section builder`、`lab` 或 `pets`, 加 `--day` 或 `--night` 跟 `--skip-max-lvl`. 候選是「下一次」那一行寫著「現在能升 N 個」的; 上一節不升或停在上限的不是候選, 時間再短也不挑. 每一類裡候選照它最快那一級的牌價時間由短到長排在最前面, 所以最短的是第一個; 研究跟戰寵一種只有一個, 最長的就是寫著「現在能升」的最後一個. 時間跟價格是遊戲表上的牌價, 活動可能讓實際的少一些, 拿來排長短就夠; **面板只在要買的時候開**, 讀那一列的實際價格給 `confirm`.

**每一格挑哪一件** (使用者定的; 時間長短是 2026-11-12 定的):

| 空出來的是                  | 挑                                                                       |
| --------------------------- | ------------------------------------------------------------------------ |
| 實驗室                      | 牌價時間最長的 (「研究的部分, 大多數情況時間越長表示該兵種 / 藥水越強」) |
| 戰寵小屋                    | 跟實驗室一樣, 牌價時間最長的 (使用者 2026-11-12 定的)                    |
| 哥布林那一格 (研究員或工人) | 牌價時間最短的, 哥布林會走; 日世界的哥布林工人一樣照下面的順序           |
| 夜世界的工人                | 英雄優先, 英雄之間挑時間最短的; 沒有英雄能升才挑建築, 一樣挑時間最短的   |
| 日世界的工人                | 照下面的順序                                                             |

哥布林那一格照它自己那一列, 不照實驗室跟夜世界工人那兩列.

**日世界的工人另有順序**: 英雄一律續升, 建築也先續升同一棟; 沒有英雄或那一棟能續升的空工人 (好了的那一棟升滿了、英雄升滿了、開始時就閒著都算), 照這個順序挑, 每一組裡挑時間最短的:

1. 地獄之塔
2. 地獄之塔都升滿了, 才換箭塔、法師塔、防空火箭、空氣炮. 地獄之塔還沒滿但沒有一座寫著「現在能升」(每一座都在升), 這個工人就挑這第二組, 不空著, 也不去升兩組以外的

兩組都升滿了才照上表夜世界的工人那一列挑.

**他開口要花的那一次 (不是託管)**: 英雄照上一節要他指名, 上面輪到英雄的那一步跳過. 倉庫付不起挑到的那一件, 就照「做完的樣子」的卡在錢回報差多少, 不改挑順序後面的: 工人一派出去就是好幾天, 綁在他排在後面的東西上不划算, 資源打得回來.

## 哥布林

**聘請哥布林的寶石有上限, 上限內直接付, 超過就改升備案, 備案也超過才問**. 上限預設是 **350 顆, 含 350** (2026-11-11 他調的). 寶石是真錢買的, 他要的是哥布林的時間不浪費, 花費也控制住.

**上限他可以暫時調** (2026-11-12 定的, 例如「活動期間拉到 500」): 用 `ai_coc note add "<上限幾顆, 到什麼時候>" --day` 記進 `state.json` 的 `notes`, 他給了期限 (活動結束, 某一天) 就寫上. `notes` 裡的上限蓋過上面的預設; 期限到了就 `ai_coc note done <第幾條> --day` 刪掉 (第幾條是 `ai_coc note` 列出來那一條前面的編號), 回到預設. 暫時的上限不改這份 skill, 上面那一行只留預設.

**哥布林工人跟研究員預設要用** (2026-11-11 他定的): 哥布林那格跟一般的格一樣拿來升. 那格做的那一件做完而還沒到頂, 就再聘一次哥布林續升; 到頂了照「沒人指名時挑哪一件」挑, 他的 `notes` 一樣優先, 寶石照下面.

1. **先挑好要升哪一件跟一件備案, 才看寶石** (備案是使用者 2026-11-12 定的). 要升的照平常的規矩挑. 備案是哥布林那一格能升的裡面, 跟要升的那一件不同、牌價時間最短的一件 (日世界的工人照「沒人指名時挑哪一件」的順序); 託管在排的時候就先定好, 寫進報告的「後續」. 聘請的寶石隨那一件的等級變貴 (紀錄上巨石投手 31 → 95 → 111 → 120 顆, 雷電飛龍 63 → 111 → 135 → 143 → 160 → 255 顆; `ai_coc tended --since 2026-10-20`), 時間短的便宜, 所以備案多半壓得進上限
2. **寶石數你自己也讀一次**: 在按下確認那次 `confirm` 存的那張圖 (`frame`) 上讀聘請鈕的寶石數, 跟它回的 `goblin.gems` 比, 不一樣就照第 4 步. 視窗有時只有中間一顆按鈕, 有時並排兩顆: 讀左邊「哥布林建築工人」那顆 (`goblin.gems` 也是它), 右邊「空出一個建築工人」是用寶石把別的工作做完, 不讀也不按. 上限跟付的數都照你讀的, 因為 parser 自己核對自己, 少讀一位數就溜過上限, 而收尾的寶石數比對要等寶石花掉了才抓得到. 上限內: `ai_coc confirm --price <你讀的寶石數> --goblin --item "<同一件>"`, 兩邊讀的一致才按得下去. 它只認聘請哥布林工人的那個視窗, 寶石數一模一樣才按 (「所有建築工人都在忙碌中！」那種用寶石把別的工作做完的視窗它不按, 回 `no_goblin`). 回 `confirmed` 就講升了什麼、付了幾顆寶石; 動手前跟收尾後讀到的寶石數 (「做完的樣子」) 要剛好差這麼多
3. 超過上限: 不按, `tap` 視窗的 X 關掉, 直接改點備案那一列, 照第 2 步讀它的寶石數, 不重挑也不先問, 他指名要升的那一件也一樣 (2026-11-12 他定的: 「改升備案, 不問」). 備案在上限內就付, 回報講用了備案、原本那一件要幾顆
4. 備案也超過上限, 你讀的寶石數跟 `goblin.gems` 不一樣, `goblin` 是 null (寶石數讀不出來), 或回 `no_goblin` (認不得的視窗): 不按, `tap` 視窗的 X 關掉、照「收尾」收乾淨、`giveback`, 再問他 (`AGENTS.md` 的 Putting a decision to the user): 哪一件、要幾顆寶石 (原本那一件跟備案各幾顆; 兩邊讀的對不上就兩個數都講), 三個選項「升級」「不升級」「我上線自己處理」. 他選升級, 回來照他選的那一件再點一次, 付他答應的那個數
5. 實驗室的哥布林研究員同一套
6. **活動最後一件一律先問, 上限內也問**: 哥布林一個月只來兩天左右, 他會在活動快結束時故意排一件超長的, 讓哥布林做到活動結束之後. 所以他講了活動幾點結束, 就用 `ai_coc note add "<活動幾點結束>" --day` 把那個時間記進 `state.json` 的 `notes`, 活動結束後刪掉; 這次聘的哥布林會做到結束之後 (現在加上那件的升級時間超過結束時間) 的, 就是最後一件, 照第 4 步問他, 讓他自己挑要排哪一件. 他沒講結束時間就照上限

`confirm --goblin` 的 `outcome` 跟一般的一樣讀, 多一個 `no_goblin`: 畫面上沒有聘請哥布林工人的視窗, 或讀不出寶石數, 什麼都沒按. `price_mismatch` 是寶石數跟給的不一樣.

## 城牆

**兩個世界都從面板進去**. 在夜世界量過; 他的日世界牆都升滿了, 照他說的先假設日世界一樣.

1. 工人分頁 (主村的「建築和英雄」) 的「其他升級」裡有一列「城牆 x N」, 寫著一面的價格. 這一列標的是金幣還是聖水會變 (聖水多的時候排在聖水區, 金幣多了換到金幣區), 兩區都要找. `tap` 它, 鏡頭跳到一面那個等級的牆並選起來, 面板不關; 再點一次會換一面同等級的牆
2. 面板左邊出現城牆的選單: 「資訊」「整排選取」「升級更多」跟兩顆升級鈕, 左邊金幣、右邊聖水, 價格一樣. 有時分兩排 (升級鈕在下排), 有時五顆排成一排, `confirm --pay` 兩種都認
3. 只升一面就跳到第 4 步. 錢夠買好幾面就用批次, 不要一面一面升 (使用者要的). 一次升好幾面: `tap`「升級更多」, 前三顆變成「移除城牆」「新增城牆」, 每按一次「新增城牆」多一面同等級的牆, 升級鈕上的價格跟著加上去 (兩面就是兩倍). 先算好要加幾面 (一面的價格乘上面數, 不要超過倉庫); 價格變紅字就是加過頭了, `tap` 面板上城牆那一列重新選一面, 少加一面重來
4. `ai_coc confirm --price <升級鈕上的價格> --pay gold --item "城牆 <升到的等級> ×<面數>"` (或 `elixir`). 它自己讀那顆鈕, 價格一模一樣、不是紅字才按; 一面的會跳確認視窗, 它再對一次價格才按; 好幾面的會跳「升級城牆／是否確定要花費…」的對話框, 它按確定. **升級鈕不要自己 `tap`**: 那樣跳出來的對話框它不會按, `tap` 也只准按取消
5. 看它回的圖, 要再升就從第 1 步再點一次城牆那一列

**「整排選取」不是升級**, 是搬移城牆的模式, 進去之後只有一顆「整排旋轉」, 按下去會把整排牆轉向, 改到村莊的佈局. 兩顆都不要點; 不小心進去了, `tap` 面板上城牆那一列就會退出來.

**牆跟建築搶同一個工人**: 牆付錢當下就升好、工人立刻還回來, 建築把工人綁住好幾天, 所以他指名要刷牆的那一趟, 牆先刷, 刷不動了才升建築. 全忙的時候一面都買不了, 按下去遊戲跳「所有建築工人都在忙碌中！」跟寶石按鈕, 跟建築一樣是 `unexpected`, `tap` 它的 X.

**牆先刷, 但先把下一件要升的錢留下來**, 不然牆會把它吃光. 牆刷完要接著升東西的那一趟才留; 刷完牆不接著升東西的 (他要的是一直刷牆) 不留:

1. 刷之前先在面板讀下一件要升的東西要多少、哪一種資源, 那一筆不動. 他沒說是哪一件, 就是剛升完、空出工人的那一件的下一級; 不知道剛升完的是哪一件, 就是第 4 步照「沒人指名時挑哪一件」會挑的那一列
2. 扣掉預留, 剩下的金幣跟聖水拿去刷牆, 兩種各算各的: 一種能刷幾面是它可用的量除以一面的價格
3. 夜世界的聖水車不另外領 (`collect` 他開口才跑): 刷完牆倉庫有空, 下一趟打資源第一輪去車子時它就自己倒進來. 日世界對應的是去部落城堡拿資源, 還沒做, 先跳過
4. 最後升那一件. 要不要升照「哪些不用問, 哪些要」: 建築工人閒著就升, 英雄要他指名 (他給過常設授權照「沒人指名時挑哪一件」挑的除外)

「升級更多」之後的按鈕數會變: 同等級的牆還很多時多一顆「新增城牆 +10」(2026-10-16 剩 14 面時有, 剩 10 面時沒有), 後面每顆都往右挪. 每按一下都照它回的那張圖找「+1」.
