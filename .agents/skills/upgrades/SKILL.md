# upgrades

一次性的升級: 答他問的升級狀況, 把他指名的東西升下去, 或開鐘塔, 做完就結束, 不睡著等時間到. 每個 `ai_coc` 指令都帶 `--agent`、`--session`、`--mission` (`AGENTS.md` 的 Say who is driving), 下面的例子為了好讀省略了.

## 做完的樣子

使用者拿到的是一段回覆, 照他問的是什麼:

- **問升級狀況**: 照「問狀況」的表
- **只問多少錢, 建議升級有哪些**: 答案本身, 名稱、等級、價格連同是哪一種資源; 紅色的 (買不起) 照讀. 什麼都不花
- **要升, 升成了**: 升了什麼, 花了多少, 現在剩多少
- **要升, 沒升成**: 卡在工人 (或實驗室、戰寵小屋) 全忙, 卡在錢, 還是面板上找不到那一列, 這三種的下一步完全不同, 要講是哪一種. 全忙的講幾點空出來 (`status` 的 `done_at`), 並問他要不要到時候替他升; 他要的話那是一趟跨時間的事, 這份不睡著等
- **英雄、研究、戰寵他沒指名是哪一個**: 讀出來的價格列給他挑, 不替他挑 (見「哪些不用問, 哪些要」)

**不要編數字**: 花了多少以前後兩次看到的倉庫差額為準, 不是標價. 差額跟標價對不上, 或者你沒動手倉庫卻少了, 多半是使用者自己在遊戲裡花的, 照實寫進回報就好, 不要為它問他: 金幣、聖水、黑水打得回來, 沒有成本.

**要盯的是寶石, 那是真錢.** 開工那張圖 (`tap`「建造」點完回來的那張) 跟收尾之後、`giveback` 之前 `capture` 的一張 (還了之後打資源的迴圈馬上開打, 寶石數就被蓋住了), 各讀一次右上角的寶石數. 少了就停手, 不再點任何東西, 馬上回報, 附那兩張圖; 這一趟照「哥布林」付過寶石的, 少的要剛好是付的那個數, 多少了才算.

**畫面停在乾淨的村莊**, 借來的模擬器還回去: 見「收尾」.

## 問狀況

**升級狀況不主動列, 他問了才列.** 不借模擬器重讀: 最新的那份村莊匯出 (`~/.ai_coc/account_json/` 裡, 每次 `status` 跟 `export` 都存當天那份; `ai_coc export --last` 不碰模擬器也不佔鎖, 回的就是遊戲最晚匯出的那份) 裡每一件在升的都帶 `done_at`, 減掉現在就是還剩多少. 那次讀完之後他說在遊戲裡動過, 或拿模擬器、手機玩過, 才照「讀一次」重讀. 讀到的每一件照 `day`、`night` 跟每一列的 `role` 分表: 日世界的建築 (含英雄)、實驗室、戰寵, 夜世界的建築 (含英雄)、實驗室, 各一張, 欄位是「預計完成時間 | 升級內容 | 等級」, 由早到晚, 時間寫日期加時刻, 等級寫成 `N→N+1` (`lvl` 是現在的等級), 升級內容寫那一列的 `zh` (遊戲自己的中文名); 沒東西在升的那一塊寫一行「沒有在升」, 帶 `timer` 卻沒有 `role` 的另外列出並講明. 鐘塔接在夜世界後面, 一行寫幾點能開 (`clock_tower_ready_at`). 他只問某一樣 (「多人箭塔幾點好」), 照下面「他問某一樣」那段用 `ai_coc search` 就好, 不用列整張表.

**他問一段時間裡升了什麼** (例如「這個月升了哪些」): `ai_coc growth --start-date <YYYY-MM-DD> --end-date <YYYY-MM-DD>`, 兩個日期不給就是存下的最舊跟最新那份; 它只讀 `~/.ai_coc/account_json/` 裡一天一份的匯出, 不碰模擬器, 列的是工人跟實驗室升的 (戰寵、英雄裝備不算), 名字是遊戲裡的中文. 要新到這一分鐘就先跑一次 `status`.

**他問升級從到點到按下確認花了多久**: `ai_coc turnaround [--since <YYYY-MM-DD>]`, 依王、實驗室、建築、戰寵印次數、中位數、平均跟最近十次, 哥布林那格跟城牆不算; 只讀 `runs.jsonl` 跟各次的 `run.log`, 不碰模擬器. 他問了才跑, 不放進任何流程.

**他問某一樣現在怎樣、滿級是幾級、能不能再升、下一級要多少錢多久**: `ai_coc search <中文名或英文名的一段, 或 data_id>`, 不碰模擬器也不佔鎖, 只讀存下的遊戲表跟最新那份村莊匯出 (上一次 `status` 或 `export` 存的; 要新到這一分鐘就先 `status`). 名字對得上的全部列出, 村莊裡有的排前面, 村莊還沒有的也查得到. 名字是遊戲自己的寫法, 不是平常的叫法 (地獄之塔, 「地獄塔」查不到), 對不上就給短一點的一段 (`地獄`). 它印的是中文摘要, 下面這些欄位在那次執行的 `result.json`. 每一種的 `max_lvl` 是遊戲的滿級; `owned` 是各幾級幾個, `upgrading` 是哪幾個在升、`done_at` 幾點好、`extra` 是不是哥布林那格; `limited_lvl` 是現在大本營 (或實驗室、英雄殿堂這些, 等級在匯出檔頂上的 `halls`) 最多讓它升到幾級, `next` 是下一次能開始的那一級, 幾個等級不同的就各一個 (`lvl`、`cost`、`time`; 正在升的那一個是再下一級; 滿級的沒有). `next.lvl` 大於 `limited_lvl` 就是被殿堂卡住, 印出來的那一行也會寫. `levels` 是遊戲表上每一級的 `needs`、`cost`、`time`, 買到那一級要的; 兵種、攻城機器跟法術的第一級是解鎖的, 不是研究的, 它的 `needs` 是訓練它的那一棟 (訓練營、闇黑訓練營、攻城機器工坊、法術工廠、闇黑法術工廠、建築大師訓練營) 要幾級, 之後每一級才是實驗室. 村莊還沒有的, 印出來那一行寫解鎖要哪一棟幾級、村莊裡現在幾級 (`unlock`). 超級兵種跟活動兵種的解鎖條件讀到的表裡沒有 (超級兵種看的是它的基本兵種幾級), 所以只印「村莊裡沒有」: 那只是最新那份匯出沒有它, 不代表他還沒解鎖. 同一種好幾棟、等級跟完成時間各不同, 加 `--all` 每一列分開列; `--section helpers` (或 `pets`、`heroes`、`units` 這些匯出裡的分區名) 列整區, 兩個世界都列, 再給名字就在那區裡找. 回 `no_tables` 是還沒存過遊戲表: 先跑 `ai_coc gamedata`, 只從模擬器讀遊戲檔, 不碰畫面也不佔鎖. 價格跟時間都是遊戲表上的牌價, 活動跟金券會打折, 實際可能只要一部分, 真要買照面板上寫的那個價格給 `confirm` (「點那一列」第 3 步).

## 讀一次

```bash
uv run --no-sync ai_coc status --label watch
```

它從遊戲自己的村莊匯出 (設定頁那一份) 讀兩個世界每件在跑的升級, 把在跑的藥水跟鐘塔算進去; 遊戲停著的那個世界, 另外讀右下角計數的閒置數字跟倉庫. **不切世界, 不問 Gemini.** 先照 `share-emulator` 的「開工先讀 `state.json`」: 背景有帶 `--yield` 的迴圈在跑時, `status` 會借走它, 讀完馬上 `ai_coc giveback` (自己一步; 使用者叫停時例外, 見 `share-emulator` 的「借, 用完還」), 不然它要等 30 分鐘才接回去. `result.json` 的欄位:

- **先看 `export`**: `exported` 才有 `timers` 跟 `clock_tower`. `no_village` 照下面的不是村莊處理; 其他的 (`settings_shut`、`row_not_found`、`nothing_copied` 之類) 是設定頁那一趟沒走完, 過幾分鐘再讀. 沒讀到的時候 `timers` 是空的, 不能拿來說沒東西在跑
- **`timers`** 由早到晚. `world` 是哪個世界; `role` 是 `builder` (工人)、`lab` (實驗室, 活動多給的研究格也算) 或 `pet` (寵物小屋, 他問才講), `null` 是還沒看過帶時間的那一區, 沒算加速, 回報時講明. `done_at` 是實際幾點好, `seconds` 是從匯出那一刻起還要幾秒, `timer` 是遊戲畫面上寫的正常速度倒數. `zh` 是遊戲自己的中文名, `en` 是英文名, 講給他聽用 `zh`; 是 `null` 的 (遊戲的表沒讀到) 不要自己翻, 看一張面板的圖. `extra` 是 `true` 的是活動哥布林那格在做的, 做完那格就收回. `max_lvl` 是遊戲的滿級, `limited_lvl` 是現在大本營或殿堂最多讓它升到幾級, `next` 是這一級升完之後的下一級 (`lvl`、牌價 `cost`、`time`), 滿級的是 `null`
- **`clock_tower`**: `ready_in` 是 0 就是現在能開, `ready_at` 是幾點能開, `boosting` 是正在跑的那一次還剩幾秒. `null` 是匯出裡沒有鐘塔, 或鐘塔正在升級
- **`helpers`**: 助手小屋裡每個助手幾點能再派, `ready_in` 是 0 就是現在能派, 名字一樣在 `zh`、`en`. 建築工人學徒跟實驗助手這兩個能派了就在下一次回話裡順口講一句, 講過就不再重講, 等它下一次冷卻完; 不幫他派, 也不為它推播
- **`builder` / `lab`** 是遊戲停著那個世界右下角計數的數字, 另一個世界的讀不到, 不為它開船. `outcome`: `counted` 讀到了; `unread` 數字讀不到, 過幾分鐘再讀; `not_a_village` 畫面不是村莊, 兩個都是就照下面的不是村莊處理
- **主村工人的總數 5、6、7 都正常, 實驗室 1 或 2 也是**: 工人常駐 5 個, 夜世界的巴布控制台解鎖之後常駐 6 個 (第六個是普通工人, 不用寶石; 使用者的帳號已經解鎖), 活動的哥布林工人再多 1 個; 實驗室常駐 1 格, 活動的哥布林研究員再多 1 格. 總數不拿來判斷有沒有空, 只看閒置數 (哥布林那格要寶石, 見「哥布林」)
- **工人學徒跟研究助手會讓掛著它們的那件比 `done_at` 早好, 目前不算** (使用者決定先跳過). 他的工人學徒是 8 倍, 實驗室助手是 12 倍, 量過跟 `done_at` 每分鐘提早的分鐘數對得上; 換成下一條 `SPEED_UPS` 的算法 (計時每秒走幾秒), 是正常的 9 倍跟 13 倍. 助手還在做的時候讀到的 `done_at`, 都比實際好的時間晚
- **匯出只寫加速還剩幾秒, 不寫倍率**, `status` 把每一種加速都照 `parsers/village.py` 的 `SPEED_UPS` 算 (工人是藥水的 10 倍). 遊戲也有只把工人加速兩倍的特殊道具, 匯出裡怎麼寫還沒量過; 跟藥水寫在同一格的話, 算出來的 `done_at` 會偏早, 照新的讀數再算就好, 不是讀錯. 照舊當 10 倍算, 使用者的決定

**讀到一次不是村莊就停**: `export` 是 `no_village`, 或兩個計數的 `outcome` 都是 `not_a_village`. 常見的原因是使用者正在手機上玩, 模擬器那邊被登出了, 而每跑一次 `ai_coc status` 都會經過 `ensure_coc` 把遊戲搶回來, 等於把他從手機上踢掉. 所以不重試: 停下來, 問他玩完了沒, 他說可以了再讀. 看欄位不要看句子, 那句話只在 `run.log` 裡. **另一部裝置登入了**: `status` 兩種都不回, exit code 不是 0, `result.json` 只有一句 `另一部裝置登入了這個帳號,沒有把登入搶回來`; 一樣停下來告訴他, 他說可以之前一個 `ai_coc` 指令都不要下.

## 開鐘塔

鐘塔的免費加速 (`clock_tower.ready_in` 是 0 才能開; 能開的標記到點才出現):

1. `world --go night` 到夜世界
2. `view --zoom out` 停好鏡頭: `boost` 自己不拉遠, 而標記的大小跟點它下方多遠都是在最遠的鏡頭量的; 開船不會替靠岸的那邊拉遠
3. `ai_coc boost`. 它只在遊戲浮在鐘塔上那個能開的時鐘標記下, 按帶著時鐘、沒標價的那顆免費加速; 冷卻中同一顆要寶石, 它不按
4. 照「收尾」取消選取 (它把鐘塔留在選著的狀態); 原本在日世界的就開回去 (`world --go` 自己會停鏡頭, 不用先 `view`)

回 `boosted` 就講一聲開了; 其他的照它的 `outcome` 講為什麼沒開成 (到點了還 `not_ready`, 多半是他自己先開了, 或標記被別的東西擋住), 附它留下的圖.

## 先確認在哪個村莊, 有沒有空

```bash
uv run --no-sync ai_coc world      # 回 day / night, 不點東西
uv run --no-sync ai_coc status     # 兩個世界每件升級幾點好, 加上這個世界閒著幾個
```

兩個世界的建築、兵種、英雄完全不同, 要升的在另一邊就先 `world --go`. **工人、實驗室、戰寵小屋各自要有空才買得了**: 全忙的時候遊戲照樣讓你打開確認視窗, 按下去它跳「所有建築工人都在忙碌中！」跟一顆寶石按鈕 (量過), `confirm` 回 `unexpected` 不再按任何東西. **有哥布林活動時, 跳的可能是聘請哥布林的視窗** (工人或研究員, 工人的量過): 左邊一隻哥布林, 標題「嘿，首領！」, 中間一顆綠色寶石鈕, X 在右上 (約 1430, 193), `confirm` 回 `unexpected`. 計數讀到有閒著的而按下去跳的是它, 那個閒著的就是哥布林那格. 付不付照「哥布林」那一節. 所以先看計數: 面板每個分頁上就寫著空閒數/總數, 開了面板看那個就夠, 不用另外跑 `status`; 計數只算遊戲停著的那個世界. 沒空就不要走到 `confirm`. 讀價格不受這個限制, 全忙也照樣開面板讀回來.

**剛好的那一件要再升 (續升) 之前, 看那個分頁的空閒數**: 活動多給的哥布林格 (工人或研究) 做完那一件就收回, 所以時間到不代表有空格. 空閒數是 0 就不升. 之前讀的 `status` 是那一件還佔著格子時讀的, 它的 `free` 本來就是 0, 不能拿來判斷.

## 面板

```bash
uv run --no-sync ai_coc tap 1495 800          # 「建造」: 先借到模擬器, 回一張點完的圖
uv run --no-sync ai_coc swipe 1385 740 1385 240   # 面板往下捲大約一頁 (7 列)
uv run --no-sync ai_coc confirm --price 10800 # 確認鈕上的價格要是這個才按
```

**每個指令都帶同一個 `--session`** (還有 `--agent`、`--mission`): 借到的那個指令沒帶的話, 它一跑完就把借用還回去, 打資源的迴圈會在你兩步之間插進來 (`share-emulator` 的「借, 用完還」).

**`tap`「建造」是第一步, 不用先 `view --zoom out`**: 面板、視窗跟它們的按鈕畫在固定的位置, 鏡頭在哪都一樣, 點建築那一列遊戲自己會把鏡頭移過去 (一次 `view` 要二十幾秒). 背景有打資源的迴圈時, 這一下會等迴圈打完手上那一場再借走模擬器, 所以座標從它回來的那張圖量, 不要從借到之前截的圖量. 之後的 `tap`、`swipe`、`confirm` 都在這次借用裡, 不會再等. 用完照 `share-emulator` 的「借, 用完還」`giveback`.

**`tap` 跟 `swipe` 每次都回一張點完的圖** (`result.json` 的 `frame`), 下一步看那張決定, **永遠照最新那張圖上的位置點**: 面板捲過、視窗開關過, 舊圖上的座標就不準了. 它們會拒絕幾種會花錢或毀掉東西的點法 (`outcome`): 確認視窗開著時只准點它右上角的 X; 遊戲對話框只准按取消; 商店跟加號那排不點 (面板開著時那排往左移, 一樣不點); 大顆的綠色按鈕不點 (確認、立即完成、寶石補位都是綠的; 面板沒開時整個畫面都算, 開著時算面板左邊); 建築選單那一排只要有「立即完成」就整排不點 (旁邊的「取消」會把在升的取消掉); 戰鬥中什麼都不點. 被拒絕的那張圖就是當下的畫面.

**面板長這樣**: 主村底下四個分頁, 從左到右「建築和英雄」(工人, 約 1222, 850)、「軍隊升級」(實驗室, 約 1330, 850)、「英雄裝備」(鐵匠鋪, 用礦石, 不碰)、「英雄戰寵」(約 1547, 850); 夜世界只有工人 (約 1277, 850) 跟實驗室 (約 1492, 850) 兩個. 面板打開時停在上一次看的分頁, 看圖上哪一個是亮的, 不是要的就點它. 每個分頁上寫著空閒數/總數. 分頁上方由上往下:

1. **正在升級的列**: 整列是綠色進度條加倒數. 點下去不花錢, 花錢的在它開出來的東西上, 那些 `tap` 會拒絕: 主村的英雄、戰寵跟實驗室的研究跳「正在將X升至N級」, 綠色的「立即完成」用寶石, 它左邊那顆 (英雄是藍色的「英雄之書」, 研究是「戰鬥之書」) 用魔法道具, 只能點 X; 建築 (兩個村莊都是) 會把鏡頭移過去選起那一棟, 跳出資訊、取消、立即完成那一排, 整排不點; 夜世界的英雄也是這樣, 選起地圖上的它, 那一排多一顆「更換造型」. **英雄、研究跟戰寵的這個視窗開著等到倒數到 0, 會自己變成「將X升至N+1級？」**, 不用關掉重找 (量過). **建築到 0 時那一排自己收掉**, 面板上那一列也移走; 這時 `tap` 地圖上的那一棟, 跳出來的那一排就有「升級」 (量過). 夜世界的英雄到 0 時那一排一樣收掉, 面板上那一列移到「建議升級」, 點它直接跳「是否提升至N+1級？」 (量過)
2. **建議升級**: 遊戲挑的幾列, 每列有名字、時間、價格跟資源圖示. 剛升完的英雄常出現在這裡, 但不保證
3. **其他升級**: 其餘每一樣能升的, 先黑水再聖水再金幣, 各自由貴到便宜. 標了 `x N` 的是同等級的 N 棟, 點下去開其中一棟. 最後面帶鎖頭的是還不能升的 (寫著要先升什麼)

往下捲一次大約七列; 捲完的圖跟上一張一模一樣就是到底了. 建築和英雄分頁大約要捲九次, 軍隊升級七次, 戰寵兩次.

## 點那一列, 然後按下去

1. 在最新那張圖上找到那一列, `tap` 它的名字
2. 回來的圖是確認視窗, **先讀標題**: 主村是「將X升至N級？」, 夜世界是「是否提升至N級？」加上視窗裡的建築名 (英雄的視窗沒寫名字, 畫的是英雄本人, 確認鈕在右下). 不是要的那個, 或者是「正在將…」, 就 `tap` 右上角的 X (主村約 1413, 70; 夜世界約 1340, 57) 關掉, 回面板重找. 這一步什麼都不花
3. 讀確認鈕上的價格, 應該跟那一列寫的一樣. 有折扣時是活動的顏色 (黃字, 半價時綠字), 下面劃掉的是原價; 列上寫的也是折扣後的價錢, 給 `confirm` 的就是這一個. 價格是選單今天寫的, 不是固定的表: 金券跟活動任務會打折, 同一級這週跟上週可能不一樣, 跟之前讀到的或 wiki 不同不算讀錯; 懷疑讀錯就裁一塊按鈕的圖來看, 不拿記得的價格比
4. `ai_coc confirm --price <那一列的價格>`. 它自己再讀一次按鈕: 是金幣、聖水或黑水的圖示, 價格一模一樣, 不是紅字, 才按, 而且只按一次

`confirm` 的 `outcome`:

- `confirmed`: 按了, 視窗關了. 看它回的圖: 面板會回來, 那一項出現在正在升級的列裡, 左邊倉庫條的數字少了 (面板開著時倉庫條整排往左移). 夜世界的研究例外: 遊戲接著開「升級部隊」視窗, 最上面那條淺綠色的就是剛開始研究的那一項跟倒數, 確認是它之後 `tap` 視窗的 X (約 1318, 62) 回到面板; 視窗上的寶石「立即完成」跟研究藥水 `tap` 都會拒絕. 主村的研究跟戰寵也不關視窗: 開始以後, 確認視窗直接變成「正在將X升至N級」, 按鈕換成寶石的「立即完成」, `tap` 它的 X (約 1413, 70) 回到面板 (量過)
- `price_mismatch`: 按鈕上的價格跟你給的不一樣 (`offer` 是它讀到的), 什麼都沒按. 多半是點錯列, 回第 2 步. 標題對而 `offer` 只差一兩位數 (夜世界放大的數字讀成 `2 400 800` 這種), 是讀錯不是點錯, 停下來回報, 附那張圖
- `not_a_resource`: 按鈕不是資源價格, 是寶石 (點到正在升級的列) 或讀不出來, 什麼都沒按
- `cannot_afford`: 紅字, 資源不夠, 什麼都沒按. 按下去遊戲會叫你用寶石補差額
- `no_sheet`: 畫面上沒有確認視窗
- `refused_by_game`: 按了之後遊戲跳兩顆按鈕的對話框, 它已經按了取消; 看回來的圖還剩什麼, 照「收尾」收乾淨
- `unexpected`: 按了之後出現別的畫面, 它沒有再按. 最常見的是「所有建築工人都在忙碌中！」跟一顆寶石按鈕: `tap` 它右上角的 X 關掉 (寶石按鈕 `tap` 會拒絕), 回報卡在工人全忙. 左邊站著一隻哥布林的是聘請哥布林的視窗, 照「哥布林」那一節
- `sheet_stayed`: 按了但確認視窗沒關, 沒有再按. 看圖, 不懂就停下來給使用者看
- `no_wall_menu` (只有 `--pay`): 面板左邊沒有選著城牆的選單, 或已經有視窗、對話框蓋著, 什麼都沒按. 你自己先 `tap` 了升級鈕的話, 確認視窗已經開著, 改用不帶 `--pay` 的 `confirm`
- `sheet_disagrees` (只有 `--pay`): 按了城牆的升級鈕, 跳出的確認視窗價格或資源跟按鈕不一樣, 視窗留著沒按: `tap` 它的 X, 重讀選單
- `no_confirmation` (只有 `--pay`): 按了城牆的升級鈕卻沒跳出確認. 看圖: 牆到了大本營的上限時, 遊戲跳的視窗確認鈕是灰的, `tap` 它的 X, 這種牆要等大本營升上去

帶 `--pay` 時 `price_mismatch` 跟 `cannot_afford` 說的是城牆選單上那顆升級鈕 (`wall`), 它也一樣沒按.

借用要留到畫面收乾淨才還: 還了之後打資源的迴圈會接著跑, 留著的視窗會擋住它.

**確認鈕永遠只用 `confirm` 按, 不要用 `tap` 點它**, `tap` 也會拒絕. 確認視窗左邊另一顆「確認」是用魔法道具 (建築之錘、戰鬥之錘、英雄之錘) 付的, 任何情況都不點.

## 收尾

升完或不升都把畫面收乾淨, 每一下都照上一張回來的圖點: `confirm` 按成之後確認視窗多半已經自己關了, 這時再點 X 的位置會點到後面面板上的那一列, 確認視窗還在才 `tap` 它的 X. 面板 `tap` 右上角的紅色 X (約 1572, 30). 面板關了那棟 (或那面牆) 還是選著的, 畫面下方留著它的選單: 先 `ai_coc view --zoom out` (選著的時候它只拉遠, 回 `selected`), 再 `tap` 村莊圍牆外的場景取消選取 (日世界現在的場景量過 1200, 560), 看回來的圖那排選單不見了才算. 不要在拉近的鏡頭上找空地點: 村莊排得密, 量過連三次分別點到城牆、看不見的陷阱跟收集器. 這一步不能省: 之後停鏡頭的指令 (`collect`、`world --go`、`view`) 都用拖曳, 選著的時候拖曳會從選單的按鈕上開始而拖不動鏡頭 (量過), 剛好從選著的建築上開始的話, 可能會把它拖到別處 (沒量過, 不要試). 取消選取之後不用再停鏡頭, 要點地圖的指令都會自己停. 最後 `giveback`, 自己一步.

## 哪些不用問, 哪些要

**這一節管他開口要花而沒說升哪一件的時候** (「這些錢幫我花在建築上」), 跟好了的那一件再升同一件. 開口是他講的, 不是你判斷出來的; 他另外給過授權的照他的. 只問多少錢、有哪些的, 什麼都不花.

- **城牆: 要使用者指名, 預設不刷.** 使用者的常設交代. 籠統的「把資源花掉」不算指名到牆
- **建築: 工人閒著就不用問**, 滿倉加上發呆的工人是雙重浪費. 他沒指名的時候, 挑「建議升級」裡買得起的, 回報講挑了什麼
- **夜世界的時光鐘樓不主動升**, 續升跟託管都不挑它, 他說要升才升. 之前停在 9 級是為了好找出來加速, 但 `boost` 找的是它頭上的時鐘標記, 不是面板. 升到 10 級之後的第一次 `boost` 要看它留下的圖: 點標記下方多遠 (`CLOCK_TOWER_BELOW`) 是在 9 級的鐘塔上量的, 換了造型可能點不中 (點不中什麼都不按, 只是沒開成)
- **聖水收集器、金礦、暗黑重油提煉井 (只有日世界有) 兩個世界都不升**, 續升跟託管都一樣: 好了的那一件是它們就當它滿級, 別的挑選也不挑它們, 問他要升什麼的選項裡也不列 (使用者要永遠記得的交代). 他自己指名要升才升
- **日世界的儲金罐跟聖水瓶只升到 18 級, 暗黑重油罐只升到 12 級**, 到了就當它滿級, 同上
- **超級蓄能暫時一律不升**, 續升跟託管都一樣: 已經滿級的建築上的超級蓄能不挑, 好了的那一件是超級蓄能也不續升. 他自己指名或說恢復才升
- **英雄、研究、戰寵: 要使用者指名**, 他給過常設授權照表挑的除外 (跨時間顧著村莊的時候). 升級中的英雄不能上場, 升一個是拿接下來幾天的進攻火力去換; 研究跟戰寵挑哪個也是他的取捨. 讀出價格列給他挑 (`AGENTS.md` 的 Putting a decision to the user)

**寶石跟現金不碰, 只有聘請哥布林照「哥布林」那一節付**, 魔法道具也不碰.

## 哥布林

**聘請哥布林的寶石有上限, 上限內直接付, 超過就問**. 上限現在是 **250 顆, 含 250**; 他之後會看情況調, 照他最新講的改這一行. 寶石是真錢買的, 他要的是哥布林的時間不浪費, 花費也控制住.

1. **先照平常的規矩挑要升哪一件, 挑好了才看寶石**, 跟一般工人一樣. 超過上限就問, **不要為了壓在上限內改挑別的**: 那樣他就收不到該問的那一題
2. 上限內: 讀視窗上的寶石數, `ai_coc confirm --price <寶石數> --goblin`. 視窗有時只有中間一顆按鈕, 有時並排兩顆: 讀左邊「哥布林建築工人」那顆的數字, 右邊「空出一個建築工人」是用寶石把別的工作做完, 它不讀也不按. 它只認聘請哥布林工人的那個視窗, 寶石數一模一樣才按 (「所有建築工人都在忙碌中！」那種用寶石把別的工作做完的視窗它不按, 回 `no_goblin`). 回 `confirmed` 就講升了什麼、付了幾顆寶石; 開工跟收尾那兩張圖的寶石數要剛好差這麼多
3. 超過上限, 或回 `no_goblin` (認不得的視窗): 不按, `tap` 視窗的 X 關掉、照「收尾」收乾淨、`giveback`, 再問他 (`AGENTS.md` 的 Putting a decision to the user): 哪一件、要幾顆寶石, 三個選項「升級」「不升級」「我上線自己處理」. 他選升級, 回來照同一件再點一次, 付他答應的那個數
4. 實驗室的哥布林研究員同一套
5. **活動最後一件一律先問, 上限內也問**: 哥布林一個月只來兩天左右, 他會在活動快結束時故意排一件超長的, 讓哥布林做到活動結束之後. 所以他講了活動幾點結束, 就用 `ai_coc note add` 把那個時間記進 `state.json` 的 `notes`, 活動結束後刪掉; 這次聘的哥布林會做到結束之後 (現在加上那件的升級時間超過結束時間) 的, 就是最後一件, 照第 3 步問他, 讓他自己挑要排哪一件. 他沒講結束時間就照上限

`confirm --goblin` 的 `outcome` 跟一般的一樣讀, 多一個 `no_goblin`: 畫面上沒有聘請哥布林工人的視窗, 或讀不出寶石數, 什麼都沒按. `price_mismatch` 是寶石數跟給的不一樣.

## 城牆

**兩個世界都從面板進去**. 在夜世界量過; 他的日世界牆都升滿了, 照他說的先假設日世界一樣.

1. 工人分頁 (主村的「建築和英雄」) 的「其他升級」裡有一列「城牆 x N」, 寫著一面的價格. 這一列標的是金幣還是聖水會變 (聖水多的時候排在聖水區, 金幣多了換到金幣區), 兩區都要找. `tap` 它, 鏡頭跳到一面那個等級的牆並選起來, 面板不關; 再點一次會換一面同等級的牆
2. 面板左邊出現城牆的選單: 「資訊」「整排選取」「升級更多」跟兩顆升級鈕, 左邊金幣、右邊聖水, 價格一樣. 有時分兩排 (升級鈕在下排), 有時五顆排成一排, `confirm --pay` 兩種都認
3. 只升一面就跳到第 4 步. 錢夠買好幾面就用批次, 不要一面一面升 (使用者要的). 一次升好幾面: `tap`「升級更多」, 前三顆變成「移除城牆」「新增城牆」, 每按一次「新增城牆」多一面同等級的牆, 升級鈕上的價格跟著加上去 (兩面就是兩倍). 先算好要加幾面 (一面的價格乘上面數, 不要超過倉庫); 價格變紅字就是加過頭了, `tap` 面板上城牆那一列重新選一面, 少加一面重來
4. `ai_coc confirm --price <升級鈕上的價格> --pay gold` (或 `elixir`). 它自己讀那顆鈕, 價格一模一樣、不是紅字才按; 一面的會跳確認視窗, 它再對一次價格才按; 好幾面的會跳「升級城牆／是否確定要花費…」的對話框, 它按確定. **升級鈕不要自己 `tap`**: 那樣跳出來的對話框它不會按, `tap` 也只准按取消
5. 看它回的圖, 要再升就從第 1 步再點一次城牆那一列

**「整排選取」不是升級**, 是搬移城牆的模式, 進去之後只有一顆「整排旋轉」, 按下去會把整排牆轉向, 改到村莊的佈局. 兩顆都不要點; 不小心進去了, `tap` 面板上城牆那一列就會退出來.

**牆跟建築搶同一個工人**: 牆付錢當下就升好、工人立刻還回來, 建築把工人綁住好幾天, 所以他指名要刷牆的那一趟, 牆先刷, 刷不動了才升建築. 全忙的時候一面都買不了, 按下去遊戲跳「所有建築工人都在忙碌中！」跟寶石按鈕, 跟建築一樣是 `unexpected`, `tap` 它的 X.

**牆先刷, 但先把下一件要升的錢留下來**, 不然牆會把它吃光. 牆刷完要接著升東西的那一趟才留; 刷完牆不接著升東西的 (他要的是一直刷牆) 不留:

1. 刷之前先在面板讀下一件要升的東西要多少、哪一種資源, 那一筆不動. 他沒說是哪一件, 就是剛升完、空出工人的那一件的下一級; 不知道剛升完的是哪一件, 就是第 4 步照「哪些不用問, 哪些要」會挑的那一列
2. 扣掉預留, 剩下的金幣跟聖水拿去刷牆, 兩種各算各的: 一種能刷幾面是它可用的量除以一面的價格
3. 夜世界的聖水車不另外領 (`collect` 他開口才跑): 刷完牆倉庫有空, 下一趟打資源第一輪去車子時它就自己倒進來. 日世界對應的是去部落城堡拿資源, 還沒做, 先跳過
